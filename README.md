# YoluPainter-rs

YoluPainter のスタンドアロン版です。2D キャンバスと 3D モデルにテクスチャを描き、レイヤー（グループ・マスク・塗りつぶし・調整を含む）とチャンネルの作業を `.ylp` に保存できます。Unity 版 YoluPainter と Live Link でつなぐと、描いた色を Unity のシーンで実際のマテリアルに重ねて確認できます。

Windows を主な対象としています。Mac・Linux は試用向けです。

## できること

- ブラシと消しゴムで描画。組み込みのブラシ 13 個、直径・硬さ・間隔・不透明度・流量、筆先の画像・ゆらぎ・紙の質感・デュアルブラシ・色の変化・フェード・ペンの傾きと回転・筆の速さ・手ぶれ補正と入り抜き、効果のブラシ（ぼかし・指先・クローン）。Windows Ink の筆圧を直径・不透明度・流量に割り当てられます。
- ブラシの画面: 左の「ブラシ」のパネルに、グループ別（ペン・筆・エアブラシ・消しゴム・効果・特殊）の一覧があり、各ブラシの名前とその設定で描いた見本のストロークが並びます。行を押してブラシを替え、右下の「+」で今の設定を自分のブラシにでき、複製・名前の変更（ダブルクリック）・削除・ドラッグでの並べ替え・元に戻すができます。組み込みのブラシは消せず、設定を変えると「変更あり」の印が付きます。その下のツールプロパティ（直径・不透明度・硬さ・流量・間隔・筆圧の切り替え・手ぶれ補正）と、決まった直径の丸（ブラシサイズ）で素早く調整し、調整のボタンで「ブラシの詳細」の窓（形状・ストローク・筆圧と入り抜き・ゆらぎ・テクスチャ・デュアルブラシ・色の揺らぎ・効果・対称）を開きます。窓は動かせて、開いたまま描けます。消しゴム（`E`）は、消しゴムのグループで最後に使ったブラシで消します。自分のブラシは設定のフォルダの `brushes/` に 1 つ 1 ファイルで保存し、壊れたファイルは読み飛ばして、起動のときに知らせます。
- レイヤーの追加・削除・複製・名前変更・ドラッグでの並べ替え、グループ（入れ子・開閉）、レイヤーマスク（有効・反転・濃度、マスクへの描画）、塗りつぶし、調整（階調の反転・レベル補正・色相/彩度/明度）、クリッピング、表示・不透明度・26 種類の合成モード、取り消しとやり直し。
- マテリアルで塗る: 「マテリアル」のタブで、Color・Roughness・Metallic・Height・Normal・Emission から塗るチャンネルを選び、それぞれの値（Color は描画色、Emission は色、データは 0〜1、Normal は傾き）で 1 回のストロークを塗れます。2D・3D・バケツ・ポリゴン塗りつぶしで効き、1 回の取り消しで全チャンネルが戻ります。
- バケツ（`G`）とポリゴン塗りつぶし（`4`）: 範囲は三角形・メッシュの塊・UV アイランド・マテリアル（バケツは 2D で近い色も）。ポインタの下の範囲を 3D では面で、2D では UV の輪郭で強調します。バケツは今の選択範囲の内側だけを塗り、ポリゴン塗りつぶしは押したまま通った範囲を足して、離したときに 1 回の取り消しになります。
- ID の色で選択（`Shift+W`）: 焼いた ID マップの色から選択範囲を作ります（`Shift` 追加・`Ctrl` 削除）。メッシュの塊ごとの手動の ID の色も付けられます。手動の ID の色は `.ylp` にまだ書けないので、付けた文書の保存は理由つきで断ります。
- 選択範囲: 長方形・楕円形・なげなわ・多角形・自動選択（許容値・隣接・全レイヤー）を、置き換え・足す・引く・重ねるで組み合わせられます。反転・拡張・縮小・境界線・ぼかし・境界をくっきりで変え、ブラシと消しゴムは選択範囲の内側だけに効きます。選択範囲は 2D のキャンバスで作り、テクスチャセットごとに `.ylp` へ保存されます。
- 対称: 2D は縦・横・両方・放射状（2〜16）で、中心を動かせます（キャンバスに軸を表示）。3D はモデルの X・Y・Z に直交する面でのミラーと、軸のまわりの放射状（2〜16）で、面はモデルの原点か境界の中央に置け、写しを見えない面にも塗るか選べます（3D ビューに面と軸を表示）。写しが面に届かない・別のテクスチャセットのときは、その写しだけ飛ばします。指先・クローンとは組めません。
- チャンネル: 標準の 6 つとユーザーチャンネル（追加・名前・種類）。描くチャンネルの選択と、2D に表示するチャンネルの切り替え。チャンネルごとに層の有効・合成モード・不透明度を持てます。
- 日本語と英語の表示（「表示」メニューで切り替え）。
- 2D 表示の拡大縮小・移動・回転・左右反転。表示だけを変え、保存する画像は回転・反転しません。
- 3D ビューの試しの立方体、または Live Link で受け取ったモデルに描画。マテリアルごとにテクスチャセットを切り替えられます。3D で効くのは直径・硬さ・流量・不透明度・筆圧・色・色の変化・消しゴム・ステンシルと、効果のブラシ（ぼかし・指先・クローン）で、筆先・ゆらぎ・質感・デュアルブラシ・フェード・ペンの傾きと回転・筆の速さ・手ぶれ補正は 2D のキャンバスだけです。3D の指先・クローンは UV の島の継ぎ目をまたいで読みます。クローンの元は、Alt を押して動かさずに離したクリックで決めます（「揃える」で前のストロークの位置関係を続け、「全レイヤーから」で見えているレイヤーの重なりを読みます）。
- 3D ビューの見た目: マテリアル（Unity の Standard と同じ BRDF の PBR。Roughness・Metallic・法線・Emission が見える）・中立・チャンネルだけを見出しで切り替え、環境（空・スタジオ）・光・トーンマッピングを小さなパネルで設定できます。詳しくは [docs/PREVIEW.md](docs/PREVIEW.md)。
- FBX のモデルを開き、骨の回転と BlendShape でポーズを付けて、その形の上から描画（ポーズは保存しません）。マテリアルごとにテクスチャセットが付き、今のセットのマテリアルの面に描けます。
- `.ylp` の新規作成・読み込み・保存。Unity 版との互換性は[下の表](#unity-版との-ylp-の受け渡し)を参照してください。
- メッシュマップのベイク（「表示 → メッシュマップをベイク…」）。3D ビューのモデルから、チェックしたテクスチャセットごとに、ワールド法線・位置・AO・曲率・厚み・ID などを別のスレッドで焼きます（進み具合と取消つき）。焼く場所は「自動・GPU・CPU」から選べます（自動は使えるハードウェアの GPU があれば GPU、なければ CPU。GPU が使えない・予算を超える・途中で失敗したときは、理由を窓に出して CPU で焼き直します）。GPU で焼いた値は CPU と全バイト一致しません（f32 と f64 の丸めと光線の当たり外れで、AO・厚み・ベントノーマルは最大でおよそ 3%、測った値は [`crates/yolu-gpu/README.md`](crates/yolu-gpu/README.md)）。焼いた場所は保存しないので、同じ設定で焼き直すと GPU のある機械では値がその差の分だけ変わり、書き出す AO の PNG も変わります。焼いたマップは `.ylp` にセットごとに保存し、2D のキャンバスに重ねて見られます。モデルや設定が変わったマップは「古い」と表示し、書き出しの AO にも使いません。高ポリからの投影は選べません。
- テンプレートでの書き出し（「ファイル → 書き出し → テンプレート」）。Unity の Standard / URP Lit・HDRP Lit・lilToon が読む詰め合わせの PNG を、全テクスチャセットぶんフォルダへ書きます。名前は `<名前>[_<セット名>]_<画像>.png`。UV の外へ色を塗り広げ（パディング。モデルが無ければ掛けません）、焼いた AO があれば使います。もうあるファイルは確かめてから置き換えます。取消や、最後の置き換えを始める前の失敗では、元のファイルを変えません。
- PSD（RGB8）の読み込み（「ファイル → 読み込み」。新しいテクスチャセットとして足すか、今のセットの文書に替える）と書き出し（「ファイル → 書き出し → PSD」）。読み込めるのは編集できる PSD で、ラスター・グループ・単色の塗りつぶし・調整（反転・レベル補正・色相/彩度）・マスク・クリッピングはレイヤーになります。原本の保持だけ・拒否・このアプリで扱えない内容（キャンバス外の画素、保存できないレイヤーのロックなど）は理由を見せて何も変えません。書き出せるのは Color の写しで、反転したマスク・クリッピングされたグループ・半透明の塗りつぶし・PSD の刻みの間の調整・Color 以外のチャンネルの中身・Color と違うチャンネルごとの合成・フィルター・Generator・Anchor・パスがあれば理由を見せて書きません。取り込んだ PSD は書き換えません。
- アセットの棚（左の「アセット」）。選んだレイヤー（グループなら中身ごと）・レイヤーのマスクを「層を保存」「マスクを保存」でスマートマテリアル・スマートマスクとして棚に入れ、棚の素材をダブルクリック・右クリック・「置く」・レイヤーの一覧へのドラッグで今のテクスチャセットへ置きます（スマートマテリアルは落とした行の間かグループの中、スマートマスクは落とした行のマスク。1 回の取り消しで戻ります）。大きさが違うテクスチャセットには引き伸ばして置きます。棚は `.ylp` の resources に保存され、開くと戻ります。外の `.ylsmart` を棚へ読み込み・書き出せます（窓へ落としても読み込めます）。棚の画像は 1 枚のレイヤーとして置けます。画像を同梱した素材・Generator の再固定のある素材・フィルターなど core が持てない中身を含む素材は並ぶだけで、理由を見せて置きません（書き出せば原本のまま Unity 版で使えます）。ブラシとマテリアルも並ぶだけです。ユーザーチャンネルを使うレイヤーと、層のロックのあるレイヤーは `.ylsmart` に書けないので保存できません。棚に入れられるのは 256 個までで、いっぱいのときは足さずに理由を出します。大きな素材やいっぱいに近い棚への「層を保存」は別のスレッドで進み（その間は消す・読み込むを断ります）、消す・読み込むは棚の大きさに応じて、数百 MiB の棚では数秒止まります。
- ステンシル（プロパティの「ステンシル」タブ）。PNG を読み、画面に半透明で重ねた画像を通して、2D のキャンバスと 3D のビューの両方に塗れます。灰色の画像は量（輝度 × 透明度）、色の画像は色として読み（自動・量・色から選べます）、繰り返し（横・縦・縦横）・反転・重ねの濃さ・大きさ・角度を変えられます。置き場は画面に貼り付き、`T` を押したままドラッグして動かします（[操作の表](#最初の操作)）。2D のキャンバスでも 3D のビューでも、効果のブラシ（ぼかし・指先・クローン）にも効きます。ステンシルはアプリの状態で、`.ylp` にもブラシのプリセットにも保存しません（新規作成や開き直しでも残ります）。Linux の試験で確かめた機能で、Windows の Direct3D 12・Vulkan の実機、ペン、高 DPI の画面ではまだ確かめていません。

PNG の取り込みはステンシルだけです（棚に入れられるのは `.ylsmart` だけです）。

## ダウンロードとインストール

[Releases](https://github.com/YozoraKurage/YoluPainter-rs/releases) から入手します。Windows（64 ビット）には 2 つの形があります。

- `yolupainter-<版>-x86_64-pc-windows-msvc-setup.exe`（インストーラー）: 利用者ごとにインストールします。管理者権限は要りません。入れ先は `%LOCALAPPDATA%\Programs\YoluPainter`（変えられます）で、スタートメニューに登録し、`.ylp` をこのアプリで開く関連付けは選べます。アンインストールは「設定 → アプリ」から行い、設定・ブラシ・復旧用のデータも消すかを聞かれます（聞かれなければ残ります）。画面を出さずに入れるときは `/S`、関連付けは `/ASSOC=1`（付けない `/ASSOC=0`）、入れ終わったあとにアプリを起動するときは `/RUN` を付けます。
- `yolupainter-<版>-x86_64-pc-windows-msvc.zip`: 展開して `yolupainter.exe` を実行します（インストール不要）。

### 更新

初めて起動したとき「起動時に更新を確かめますか？」と聞きます。「はい」を選んだときだけ、起動のたびに GitHub へ最新の版を問い合わせます。この選択は「ヘルプ → 起動時に更新を確かめる」でいつでも替えられ、「ヘルプ → 更新を確かめる…」で手でも確かめられます。

新しい版があると「ヘルプ」の見出しに印が付き、インストーラーで入れた Windows では「YoluPainter x.y.z に更新」で、ダウンロード・検証・更新までを進めます（保存していない変更があるときは、先に保存するか聞きます）。ダウンロードは、署名つきの更新情報の署名・大きさ・SHA-256 を確かめたものだけを使います。zip で展開した Windows と Linux では、その版のリリースのページを開きます。ソースからビルドしたアプリには、更新の項目はありません（配布物のビルドだけが、更新用の公開鍵を組み込みます）。

### 起動時の警告（SmartScreen）

現在の配布物にはコード署名がありません。Windows の SmartScreen が「Windows によって PC が保護されました」と出したときは、「詳細情報」→「実行」で起動できます。

## 動く環境とソースからの起動

Rust の stable ツールチェーンと C/C++ のビルド環境が必要です。導入方法は [Rust のインストール手順](https://doc.rust-lang.org/book/ch01-01-installation.html)を参照してください。ソースを取得・展開し、`Cargo.toml` のあるフォルダで次のコマンドを実行します。初回のビルドには依存パッケージを取得するネット接続が必要です。

表示には GPU と対応ドライバーが必要です。描画基盤は [wgpu](https://docs.rs/wgpu/30.0.1/wgpu/struct.Backends.html) で、Windows は Direct3D 12 または Vulkan、Mac は Metal、Linux は Vulkan などを使います。アプリ単体の起動に Unity は必要ありません。

### Windows

64 ビットの Windows と、Visual Studio Build Tools の「C++ によるデスクトップ開発」（Windows SDK を含む）、Rust の MSVC ツールチェーンを用意します。PowerShell で実行します。

```powershell
cargo build --release -p yolu-app --locked --target x86_64-pc-windows-msvc
.\target\x86_64-pc-windows-msvc\release\yolupainter.exe
```

ペンタブレットはドライバー側でも Windows Ink を有効にしてください。ブラシのツールプロパティのペンのボタンで、どの項目を筆圧で変えるか選べます。

### Mac（試用）

Xcode Command Line Tools と Rust を用意し、Metal が使える環境で実行します。

```sh
cargo build --release -p yolu-app --locked
./target/release/yolupainter
```

Windows Ink に相当する専用のペン入力処理はありません。マウス操作を基本とし、筆圧の取得は OS と入力機器に依存します。現在の Unity 用ブリッジの作成ツールは Mac 用ライブラリを生成しません。

### Linux（試用）

C/C++ コンパイラー、`pkg-config`、X11 または Wayland のデスクトップ環境、GPU ドライバーを用意します。ファイル選択には D-Bus セッションと `xdg-desktop-portal`、デスクトップに合うポータルのバックエンドが必要です。日本語表示には Noto Sans CJK を使用します。

Debian・Ubuntu 系でのパッケージ名の例は `build-essential`、`pkg-config`、`libxkbcommon-dev`、`libwayland-dev`、`libvulkan1`、`xdg-desktop-portal`、`xdg-desktop-portal-gtk`、`fonts-noto-cjk` です。GPU ドライバーは機器に合うものを使用してください。

```sh
cargo build --release -p yolu-app --locked
./target/release/yolupainter
```

マウスで描画できます。筆圧の取得はデスクトップ環境と入力機器に依存します。

## 最初の操作

起動すると、2048 × 2048 のキャンバスと試しの立方体が表示されます。カラー欄で色を選び、2D または 3D ビューを左ドラッグすると描けます。レイヤー欄で描く層を選び、必要に応じて「レイヤー」メニューから新しい層を追加してください。

| 操作 | 入力 |
|---|---|
| ブラシ／消しゴム | `B` / `E` |
| バケツ／ポリゴン塗りつぶし／ID の色で選択 | `G` / `4` / `Shift+W` |
| ブラシを小さく／大きく | `[` / `]` |
| 選択の道具（長方形／楕円形／なげなわ／多角形／自動選択） | `M` / `Shift+M` / `L` / `Shift+L` / `W` |
| すべてを選択／選択を解除／選択範囲を反転 | `Ctrl+A` / `Ctrl+D` / `Ctrl+Shift+I` |
| 選択範囲に足す／引く／重ねる | 選択の道具で `Shift`／`Ctrl`／`Shift+Ctrl`＋ドラッグ（オプションバーでも選べます） |
| 多角形を閉じる／最後の点を消す | `Enter`（始めの点・ダブルクリックでも）／`Backspace` |
| 取り消し／やり直し | `Ctrl+Z` / `Ctrl+Shift+Z` または `Ctrl+Y` |
| コピー／カット／結合してコピー／ペースト | `Ctrl+C` / `Ctrl+X` / `Ctrl+Shift+C` / `Ctrl+V`（「編集」メニューにも） |
| 描いているストローク・選択の途中の取消 | `Esc` |
| 2D の拡大縮小 | ホイール |
| 2D の移動 | 中ボタンドラッグ、または `Space`＋左ドラッグ |
| 2D の回転 | `R`＋左ドラッグ、または `Shift`＋中ボタンドラッグ |
| 2D の回転を戻す／左右反転 | `Shift+R` / `H` |
| 2D を画面に合わせる | `Ctrl+0` |
| ステンシルを回す／動かす／大きさを変える | `T` を押したまま、左ドラッグ（`Shift` で 15° 刻み）／中ボタンドラッグか `Ctrl`＋左ドラッグ／右ドラッグか `Alt`＋左ドラッグ（2D・3D とも） |
| ステンシルを使わない | `N` を押しているあいだ |
| 3D の回転 | 右ドラッグ、または `Alt`＋左ドラッグ |
| 3D の移動／拡大縮小 | 中ボタンドラッグ／ホイール |
| 新規／開く／保存／別名で保存 | `Ctrl+N` / `Ctrl+O` / `Ctrl+S` / `Ctrl+Shift+S` |

コピー・カットは選択範囲（無ければ層全体）の画素を、描くチャンネル（マスクを描いているならマスク）から写し、同じ画素を OS のクリップボードへ画像でも書きます。ペーストは新しい層になり、ほかのアプリでコピーした画像も貼れます（テクスチャセットより大きい画像は貼れません）。Linux は Wayland の data-control に対応していれば Wayland で、そうでなければ X11 で OS のクリップボードを使います。

Mac では表の `Ctrl` を `Command` に読み替えてください。メニューの表示は `Ctrl` です。`.ylp` はウィンドウへドラッグ＆ドロップしても開けます。モデル全体を見失ったら「表示 → 3D ビューでモデル全体を見る」、パネルを戻すには「表示 → パネルの並びを戻す」を使います。

## Unity との Live Link

同じ PC で動く Unity エディターと接続します。Unity 2022.3 のプロジェクトに、**Live Link 対応の Unity 版 YoluPainter（VPM パッケージ `net.yozolab.yolupainter`）と OS に合うネイティブブリッジ**が必要です。`YozoLab → YoluPainter → Live Link` がない版では、この接続は利用できません。Windows 用は `yolu_bridge.dll`、Linux 用は `libyolu_bridge.so` です。

1. スタンドアロンを起動し、「ファイル → Live Link」を有効にします。下の状態欄に Unity を待っていることが表示されます。
2. Unity で `YozoLab → YoluPainter → Live Link` を開きます。接続名（`Link name`）を `yolupainter-livelink` にして `Connect` を押します。
3. シーンのモデルのゲームオブジェクトを指定します。選択中のものなら `Use selection` を押し、`Send model` で送ります。
4. スタンドアロンのテクスチャセット欄でマテリアルを選び、2D または 3D ビューで描きます。表示中で、Unity 側に Color の反映先があるセットの合成結果が Unity に送られます。
5. 作業を `.ylp` に保存します。接続を終えるには Unity の `Disconnect`、またはスタンドアロンの「ファイル → Live Link」を使います。

Unity では lilToon・Standard などのマテリアルに描いた色を一時表示します。元のテクスチャやマテリアルのアセットへ書き込む操作ではありません。切断すると一時表示を外します。Live Link は作業ファイルの保存を代行しないため、スタンドアロン側で保存してください。

つなげるのは同じ PC の同じユーザーのプログラムだけです。スタンドアロンは待ち受けるたびに乱数の鍵を作り、自分だけが開けるフォルダ（Windows は `%LOCALAPPDATA%\YoluPainter\LiveLink`、Linux は `$XDG_RUNTIME_DIR/yolupainter` か `/run/user/<UID>/yolupainter`（無ければ `/tmp/yolupainter-<UID>`）、Mac は `/tmp/yolupainter-<UID>`）に置きます。Unity のブリッジは鍵を知っていることを挨拶で示し、スタンドアロンも鍵を知っていると確かめられてからモデルを送ります。つなぐ入り口（ソケット・名前付きパイプ）と、画素を渡す共有メモリのファイルも、そのユーザーだけが開けます。鍵に対応していない古い版とは、状態欄に理由を出してつなぎません（スタンドアロンと Unity のパッケージは同じ版にそろえてください）。待ち受けを始めるとき、落ちたスタンドアロンが残した共有メモリのファイルを片付けます。同じユーザーの別のプログラムは鍵のファイルを読めるので、つなげます。

接続できる Unity は一度に 1 つです。版の不一致や待ち受け失敗は状態欄で確認できます。ブリッジを更新したときは Unity を再起動してください。接続名を変える場合は、スタンドアロン起動前に環境変数 `YOLUPAINTER_LINK_NAME` を設定し、Unity 側にも同じ名前を指定します。

## Unity 版との .ylp の受け渡し

| 内容 | スタンドアロンでの扱い |
|---|---|
| `.ylp` 形式 1〜7、内部の文書形式 1〜21 | 読み込み。保存時は `.ylp` 形式 7 に更新 |
| ラスター層（6 つの標準チャンネル）、グループ（通過・分離）、マスク、塗りつぶし、調整（反転・レベル補正・色相/彩度/明度）、クリッピング、チャンネルごとの有効と合成、Normal の設定 | 編集と保存。文書・レイヤーの ID、透明画素の RGB を保持 |
| ユーザーチャンネル | 編集と保存。ユーザーチャンネルのあるセットだけ文書形式 22 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません |
| メッシュマップ（セットごとの `meshmap-<種類>.bin`） | 読み込み・保存。焼いて保存していないマップだけを書き、開いたときのものはそのまま残します。モデルや設定が今と違えば「古い」と表示し、使いません |
| フィルター（層・マスク）、Anchor、2D・3D のパス | 編集と保存。設定ごと保持し、評価は合成のときに行う（画面・書き出す合成の PNG に効果が入る） |
| メッシュマップ・画像を使う Generator、塗りつぶしの画像と投影・グラデーション、デカール | 設定ごと保持。スタンドアロンはメッシュマップと画像をまだ評価に渡せないので、効かない効果（渡せないマップ・画像を使うもの、読む Anchor が無いものなど）を含むセットは読み取り専用（保存済みの合成を表示し、元の文書を保持） |
| ロック、手動の ID の色 | 含むセットを読み取り専用にし、理由を表示。元の文書を保持。手動の ID の色はスタンドアロンで付けられますが、付けた文書の保存は理由つきで断ります |
| 読み取り専用セットの見た目 | 保存済みの Color 合成画像を表示。画像がない・読めない場合は空の表示と理由を提示 |
| アセットの棚（`resources.json` と `resources/`: 画像・ブラシ・マテリアル・スマートマテリアル・スマートマスク） | 読み込み・保存。棚を変えたときだけ書き直し（書き手は YoluPainter-rs）、変えていなければ開いたときのバイト列のまま残します。このアプリで入れたスマートマテリアル・スマートマスクは Unity 版が読める `.ylsmart`（形式 1）です |
| 編集していないセット、埋め込みリソース、未知の追加エントリ | 元のデータを保持して保存 |
| より新しい形式や未知の値、壊れたファイル | 読み込みを拒否して理由を表示 |

Unity へ戻すときは、形式 7 と文書形式 21 を読める Unity 版で開いてください。古い Unity 版へ戻すための形式への変換はありません。読み取り専用セットは合成画像に置き換えて保存するのではなく、元の編集情報を残します。ただし、保存済み画像は最新の効果を再計算したものとは限りません。

編集したセットは文書形式 21（ユーザーチャンネルがあれば 22）と、使っている標準チャンネルの合成画像で保存します。Undo の履歴は保存しません。`.ylp` 全体の ZIP バイト列や、ウィンドウ配置・モデルの接続状態まで両アプリで同じになることは保証しません。

上書き時の直前の版は、同じフォルダの `<ファイル名>-backups~/` に残ります。既定ではすべて残して自動削除せず、メニューの「表示」の「設定…」にある「退避を残す数」で、新しい順に残す数（0〜1000。0 は残しません）を選べます（その数を超えた古い退避だけを消します）。保存先の名前は `.ylp` で終わる必要があり、保存先のフォルダーがなければ作ります。読み込み後に別のアプリがファイルを書き換えた場合は、上書きを断ります。同じファイルを両アプリで同時編集せず、保存してからもう一方で開き直してください。

- 作者（ソースの変更）・レビュー・署名の承認: すべて [YozoraKurage](https://github.com/YozoraKurage)（1 人）が務めます。
- プライバシー: 更新の確認を選んだとき（「起動時に更新を確かめる」を「はい」にしたとき、または「更新を確かめる…」を押したとき）に GitHub へ最新の版を問い合わせるほかは、ネットワークへ情報を送りません。問い合わせは、更新情報のファイルを取る通常の HTTPS の要求だけです。アプリの名前と版（User-Agent）のほかに、利用者を識別する情報は付けません。Live Link は同じ機械の中の通信だけです。
  This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.
