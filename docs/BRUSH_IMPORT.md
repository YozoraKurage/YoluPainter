# ブラシの取り込み

ブラシの一覧の「取り込み」（ファイルの選択、またはファイルのドロップ）で、他のアプリのブラシを利用者のブラシ（グループ「取り込み」）にします。
読める形式は GIMP の `.gbr`・`.gih`・`.vbr`、Photoshop の `.abr`・`.pat`、PNG の筆先、CLIP STUDIO PAINT の `.sut`。Krita のプリセット（`.kpp`）は理由を
示して断ります。このアプリで表せない設定は黙って捨てず、ブラシの行の印とツールチップに**表せなかった項目の名前**で出します。
読み込みは裏のスレッドで行い、読めなかったファイルは理由を状態の帯に出します。形式ごとの細かい扱い（上限・壊れたファイルの扱い）は
[`crates/yolu-io/README.md`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/README.md) の「ブラシ形式の取り込み」を参照してください。

## CLIP STUDIO PAINT のブラシ（`.sut`）

`.sut` はサブツール 1 つを書き出したファイルで、中身は SQLite のデータベースです。公開の仕様はなく、公開された解析から分かる範囲だけを読みます。
**本物の `.sut` での確かめはまだしていません**（試験は、下に書いた形を試験の中で組んだ合成のファイルで行っています）。列の名前と単位の一部は
解析からの推定で、CLIP STUDIO の版によって列の集まりが違うので、「在る列だけを読む」作りにしています。

### 読み方

- ファイルは一時的な場所へ写さず、メモリの上の読み取り専用のデータベースとして開きます（元のファイルは書き換えず、そばにジャーナルなどを作りません）。
- 拡張は読み込みません。SQLite 本体には拡張を読み込む機能がコンパイルされていますが、SQL の `load_extension()` は有効化の関数を呼ばない限り
  使えず（「not authorized」）、読み手はその関数を呼びません（試験で確かめています）。防御モード・信頼しないスキーマ・トリガーとビューの無効・
  ATTACH の禁止に加え、文字列と行の大きさ・式の深さ・命令の数・経過時間に上限を置きます。命令の数はファイルを読む間の合計、時間は SQL の中で使った
  時間の合計で、画像の復号など SQL の外の時間は数えません。上限に当たったファイルは理由つきで断ります。問い合わせは決まった表だけで、`Variant` は
  読む列だけを選びます（読まない列の生成式は評価しません）。
- ブラシは `Node` で、現在の設定か既定の設定の番号を持つ行（256 個まで）。名前が空ならファイル名を使います。設定の行が無いものと、256 個を超えて読まなかった
  ものは、取り込めなかったものとして数えます（`Node` の行は全部を見て数えます）。
- 大きさの上限: ファイル 128 MiB、スキーマの項目（表・索引など）1024 個、素材 256 個、取り出す画像の合計 128 MiB、展開する筆先・質感の画素の合計 256 MiB
  （ほかの形式と同じ予算）、画像は 1 辺 2048 画素まで。壊れた・悪意のあるファイルは、パニックせず理由つきで断ります。
- 書き込みの記録（WAL）の形式の印がヘッダーにあるファイルも、ふつうの形式として読みます（元のファイルは書き換えません）。ヘッダーの前に別の
  ヘッダーがあるファイルも、先頭の 4 KiB 以内に SQLite の署名があれば読みます。

### 調べた形

| 場所 | 中身 | 確かさ |
|---|---|---|
| 表 `Node` | 列 `NodeName`（名前）・`NodeVariantId`（現在の設定の番号）・`NodeInitVariantId`（既定の設定の番号）。ブラシは両方か片方が 0 でない行 | 複数の解析で一致 |
| 表 `Variant` | 行の番号は列 `VariantID`（`_PW_ID` ではない。`VariantID` の列が無ければ、別の行の設定を読まないよう、設定は読まず既定のままにして知らせる）。1 列が 1 つの設定で、数百列ある。列の集まりは CLIP STUDIO の版で違う | 複数の解析で一致 |
| 表 `MaterialFile` | 列 `FileData` は無圧縮の tar。素材のプレビューの PNG（`thumbnail/thumbnail.png`）が入る。元の大きさの画像は独自の入れ物（`.layer`・`.c2f`）の中にあり、読まない | 複数の解析で一致 |
| 影響元の列（`…Effector`） | ビッグエンディアンの BLOB。先頭の整数がヘッダーの長さ（40 か 44）、3 番目が使う入力の旗（0x10 筆圧・0x20 傾き・0x40 速さ・0x80 ランダム）、4 番目が筆圧 0 のときの値（%）。続いて曲線が 0 個以上: 整数 3 つ（12・点の数・16）と、点ごとに x・y の `f64`。最初の曲線を筆圧の曲線とみなす | 旗と曲線の形は複数の解析で一致。曲線の順序（最初が筆圧）と最小値の位置は 1 つの解析 |
| 素材の参照の列（`BrushPatternImageArray`・`TextureImage`） | ビッグエンディアンの BLOB。先頭の整数（8）、項目の数、項目ごとに「大きさ・名前の長さ（バイト）・名前（UTF-16LE。元の場所）」と、種類（1 カタログの場所・それ以外は画像の名前。0 で終わり）・長さ・文字列の並び | 1 つの解析 |

### 値の写し方

「確かさ」は、列の名前と単位をどれだけ裏づけられたかです。「推定」は、公開の解析のどれかの記述か、名前からの推定で、本物のファイルで確かめていません。

| このアプリの設定 | 読む列（先に書いたものを優先） | 写し方 | 確かさ |
|---|---|---|---|
| 筆先の画像 | `BrushUsePatternImage` が 0 でない（列が無ければ参照の列があれば）、`BrushPatternImageArray` | 参照の名前から素材を決め、プレビューの PNG を筆先にする。暗いほど塗る（被覆率 = (1 − 輝度) × アルファ）。複数なら筆先の並びにして、順序の設定は読まずランダム | 画像の場所は複数の解析で一致。参照の読み方は推定 |
| 直径 → 半径 | `BrushSize` | px として 2 で割る。列が無ければ筆先の長い辺 | 推定（単位の列は読まない） |
| 不透明度・流量 | `Opacity`（`BrushOpacity`）・`BrushFlow` | 1 より大きければ百分率、以下なら割合 | 推定 |
| 硬さ | `BrushHardness` | 丸い筆先のときだけ。百分率 | 推定 |
| 間隔 | `BrushInterval` | 直径に対する割合（1 より大きければ百分率）。0.01〜4 に収める | 推定（px とする解析もある） |
| 真円率 | `BrushThickness` | 100 で円。0.01〜1 | 推定 |
| 筆圧の影響（大きさ・不透明度・流量） | `BrushSizeEffector`・`OpacityEffector`（`BrushOpacityEffector`）・`BrushFlowEffector` | 旗に筆圧があれば、最小値と曲線（点を通る曲線。16 点までに収める）を筆圧の応えにする | 形は複数の解析で一致。列の名前は推定 |
| 質感 | `TextureImage`、`TextureDensity`・`TextureScale2`（`TextureScale`）・`TextureReverseDensity` | 素材を決めて、白が塗れる質感（乗算）にする。深さ・拡大は割合、反転があれば反転 | 推定 |

素材の決め方: 参照の文字列と、素材の行の文字の列を、場所と拡張子を落として突き合わせます（短すぎる名前・`thumbnail` などの一般的な名前では当てません）。
名前で当たらなかった参照は、ブラシが筆先と質感の片方だけを使い、参照の個数が最後まで読めていて、素材を上限まで読み切れていて、名前で当たらなかった参照の数と
まだ使われていない素材の数が**ちょうど同じ**ときに限って、当たった素材を除いた素材を並びの順で当てます（ファイルには読まない設定の素材も入りうるので、
素材が多いときは決めません）。並びで当てた筆先・質感は推定なので、「筆先の画像」「質感の模様」の項目で知らせます。
参照の BLOB を読めないときは、質感を使わないブラシの素材をすべてそのブラシの筆先とみなし（これも推定として知らせます）、質感は素材が 1 つだけのときにそれを当てます。
決められない・画像を取り出せない筆先は使いません。1 枚でも欠けたら「筆先の画像」で知らせ、1 枚も無ければ丸い筆先（質感は質感なし）にします
（当てずっぽうで別の画像を使いません）。質感は 1 つ目の参照だけを使い、1 つ目が決まらないときに 2 つ目以降の素材を質感にしません。
筆先は 1 つのブラシで 256 枚までで、超える分は使わずに知らせます。

### 表せなかった項目

ブラシの行のツールチップに、次の項目の名前が並びます（旗が立っているものだけ）。

| 項目の名前 | 元の設定 |
|---|---|
| 画像の解像度 | 筆先・質感の画像が素材のプレビュー（原寸ではない） |
| 筆先の画像 | 筆先の素材を決められない・画像を取り出せない・256 枚を超えた（その筆先は使わず、1 枚も無ければ丸い筆先にした）。または、素材の名前では決められず並びで当てた推定 |
| 筆先の順序 | 複数の筆先を使う順序（ランダムにした） |
| 質感の模様・質感の回転・質感の明るさ・質感のコントラスト・質感の合わせ方・描点ごとの質感 | 質感の素材（決められない・取り出せない、または並びで当てた推定）と、質感の細かい設定 |
| 筆先の向き | 向きの角度・向きに従う設定 |
| 色の混ぜ | 絵の具量（`BrushMixColor`）・絵の具濃度（`BrushMixAlpha`）・色延び（`BrushMixColorExtension`）を 0〜100 から 0〜1 にして「絵の具で混ぜる」の量・濃さ・色延びへ写す。値が無く混色の旗だけのものは知らせる |
| 吹き付け・デュアルブラシ・入り抜き・手ぶれ補正・色の変化・合成モード | それぞれの設定が入っているとき |
| ウェットエッジ | 水彩縁 |
| コントロール | 影響元の傾き・速さ・ランダム、太さの筆圧、読めなかった影響元 |
| 筆圧の曲線 | 点が 16 を超えて 16 点に取り直した |
| ブラシの設定 | 設定の表（`Variant`）か、行の番号の列（`VariantID`）が無い |

### 確かめた範囲

- 合成の `.sut` で確かめたこと: 設定の写し、画像（プレビュー・平らな PNG・埋め込まれた PNG）の取り出しと被覆率、複数の筆先の順、名前で決まらないときの並び、
  質感、影響元（筆圧の最小値と曲線、傾き・速さ・ランダム、読めない・大きすぎる BLOB）、旗の注記、表の欠け、`VariantID` の列の欠け、ノード・素材の数の上限、
  筆先の一部が欠けたときの知らせ、並びで当てる条件（素材と参照の数がちょうど同じ）と推定の知らせ、筆先 256 枚の打ち切り、命令の数と時間の上限
  （上限を小さくして踏む試験と、実際の上限で断られる走査の多いファイル）、SQL からの `load_extension()` の拒否、画素の予算、
  ビュー・仮想表の拒否、読まない生成列の不評価、WAL の印、約 32 万通りの壊し方（全バイトの書き換え・切り詰め・極端な値）と、壊し方では届かない
  形の正しい極端なファイル（参照が上限いっぱい・素材が上限など）。
  Windows 向け（GNU）のビルドを Wine で動かした試験も通っています（実機の Windows では確かめていません）。
- 確かめていないこと: 本物の `.sut`（CLIP STUDIO の版ごと）での列の名前・単位・曲線の意味、`.sut` を CLIP STUDIO で再び読み込めること（書き出しはしません）。
