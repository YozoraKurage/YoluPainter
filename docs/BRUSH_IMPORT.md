# ブラシの取り込み

ブラシの一覧の下の帯の「ブラシを取り込む」（ファイルの選択、またはファイルのドロップ）で、他のアプリのブラシを利用者のブラシ（グループ「取り込み」）にします。
読める形式は GIMP の `.gbr`・`.gih`・`.vbr`、Photoshop の `.abr`・`.pat`、PNG の筆先、CLIP STUDIO PAINT の `.sut`。Krita のプリセット（`.kpp`）は理由を
示して断ります。このアプリで表せない設定は黙って捨てず、ブラシの行の印とツールチップに**表せなかった項目の名前**で出します。
ブラシの一覧の下の帯のもう 1 つのボタン「CLIP STUDIO から取り込む」は、CLIP STUDIO PAINT のサブツールのフォルダを探して `.sut` を一覧にし、選んだものだけを取り込みます
（下の「サブツールのフォルダから選ぶ」）。
読み込みは裏のスレッドで行い、読めなかったファイルは理由を知らせます。形式ごとの細かい扱い（上限・壊れたファイルの扱い）は
[`crates/yolu-io/README.md`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/README.md) の「ブラシ形式の取り込み」を参照してください。

## CLIP STUDIO PAINT のブラシ（`.sut`）

`.sut` はサブツール 1 つを書き出したファイルで、中身は SQLite のデータベースです。公開の仕様はなく、公開された解析から分かる範囲だけを読みます。
列の名前と単位の一部は解析からの推定で、CLIP STUDIO の版によって列の集まりが違うので、「在る列だけを読む」作りにしています。

筆先と質感の画像は、素材の独自の入れ物（C2F、拡張子 `.layer`）の中の原寸の画像を読みます（下の「素材の入れ物 C2F」）。読めなければ、素材の中の
プレビューの PNG（原寸ではないので知らせます。どの素材にも同じ汎用の絵が入っていたときは、違う絵を筆先にしないため使いません）、それも無ければ丸い筆先・質感
なしで設定（大きさ・間隔・流量・筆圧など）だけを取り込み、「独自の形式で読めない」と知らせます。
試験は、下に書いた形を試験の中で作った合成のファイルで行っています。

### サブツールのフォルダから選ぶ

ブラシの一覧の下の帯の「CLIP STUDIO から取り込む」でウィンドウを開くと、CLIP STUDIO PAINT の設定のフォルダの下の `.sut` を探して一覧にします（名前と筆先の見本。選ぶ印・
すべて選ぶ・取り込む）。選んだものだけを、ふつうの `.sut` の取り込みと同じ道で取り込みます。ウィンドウの下の帯の「フォルダ…」で、探すフォルダを手で選ぶこともできます（CLIP STUDIO の外の
フォルダでも、同じ探し方で一覧にします）。「探し直す」は今の場所をもう一度探します。見つからないときは、ウィンドウの状態の 1 行に理由（フォルダが見つからない・開けない・
サブツールが無い）を出します。

- **探す場所**: CELSYS の設定のフォルダは、CLIP STUDIO の公式の案内（サポートと CLIP STUDIO ASK の回答）で、Windows の
  `C:\Users\<名前>\AppData\Roaming\CELSYSUserData\CELSYS`（V1.10.13 以降）と、それ以前の `C:\Users\<名前>\Documents\CELSYS`（OneDrive が書類を同期していれば
  `OneDrive\Documents\CELSYS`）です。この 2〜3 か所を、環境変数 `APPDATA`・`USERPROFILE`・`OneDrive` から作って探します。**ここまでは公開の情報で確かめました。**
- **その下**: `.sut` がどのフォルダに置かれるか（`CLIPStudioModule\SubTool\…`、版ごとのフォルダ `CLIPStudioPaintVer…`、ダウンロードした素材の `CLIPStudioCommon\Material\…` など）は、
  公開の情報で確かめられませんでした。フォルダの名前を決め打ちにせず、設定のフォルダの下を浅い所から順に（幅優先で）数えて、拡張子 `.sut` のファイルを集めます
  （深さ 8・見る項目 60000・集める数 1000 まで。上限に達したら一覧に「一部のみ」と出します。シンボリックリンクはたどりません）。
  CLIP STUDIO が `.sut` をその形で置いていなければ、見つかりません（そのときは「フォルダ…」で、`.sut` を書き出したフォルダを選びます）。
- **読むだけ**: 探す所はディレクトリの一覧とファイルの大きさだけを読み、`.sut` の中身はメモリへ読み込んでから開きます。CLIP STUDIO のフォルダへ書かず・ファイルを動かさず・
  消さず・そばに作業用のファイルも作りません。一時フォルダへ写してから開く方式は採りませんでした（写す瞬間に書き込みの途中を取りうる点は同じで、一時ファイルの掃除の失敗も増えるため）。
- **CLIP STUDIO が開いている間**: ファイルは共有の読み取りで開くので、書き込みの最中でなければ読めます（Windows の標準のファイルの開き方は、ほかの読み書きと
  共有します。SQLite の鍵はファイルの先頭のずっと先の範囲の鍵で、先頭の読みを妨げません）。書き込みの途中を取らないよう、読む前後で次の 2 つを確かめ、外れたら少し待って
  取り直します（3 回まで。それでも外れるなら理由を出して読みません）。
  - ファイルの大きさと更新時刻が同じ。
  - 確定前のページが本体に書かれているかもしれない退避のファイル（`<ファイル名>-journal`）が残っていない。書き手は、キャッシュが溢れたりコミットの最中だったりすると、
    確定していないページを先に本体へ書きます（元のページは退避のファイルへ置きます）。その書き込みが読み始める前に済んで止まっていると、本体の大きさも更新時刻も読む間は
    変わらないので、上の確かめでは見分けられません（コミットの最中に CLIP STUDIO が落ちて、退避のファイルが残った場合も同じです）。退避のファイルの先頭の 1 バイトは、
    書き手が中身を同期して初めて 0 でなくなり、本体のページを上書きするのはそれより後なので、先頭が 0 でない間だけ断ります（SQLite 自身の判定と同じです。小さな書き込みの最中は
    まだ 0 なので読めます）。SQLite が自分で読むときは残りを元に戻してから読みますが、ここは書かないので、戻さずに断ります。
  書き込みの記録（`-wal`）のファイルは読まないので、まだ本体に書き戻されていない最新の変更は見えません（書き戻し済みの本体を読みます）。書き込みの記録の書き戻しの最中は、
  大きさと更新時刻の確かめだけで見分けます。
- 試験は、試験用の一時フォルダの構成（新旧の設定のフォルダ・浅い所と深い所・大文字の拡張子・`.sut` でないもの）、読み取り専用のファイル、排他の書き込みの途中の
  ファイル、キャッシュを溢れさせて確定前のページを本体に書かせたファイル、コミットの途中で残った退避のファイル（残りの有無と、終えた後の無効な先頭）、WAL の形式のファイル、
  上限、シンボリックリンクの輪で、見つけ方・理由・「更新時刻・大きさ・中身・項目の数が変わらないこと」を確かめています。
  **実機の Windows では確かめていません**（CLIP STUDIO の入った PC でフォルダが見つかるか、CLIP STUDIO が開いているときに読めるかは、実機での確認が要ります）。

### 読み方

- ファイルは一時的な場所へ写さず、メモリの上の読み取り専用のデータベースとして開きます（元のファイルは書き換えず、そばにジャーナルなどを作りません）。
- 拡張は読み込みません。SQLite 本体には拡張を読み込む機能がコンパイルされていますが、SQL の `load_extension()` は有効化の関数を呼ばない限り
  使えず（「not authorized」）、読み手はその関数を呼びません（試験で確かめています）。防御モード・信頼しないスキーマ・トリガーとビューの無効・
  ATTACH の禁止に加え、文字列と行の大きさ・式の深さ・命令の数・経過時間に上限を置きます。命令の数はファイルを読む間の合計、時間は SQL の中で使った
  時間の合計で、画像の復号など SQL の外の時間は数えません。上限に当たったファイルは理由つきで断ります。問い合わせは決まった表だけで、`Variant` は
  読む列だけを選びます（読まない列の生成式は評価しません）。
- ブラシは `Node` で、現在の設定か既定の設定の番号を持つ行（256 個まで）。名前が空ならファイル名を使います。設定の行が無いものと、256 個を超えて読まなかった
  ものは、取り込めなかったものとして数えます（`Node` の行は全部を見て数えます）。
- 大きさの上限: ファイル 128 MiB、スキーマの項目（表・索引など）1024 個、素材 256 個、取り出す画像の合計 128 MiB、展開する筆先・質感の画素の合計 256 MiB
  （ほかの形式と同じ予算。素材の C2F の展開は別に、取り込み全体で 256 Mi 画素まで）、画像は 1 辺 2048 画素まで。壊れた・悪意のあるファイルは、パニックせず理由つきで断ります。
- 素材の C2F は SQLite 本体を通さず、自前の読み手（`src/brushes/sut/c2f.rs`）で読みます（最初のページが読めず、正しいデータベースにならないため）。拡張や SQL は
  関係せず、塊・ページ・B 木・行・画素の大きさの上限は上の「素材の入れ物 C2F」の末尾のとおりです。
- 書き込みの記録（WAL）の形式の印がヘッダーにあるファイルも、ふつうの形式として読みます（元のファイルは書き換えません）。ヘッダーの前に別の
  ヘッダーがあるファイルも、先頭の 4 KiB 以内に SQLite の署名があれば読みます。

### 調べた形

| 場所 | 中身 | 確かさ |
|---|---|---|
| 表 `Node` | 列 `NodeName`（名前）・`NodeVariantId`（現在の設定の番号）・`NodeInitVariantId`（既定の設定の番号）。ブラシは両方か片方が 0 でない行 | 複数の解析で一致 |
| 表 `Variant` | 行の番号は列 `VariantID`（`_PW_ID` ではない。`VariantID` の列が無ければ、別の行の設定を読まないよう、設定は読まず既定のままにして知らせる）。1 列が 1 つの設定で、数百列ある。列の集まりは CLIP STUDIO の版で違う | 複数の解析で一致 |
| 表 `MaterialFile` | 列 `FileData` は無圧縮の tar。素材のプレビューの PNG（`thumbnail/thumbnail.png`）、素材の種類の印（`icedata/layerData.xml` の `systemtag`。筆先は `BrushPattern`、質感は `PaperTexture`）、元の大きさの画像の入れ物（`data/material.layer` か `material_0.layer`。C2F）が入る。`catalog.zip`・`info.zip` も C2F だが、中身は読まない塊（下を参照） | tar とプレビューは複数の解析で一致。`systemtag` と C2F は本物の 1 つのファイルの素材 4 つで確かめた |
| 影響元の列（`…Effector`） | ビッグエンディアンの BLOB。先頭の整数がヘッダーの長さ（40 か 44。実物はすべて 44＝整数 11 個）、3 番目が使う入力の旗（0x10 筆圧・0x20 傾き・0x40 速さ・0x80 ランダム）、4 番目が筆圧 0 のときの値（%）、9・10 番目が曲線 2 つのバイト数（0 は無い。筆圧の曲線・筆圧でない 2 つ目の曲線の順）。続いて曲線が 0 個以上: 整数 3 つ（12・点の数・16）と、点ごとに x・y の `f64`。曲線は枠の順に並び、2 つ目の曲線を傾きの曲線とみなす（曲線の枠が読めないヘッダーは、最初の曲線を筆圧の曲線とみなし、傾きは写さない） | 旗と曲線の形は複数の解析で一致。**実物 7 つで確かめた**: 影響元の BLOB 176 件はすべてヘッダー 44 バイトで、9・10 番目が曲線のバイト数（12 + 16 × 点の数）と全件でちょうど合う。使う入力の旗の組は 0x10・0x20・0x30・0x50・0x80・0x90・0xB0（0x80 までの旗の外は無い）。4 番目は旗に筆圧がある設定にだけ 0 でない値（8 件）。傾きだけを使う 3 件のうち 2 件は、曲線が 2 つ目の枠だけにある（9 番目が曲線の長さで 8 番目が 0）。速さの旗は 1 件だけで、その設定にも曲線は 2 つ（2 つ目が傾きのものか速さのものかは決められない）。ヘッダーの 2・5〜8・11 番目の意味（2 番目は選べる入力の旗、5〜8 番目はランダム・速さ・傾きの値と思われる）は特定できず、読まない |
| 素材の参照の列（`BrushPatternImageArray`・`TextureImage`） | ビッグエンディアンの BLOB。先頭の整数（8）、項目の数、項目ごとに「大きさ・名前の長さ（バイト）・名前（UTF-16LE。元の場所）」と、種類（1 カタログの場所・それ以外は画像の名前。0 で終わり）・長さ・文字列の並び | 1 つの解析 |
| 入り抜きの列 | `BrushUseIn`・`BrushUseOut`（旗の整数）、`BrushInLength`・`BrushOutLength`（実数。値は画素と推定）、`BrushInLengthUnit`・`BrushOutLengthUnit`（整数。実物はすべて 0）、`BrushInRatio`・`BrushOutRatio`（実数。実物はすべて 30）、`BrushInOutBySpeed`（旗）、`BrushInOutType`（整数。実物はすべて 0）、`BrushInOutTarget`（BLOB。整数 12・項目の数・12 のあと、項目ごとに「項目の番号・旗・旗」。実物は項目 21 個で旗はすべて 0） | 列の名前と値の型は実物 7 つで確かめた。単位 0 が画素・影響先の既定が大きさであること、割合の意味は推測（実物はどれも既定の値で、ほかの値を見ていない） |
| 手ぶれ補正の列 | `BrushUseRevision`（旗）、`BrushRevision`（整数。実物は 2・6・10）、`BrushRevisionBySpeed`・`BrushRevisionByViewScale`・`BrushRevisionBezier`（旗） | 列の名前と型は実物で確かめた。段階の単位と式は推測 |
| 筆先の向きの列 | `BrushRotation`（実数の度。実物は 0・1・180・220）、`BrushRotationEffector`（整数の旗。実物は 1・3・129・131・147。0x80 がランダム、0x10・0x20・0x40 は影響元の旗と同じ並びと推定、下の 2 ビットは意味を確かめられず、実物ではほとんどのブラシに立っていた）、`BrushRotationRandomScale`（百分率の整数。実物は 30・80・100） | 列の名前と型は実物で確かめた。旗の意味と強さの意味は推測 |
| 割合の列 | `Opacity`・`BrushFlow`・`BrushHardness`・`BrushThickness`・`TextureDensity`・`BrushRevision`・`BrushRotationRandomScale` などは整数で宣言された列で、実物 7 つのすべてで 0〜100 の百分率（硬さの 1 は 1%）。大きさ・間隔・角度・長さ・拡大などは実数で宣言された列 | 実物 7 つで確かめた（スキーマの型と値） |

### 素材の入れ物 C2F（`.layer`）

素材の原寸の画像は、素材の tar の `data/material.layer`（か `material_0.layer`）にあり、CLIP STUDIO 独自の入れ物（C2F）に入っています。公開された仕様はなく、
**本物の `.sut` 1 つの素材 4 つ（質感 2・筆先 2）を調べて分かった形**です。解析のツールのコードと CLIP STUDIO の実行ファイルは見ていません（B 木のページの形は
SQLite の公開のファイル形式の文書 <https://www.sqlite.org/fileformat2.html> に従います）。CLIP STUDIO の版が 1 つだけなので、別の版で同じとは言えません。

| 場所 | 中身 | 確かさ |
|---|---|---|
| 先頭 8 バイト | `\x89C2F\r\n\x1a\n` | 確か |
| 塊の並び | 長さ（u32 LE）・種類（4 文字）・中身・CRC32（LE。種類と中身に対する値）の繰り返し。`HEAD`（中身なし）・`dATA` 2 つ・`TAIL`（中身なし）。全部の塊で CRC が合った。tar の `catalog.zip`・`info.zip` も同じ入れ物 | 確か |
| 1 つ目の `dATA`（5130 バイト） | 先頭 2 バイトが `01 00`。残りは値の偏りがほとんど無く（1 バイトあたり 8 ビットに近い）、素材ごとに違う。標準の展開器（zlib・生の deflate・bzip2・lzma。塊の先頭からと、先頭 2 バイトの後ろから）では開けなかったので、それ以上は調べておらず、このアプリは読みません。`catalog.zip`・`info.zip` の C2F も同じ塊の並びで、中身の `dATA`（`catalog.zip` が 909〜934 バイト、`info.zip` が 348〜352 バイト）は先頭 2 バイトが同じ `01 00`。塊の並びと CRC を確かめただけで、中身は読んでいません。2 つ目の塊の中身の最初に当たる SQLite の最初の 5 ページ（ページ 1 を含む）がここに入っていると推測している | 長さと先頭の 2 バイトは確か。中身は不明 |
| 2 つ目の `dATA` | 先頭 2 バイトが `00 00`、続けて 1024 バイトのページの並び（長さ = 2 + 1024 × ページ数）。SQLite の表の B 木（葉 0x0d・内部 0x05・オーバーフロー）で、文字は UTF-8 の素材と UTF-16LE の素材があった。ページ番号は 1 つ目の塊のページ（`(長さ − 2) / 1024` 個）に続けて数える（本物では 1 つ目の塊が 5 ページで、2 つ目の最初のページが 6 番。内部ページの子の番号が葉のページに当たることで確かめた） | 確か（4 つの素材） |
| 表の定義 | 最初のページが読めないので根からは辿らず、読める葉ページの中の `sqlite_master` の行（`table`・名前・名前・根のページ・`CREATE TABLE …` の 5 列）を集め、列の名前は `CREATE` 文から読む（列の位置を決め打ちにしない）。同じ名前で根が違う表が見つかったら決めない | 確か |
| 画像をたどる表 | `Layer`（フォルダでないレイヤーがちょうど 1 枚）の `ResizableOriginalMipmap`（元の画像。無ければ `LayerRenderMipmap`）→ `Mipmap.BaseMipmapInfo` → `MipmapInfo.Offscreen` → `Offscreen`。参照は各表の `MainId`（行の番号ではない）。描画用の面は空で、元の画像の面にだけ画素があった | 確か（4 つの素材） |
| `Offscreen.Attribute` | u32 BE の 16 と 3 つの区画の長さ、続けて名前つき（長さ u32 BE + UTF-16BE）の区画 `Parameter`・`InitColor`・`BlockSize`。`Parameter` の語は、幅・高さ・タイルの数（横・縦）・…、8 番目が面の数（灰色 1・色 5）、15〜16 番目がタイルの大きさ（256）、17〜18 番目がビット数（8）。`InitColor` は空のタイルの値で、見たものは全部同じ値。`BlockSize` はタイルごとの長さ | 並びと長さは確か。語の意味は値の並びからの推測で、読むのは幅・高さ・タイルの数・面の数・タイルの大きさ・ビット数と `InitColor` だけ |
| `Offscreen.BlockData` | タイルごとの塊: 全長（u32 BE）・`BlockDataBeginChunk`（長さ u32 BE + UTF-16BE）・u32 BE が 5 つ（タイルの番号・タイルの大きさ 65536・256・256・画素の有無）・（有れば）長さ（u32 BE）と［zlib の長さ（u32 LE）・zlib］・`BlockDataEndChunk`。タイルの番号は左から右、上から下。最後に `BlockStatus`（タイルごとの有無）などが続く | 確か（タイルの継ぎ目が連続することで確かめた） |
| 画素 | 256×256 の 1 画素 1 バイトの面 1 つ。幅・高さで切り取る。画素の無いタイルは 0 | 確か |
| 画素の意味 | 0 が空で、値は黒のインクの不透明度。素材の中のデータベースには CLIP STUDIO が作った 300×300 の見本（`MaterialThumbnail`。RGBA の PNG で、不透明な所の色は黒）が入っている。読んだ画素を 300×300 に面積平均で縮めた値と見本の不透明度の相関は、筆先の素材で 0.9999（最大値は 95、平均は 17.00 と 16.89。上下や左右を逆にすると 0.96）、質感の素材で 0.74（平均は 142.4 と 141.7。見本が単純な縮小ではないらしく相関は低いが、上下・左右を逆にすると 0 付近になり、255 − v にすると符号が逆になる）。見本の無い素材（`CanvasPreview` を持つ素材 2 つ）は確かめていない。筆先の被覆率 = v / 255 とする | 筆先は確か。質感は値の向きと上下左右の向きまでで、「白が塗れる」向き（CLIP STUDIO が質感を塗りに使う向き）は推測 |

次のものは読まずに断り、素材の画像は無いものとして（プレビューがあればそれを）扱います: 先頭が C2F でない・塊が切れている・CRC が合わない・知らない種類の塊・塊が 64 を超える・
必要なページが読めない側（1 つ目の塊）にある・ページ・B 木・行が壊れている（輪になった木・葉が深さ 8 を超える木・行が 64 MiB を超える）・1 回の取り込みで使える仕事を使い切った（下）・文字の形（UTF-8 と UTF-16LE）が表の定義の行どうしで混ざる・
必要な表が無い・同じ名前の表の根が決まらない・フォルダでないレイヤーが 1 枚でない・画素が 1 つも無い・面が色（5 面）・8 ビットでない・256 でないタイル・初期色が 0 でない・
1 辺が 2048 を超える・タイルの画素（zlib）が壊れている（長さが 65536 でない）・タイルの番号が重なる、またはタイルの数が合わない。

素材の C2F を読む仕事には、素材ごとの上限に加えて、**1 つの `.sut` の取り込み全体の合計**があります（素材は 256 個まであり、小さな素材を並べるだけで仕事が 256 倍になるため）。
組み立てる行の大きさの合計は 256 MiB まで、画像の面に展開する画素の合計は 256 Mi 画素まで（筆先・質感の画素の予算とは別に数えます）。画素は、面を確保する前に幅 × 高さを引くので、
画素が 1 つも無い面でも引きます。どのブラシにも使われない素材も数えます（素材は並べるときにまとめて読むため）。使い切ったあとの素材は、画像が無いものとして扱います
（プレビューがあればそれを使い、無ければ丸い筆先・質感なしにして、「独自の形式で読めない」と知らせます）。

### 値の写し方

「確かさ」は、列の名前と単位をどれだけ裏づけられたかです。「推定」は、公開の解析のどれかの記述か、名前からの推定で、本物のファイルで確かめていません。

| このアプリの設定 | 読む列（先に書いたものを優先） | 写し方 | 確かさ |
|---|---|---|---|
| 筆先の画像 | `BrushUsePatternImage` が 0 でない（列が無ければ参照の列があれば）、`BrushPatternImageArray` | 参照から素材を決め、素材の原寸の画像（C2F。読めなければプレビューの PNG）を筆先にする。暗いほど塗る（被覆率 = (1 − 輝度) × アルファ。C2F の画像は黒の不透明度 v を輝度 255 − v の灰色にして渡すので、被覆率 = v / 255）。複数なら筆先の並びにして、順序の設定は読まずランダム | 画像の場所は複数の解析で一致、C2F の画素の意味は本物で確かめた（下）。参照の読み方は推定 |
| 直径 → 半径 | `BrushSize` | px として 2 で割る。列が無ければ筆先の長い辺 | 推定（単位の列は読まない） |
| 不透明度・流量 | `Opacity`（`BrushOpacity`）・`BrushFlow` | 整数の列は百分率（実物 7 つで確かめた）。実数の列は 1 より大きければ百分率、以下なら割合 | 列の型と値は実物で確かめた。名前は複数の解析で一致 |
| 硬さ | `BrushHardness` | 丸い筆先のときだけ。整数の列は百分率（1 は 1%）。実数の列は 1 より大きければ百分率 | 実物で確かめた（整数で宣言され、1 と 100 を見た） |
| 間隔 | `BrushInterval` | 直径に対する割合（1 より大きければ百分率）。0.01〜4 に収める | 推定（px とする解析もある。実数の列で、実物は 10・20・25） |
| 真円率 | `BrushThickness` | 整数の列。100 で円。0.01〜1 | 値は実物で確かめた（16 と 100） |
| 筆圧の影響（大きさ・不透明度・流量） | `BrushSizeEffector`・`OpacityEffector`（`BrushOpacityEffector`）・`BrushFlowEffector` | 旗に筆圧があれば、最小値と曲線（点を通る曲線。16 点までに収める）を筆圧の応えにする。曲線は 1 つ目の枠の曲線 | 形は複数の解析で一致。最小値と曲線の枠は実物で確かめた（上の表）。列の名前は推定 |
| 傾きの影響（大きさ・不透明度・流量） | 同じ影響元の列。旗 0x20 と 2 つ目の枠の曲線 | 直立で 1・寝かせきって 0 へ全幅で下がる曲線だけを、「傾き」の切り替え（1 − 傾きを掛ける）へ写す。曲線は直線に近似するので、直線から 0.1 を超えて外れる形は「傾きの曲線」を注記する。上がる曲線・半分までしか下がらない曲線・太さへの傾き・速さも使う設定は写さず、従来どおり「コントロール」に注記する | 旗と 2 つ目の枠は実物で確かめた（上の表）。曲線の横軸が「直立 0〜寝かせきって 1」で、下がる曲線が「傾くほど小さい」の意味であることは推測（実物の傾きの旗つきの影響元 9 件の傾きの曲線は、直立で 1・寝かせきって 0 へ下がる形が 5 件、上がる形が 3 件、0.745 から下がる形が 1 件。写すのは前の形のうち大きさへのもの 4 件） |
| 入り抜き | `BrushUseIn`・`BrushUseOut`、`BrushInLength`・`BrushOutLength`、`…LengthUnit`・`BrushInOutType`・`BrushInOutTarget` | 影響先が既定（種類 0・影響先の旗がすべて 0）で、長さの単位が 0 のものだけ、入り・抜きの長さ（画素。大きさにだけ効く）を線の補助の入り・抜きへ。長さ 0 は何もしない。影響先・単位が合わない・長さが読めないものは「入り抜き」に注記。写したときは「入り抜きの速さ・割合」を注記する（速さに応じた長さ `BrushInOutBySpeed` と割合 `BrushInRatio`・`BrushOutRatio` は読まない） | 列は実物で確かめた。単位 0 = 画素・影響先の既定 = 大きさ・割合の意味は推測。長さの値は実物で 14・20・1130 を見た |
| 手ぶれ補正 | `BrushUseRevision`・`BrushRevision` | 強さ（段階）を、糸の長さ（画素）へ 1 対 1 で写す。写したときは「手ぶれ補正の強さ」を注記する。強さが読めなければ「手ぶれ補正」に注記して写さない | 列は実物で確かめた。段階 1 = 1 画素は推測（このアプリの補正は糸の長さで、CLIP STUDIO の式とは別物） |
| 筆先の角度 | `BrushRotation` | 度。-180〜180 に巻いて筆先の角度へ。向きの正負は確かめていないので、エンジンと同じ向きとして写す | 列は実物で確かめた。向きの正負は推測 |
| 角度のランダム | `BrushRotationEffector` の 0x80、`BrushRotationRandomScale` | 強さ（百分率の整数）を 0〜1 の角度のゆらぎへ | 旗と強さの列は実物で確かめた（0x80 の設定 3 つで強さ 30・80・100）。「強さ 100 が ±180°」の意味は推測 |
| アンチエイリアス | `AntiAlias` | 整数 0〜3 を、なし・弱・中・強へ。ほかの値は写さず（なし）、「ブラシの設定」で知らせる。デュアルブラシの `DualAntiAlias` は読まない（デュアルブラシごと表せない） | 列と値は実物で確かめた（実物 7 つの `Variant` で、値のある行に 0・1・2 を見た。もう一方の行は空）。0〜3 が画面の選び（なし・弱・中・強）の順であることは推測 |
| 質感 | `TextureImage`、`TextureDensity`・`TextureScale2`（`TextureScale`）・`TextureReverseDensity` | 素材を決めて、白が塗れる質感（乗算）にする（C2F の画像は同じ灰色。輝度 255 − v）。深さ（整数の列は百分率）・拡大は割合、反転があれば反転 | 推定（「白が塗れる」向きは本物で確かめていない） |

素材の決め方: 参照の文字列と、素材の行の文字の列を、場所と拡張子を落として突き合わせます（短すぎる名前・`thumbnail` などの一般的な名前では当てません）。
名前で当たらなかった参照は、ブラシが筆先と質感の片方だけを使い、参照の個数が最後まで読めていて、素材を上限まで読み切れていて、名前で当たらなかった参照の数と
まだ使われていない素材の数が**ちょうど同じ**ときに限って、当たった素材を除いた素材を並びの順で当てます（ファイルには読まない設定の素材も入りうるので、
素材が多いときは決めません）。並びで当てた筆先・質感は推定なので、「筆先の画像」「質感の模様」の項目で知らせます。
素材の中の `systemtag` で全部の素材の種類（筆先・質感）が分かるファイルでは、種類ごとにも当てます。デュアルブラシを使う設定のファイルには、メインの筆先・質感の
素材に加えて、デュアルブラシの筆先・質感の素材も入るので、その種類の参照（メイン + デュアルの `DualPatternImageArray`・`DualTextureImage`）のうち名前で当たらなかった
数と、まだ使われていないその種類の素材の数が**ちょうど同じ**ときに限り、参照の順（メインが先）と素材の並びで当てます（素材の名前は CLIP STUDIO の内部の名前で、参照の名前は
表示の言語の名前なので、名前では当たりません）。種類の分からない素材が 1 つでもある・数が合わないときは決めません。これも推定として知らせます。本物の 1 つのファイルで、
現在の設定が参照する 4 つの素材（筆先 2・質感 2）だけが入り、種類の中ではメインが先だったことに基づく規則で、ほかのファイルで同じ並びとは限りません。
参照の BLOB を読めないときは、質感を使わないブラシの素材をすべてそのブラシの筆先とみなし（これも推定として知らせます）、質感は素材が 1 つだけのときにそれを当てます。
決められない・画像を取り出せない筆先は使いません。1 枚でも欠けたら「筆先の画像」で知らせ、1 枚も無ければ丸い筆先（質感は質感なし）にします
（当てずっぽうで別の画像を使いません）。質感は 1 つ目の参照だけを使い、1 つ目が決まらないときに 2 つ目以降の素材を質感にしません。
筆先は 1 つのブラシで 256 枚までで、超える分は使わずに知らせます。

### 写した項目と表せなかった項目

ブラシの行のツールチップには、CLIP STUDIO から取り込んだブラシについて、**写した項目**（筆先の画像・質感・筆圧・傾き・入り抜き・手ぶれ補正・筆先の角度・角度のランダム・
色の混ぜ・アンチエイリアスのうち、取り込んだとき、このアプリの設定へ写せたもの）と、**表せなかった項目**（下の表。近似して写したものの近似した中身を含む）を分けて並べます。
大きさ・不透明度・流量・硬さ・間隔・真円率は、どのブラシにも写すので並べません。どちらの一覧も取り込みのときの結果をブラシのファイルに残すので、取り込んだあとに傾きや筆圧を入れて登録しても、
ファイルから写した項目には並びません（今の設定から導き直しません）。

入り抜きと手ぶれ補正は、このアプリでは描き手の設定で、ブラシを替えても残ります。取り込んだブラシが持つ入り抜き・手ぶれ補正は、そのブラシを選んでいる間だけ今の設定に重なり、
別のブラシへ替えると、重なる前の描き手の設定へ戻ります（曲線の切り替えは描き手のままです）。ブラシを選んでいる間に変えた値は、別のブラシへ替えると戻ります
（そのブラシへ保存するには「登録」）。持つブラシの保存は `.ylbrush` の版 4 で、持たないブラシのファイルは今までの版・同じバイトのままです（[BRUSH.md](BRUSH.md) の「保存」）。

### 表せなかった項目

| 項目の名前 | 元の設定 |
