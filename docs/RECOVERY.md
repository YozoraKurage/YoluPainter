# 復旧がディスクに使う量

保存していない作業を落ちても失わないために、YoluPainter は裏で復旧用の世代を書き置きます（「ファイル → 復旧…」の窓から開く・捨てる）。この頁は、その世代が**ディスクを使いすぎない**ための決まり — 量の数え方、上限と消し方、空きの守り、落ちた実行の分の残り方 — を書きます。書き置きの頃合いや開き方は README の復旧の段落にあります。

## 置き場の形

設定のフォルダの `recovery/`（`recovery.conf` の `directory` で変えられます）の下に、起動 1 回につき 1 つの**プール**（フォルダ。名前は `<UTC の時刻>-<乱数 16 桁>`）を作ります。プールの中が世代の置き場で、Unity 版の復旧と同じ形です。

```text
<置き場>/<プール>/current                世代の名前（最後に置き換えて確定）
<置き場>/<プール>/previous               1 つ前の世代の名前
<置き場>/<プール>/generations/<世代>/     manifest（どの中身を使うか）
<置き場>/<プール>/contents/<SHA-256>.bin  変わらない中身は世代の間で 1 つを共有
<置き場>/<プール>/session.lock | crashed 動いている・落ちたの印
```

共有するのは**同じプールの中の世代どうし**です。プールをまたいでは共有しないので、プールを丸ごと消しても、ほかのプールの世代は読めます。

## 数え方

- 置き場の下の、名前が上の形のプールだけを数えます。プールの中のファイルの長さの合計（共有の中身・書いている途中のもの・印のファイルを含む）です。シンボリックリンクは辿りません。
- 置き場の下のほかのフォルダ・ファイル（利用者が置いたもの、Unity 版の `recovery-<GUID>`）は数えず、消しません。
- ファイルシステムの圧縮・クラスタの丸めは見ず、ファイルの長さで数えます（ファイルマネージャーの「サイズ」と同じ向き）。
- 別のウィンドウが動かしているプールは、数えますが消しません（動いているあいだは触らない）。
- 書き込みの途中で落ちた・異常終了したときの残り（作りかけの `.staging-<世代>/`、そこにある `<札>.pending`、確定の前に落ちて誰も使わない `contents/*.bin`）も数えます。大きな文書では、これだけで GB 単位になります。下の「落ちた書き込みの残り」で片付けます。

窓の下の帯の左に、いま使っている量を短く出します（`使用中 1.2 GB`）。ツールチップに、この実行・落ちた実行・閉じた実行・ほかのウィンドウ・上限・ディスクの空きの内訳が出ます。単位は 1 GB = 1024 MB です。

## 使う量の上限

窓の「使う量」で選びます。段の名前だけを出し、数は「詳しく」の中のスライダー（1〜256 GB）にあります。

| 選び | 上限 |
|---|---|
| 自動（既定） | 2 GB と、復旧が使えるディスク（空き + いま使っている量）の 10% の小さいほう。下限は 256 MB。ディスクの空きが分からないときは 2 GB |
| 少なめ | 1 GB |
| 標準 | 2 GB |
| 多め | 8 GB |
| 指定 | 「詳しく」のスライダーで決めた量。動かしている間は当てず、離したときに当てる |

選びは `recovery.conf` の `disk=` に書きます（`auto`・`low`・`standard`・`high`、または GB の数）。範囲の外の値は既定（自動）へ戻し、理由を状態の帯に出します。`disk=` の無い古い設定は自動で読みます。

### 超えたときの消し方

合計が上限を超えているときだけ、まず「落ちた書き込みの残り」（下）を片付け、それでも超えていれば、**古い世代から**消します（世代の名前の順 = 時刻の順。プールをまたぎます）。書き置きが確定した直後、起動したとき、正しく閉じるとき、窓で量を選んだときに行います。

- 守る世代は消しません:
  - この実行のプールの、いちばん新しい読める世代
  - 落ちた実行のプールごとの、いちばん新しい読める世代（下の「落ちた実行の分」）
- 世代を消して空くのは、その世代だけが使う共有の中身です。ほかの世代が使っている中身は、使う世代が無くなるまで残ります。全部がほかの世代と共有の世代は、消しても何も空かないので飛ばします（同じ中身の世代どうしだけが残って超えているときだけ、古いほうを 1 つ消して相方を空く世代にします）。
- 壊れた世代（manifest が読めない）は、空く量が 0 でも、読める世代より先に消します。残ると、同じプールの共有の中身を消せなくなり、読める世代を消しても量が減らないためです。
- 世代が無くなったプールは（この実行のものを除いて）フォルダごと消します。
- 守る世代だけで上限を超えているときは、それ以上消さず、超えたままにします。
- 世代を消した回のあとに、実際の量を数え直します。見積もったほど減っていなければ（消しても空かないものが残っている）、それ以上は世代を消しません。見積もりが外れたまま古い世代を消し続けて、残る世代を無駄に失わないためです。
- 「残す世代」の数による整理（閉じた実行の分を合わせて設定の数だけ残す）は別で、そのまま働きます。上限は、その整理のあとにもう 1 つ足す歯止めです。

保証の射程: 上限は書き置きを確定した**あと**に整理するので、書いている間は新しい世代 1 つぶん超えることがあります（超えるぶんは空きの守りが受け止めます）。ほかのウィンドウが動かしているプールを消せないので、そのぶん上限を超えたままになることがあります。

初めてこの版で起動したとき、すでに上限（自動なら 2 GB 前後）を超える世代が溜まっていれば、その場で古い世代から消えます。

### 落ちた書き込みの残り

書き込みの途中で落ちる・パニックすると、作りかけの世代 `.staging-<世代>/`（共有の中身を書いている途中の `<札>.pending` を含む）が残ります。manifest がまだ無いので、これが 1 つでもあるプールでは、どの世代も使わない共有の中身も消せません。そのため、世代を消しても量が減らず、上限の整理が古い世代だけを消し切ってしまいます。これを避けるため、上限を超えているときは、世代を消す前に次を行います。

- そのプールの `.save.lock` を取れたとき（書いている道具が今は無いとき）だけ、`.staging-*` のフォルダを消し、そのあと、どの世代も使わない共有の中身を消します。書き込みは確定の間ずっとロックを持つので、ロックが取れて残っているものは、落ちた書き込みの残りです。ロックを持たれているプール（書いている最中）と、別のウィンドウが動かしているプールは飛ばします。
- 世代（`current`・`previous` が指すものを含む）には触れません。残りを片付けて収まるなら、世代は 1 つも消しません。
- シンボリックリンクの `.staging-*` は辿らず、消しません（残すと共有の中身が消せないので、その分は、世代を消した回のあとの量の確かめ（上）が受け止めます）。

上限に収まっているあいだは、残りもそのまま置きます（収まっているので、ディスクを使いすぎてはいません）。

### 設定を読めないとき

`recovery.conf` を読めないあいだは、選んだ量が分からないので、上限では消しません（世代の数の整理と同じ扱い）。窓で量を選べば、その実行のあいだは選んだ量で整理します。読めない設定のファイルは書き換えません。空きの守りは、設定に関わらず働きます。

## 空きの守り

書き置きの世代を書く前に、置き場のあるディスクの空きを見ます。**今回新しく書くバイト数**（前の世代と同じ中身は数えない）を空きから引いて、残りが「空けておく量」を割るなら、その書き置きは書かず、状態の帯に短い理由を出します（`復旧用の書き置きを見送りました: ディスクの空きが少ない`）。描くのは止めません。次の間隔で空きを見直し、戻れば書いて「復旧用の書き置きが戻りました」を出します。空きが足りないあいだは、毎回の間隔で、材料を取る以外は空きを見るだけで断ります（書き込みの最初に、書くものを 0 として空きが空けておく量を割っていないかを 1 度見て、割っていれば、世代の組み立ても、直前の世代の読み直しも、ハッシュも行いません）。新しく書く量を足した確かめは、書く直前にもう 1 度行います。正しく閉じるときの最後の書き置きも同じです（前の世代が残ります）。

| | |
|---|---|
| 空けておく量 | 1 GB と、ディスク全体の 5% の大きいほう。ただし 10 GB まで（大きなディスクで 5% が何十 GB にもなり、空きに余裕があるのに書かなくなるのを避けるため） |
| 空きが分からないとき | 確かめずに書く（OS が空きを答えないことで保存を止めない） |
| 空きの見方 | Linux は `statvfs` の使える空き、Windows は `GetDiskFreeSpaceExW`（そのユーザーが使える空き。クォータを含む） |

## 落ちた実行の分

起動時に前の実行の印（`session.lock`）が残っていれば、落ちた実行として `crashed` に替え、窓を出します。落ちた実行の分は次のとおりです。

- 落ちた実行ごとの、いちばん新しい読める世代は、**利用者が捨てるか、その世代が 30 日より古くなるまで**、上限で消しません。30 日は決まった値で、設定にはありません。
- それ以外の世代（その実行の古い世代、30 日を過ぎた最新の世代）は、上限を超えたときの対象で、古いほうから消えます。上限に収まっているあいだは残ります（30 日を過ぎただけでは消しません）。
- 窓の「捨てる」はいつでも使えます。

### GPU の装置を失ったとき

GPU の装置（ドライバーの再起動・デバイスの取り外しなど）を失うと、窓を描き直せなくなります。YoluPainter はそのとき、描いていた絵には触らず、変更があれば復旧用の世代を今すぐ書き、理由を OS の窓で知らせて終わります。描いている最中のストロークは、描いた所までで確定します。終わるときは `session.lock` の印を消さない（落ちたときと同じ）ので、次の起動の復旧の窓から続きを開けます。保存の途中なら、保存が終わるまで待ってから終わります。同じ出来事を、クラッシュの記録（`logs/crash-*.log`）にも残します。

GPU への誤りのうち、受け手の無いもの（検証・メモリ不足）は、アプリを止めずに普段のログ（`logs/session-*.log`）へ 1 行書きます。メモリの確保が失敗して止まるときは、失敗した大きさと呼び出しの番地を、クラッシュの記録に書きます（受け止めて動き続けた失敗は、正常に終われば記録に残しません）。

## Unity 版が書いた世代

Unity 版の復旧は、Unity プロジェクトの `Library/YoluPainter/recovery-<GUID>/` に、同じ形の世代の置き場を書きます。スタンドアロン版はそのフォルダを**数えず、消さず、一覧にも出しません**（プールの名前の形ではないため）。`directory` を Unity の `Library/YoluPainter` に向けても同じです。逆に、このアプリが書いた世代を Unity 版が読めるのは、入れ子の名前（開いた `.ylp` の合成の PNG など）を含まない世代だけです（Unity 版は入れ子の名前を「安全でない名前」として断ります）。この頁の上限・空きの守りは、世代の置き場の形（上の図）を変えません。

## 確かめ方

```text
cargo test -p yolu-io --test projects generation::   世代の置き場（量の数え方・書く前の空きの確かめ）
cargo test -p yolu-app --lib recovery::        上限の消し方・空きの守り・設定
cargo test -p yolu-app --test headless recovery::   書き置きと上限・空きの守り・窓の数え直し
cargo test -p yolu-app --test gui_shell recovery_ui::   窓（使う量・詳しく・使用中）
```

空きの守りは、試験では空きを偽って確かめます。実際のディスクを満杯にした試験はしていません。Windows の `GetDiskFreeSpaceExW` の呼び出しは、`x86_64-pc-windows-gnu` 向けにコンパイルが通ることまでで、実機では確かめていません。
