# .ylp の形式を決めた理由

.ylp の形式（[YLP_FORMAT.md](YLP_FORMAT.md)）の形を選んだ理由・採らなかった案・保証の射程です。
以前の Unity 実装の読み手に実際に読ませた記録は `crates/yolu-io/tests/fixtures/*.unity.txt` にあります。

## バージョンの番号の付け方

正本のバージョン・中身の形式・種類の番号を、どう割り振るかの理由です。
決まりそのものは、[YLP_FORMAT.md](YLP_FORMAT.md) の「正本のバージョンの決まり」にあります。

- **正本のバージョン 22〜25 と 27〜30・32〜35 は、以前の Unity 実装に無い機能を使う文書だけが新しいバージョンになるためのバージョンにする。**
  以前の Unity 実装（0.4.x まで）の読み手は、バージョンの数だけで、ファイルに触れずに断る。
  正本のバージョン 22・23・24 は、以前の Unity 実装の `Runtime/Core` の読み手に読ませた記録がある（`crates/yolu-io/tests/fixtures/*.unity.txt`）。
- **中身の形式（7）は上げない。** 上げると、その機能を使わないセットも含めて、ファイル全体を以前の Unity 実装が開けなくなる。
- **Unity ブリッジが 0.5.0 から .ylp を扱わなくなっても、バージョンの数の意味は変えない。**
  同じバージョンの数が別の意味になると、古い読み手も新しい読み手も、相手の文書を読み違える。
- **種類の番号の 8〜63（Generator）・3〜63（調整）・7〜63（フィルター）は、以前の Unity 実装の並びのために空けたままにする。**
  このアプリだけの種類は、64 から振る。
- **正本のバージョン 31 は欠番にして、これからも割り振らない。**
  - 読み手が読むバージョンは 1〜25・26・27〜30・32〜35 だけにして、間の 31 は意味を決めていないので、範囲に入れずバージョンの数で断る。
    正本のバージョン 25 の並びとして読むと、意味の無いバージョンの文書を黙って読んでしまう。
  - バージョンは積み重ね（上のバージョンは下のバージョンの機能を全部持てる）なので、正本のバージョン 32・33 の読み手は、31 に後から意味を付けた中身を知らない。
    31 を使うと、正本のバージョン 32・33 の文書を、前の読み手が読み違える。
  - 新しい機能のバージョンは、配った一番上のバージョンより上の番号にする。

## Live Link の相手を別のエントリにした

- **状態のエントリ（採用）。** 相手の記録は画素の意味を変えないので、中身の形式を上げると Live Link を使っただけで古い読み手がファイル全体を開けなくなる。
  別のエントリなら、0.4.x は知らないエントリとしてバイト列のまま残し（`Note::UnknownEntryKept`）、テクスチャセットは鍵（Unity のマテリアルの GUID と localFileId）のまま開ける。
  失うのは、0.4.x で開いている間のモデルの表示だけ。
- **ポーズを `pose.json` に書く案（採らない）。** `pose.json` はプロジェクトのモデルのファイル（`view.json` の `standaloneModel`）のポーズで、
  0.4.x はモデルのファイルの無い文書を保存するとき `pose.json` を外す。相手のポーズを `livelink.json` の中に持てば、0.4.x で保存し直しても失わない。
- **値（lilToon のマテリアルの値）は書かない。** 値は `look.json` の `received` にあり、保存するかは利用者の設定で決まる。同じ値を 2 か所に持つと、設定で外したのに残る・食い違う。

## 見た目の設定を別のエントリにした

選んだ理由と、採らなかった案:

- **別のエントリ（採用）。** 見た目の設定は画素の意味を変えないので、正本のバージョンを上げると、lilToon の見た目にしただけで Unity 0.2.0 がファイル全体を開けなくなる。
  別のエントリなら Unity 0.2.0 は開けて、失うのは見た目の設定だけで済む。
- **正本のバージョンを上げて正本の中に持つ。** 上の互換の損失が大きい。
- **view.json に入れる。** 以前の Unity 実装 0.2.0 は view.json を自分の項目（モデル・選んだチャンネル・可視性）だけで書き直す（`JsonUtility`）ので、以前の Unity 実装で保存すると落ちるのは同じ。
  画面の状態と、保存する文書の見た目の値を同じ場所に混ぜない。

## 正本のバージョン 22 ユーザーチャンネル

Unity 0.2.0 は正本のバージョン 22 を「Unsupported archive version; source retained unchanged.」で断る。
C#の `DocumentBinary.Read` / `ReadId` / `YlpFormat.Open`（`Runtime/Core` をそのままコンパイル）
にRustが書いた正本のバージョン 22 を読ませた記録が
[`user-channels-v22.unity.txt`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/tests/fixtures/user-channels-v22.unity.txt)
で、外側の .ylp と `project.json` は読め、開く手順のセットの正本の読みで断る（全部のセットを読めてから入れ替えるので、Unityの状態は変わらず、ファイルも書き換えない）。
記録の最後の行は、ウィンドウ（`TexturePaintWindow`）が正本の読みの失敗に付ける文を、読み手の例外から同じ形に作ったもの。

選んだ理由と、採らなかった案:

- **バージョンを上げる（採用）。** 以前の Unity 実装が新しい機能を追加するたびに使ってきた決まりで、古い読み手はバージョンの数だけで、ファイルに触れずに断る。
  ユーザーチャンネルが無い文書は正本のバージョン 21 のままなので、既存の文書、Rust 実装で保存した大多数の文書をUnity 0.2.0が開ける。
- **全部の文書を正本のバージョン 22（0個の一覧）で書く。** Unity 0.2.0が Rust 実装で保存した文書を1つも開けなくなる。ユーザーチャンネルを使わない人まで巻き込むので採らない。
  失うもの: チャンネルを追加すると正本のバージョンが 22 に、全部消すと 21 に変わる（保存のたびに今の中身で決まる）。
- **中身の形式を 8 にする。** Unity 0.2.0は `ylp.json` の時点でファイル全体を断る。ユーザーチャンネルを持たないセットも巻き添えになる。中身の形式を上げる決まり（エントリの追加・意味の変更）に当たらない。
- **ユーザーチャンネルの画素を別のエントリに置き、`document.utpaint` は正本のバージョン 21 のままにする。** Unity 0.2.0は知らないエントリとして一覧に出すだけで、そのまま開き、
  保存するとそのエントリを落とす。ユーザーチャンネルを黙って失う保存ができてしまうので、「未対応の情報を黙って捨てない」に反する。
- **正本のバージョン 21 のまま番号6〜63を許す。** Unity 0.2.0は `Invalid or duplicate channel` の汎用の文で断り、新しいバージョンが要るとは言えず、破損と区別できない。
  名前・種類・色空間・既定値の置き場も無い。
- **`ylp.json` に機能の旗を追加する。** Unity 0.2.0は知らないキーを読み飛ばすので、効かない。

移行: 正本のバージョン 1〜21 はそのまま読め（ユーザーチャンネルの一覧は空）、coreを通して保存すると正本のバージョン 21（ユーザーチャンネルがあれば正本のバージョン 22）になる。
正本のバージョン 22 を読む Rust 実装は、正本のバージョン 21 までを読む規則を変えない。正本のバージョン 22 から 21 へ戻すには、ユーザーチャンネルを消して保存し直す。

保証の射程と失うもの:

- 1つのセットでも正本のバージョン 22 なら、その .ylp 全体をUnity 0.2.0は開けない（セットごとには開けない）。Unityで開く必要があるときは、ユーザーチャンネルを消したファイルを保存する。
  正本のバージョン 22 から 21 へ直す移行はUnity側には無い。
- 正本のバージョン 22 の意味は [YLP_FORMAT.md](YLP_FORMAT.md) の「頭」の節（`user_channels`）に固定する。
  以前の Unity 実装が正本のバージョン 22 以降を別の意味で使うなら、同じ形式を仕様にして揃える（バージョンの数が食い違うと、どちらの書き手も相手の文書を読み違える）。
- ユーザーチャンネルはC#に書き手が無い。合成は（標準のチャンネルも）coreのf32の合成の式が正本で、Unity 0.2.0のC#の合成と画素の一致は保証しない（保証は読み手の結果と往復のバイト一致の範囲）。
  合成のPNG（`composite/<チャンネル>.png`）は標準のチャンネルだけで、ユーザーチャンネルの分は書かない。
- 保証の範囲は `Runtime/Core` の読み手（`DocumentBinary`・`YlpFormat`）の結果まで。Unityのウィンドウ（EditorWindow）の操作の結果は範囲に含めない。

## 正本のバージョン 23 ノイズとグランジ

評価の約束: 位置（Position）のマップが使える間は、位置から 3D で評価する（UV アイランドの継ぎ目で模様がずれない）。
2D の模様のプリセット（傷の筋・指紋・布目）は、位置の空間では自動でトライプラナー（向きのマップが要る。塗りつぶしの投影と同じ重み）。
位置のマップが使えない（無い・古い・大きさが違う・ピンと違う・境界箱が 0）ときは、入力のまま通さず UV の空間に落とし、理由を `BoundGenerator::fallback` と
`Document::fallback_effect_list` で返す（値は出ている。UV では x・y の格子を周期で巻くので端で継ぎ目が出ず、回転は効かない）。
式は + − × ÷ sqrt floor と整数だけで書き（sin・cos・pow・exp を使わない）、同じ設定・シード・マップなら、スレッド数・領域・ブロックの大きさに依らず同じバイトになる。

Unity 0.2.0 は正本のバージョン 23 を、正本のバージョン 22 と同じく「Unsupported archive version; source retained unchanged.」で断る。
C#の `DocumentBinary.Read` / `ReadId` / `YlpFormat.Open`（`Runtime/Core` をそのままコンパイル）
にRustが書いた正本のバージョン 23 を読ませた記録が
[`procedural-v23.unity.txt`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/tests/fixtures/procedural-v23.unity.txt)（正本は
[`procedural-v23.utpaint`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/tests/fixtures/procedural-v23.utpaint)）。

選んだ理由と、採らなかった案:

- **バージョンを上げる（採用）。** ユーザーチャンネルと同じ流儀で、古い読み手はバージョンの数だけで、ファイルに触れずに断る。この種類を使わない文書は正本のバージョン 21（ユーザーチャンネルがあれば22）のままなので、
  Unity 0.2.0が開ける範囲は変わらない。
- **正本のバージョン 21 のまま種類 64・65 を許す。** バージョンの数が食い違うと、どちらの書き手も相手の文書を読み違える（正本のバージョン 22 の節と同じ理由）。
  以前の Unity 実装が将来 64 以降を別の意味で使うと、同じ正本のバージョン 21 のファイルの意味が割れる。
- **既存の種類（EdgeWear・Dirt）の「重ねるノイズ」を拡張する。** 同じ種類の画素が以前の Unity 実装と変わり、C# の正解との全バイト一致（338事例）を壊す。
- **`.ylsmart` の形式 1 に入れる。** この形式 1 は以前の Unity 実装と共有で、正本のバージョン 23 の断片を入れた .ylp を以前の Unity 実装がアセットごと開けなくなる。
  ユーザーチャンネルと同じく、この種類を含む素材は `SmartFile::from_core` が理由を添えて断る（`REFUSAL_RUST_GENERATORS`）。
  失うもの: ノイズ・グランジを使ったレイヤーを「レイヤーから保存」でアセットへ入れられない（同梱の素材はコードで作った core の素材をアセットの「組み込み」に並べるので影響しない）。
  `.ylsmart` の形式 2 を決めれば入れられる。

移行: 正本のバージョン 1〜22 はそのまま読める。この種類の段を消して保存し直すと、正本のバージョン 21（ユーザーチャンネルがあれば22）に戻る。

保証の射程と失うもの:

- 1つのセットでも正本のバージョン 23 なら、その .ylp 全体をUnity 0.2.0は開けない。Unityで開く必要があるときは、ノイズ・グランジの段を消した（または焼き込んだ）ファイルを保存する。
- 画素は Rust の式で、C#に対応する実装が無い。外部の正解は無く、`tests/procedural-index.txt`（実装を固定するハッシュ。回帰の固定）と性質のテスト（決定性・継ぎ目・取消・予算・検査）で守る。
  式を変えると既存の文書の見た目が変わるので、変えるときはアルゴリズムのバージョンを上げて古い式を残す。
- 数値の一致は Linux x86_64 で確かめた範囲。Windows での確認は未測定。
- 保証の範囲は `Runtime/Core` の読み手（`DocumentBinary`・`YlpFormat`）の結果まで。Unityのウィンドウ（EditorWindow）の操作の結果は範囲に含めない。

## 正本のバージョン 24 色調補正

Unity 0.2.0 は正本のバージョン 24 を、正本のバージョン 22・23 と同じく「Unsupported archive version; source retained unchanged.」で断る。
C#の `DocumentBinary.Read` / `ReadId` / `YlpFormat.Open`（`Runtime/Core` をそのままコンパイル）
にRustが書いた正本のバージョン 24 を読ませた記録が
[`adjust-v24.unity.txt`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/tests/fixtures/adjust-v24.unity.txt)（正本は
[`adjust-v24.utpaint`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/tests/fixtures/adjust-v24.utpaint)）。

選んだ理由と、採らなかった案:

- **使う文書だけバージョンを上げる（採用）。** ユーザーチャンネル・手続き型と同じ流儀で、古い読み手はバージョンの数だけで、ファイルに触れずに断る。
  色調補正を使わない文書は正本のバージョン 21・22・23 のままなので、Unity 0.2.0が開ける範囲は変わらない。
- **使わない文書も正本のバージョン 24 に上げる。** Unity 0.2.0 が開けなくなる互換の損失が大きい。
- **正本のバージョン 21 のまま種類 64〜69 を許す。** バージョンの数が食い違うと、どちらの書き手も相手の文書を読み違える。以前の Unity 実装が将来 64 以降を別の意味で使うと、同じ正本のバージョン 21 のファイルの意味が割れる。
- **`.ylsmart` の形式 1 に入れる。** この形式 1 は以前の Unity 実装と共有で、正本のバージョン 24 の断片を入れた .ylp を以前の Unity 実装がアセットごと開けなくなる。
  この種類を含む素材は `SmartFile::from_core` が理由を添えて断る（`REFUSAL_RUST_ADJUSTMENTS`）。失うもの: 色調補正を使ったレイヤーを「レイヤーから保存」でアセットへ入れられない。
  `.ylsmart` の形式 2 を決めれば入れられる。

移行: 正本のバージョン 1〜23 はそのまま読める。色調補正のレイヤーと段を消して保存し直すと、正本のバージョン 21（ユーザーチャンネルがあれば22、ノイズ・グランジがあれば23）に戻る。

保証の射程と失うもの:

- 1つのセットでも正本のバージョン 24 なら、その .ylp 全体をUnity 0.2.0は開けない。Unityで開く必要があるときは、色調補正のレイヤーと段を消した（または焼き込んだ）ファイルを保存する。
- 式（輝度の重み・明るさ/コントラストの式など）はRustの式で、PhotoshopやCLIP STUDIOの同名の調整と一致するとは言わない。C#に対応する実装は無い。式を変えると既存の文書の見た目が変わる。
- PSDの調整レイヤーとしての読み書きは、`crates/yolu-io/README.md` の「PSD・PSB」の表のとおり。
- 保証の範囲は `Runtime/Core` の読み手（`DocumentBinary`・`YlpFormat`）の結果まで。Unityのウィンドウ（EditorWindow）の操作の結果は範囲に含めない。

## 正本のバージョン 25 グラデーションマップの混色

Unity 0.2.0 は正本のバージョン 25 を、正本のバージョン 22〜24 と同じくバージョンの数だけで断る（以前の Unity 実装の `DocumentBinary.IsReadable` は 1〜21 だけを読み、
21 を超えるバージョンを「Unsupported archive version; source retained unchanged.」で断る。正本のバージョン 22〜24 は実際に読ませた記録がある。
正本のバージョン 25 の文書そのものを読ませた記録は、この環境に .NET が無く取れていない）。

選んだ理由と、採らなかった案:

- **使う文書だけバージョンを上げる（採用）。** 色調補正を使わない文書は 21〜23、使うだけなら 24 のまま。古い読み手が開ける範囲は広がらない。
- **塗りつぶしのグラデーションのランプにも混色を持たせる。** そのランプの並びは以前の Unity 実装と共有（正本のバージョン 21）で、意味を変えられない。
  混色を持つランプが塗りつぶしのグラデーションに入っていれば、黙って落とさず保存を断る（`Unwritable::GeneratorRampMixing`。画面は塗りつぶしのグラデーションに混色を出さない）。
- **正本のバージョン 24 のまま混色の欄を追加する。** 正本のバージョン 24 のグラデーションマップを書く既存の書き手と、バージョンの数が同じで並びが違うファイルができ、どちらも相手を読み違える。

移行: 正本のバージョン 1〜24 はそのまま読める。混色をやめて保存し直すと、正本のバージョン 24（ほかの機能が無ければ 21〜23）に戻る。

保証の射程と失うもの:

- 1つのグラデーションマップでも混色を使えば、その .ylp 全体を Unity 0.2.0 は開けない。
- 混色の式はこのアプリの式で、CLIP STUDIO・Photoshop の同名のモードと画素まで一致するとは言わない。式を変えると既存の文書の見た目が変わるので、変えるときはバージョンを追加して古い式を残す。
- `.ylsmart` の形式 1 には入れない（正本のバージョン 24 の色調補正と同じ断り）。

## 正本のバージョン 27 パスの一覧

1 つのレイヤーに何本ものパスを置く（パスごとに名前・表示）。パスの種類（ストローク・リボン・塗り・指先・消しゴム）、筆先の画像・角度・向き、投影の深さ、対称と、点ごとの接線（角・取っ手）を持つ。
塗りつぶしレイヤーにもパスを置ける（塗りつぶしと効果のスタックの上にパスの画素を重ねる）。Unity 0.2.0 は正本のバージョン 22〜25 と同じくバージョンの数だけで断る（`DocumentBinary.IsReadable` は 1〜21
だけを読む。正本のバージョン 27 の文書そのものを読ませた記録は取れていない）。スタンドアロン 0.4.x は「`.version の値 27 は未対応または範囲外です (1..25)`」で断る（読み手の範囲は 1〜26。
テスト `crates/yolu-io/tests/ylp/path_lists_bridge.rs`）。

選んだ理由と、採らなかった案:

- **使うレイヤーだけ一覧の形で書く（採用）。** 名前の無い見せる 1 本のパスは、今の `surface_path`・`canvas_path` のまま書くので、一覧を使わない文書は前と同じバージョン・同じバイト列。
- **レイヤーの属性のビットで一覧を追加する（採用）。** 一覧を持たないレイヤーは 1 バイトも増えない（レイヤーごとの bool を追加すると、正本のバージョン 27 以降の全部のレイヤーが 1 バイトずつ増える）。
- **1 本のパスの欄を並べて繰り返す。** 古い欄はレイヤーに 1 つの決まりで、2 つ目を置く場所が無い。
- **一覧の 1 本目を古い欄に書き、2 本目からを一覧に書く。** 古い読み手が一部だけを読んで保存し直すと、2 本目からを黙って失う。バージョンで丸ごと断る方がよい。
- **新しいパスの設定は一覧の項目の `extra` に置く（採用）。** 1 本のパスの並び（正本のバージョン 8・10・18）は以前の Unity 実装と同じ並びのまま残し、その並びで表せない設定を使うパスだけを一覧の形で書く。
  接線は滑らかでない点だけを書く（多くの点は滑らかなので、点ごとに 1 バイトを追加するより小さい）。
- **滑らかな区間の式を Catmull–Rom のまま残す（採用）。** 角・取っ手の無いパスは前と同じバイトで描く。全部の区間をベジェに直す案は、同じ曲線でも浮動小数の丸めが変わり、今の文書の画素が変わるので採らない。

移行: 正本のバージョン 1〜26 はそのまま読める（古い 1 本のパスは名前の無い、見せる一覧の 1 本として読む）。パスを 1 本に戻し名前を消し、拡張の設定を外して（点を滑らかに戻して）保存し直すと、ほかの機能が無ければ前のバージョンに戻る。

保証の射程と失うもの:

- 一覧を使うレイヤーが 1 つでもあれば、その .ylp 全体を Unity 0.2.0 とスタンドアロン 0.4.x は開けない。
- `.ylsmart` の形式 1 には入れない（書き手が理由を添えて断る。1 本のパスは今までどおり入る）。

## 正本のバージョン 28 0.5.0 の効果

フィルターの段の種類 70〜79（ヒストグラムスキャン・ヒストグラムレンジ・スロープぼかし・方向のぼかし・ゆがみ・モルフォロジー・エッジ検出・ハイパス・メディアン・グロー）と、
Generator の種類 66 模様・67 アイランドごとのばらつき・68 ライト・69 マスクの組み立て・70 画像を追加したバージョン。

モデルの UV アイランドの番号とシードからアイランドごとに 1 つの値を出す。画像（70）はアセットの画像を、塗りつぶしレイヤーの画像と同じ投影（UV・トライプラナー・平面・球・円柱）で読み、フィルターのスタックの段の値にする。

選んだ理由と、採らなかった案:

- **使う文書だけバージョンを上げる（採用）。** 正本のバージョン 22〜25 と同じ流儀で、この種類を使わない文書は前のバージョンのまま。正本のバージョン 25 までの読み手（スタンドアロン 0.4.x）

  Unity 0.2.0 はバージョンの数だけで「Unsupported archive version; source retained unchanged.」と、ファイルに触れずに断る。
- **共通の欄（`radius`・`amount`・`threshold`・`seed`）に種類ごとの値を詰める。** 欄の意味が種類で変わり、
  範囲の検査（`radius` は種類ごとに上限が違う・`amount` は 0〜5）を種類ごとに書き分けることになる。実数の長さ（スロープぼかし・ゆがみ・方向のぼかし）は int の `radius` に入らない。
- **色調補正の `adjust` の塊に入れる。** `adjust` は調整レイヤーの `detail` と同じ並び（調整レイヤーと共有の種類 64〜69）で、フィルターにしか無い種類を混ぜると調整レイヤーの種類の番号と食い違う。
- **投影の欄を画像の段のために作り直す。** 塗りつぶしレイヤーの `projection` と同じ並びなら、読み手の検査（範囲・置き場）と書き手を 1 つにでき、塗りつぶしレイヤーと画像の段で同じ設定が同じ位置を読む。
  違う並びにすると、片方だけ直したときに食い違う。
- **デカールを許す。** デカールは箱の外に値が無く、縁のやわらかさと裏向きの消え方を見える度合いに掛けるので、段の値（0〜1 の値か画素の色）と意味が合わない。デカールは塗りつぶしレイヤーで置く。
- **画像の画素を正本に入れる。** 画像はアセット（`resources.json`）に 1 度だけ入り、塗りつぶしの画像と同じく ID で指す。同じ画像を読む段が増えても .ylp は大きくならない。

移行: 正本のバージョン 1〜27 はそのまま読める（正本のバージョン 28 の正本は正本のバージョン 27 の中身（パスの一覧）も読み書きできる）。これらの段を消して保存し直すと、使う機能に応じて 21〜25・27 に戻る。
継ぎ目の設定（正本のバージョン 32）を切った文書は、これらの段を持てる正本のバージョン 32 のまま（正本のバージョン 32 の正本は正本のバージョン 28 の中身も読み書きできる。
書き手は継ぎ目の設定を切っていれば 32、切っていなくてこれらの段があれば 28 で書く）。

保証の射程と失うもの:

- 1 つの段でも種類 70〜79・Generator の 66〜70 を使えば、その .ylp 全体をスタンドアロン 0.4.x と Unity 0.2.0 は開けない。
- アイランドごとのばらつき（67）の値はアイランドの番号で決まるので、同じ文書でもモデル（三角形の並び・UV）を替えるとアイランドの番号が変わり、値も変わる。
  アイランドの図は保存しないので、開き直したときにモデルが無ければ入力のまま通す（設定は残る）。
- 式は Rust の式（`yolu_core::filter`。スロープぼかし・ゆがみが読む内蔵の値ノイズは Generator のノイズと同じ hash）で、
  Substance Painter などの同じ名前のフィルターと画素まで一致するとは言わない。式を変えると既存の文書の見た目が変わるので、変えるときはバージョンを追加して古い式を残す。
- 読み方は塗りつぶしレイヤーの画像の読み方（ミップマップ・投影の式）で、

  読み方の式を変えると両方の見た目が変わる。
- `.ylsmart` の形式 1 には入れない（`REFUSAL_NEW_FILTERS`・`REFUSAL_IMAGE_GENERATORS`。正本のバージョン 24 の色調補正と同じ断り）。

## 正本のバージョン 29 点のグラデーションと画像の読み方

塗りつぶしレイヤーのチャンネルごとの点のグラデーション（モデルの空間か UV の空間の点の色を、逆距離の 2 乗の重みで混ぜる）と、塗りつぶしの画像ごとの異方性のフィルターの入・切（既定は入。
切った画像だけ `false`）を追加したバージョン。レイヤーの属性の印（1 バイト）はビット 6 まで使い切ったので、ビット 7 を「続きの属性の印 `attributes_ext`（int）が続く」にし、
点のグラデーションはその続きの印のビット 0 に置く。続きの印はロックの直後に書き、0 なら書かない。

選んだ理由と、採らなかった案:

- **続きの属性の印を int で追加する（採用）。** 属性の印の空きはビット 7 だけで、点のグラデーションに使うと次の機能が置けない。
  int の続きの印なら 31 個のビットが残り、使わないレイヤーは今までどおり 1 バイトも増えない。
- **レイヤーの種類ごとに同じビットの意味を変える。** 点のグラデーションは塗りつぶしレイヤーだけなので、ほかのレイヤーの機能とビット 6 を分け合える。
  ただ、パスの一覧はラスターと塗りつぶしの両方のレイヤーで使うので分け合えず、読み手の検査も種類ごとに分かれて食い違いやすい。
- **レイヤーごとに bool を追加する。** 使わないレイヤーまで 1 バイトずつ増える。

移行: 正本のバージョン 1〜28 はそのまま読める（正本のバージョン 29 の正本は正本のバージョン 27・28 の中身も読み書きできる）。点のグラデーションを消し、画像の異方性を入に戻して保存し直すと、ほかの機能で決まるバージョンに戻る。
正本のバージョン 32 の正本は正本のバージョン 29 の中身も読み書きできる。

保証の射程と失うもの:

- 1 つのセットでも点のグラデーションか異方性を切った画像を使えば、その .ylp 全体をスタンドアロン 0.4.x と Unity 0.2.0 は開けない（バージョンの数だけで断る）。
- `.ylsmart` の形式 1 には入れない（`REFUSAL_POINT_GRADIENTS`）。
- 正本のバージョン 29 の正本は、画像ごとに `anisotropic` の bool を書く（入のままの画像も書く。正本のバージョン 28 までは書かない）。

## 正本のバージョン 30 テキストレイヤー

テキストレイヤーを追加したバージョン。ラスターのレイヤーにテキストの値（文・フォント・サイズ・色・行間・字間・揃え・位置・回転・折り返しの幅）を持たせ、レイヤーの Color の画素はその値から描いた結果としてほかのレイヤーと同じタイルで書く。
値はレイヤーの末尾（パスの一覧の後）の `text` の塊に置き、続きの属性の印（`attributes_ext`）のビット 1 で続くことを示す。

選んだ理由と、採らなかった案:

- **使う文書だけバージョンを上げる（採用）。** 正本のバージョン 22〜25 と同じ流儀で、テキストレイヤーの無い文書は前のバージョンのまま。正本のバージョン 25 までの読み手（スタンドアロン 0.4.x）
  は「`.version の値 30 は未対応または範囲外です`」（分けた正本なら「分けた正本の中のバージョン 30 は未対応です」）、
  Unity 0.2.0 はバージョンの数だけで「Unsupported archive version; source retained unchanged.」と、ファイルに触れずに断る。
- **レイヤーの種類はラスター（`kind` 0）のまま、テキストの値を追加する（採用）。** パスのレイヤー（正本のバージョン 8・10）と同じ形で、画素はいつもタイルにあるので、
  テキストを知らない処理（合成・書き出し・PSD）も今のレイヤーと同じに扱える。種類の値（4 など）を追加すると、以前の Unity 実装のレイヤーの種類と同じ番号の意味が分かれるおそれがあり、番号を空けておける。
  失うもの: 種類の値だけではテキストレイヤーを見分けられない（続きの属性の印のビット 1 を見る）。
- **フォントのファイルを入れない（採用）。** フォントの許諾は、文書に埋めて配ることを許すとは限らない。文書は名前（同梱のフォント）か、
  道・中身の SHA-256・ファミリー名・PostScript 名・太さ・斜体か（ファイルのフォント）だけを持つ。失うもの: フォントの無い所で開くと、テキストの値は編集できない（画素はそのまま見え、書き出しも変わらない）。
- **名前と太さも持つ（採用）。** 道と SHA-256 だけでは、別の PC（フォントのフォルダが違う）で同じフォントを見つけられない。
  PostScript 名は 1 つのスタイルを指し、無いフォントや重なる名前のためにファミリー名と太さ・斜体かも持つ。スタイルの名前（name の 17・2 番）は言語で変わり、探す手がかりにしにくいので持たない。
- **画素も保存する（採用）。** 開くときに描き直すと、フォントの無い所で何も見えなくなり、並べ・塗りの式を変えたときに古い文書の見た目が変わる。失うもの: テキストレイヤーの分だけファイルが大きい（文字の覆う所のタイルだけ）。
- **文の上限を 4096 バイトにする。** 正本の文字列の上限（4096 バイト）と同じにして、文字列の欄の読み書きを今のままにした。

移行: 正本のバージョン 1〜29 はそのまま読める（正本のバージョン 30 の正本は正本のバージョン 27〜29 の中身も読み書きできる）。テキストレイヤーをラスタライズ（値を外す）か消して保存し直すと、ほかの機能で決まるバージョンに戻る。
正本のバージョン 32 の正本は正本のバージョン 30 の中身も読み書きできる（継ぎ目の設定を切った文書のテキストレイヤーは正本のバージョン 32 で書く）。

保証の射程と失うもの:

- 1 つのセットでも正本のバージョン 30 なら、その .ylp 全体をスタンドアロン 0.4.x と Unity 0.2.0 は開けない。開く必要があるときは、テキストレイヤーをラスタライズして保存する。
- 描いた画素はこのアプリの並べ・塗りの式で、ほかのアプリの同じフォント・同じサイズの文字と画素まで一致するとは言わない。
- `.ylsmart` の形式 1 には入れない。スマートマテリアルにしたテキストレイヤーは画素だけになる（知らせる）。
- PSD の書き出しではテキストレイヤーを画素のレイヤーとして書く（PSD のテキストレイヤーは書かない）。PSD の取り込みのテキストレイヤーは今までどおり画素で読む。

## 正本のバージョン 32 継ぎ目の設定

文書の設定「フィルターが UV の継ぎ目をまたぐ」（`filter_seams`）。入のとき、モデルの UV の位相がある文書では、レイヤーのフィルターの近傍の段（ぼかし・シャープなど）が、
アイランドの外の帯を継ぎ目の相手のアイランドの画素で埋めてから評価し、アイランドの外は段の入力のまま戻す。合成の画素が変わるので、正本の頭の欄にした。既定は入で、入の文書はバージョンを上げない（正本のバージョン 21〜25・27・28 のまま）。
切った文書だけが正本のバージョン 32 になる。

選んだ理由と、採らなかった案:

- **切った文書だけバージョンを上げる（採用）。** 既定の入は欄を書かずに表せるので、使わない文書のバージョンは変わらない。古い読み手（0.4.x・Unity 0.2.0）はもともと継ぎ目をまたがないので、
  入の文書を開いても読み違えは無い（見た目は 0.4.x の評価になる）。
- **状態のエントリ（`look.json` のような別のエントリ）にする。** 古い読み手が開けるようにはなるが、合成の画素を変える設定を、以前の Unity 実装が保存で落とす所に置くことになる。
  落ちると切った文書が黙って入に戻り、見た目が変わる。
- **レイヤーごと（フィルターの段の欄）に持つ。** モデルの継ぎ目は文書に 1 つなので、レイヤーごとに違えると、同じ縁でレイヤーによって継ぎ目が出る。段の欄を増やすと、使わない文書のフィルターの並びも変わる。

移行: 正本のバージョン 1〜28 はそのまま読み、継ぎ目の設定は入。設定を入に戻して保存し直すと、ほかの機能で決まるバージョン（21〜25・27・28）に戻る。
正本のバージョン 32 の中身は正本のバージョン 28（0.5.0 の効果）の並びを含むので、正本のバージョン 28 の段のある文書は継ぎ目の設定を切るだけで 28 から 32 へ上がる。

保証の射程と失うもの:

- 1つのセットでも設定を切っていれば、その .ylp 全体を 0.4.x のスタンドアロンと Unity 0.2.0 は開けない（バージョンの数だけで、ファイルに触れずに断る）。
- 欄は設定だけで、帯の写し（モデル・解像度ごとに作り直せる）は書かない。モデルが無い文書では、入でも評価は 2D のまま。

## 正本のバージョン 33 ベイクの優先

重なった UV（同じテクセルを 2 つ以上の三角形が覆う）で、どの三角形がテクセルを焼くかの決め方（`bake_priority`）。
テクスチャセットごとの文書の設定で、決め方で焼く値が変わり、手で選んだアイランド（三角形の番号）はモデルの形に結び付くので、正本の頭の欄にした。
既定（番号の小さい三角形・外さない・手で選んだアイランドなし）は欄を書かずに表せ、既定の文書はバージョンを上げない（正本のバージョン 21〜25・27〜30・32 のまま）。変えた文書だけが正本のバージョン 33 になる。

選んだ理由と、採らなかった案:

- **変えた文書だけバージョンを上げる（採用）。** 0.4.x と Unity 0.2.0 の読み手はもともと番号の小さい三角形で焼くので、既定の文書は古い読み手で開いても意味が同じ。
- **状態のエントリ（`look.json` のような別のエントリ）にする。** 古い読み手が開けるようにはなるが、焼く値を変える設定を以前の Unity 実装が保存で落とす所に置くことになり、
  落ちると決め方が黙って既定に戻る（焼き直すと値が変わる）。
- **焼いたメッシュマップの由来の鍵だけで表す。** 鍵には決め方の SHA-256 だけが入り（`;owner=…;outside=skip;islands=<SHA-256>`、既定は何も追加しない）、
  手で選んだアイランドの番号は戻せない。マップを消すと設定も消える。
- **アイランドを UV の座標で覚える。** UV をぴったり重ねたミラーの両側は UV の座標で区別できない。三角形の番号とモデルの指紋（`MeshBakeInput` のトポロジーの SHA-256）で覚え、
  指紋の違うモデルではベイクの前に断る（黙って別のアイランドを外さない）。

移行: 正本のバージョン 1〜32 はそのまま読み、ベイクの優先は既定。既定に戻して保存し直すと、ほかの機能で決まるバージョン（21〜25・27〜30・32）に戻る。正本のバージョン 33 の正本は正本のバージョン 27〜32 の中身も読み書きできる。

保証の射程と失うもの:

- 1つのセットでも決め方を変えていれば、その .ylp 全体を 0.4.x のスタンドアロンと Unity 0.2.0 は開けない（バージョンの数だけで、ファイルに触れずに断る）。
- 手で選んだアイランドは、三角形の数・UV・スロット・レンダラーが同じモデルでだけ使える。モデルを作り直したら、一覧を外して選び直す。
- 焼いたマップの値の計算（法線・AO など）は変えない。変わるのは、重なったテクセルをどの三角形の値にするかと、焼かないアイランドのテクセルが空になることだけ。

## 正本のバージョン 34 パスのブラシのアンチエイリアス

パスのブラシ（2D・3D のパスの `brush` の塊）の縁のアンチエイリアスの段（`anti_alias` byte。0 なし・1 弱・2 中・3 強）。
パスは保存した設定から描き直すので、段で描く画素が変わる設定を正本のパスに置いた。なし（今の式）は欄を書かずに表せ、なし のパスだけの文書はバージョンを上げない（ほかの機能で決まるバージョンのまま）。
なし でないパスが 1 本でもある文書だけが正本のバージョン 34 になる。

移行: 正本のバージョン 1〜33 はそのまま読み、パスのブラシは なし。正本のバージョン 34 の正本は正本のバージョン 27〜33 の中身も読み書きできる。

保証の射程と失うもの:

- 1 つのセットでも なし でないパスがあれば、その .ylp 全体を 0.5.x までのスタンドアロンは開けない（バージョンの数だけで、ファイルに触れずに断る）。
  以前の Unity 実装（0.4.x まで）もバージョンの数で断る（0.5.0 からの Unity ブリッジは .ylp を開かない）。開くには、そのパスを なし に戻して保存し直す。
- 新しく作るパスは今のブラシの段を取る（アプリの既定のブラシは 中）。そのため、このアプリでパスを新しく作った文書は、ふつう正本のバージョン 34 になる。
- 段の式（帯の幅・小さなダブの濃さ）は、このアプリのブラシの式（[BRUSH.md](BRUSH.md) の「アンチエイリアス」）。

## 正本のバージョン 35 定規

定規は、描くときの寄せ先（直線定規・平行線・同心円・パース）と対称（対称定規）で、レイヤー（グループも）に付けて正本に入れた
（レイヤーの続きの属性の印のビット 2、レイヤーの末尾の `ruler_count`・`rulers[i]`）。パスの 2D の対称にも、角度つきの線対称（`canvas_symmetry` の `mode` 5・`angle`）を足した。
定規を持つレイヤーか、線対称の 2D のパスのある文書だけが正本のバージョン 35 になり、ほかの文書は前のバージョンのまま（定規を全部消して保存し直すと、定規が無かったときと同じバイト列に戻る）。

選んだ理由と、採らなかった案:

- **レイヤーに付けて正本に入れる（採用）。** 定規はレイヤーと一緒に取り消し・複製・結合・削除される本体の値で、描くレイヤーから見える定規が寄せ先と対称を決める。
- **定規を状態のエントリ（例 `sets/<ID>/rulers.json`）に分け、正本のバージョンを上げない。** 古い読み手が知らないエントリをバイト列のまま残すので、開けて定規も残る。
  捨てた理由: (1) 古い読み手がレイヤーを消して保存すると、残ったエントリが無いレイヤーを指す（開き直したときに黙って落とすか、どこかへ付け替えるしかない）、
  (2) 状態のエントリは「読めなければ既定に戻す」種類で、作業の一部（対称で描く準備）を黙って失いうる、
  (3) レイヤーの複製・結合の取り消しと、2 か所の書き込みを揃える仕事が増える。
- **2D は文書の画素、3D はモデルの空間に置く。** 2D は 2D のパスと同じ空間で、サイズ変更で一緒に動く。3D は投影の箱・デカールと同じ空間で、モデルの三角形には結び付けない
  （3D のパスと違い、面の上の点ではない。別のモデルに替えても座標のまま残る）。採らなかった案: 3D の定規を位置・オイラー角・大きさで持つ（形のギズモには載るが、
  直線定規・パースの 2 点を表すのに向かず、2D との対応も切れる）。
- **パスの対称は、定規を参照せず、パスの中に自分で持つ。** パスの画素は保存した設定から描き直す値なので、定規を動かすとパスの画素が変わってしまう。線対称は角度が要るので `mode` 5 を足した。
  採らなかった案: パスの対称をやめて定規に従わせる。

移行: 正本のバージョン 1〜34 はそのまま読み、定規は無く、パスの対称は 1〜4 のまま。正本のバージョン 35 の正本はバージョン 27〜34 の中身も読み書きできる。
前のバージョンのファイルには定規も対称も保存されていないので、移す物は無い。

保証の射程と失うもの:

- 定規を 1 つでも持つ .ylp は、0.5.x までのスタンドアロンは開けない（バージョンの数だけで、ファイルに触れずに断る）。定規だけを捨てて開く道は作らない。
  以前の Unity 実装（0.4.x まで）もバージョンの数で断る（0.5.0 からの Unity ブリッジは .ylp を開かない）。開くには、定規を全部消し、線対称のパスを縦・横・両方・放射状に戻して保存し直す。
- 3D の定規は、ポーズを付けたモデルではボーンに付いて動かない（今の 3D の対称と同じ空間）。
- スマートマテリアル（`.ylsmart`）は定規を持たない。レイヤーを写して保存すると定規は外れ、外したことを知らせる。
- 結合は、外すレイヤーの定規を結果のレイヤーへ全部移す。結果が 64 個を超えるときだけ、何も変えずに断る。

## 正本のバージョン 36 レイヤーセット

レイヤーセットは、セットの中の名前の付いたレイヤーの束で、出力の割り当て（チャンネルごとに最終の結果を取るレイヤーセット）と一緒に正本の頭に置き、
レイヤーには入っているレイヤーセットの ID を置いた（レイヤーの末尾の `set`）。レイヤーセットが 1 つで、名前が空で、全部のチャンネルをそこへ割り当てた文書は
欄を書かずに表せるので、前のバージョンのまま書く（今までの文書は全部この形で、前のバージョンのアプリで開ける）。

選んだ理由と、採らなかった案:

- **レイヤーの並びを 1 本のまま、レイヤーに所属を持たせる（採用）。** 並べ替え・親子・履歴・結合は、同じレイヤーセットの中だけを条件に足すだけで済み、
  レイヤーの欄も ID 1 つだけが増える。
- **レイヤーの木をレイヤーセットごとに分ける（`layers` を `layer_sets[i].layers` にする）。** 並べ替え・履歴・結合の全部に手が入り、前のバージョンと同じ並びで書く道が二重になる。
- **チャンネルをどれか 1 つのレイヤーセットに振り分ける（レイヤーセットがチャンネルの組を持つ）。** 出力の割り当てを 1 通りに固めた特別な場合で、
  同じチャンネルの案を 2 つのレイヤーセットに持って見比べる使い方ができない。
- **割り当てを全部のチャンネルについて書く。** 欠けたチャンネルを黙って既定にせず、開くのを断れるようにした。

移行: 正本のバージョン 1〜35 はそのまま読み、名前の空のレイヤーセット 1 つに全部のレイヤーと全部のチャンネルが入る。正本のバージョン 36 の正本はバージョン 27〜35 の中身も読み書きできる。

保証の射程と失うもの:

- レイヤーセットを 2 つ以上持つ .ylp（名前を付けた・割り当てを変えたものも）は、0.6.x までのスタンドアロンは開けない（バージョンの数だけで、ファイルに触れずに断る）。
  開くには、レイヤーセットを 1 つにし、名前を空に戻し、全部のチャンネルをそこへ割り当てて保存し直す。
- 前のバージョンで書く形のレイヤーセットの ID は保存しない（開くたびに新しい ID になる）。
- 効果は、そのレイヤーのレイヤーセットの中だけを読む。別のレイヤーセットの Anchor を読む参照は、消えた Anchor と同じに入力を通す。

## 中身の形式 9 複数のマテリアルのセット

1 つのテクスチャセットが 2 つ以上のマテリアルを持てるようにした（同じテクスチャに、複数のマテリアルの面を描く）。マテリアルが 2 つ以上の
セットだけ、`project.json` の `sets[].materials`（鍵の並び）で書き、`material` は書かない。マテリアルが 1 つのセットは、今までと同じ `material` のまま。

選んだ理由と、採らなかった案:

- **使うファイルだけを中身の形式 9 にする（採用）。** 中身の形式 8（名前を付けて残した選択範囲）と同じやり方。どのセットもマテリアルが 1 つの
  ファイルは今までと同じ 7・8 で書くので、0.6.x までのアプリでも開ける。2 つ以上を使うファイルは、中身の形式 8 までの読み手が、書いたアプリを
  添えて、ファイルに触れずに断る。
- **いつも中身の形式 9 で書く。** 複数のマテリアルを使わないファイルまで、0.6.x までのアプリで開けなくなる。
- **`material` を残し、増えたマテリアルを `extraMaterials` のような別のキーに書く（中身の形式を上げない）。** 古い読み手は知らないキーを読み飛ばす
  ので、1 つ目のマテリアルだけのセットとして黙って開き、保存し直すと、ほかのマテリアルへの結び付きが消える。
- **鍵の無いセット（マテリアルなし）を `materials` の空の並びで書く。** 結び付けないセットは、今までもモデルのスロットの数より後の `slot` で書いて
  いて、0.6.x までのアプリで開ける。空の並びのためだけに形式を上げない。`unassigned` は「モデルのマテリアルの無いスロットの全部」という鍵で、
  マテリアルなしの意味には使えない。

保証の射程と失うもの:

- 1 つのマテリアルは 1 つのセットだけが持つ決まりは変えない（排他の鍵は、`materials` の中のものも、ファイル全体で 1 回）。
- `materials` の要素の知らないキーは残さない（書くたびに今の鍵だけで作り直す）。セットの知らないキーと、1 つのときの `material` の知らないキーは残す。
- 鍵がとても多いと、`project.json` の予算（64 KiB）を超え、保存を断る。

## 手動の ID の色を書く

塊の形は、以前の Unity 実装の `DocumentBinary`（`WriteIdColors`・`ReadIdColors`）が決めたもので、
このアプリの書き手は C# の書き手が作った見本（`native-rich-v21.utpaint`）を読んで書き戻すと同じバイト列になる。

選んだ理由と、採らなかった案:

- **色があるときだけ塊を書き、バージョンは上げない（採用）。** 塊は正本のバージョン 19 から置けて、書き手のバージョン（21 以上）はどれも 19 以上なので、色のためにバージョンを追加する必要が無い。
  色だけを持つ文書は正本のバージョン 21 のままで、以前の Unity 実装が読める。全部外すと塊も消え、色を持たなかったときと同じバイト列に戻る。
- **新しいバージョンの番号を使う。** 色を使うだけで、以前の Unity 実装が文書ごと開けなくなる。塊の形と正本のバージョン 19 は仕様にあり、以前の Unity 実装は読み書きできるので、追加する必要が無い。
- **指紋が今のモデルと合わない色を、読むときに捨てる・読むのを断る。** モデルがまだ読み込まれていない間は照合できず、別のモデルを開いて保存し直しただけで色が消える。
  読み手は書いてあったとおり文書に戻し、使う側が照合する（合わなければ、色の編集と ID マップのベイクを断る）。
- **色を正本の外のエントリに置く。** 色は文書の一部（Undo の対象で、ID マップを焼く条件）で、`document.utpaint` のバージョン 19 に決まった置き場がある。別のエントリにすると、以前の Unity 実装が保存で落とす。

保証の射程と失うもの:

- 色は塊の番号（メッシュの塊の連番）で結ばれる。モデルの塊の数や並びが変わると、指紋が変わって別のモデルのものとして扱う（番号を使って色を別の塊へ当てはめない）。
- 色は 4096 個まで、塊の番号は 0〜3999999、色は 0xRRGGBB。範囲の外の値は、書き手に届く前に文書が断り、読み手も断る。
