# .ylp ファイルの形式

YoluPainter の作業ファイル `.ylp` の仕様です。

読む人は、外のツール（変換・検査・ビルドの途中で .ylp を読むもの）を作る人と、形式を変える人です。
この文書が形式の唯一の仕様です。コードとこの文書が食い違ったら、それは不具合です。
形式を変えるコミットは、同じコミットでこの文書を直します。

- 形式を選んだ理由・採らなかった案・保証の射程は [YLP_DECISIONS.md](YLP_DECISIONS.md) にあります。
- 読み書きのコードは `crates/yolu-io` にあります。
  - 外側は `package.rs`・`archive.rs`
  - 中身の形式は `project.rs`
  - セットの正本は `native.rs`・`bigdoc.rs`
  - ほかのエントリは、エントリごとの読み手のコード
- `crates/yolu-io/tests/ylp/format_doc.rs` は、このアプリが書くエントリ・版の定数・正本の欄の名前・JSON のキーが
  この文書に載っているかを確かめます。

## 概要

### .ylp とは

.ylp は作業ファイルで、テクスチャではありません。
マテリアルには、書き出した PNG を割り当てます。.ylp を配った先に YoluPainter があるとは限らないためです。

.ylp は zip です。zip の中の 1 つ 1 つのファイルを、この文書ではエントリと呼びます。

- 1 つの .ylp は、テクスチャセット（以下セット）を 1〜64 個持ちます。
- セットは、モデルの 1 つのマテリアルに対応するテクスチャの一式で、文書（レイヤーと画素）を 1 つ持ちます。
- アセット（画像・スマートマテリアル・ブラシなど）は、.ylp 全体で持ちます。

### 中の木

このアプリが書く典型の .ylp です。外側の版は `YLP-3`、中身の形式は 7 で、セットが 1 つ、アセットがあります。
「あるときだけ」と書いたエントリは、使っていなければ書きません。

```text
example.ylp                      zip
├─ mimetype                      無圧縮。中身は application/x-yolupainter
├─ manifest.sha256               1 行目が外側の版（YOLUPAINTER-YLP-3）。続く行が、mimetype とこのエントリを除く全エントリの
│                                SHA-256・長さ・名前
├─ ylp.json                      中身の形式（7）と、書いたアプリ
├─ project.json                  セットの並びと、今のセット
├─ resources.json                アセットの並び（アセットがあるときだけ）
├─ resources/
│  ├─ <content>.png              アセットの画像
│  ├─ <content>.ylsmart          スマートマテリアル・スマートマスク・マテリアル（あるときだけ）
│  └─ <content>.ylbrush          Unity 版のブラシ（あるときだけ。このアプリは書かず、読んで残すだけ）
├─ view.json                     画面の状態（モデルのファイルの参照など。あるときだけ）
├─ pose.json                     モデルの今のポーズ（あるときだけ）
├─ livelink.json                 Live Link の相手の文書（あるときだけ）
└─ sets/
   └─ <ID>/                      セット 1 つ。ID は小文字のハイフン付き GUID
      ├─ document.utpaint        セットの正本。レイヤーと画素。正本の版は使う機能で決まる
      ├─ selection.bin           今の選択範囲（あるときだけ）
      ├─ look.json               3D ビューの見た目の設定（あるときだけ）
      ├─ composite/
      │  └─ Color.png ほか       標準のチャンネルの合成（派生）
      └─ meshmap-<種類>.bin      焼いたメッシュマップ（派生。焼いたときだけ）
```

エントリごとの種類と意味は [エントリの一覧](#エントリの一覧) にあります。

### 言葉

| 言葉 | 意味 |
|---|---|
| エントリ | zip の中の 1 つのファイル。名前は `sets/<ID>/document.utpaint` のように `/` で区切る |
| 外側 | zip の作り方、`mimetype`、`manifest.sha256`、エントリの名前と大きさの決まり |
| 中身 | エントリのバイト列の内容。表の「中身」の列は、エントリや欄の内容の説明 |
| 読み手・書き手 | .ylp を読むプログラム・書くプログラム。単に「書き手」「読み手」と書くときは、このアプリのこと。外のツールも守る決まりは、「どの書き手も」「どの読み手も」と書く |
| テクスチャセット（セット） | 1 つのマテリアルに対応するテクスチャの一式。文書を 1 つ持つ。並びは `project.json` が持つ |
| アセット | レイヤーや見た目の設定が `id` で指す、.ylp 全体の画像・スマートマテリアル・ブラシ。並びは `resources.json` が持つ |
| 本体 | エントリの種類の 1 つ。失うと作業を失うエントリ。読めなければ開くのを断る |
| 状態 | エントリの種類の 1 つ。開いた後の画面の状態。読めなければ既定に戻して知らせ、エントリはバイト列のまま残す |
| 派生 | エントリの種類の 1 つ。本体から作り直せるもの。読めなければ使わずに作り直す。本体の代わりにはしない |
| 記録 | エントリの種類の 1 つ。`ylp.json`。書いたアプリと中身の形式を持つ。読めなければ開くのを断る |
| セットの正本（正本） | `document.utpaint`。1 つのセットのレイヤー・画素・設定を全部持つバイナリ。「正本の版」「分けた正本」「正本の欄」の正本も、これ |
| 正本の版 | `document.utpaint` の版。`DOTPAINT` の次の int |
| 分けた正本 | 大きなセットの正本を `document.utpaint` と `document.utpaint.<n>` に分けたもの。正本の版は 26 |
| 分ける前の正本の版 | 分けた正本が、分ける前の並びとして持つ正本の版 |
| 外側の版 | `manifest.sha256` の 1 行目の版。`YOLUPAINTER-YLP-1`〜`4` |
| 中身の形式 | `ylp.json` の `format`。エントリの並びと、各 JSON の形を決める |
| straight RGBA8 | RGB にアルファを掛けない、RGBA 各 8 bit の画素。透明画素の RGB も保つ |
| Unity 版 | Unity のパッケージの 0.4.x まで（EditorWindow とインポーター）。Unity ブリッジの 0.5.0 以降は .ylp を開かず、書かない |

エントリの種類は、本体・状態・派生・記録です。
「正本」は、種類の名前としては使いません。`document.utpaint`、つまりセットの正本の意味だけで使います。

### 版の数

.ylp には、互いに独立した版の数がいくつもあります。どれもアプリの版（0.5.1・0.6.0 など）ではありません。

| 版の数 | 書かれる場所 | 変えるとき | 範囲 | このアプリが書く値 |
|---|---|---|---|---|
| 外側の版 | `manifest.sha256` の 1 行目 `YOLUPAINTER-YLP-<n>` | エントリの名前と大きさの決まりを広げるとき | 1〜4 | 3。今の上限に収まらないファイルだけ 4 |
| 中身の形式 | `ylp.json` の `format` | エントリの追加・名前や置き場・意味を変えるとき | 1〜8 | 7。名前を付けて残した選択範囲を使うファイルだけ 8 |
| 正本の版 | `document.utpaint` の `DOTPAINT` の次の int | `document.utpaint` の欄を増やすとき | 1〜30・32〜35（31 は欠番） | 使う機能で決まる 21〜25・27〜30・32〜35。512 MiB を超えるセットの正本だけ 26。分ける前の正本の版は 21〜25・27〜30・32〜35 |
| メッシュマップの版 | `meshmap-<種類>.bin` の `YLPMMAP\0` の次の int | `meshmap-<種類>.bin` の欄を変えるとき | 1〜3。エンジンの版は 2 | 3 |
| 選択範囲の版 | `selection.bin`・`selection-<印>.bin` の `YLSL` の次の int | 選択範囲の欄を変えるとき | 1 | 1 |
| JSON の `format` | `look.json`・`pose.json`・`selections.json`・`livelink.json` の `format` | その JSON の形を変えるとき | 1 | 1 |
| `.ylsmart` の版 | manifest の `YOLUPAINTER-SMART-1` と `smart.json` の `format` | `.ylsmart` の形を変えるとき | 1 | 1 |
| `.ylbrush` の版 | manifest の `YOLUPAINTER-BRUSH-1` と `state.json` の `schema` | Unity 版のブラシの形。このアプリは変えない | `schema` 1〜3 | 書かない。読んでバイト列のまま残す |

- このアプリは、使う機能が要る一番低い版を書きます。同じアプリでも、使う機能によって書く値が変わります。
- 書く値の下限は、外側の版 3・中身の形式 7・正本の版 21 です。
- 新しい機能を使わない .ylp は、前の版と同じ並びで書くので、古いアプリでも開けます。
- 例えば「正本の版 27」は、`document.utpaint` の版 27 です。パスの一覧を入れた版です。
- 例えば「中身の形式 7」は、`ylp.json` の `format` が 7 であることです。セットがマテリアルごとの形です。
- この文書は、版の数を書くときに、何の版かを付けます。裸の「版 27」「形式 7」とは書きません。
- アプリの版ごとにどこまで読めるかは [読み手ごとの範囲](#読み手ごとの範囲) にあります。
- 版ごとに増えたものは [中身の形式の版](#中身の形式の版) と [正本の版ごとの追加](#正本の版ごとの追加) にあります。

## 外側

外側は、zip の作り方と、エントリの名前と大きさの決まりです。

### zip の並び

- 先頭は無圧縮の `mimetype` で、中身は `application/x-yolupainter` です。
- 次が `manifest.sha256` で、続いてエントリを名前の順に置きます。
- `mimetype` と、名前が `.png` で終わるエントリは、無圧縮で入れます。ほかは Deflate で入れます。
- 圧縮しても小さくならないエントリは、無圧縮で入れます。
- `YLP-4` の 4 MiB 以上のエントリは、はじめの 1 MiB を試しに圧縮します。97% 未満に縮まなければ、全体を圧縮せず無圧縮で入れます。
- zip の日時と圧縮の結果は形式の一部ではありません。同じ中身でもバイト列が同じとは限りません。

### manifest.sha256

UTF-8 のテキストです。

- 1 行目は外側の版です（`YOLUPAINTER-YLP-1`〜`4`）。
- 続く各行は `<SHA-256> <バイト数> <名前>` で、名前の順に並べます。
- 載せるのは、`mimetype` と `manifest.sha256` を除く全エントリです。この 2 つを載せたものは断ります。
- SHA-256 は小文字の 16 進 64 桁です。
- 中身の正しさは SHA-256 で決め、zip の CRC-32 も確かめます。
- 次のものは、どれも読まずに断ります。
  - manifest に無いエントリ
  - manifest にあってファイルに無いエントリ
  - 長さや SHA-256 の違い

### エントリの名前

- 使える文字は英数字と `.` `-` `_` で、96 バイトまでです。
- `.` で始まる名前・`..` を含む名前・空の名前は断ります。
- 置けるフォルダは、外側の版で決まります。

| 外側の版 | 中身の形式 | 置けるフォルダ |
|---|---|---|
| `YOLUPAINTER-YLP-1` | 1・2 | 根と `composite/` の下だけ。根に `document.utpaint` が要る |
| `YOLUPAINTER-YLP-2` | 3 | 加えて、名前の前に `sets/<ID>/` を 1 つ。`sets/<ID>/composite/` も。`document.utpaint` は根かどれかの `sets/<ID>/` に要る |
| `YOLUPAINTER-YLP-3` | 4 から | 加えて、根の `resources/` の下に 1 段の名前。その下にフォルダは置けない。`sets/<ID>/resources/` も置けない |
| `YOLUPAINTER-YLP-4` | `YLP-3` と同じ | 名前の決まりは `YLP-3` と同じ。上限と zip64 だけが違う（下） |

- `<ID>` は小文字のハイフン付きの GUID 36 文字です。大文字・ハイフン無し・空の GUID は断ります。
- 名前の決まりを広げるときは、外側の版を上げます。
- 古い読み手は、名前の不正としてではなく、新しいアプリで書かれたファイルとして断ります。

### 上限

| 上限 | `YLP-1`〜`3` | `YLP-4` |
|---|---|---|
| 1 エントリ | 512 MiB | セットの正本の部分（`document.utpaint.<n>`）が 256 MiB、ほかは 512 MiB |
| 合計 | 768 MiB | 下の「`YLP-4`」 |
| エントリの数 | 1000 | 65000 |
| manifest | 1 MiB | 16 MiB |
| zip64 | なし | 要るときだけ |

どの外側の版も、宣言した長さを超えて展開しません。

#### `YLP-4`

`YOLUPAINTER-YLP-4`（`package.rs`）は、`YLP-3` の上限に収まらないファイルだけに使います。
収まるプロジェクトは `YLP-3` で書き、バイト列も `YLP-4` を追加する前と同じです。

次の 2 つの上限（セットごと・全体）は、読み手ごとの設定で決まる予算です。形式の制約ではありません。

- セットごとの正本（`document.utpaint` と部分の長さの合計）は、設定「レイヤーのメモリ」の予算の 4 倍までです。
  この予算は 256 MiB を下回りません。
- 全体は「正本のあるセットの数 × セットごとの上限 ＋ 768 MiB」までです。

予算を超えたときの動きです。

- このアプリは、予算を超えても書きます。今の予算で開き直せないことを、保存のときに知らせます。
- このアプリは、読むとき、どの予算かだけを言って、展開の前に断ります。

zip64 は、要るときだけ使います。

- 4 GiB を超える位置のローカルヘッダーは、中央ディレクトリの zip64 の拡張で指します。その記録の版は 45 です。
- 65535 を超えるエントリか、4 GiB を超える中央ディレクトリは、zip64 の終端の記録と目印を書きます。
- `YLP-3` までのファイルに zip64 の構造があれば断ります。
- このアプリは、データ記述子を書きません。読むときは受けます。

エントリの種類は、[言葉](#言葉) の表のとおりです（本体・状態・派生・記録）。

- 「から」: そのエントリを置ける中身の形式。空は、中身の形式 1 から。
- 「要るか」: 必須か、あるときだけか。
- 「このアプリ」: このアプリが書くか。書かないものは、読んでバイト列のまま残します。

## JSON のエントリと選択範囲

各エントリについて、何のためのものか、欄、決まりを書きます。
どの中身の形式から置けるかは [エントリの一覧](#エントリの一覧) の「から」の列にあります。

### JSON に共通の決まり

- どの書き手も、UTF-8 の JSON のオブジェクトで書きます。
- キーの重複、深さ 16 を超える入れ子、1024 文字（UTF-16）を超える文字列とキーは、書いてはいけません。
  このアプリは、これらを断ります。
- 本体と記録の JSON（`ylp.json`・`project.json`・`resources.json`、`.ylsmart` の `smart.json`）はこの決まりで読みます。

エントリごとの大きさの上限は次のとおりです。

| エントリ | 上限 |
|---|---|
| `ylp.json`・`project.json` | 64 KiB |
| `resources.json` | 1 MiB |
| `view.json` | 256 KiB |
| `pose.json` | 8 MiB |
| `look.json` | 1 MiB |
| `livelink.json` | 16 MiB |
| `selections.json` | 256 KiB |

### ylp.json

中身の形式と、書いたアプリを持つ記録です。

```json
{
  "format": 7,
  "savedBy": { "app": "YoluPainter", "version": "0.4.0", "unity": "standalone" },
  "createdBy": { "app": "YoluPainter", "version": "0.4.0", "unity": "standalone" }
}
```

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `format` | 整数 | 必須。2 以上 | 中身の形式 |
| `savedBy` | オブジェクト | 必須 | 最後に保存したアプリ |
| `createdBy` | オブジェクト | 省略可 | 最初に作ったアプリ |

`savedBy` と `createdBy` の中のキーは同じです。

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `app` | 文字列 | 1〜256 文字 | アプリの名前 |
| `version` | 文字列 | 1〜256 文字 | アプリの版 |
| `unity` | 文字列 | 1〜256 文字 | Unity 版は Unity の版を書く。このアプリは `standalone` を書く |

- 中身の形式 1 のファイルから作ったものは、最初に作ったアプリが分からないので、`createdBy` を書きません。
- 知らないキーは読み飛ばします。

### project.json

セットの並びと、今のセットを持つ本体のエントリです。ここに書く形は、中身の形式 7 の形です。

```json
{
  "sets": [
    {
      "id": "0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0",
      "name": "Body",
      "material": { "name": "Skin", "guid": "0123456789abcdef0123456789abcdef", "fileId": 2100000 }
    },
    { "id": "11111111-2222-3333-4444-555555555555", "name": "Hair", "material": { "name": "Hair" } },
    { "id": "22222222-3333-4444-5555-666666666666", "name": "Unassigned", "material": { "unassigned": true } },
    { "id": "33333333-4444-5555-6666-777777777777", "name": "Texture Set 1", "material": { "slot": 0 } }
  ],
  "current": "11111111-2222-3333-4444-555555555555"
}
```

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `sets` | 配列 | 必須。1〜64 個 | セットの並び。並びの順がパネルの順 |
| `sets[].id` | 文字列 | 必須。小文字のハイフン付きの GUID。ほかのセットと重ならない | セットの ID。エントリの置き場 `sets/<id>/` の名前 |
| `sets[].name` | 文字列 | 必須。1〜256 文字。空白だけでない。制御文字なし。大文字小文字を区別せず、ほかのセットの名前と重ならない（重なれば断る） | セットの名前。書き出すファイルの名前に使う |
| `sets[].material` | オブジェクト | 必須（中身の形式 7 から） | マテリアルの鍵（下） |
| `sets[].materialSlot` | 整数 | 中身の形式 6 まで | 中身の形式 7 では読まない。移行が `material` の `slot` にする |
| `current` | 文字列 | 必須。`sets` にある `id` | 今のセット |

- 知らないキー（根・各セット）は読み飛ばし、書き直すときも残します。
- 決まりに合わないものは、既定に戻して開かず、開くのを断ります。
- 並びにあるセットに `sets/<id>/document.utpaint` が無ければ断ります。

#### material（マテリアルの鍵）

次のどれか 1 つの形で書きます。2 つ以上の形、またはどの形でもないものは断ります。

| 形 | キー | 範囲 | 意味 |
|---|---|---|---|
| 名前 | `name` | 0〜256 文字。制御文字なし | マテリアルの名前 |
| Unity のアセット | `name` と `guid`・`fileId` | `guid` は小文字の 16 進 32 文字。`fileId` は符号付き 64 bit の整数 | Unity のアセットのマテリアル。`guid` と `fileId` は揃えて書く |
| 未割り当て | `unassigned` | `true` | モデルのマテリアルの無いスロットの全部 |
| スロット | `slot` | 0〜65535 | まだマテリアルに結び付けていないスロットの番号。中身の形式 6 までのファイル |

- 同じ `guid`・`fileId` の 2 つ、2 つの `unassigned`、同じ `slot` の 2 つは断ります。
- 名前だけの鍵は、重なってよい。
- モデルのマテリアルとの照合は、識別子（`guid`・`fileId`）、`unassigned`、名前、`slot` の順に行います。
- 名前は、大文字小文字まで同じものを先に照らし、次に区別せずに照らします。
- 1 つのマテリアルは、1 つのセットだけが持ちます。
- 合わないセットも開けます。3D に見えないだけです。

### resources.json と resources/

アセット（プロジェクトのリソース）の並びと、その中身です。
アセットが空なら `resources.json` を書きません。無いファイルは、アセットが空です。

```json
{
  "resources": [
    {
      "id": "aaaaaaaa-0000-4000-8000-000000000001",
      "kind": "image",
      "name": "Scratches",
      "content": "<64 桁の小文字 16 進>",
      "width": 1024,
      "height": 1024,
      "colorSpace": "srgb",
      "origin": {
        "type": "unityAsset",
        "guid": "0123456789abcdef0123456789abcdef",
        "path": "Assets/Textures/Scratches.png",
        "stamp": "<Unity の依存ハッシュ>",
        "localFileID": 2800000
      }
    },
    {
      "id": "bbbbbbbb-0000-4000-8000-000000000002",
      "kind": "smartMaterial",
      "name": "Rusty",
      "content": "<ファイルの SHA-256>",
      "length": 5519,
      "origin": { "type": "library", "file": "Rusty.ylsmart", "sha256": "<同じ>", "length": 5519 }
    }
  ]
}
```

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `resources` | 配列 | 必須。0〜256 個 | アセットの並び。並びの順がパネルの順 |
| `resources[].id` | 文字列 | 必須。小文字のハイフン付きの GUID。重ならない | アセットの ID。セットの正本のレイヤー（塗りつぶしの画像の `resource_id`）と、`look.json` の `image` が指す名前 |
| `resources[].kind` | 文字列 | 必須（下） | アセットの種類 |
| `resources[].name` | 文字列 | 必須。1〜256 文字。空白だけでない。制御文字なし。重なってよい | アセットの名前 |
| `resources[].content` | 文字列 | 必須。64 桁の小文字の 16 進 | 中身の SHA-256（下） |
| `resources[].width`・`resources[].height` | 整数 | `image` だけ。必須。1〜8192。PNG と同じでなければ断る | 画像の大きさ |
| `resources[].colorSpace` | 文字列 | `image` だけ。省略可。`srgb`・`linear`・`unspecified`。既定は `unspecified` | 画像の色空間 |
| `resources[].length` | 整数 | `image` 以外。必須。1〜512 MiB。ファイルの長さと同じ | ファイルの長さ |
| `resources[].origin` | オブジェクト | 省略可。既定は `{ "type": "none" }` | 出どころ。写しは、出どころが消えても使える |

`kind` の値は次のとおりです。知らない種類は断ります（落として保存しません）。

| `kind` | から | 中身のファイル |
|---|---|---|
| `image` | 中身の形式 4 | `resources/<content>.png` |
| `smartMaterial`・`smartMask` | 中身の形式 5 | `resources/<content>.ylsmart` |
| `brush` | 中身の形式 6 | `resources/<content>.ylbrush` |
| `material` | 中身の形式 6 | `resources/<content>.ylsmart` |

`content` は次のハッシュです。

- `image`: ASCII の `YLPRGBA8`、幅と高さ（32 bit の little-endian）、straight RGBA8 の画素（下の行から）を続けた SHA-256。
- ほか: ファイルのバイト列の SHA-256。

#### origin（出どころ）

| `type` | キー | 範囲・意味 |
|---|---|---|
| `none` | | 写しだけ |
| `unityAsset` | `guid` | 32 桁の小文字の 16 進 |
| | `path` | 1〜1024 文字。見せるだけ |
| | `stamp` | 省略可。0〜128 文字。Unity の依存ハッシュ |
| | `localFileID` | 省略可。符号付き 64 bit。無い・0 は主アセット |
| | `readThroughGpu` | 省略可 |
| `file` | `path` | 絶対パス。1〜1024 文字 |
| | `sha256` | ファイルの SHA-256 |
| | `length` | ファイルの長さ |
| `library` | `file` | 置き場の中の `/` 区切りの相対パス。`\`・`:`・空の区間・`.`・`..` は断る |
| | `sha256` | ファイルの SHA-256 |
| | `length` | ファイルの長さ |
| `builtIn` | `key` | 1〜64 文字の `a-z 0-9 -` |
| | `version` | 1 以上 |

#### resources/ の中身

- 2 つのリソースが同じ中身を持ってよく、そのときエントリは 1 つです。
- `resources/<content>.png`
  - 色の型 6（RGBA）・8 bit・インターレース無し・補助のチャンクなしです。ICC・gAMA を付けません。
  - 透明画素の RGB も保ちます。
  - 開くときに全部を復号し、画素のハッシュが名前と、大きさが並びと同じかを確かめます。
  - 保存は、読んだバイト列をそのまま書きます。
- `resources/<content>.ylsmart`・`.ylbrush`
  - [.ylsmart](#ylsmart) と [.ylbrush](#ylbrush) のファイルを、置き場のファイルと同じバイト列で入れます。
  - 開くときに、長さ・SHA-256・中身の種類を確かめます。

決まりは次のとおりです。

- 並びにあるのにエントリが無い・壊れているものは、どれかを添えて開くのを断ります。
- 並びに無い `resources/` のエントリは、知らないエントリとして知らせます。
- このアプリは、アセットを変えたときだけ `resources.json` と `resources/` を書き直します。
  変えていなければ、開いたときのバイト列のまま書きます。
- メモリの予算は 768 MiB です。復号した画像の画素・スマートマテリアルのファイルと画素・ブラシのファイルと筆先を合わせます。

### view.json

画面の状態を持つ状態のエントリです。このアプリは、オブジェクトでなければ読みません。知らないキーは残します。

| キー | 書き手 | 中身 |
|---|---|---|
| `modelAssetGuid` | Unity 版 | モデルのアセットの GUID。このアプリが新しく作るときは空の文字列 |
| `selectedChannel` | Unity 版 | 選んだチャンネル。このアプリが新しく作るときは 0 |
| `visibility` | Unity 版 | 非表示の指定（下） |
| `standaloneModel` | このアプリ | モデルのファイルの参照（下） |
| `materialSlot` | 中身の形式 2 まで | 中身の形式 3 への移行が読む。今は書かない |

`visibility` の中のキーです。

| キー | 中身 |
|---|---|
| `hiddenSets` | 非表示のセットの ID |
| `hiddenRenderers` | 非表示のレンダラーの鍵。モデルの中の兄弟番号の道とレンダラーの番号。例 `000001/000000:0` |

上限は、セット 64、レンダラー 4096、鍵 2048 文字です。

`standaloneModel` は `{ "path": <道> }` の形です。
`path` は、モデルのファイル（FBX など）の、.ylp からの相対か絶対の道です。1〜1024 文字（UTF-16）で、制御文字は使えません。

相対の道の基準は、次のとおりです。

- 基準は、.ylp のあるフォルダです。
- 退避のフォルダ（`<ファイル名>-backups~/`）の中の退避は、退避した元の .ylp のあるフォルダが基準です。
- 退避の名前は、次のどちらかの形です。
  - 元のファイルの拡張子を除いた名前に、`-` と UTC の時刻 `yyyyMMddTHHmmssfffZ` を付けたもの。時刻が重なると、後ろに `_` が付きます。
  - 以前の版の SHA-256。小文字の 16 進 64 桁です。
- 退避の退避は、元のファイルまでたどります。
- モデルを探すのは、この基準のフォルダの 1 か所だけです。
- このアプリは、保存のとき同じ基準で相対の道を書きます。

### pose.json

モデルの今のポーズを持つ状態のエントリです（根）。ポーズのプリセット（`.ylpose`）と同じ表し方です。

- 休みの形からの差だけを持ちます。
- ボーンは名前の道で、BlendShape はメッシュの名前と BlendShape の名前の組で持ちます。
- 名前の組が同じモデルへ戻せます。合わないものは、戻すときに理由をつけて飛ばします。

```json
{
  "format": 1,
  "bones": [
    {
      "path": ["Hips", "Spine"],
      "translation": [0.0, 0.01, 0.0],
      "rotation": [0.0, 0.0, 0.1, 0.99],
      "scale": [1.0, 1.0, 1.0]
    }
  ],
  "shapes": [ { "mesh": "Face", "name": "Smile", "weight": 40.0 } ],
  "take": { "name": "Take 001", "frame": 12 }
}
```

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `format` | 整数 | 1 | ほかは読まずに断る |
| `bones` | 配列 | 4096 個まで | ボーンの差 |
| `shapes` | 配列 | 4096 個まで | BlendShape の重み |
| `take` | オブジェクト | 無くてよい | ポーズの欄で選んでいるモデルのテイク |

`bones[]` の欄です。

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `path` | 文字列の配列 | 1〜256 段。名前は 1〜256 文字 | 根からボーンまでの名前の並び |
| `translation` | 数 3 つ | 絶対値 1e6 まで | 親の空間での足し算の差 |
| `rotation` | 数 4 つ | 単位クォータニオン x・y・z・w。長さの許す幅は 0.01 | ボーンのローカルの差。読んだ後で正規化する。今の回転 = 休みの回転 × 差 |
| `scale` | 数 3 つ | 絶対値 1e6 まで | 休みの大きさとの比 |

`shapes[]` の欄です。

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `mesh` | 文字列 | 1〜256 文字 | メッシュの名前 |
| `name` | 文字列 | 1〜256 文字 | BlendShape の名前 |
| `weight` | 数 | 絶対値 1e4 まで | Unity と同じ 0〜100 の目盛り |

`take` の欄です。

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `name` | 文字列 | 1〜256 文字 | テイク（FBX の中のアニメのスタック）の名前 |
| `frame` | 整数 | 絶対値 1e9 まで | フレーム |

- `take` は、開いたときに欄の選びを戻すだけです。ポーズの値は `bones` と `shapes` が持ちます。
- テイクがモデルに無ければ、欄は最初のテイクのままです。
- [配布用に保存](SAVE_FOR_DISTRIBUTION.md)で「モデルの参照」を除いた写しには、このエントリを入れません。
- 範囲の外・数でない値・単位でない回転・ボーンや BlendShape の重なり・数の上限を超えたものは、エントリごと断ります。
  一部だけを読みません。断ったエントリは、バイト列のまま残ります。
- 中身の形式も正本の版も上げない状態のエントリです。
- `take` は 0.5.0 から書きます。0.4.x のスタンドアロンは、知らないキーとして読み飛ばします。
  保存し直すと落ちますが、失うのは欄の選びだけです。
- Unity 版は、知らないエントリとして知らせて、保存で落とします。失うのはポーズだけです。
- スタンドアロン 0.3.x は、バイト列のまま残します。

### look.json

セットの 3D ビューの描き方（`standard` の物理ベースの描き方（PBR）か、`lilToon` の再現か）と、lilToon のときのマテリアルの値を持つ状態のエントリです。
標準の見た目で何も設定していないセットは、エントリを書きません。

```json
{
  "format": 1,
  "kind": "lilToon",
  "shader": "Hidden/lilToonCutoutOutline",
  "properties": {
    "_ShadowBorder": { "float": 0.5 },
    "_UseShadow": { "int": 1 },
    "_ShadowColor": { "color": [0.82, 0.76, 0.85, 1.0] },
    "_MainTex_ST": { "vector": [1.0, 1.0, 0.0, 0.0] }
  },
  "textures": {
    "_MainTex": { "channel": 0 },
    "_ShadowStrengthMask": {
      "packed": [ { "channel": 7, "component": 0 }, { "channel": 7, "component": 0 }, "zero", "one" ]
    },
    "_MatCapTex": { "image": "<アセットの画像の id からハイフンを除いた 32 桁の 16 進>" }
  },
  "keywords": [],
  "kindChosen": true,
  "received": {
    "kind": "lilToon",
    "shader": "Hidden/lilToonTransparent",
    "source": "lilToon 2.3.4 · Standard/Transparent",
    "properties": {},
    "textures": { "_MainTex": { "channel": 0 } },
    "keywords": [],
    "missing": { "_MatCapTex": "pending", "_ShadowColorTex": "overBudget" }
  }
}
```

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `format` | 整数 | 1 | 2 以上は読まずに断る |
| `kind` | 文字列 | `standard`・`lilToon` | 描き方。知らない `kind` は読まずに断る |
| `shader` | 文字列 | 1〜256 文字 | lilToon のシェーダーの名前。描画モードと輪郭線はここから読む |
| `properties` | オブジェクト | 2048 個まで | lilToon のプロパティ（下） |
| `textures` | オブジェクト | スロット 256 個まで | スロットごとのテクスチャの元（下） |
| `keywords` | 配列 | 256 個まで | シェーダーのキーワード |
| `kindChosen` | 真偽 | 無ければ偽 | 利用者が描き方を選んだか |
| `shaderGuid` | 文字列 | 任意。1〜128 文字 | Unity のシェーダーのアセットの GUID。持つだけ。無ければ不明 |
| `shaderVersion` | 文字列 | 任意。1〜128 文字 | Unity のシェーダーのアセットの版。持つだけ。無ければ不明 |
| `renderQueue` | 整数 | 任意。符号付き 32 bit | Unity のマテリアルの描画の順。持つだけ。無ければシェーダーの既定 |
| `received` | オブジェクト | 任意 | Live Link で Unity のマテリアルから受けた値（下） |

- 名前は 1〜128 文字（UTF-16）で、制御文字は使えません。シェーダーの名前は 256 文字までです。
- 値は有限の数だけです。
- `properties` は、プロパティの名前と型（`float`・`int`・`color`・`vector`）を組にします。
  色はガンマの空間で、Unity のマテリアルの値と同じです。知らないプロパティも残します。
- `kindChosen` が偽で、Unity から受けた値があるときは、受けた描き方で描きます。

`textures` のスロット（テクスチャのプロパティの名前）ごとの元は、次のどれかです。

| キー | 値 | 意味 |
|---|---|---|
| `channel` | 標準 0〜5、ユーザーチャンネル 6〜63 | チャンネルの絵。文書に無いチャンネルは、割り当てなしとして扱う |
| `packed` | R・G・B・A の 4 つ。それぞれ `zero`・`one`・`{ "channel", "component" }` | チャンネルの成分を詰めた絵 |
| `image` | アセットの画像の `id` からハイフンを除いた 32 桁の 16 進 | アセットの画像 |

`received` の中のキーです。

| キー | 意味 |
|---|---|
| `kind`・`shader`・`shaderGuid`・`shaderVersion`・`renderQueue`・`properties`・`textures`・`keywords` | 本体と同じ形 |
| `source` | 出どころの文 |
| `missing` | 絵の無いスロットの理由（下） |

`missing` の理由です。

| 値 | 意味 |
|---|---|
| `overBudget` | 受けた絵の予算を超えた |
| `unreadable` | 絵のファイルを読めない |
| `notAFile` | 絵が Unity の中にしかない |

- 受けた絵の画素は書きません。
- 絵のあったスロットは、`missing` にも書きません。開き直すと、`livelink.json` の絵のファイルから読み直します。
- 0.4 までの書き手の `pending`（届いていない）は、`unreadable` として読みます。
- 描くときは、受けた値の上に本体を重ねます。
- 書き直すとき、前のエントリが同じ `format` なら、知らないキーを残します。
- 読めないエントリ（`format` が 2 以上・知らない `kind`）は、エントリをそのまま残します。
  標準の見た目で開き、見た目を変えずに保存すれば残します。
  見た目を変えて保存すると、今の設定で上書きし、保存の知らせで言います。
- 中身の形式も正本の版も上げない状態のエントリです。
  Unity 版は、知らないエントリとして知らせて、保存で落とします。失うのは見た目の設定だけです。

### livelink.json

Live Link の相手の文書（Unity のシーンのオブジェクトを開いた文書）を持つ状態のエントリです（根）。
Unity なしで開き直したとき、同じモデル（FBX の並び・レンダラーとマテリアルの結び）とポーズになるように残します。
中身は Live Link の頼み（[LIVELINK.md](LIVELINK.md) の「頼み」）と同じ形で、`format` は 1、`kind` は `"open"` です。

| キー | 中身 |
|---|---|
| `target` | 相手の身元 `key`・名前・書き出しの置き場 |
| `models` | FBX の絶対の道・GUID・取り込みの設定 |
| `renderers` | レンダラーの道・FBX の中のメッシュの道・入切・サブメッシュごとのマテリアルの番号・今の BlendShape の重み |
| `bones` | 今のポーズで休みと違うボーンの、FBX の親のボーンに対するローカル |
| `materials` | 鍵・名前・シェーダーの身元・テクスチャの道（下） |
| `refused` | Unity が送れなかったレンダラー |

- `materials` に値は書きません。値は、各セットの `look.json` の `received` にあります。
- ただし lilToon の印の値 `_lilToonVersion` だけは残します。開き直したとき、lilToon のスロットの絵をファイルから読むかを決めます。
- ボーンの道は、Unity の根から名前で下ります。
- 道で指せないボーンの値は書けません。畳んだ FBX の根のボーンのような Unity の根の外のボーンと、同じ名前の兄弟です。
  保存の知らせにボーンの名前を出します。開き直すと休みに戻ります。
- このアプリは、大きさ・JSON のオブジェクト・`format` 1 を確かめ（`livelink::validate`）、中身は Live Link の頼みと同じ決まりで読みます。
  決まりは、数の上限・有限の数・番号の範囲です。
- 読めないものは、モデルを開き直さずに、エントリをバイト列のまま残します。
- FBX・絵の道がネットワークの道（`\\host\share`）なら、開いたときに自動では読みません。
- 開き直すとき、セットは鍵で結ぶだけで、増やしません。元の絵は入れ直しません（レイヤーに入っています）。
  スロットの絵は道から読み直します。
- モデルを FBX・形ごと渡されたメッシュに替えて保存すると、エントリを外します。
- モデルがまだ無い間の保存は、エントリに触れません。モデルが無いのは、開き直している最中と、開き直せなかったときです。
- [配布用に保存](SAVE_FOR_DISTRIBUTION.md)で「モデルの参照」を除いた写しには、このエントリを入れません。FBX と絵のファイルの絶対の場所を持つためです。
- 中身の形式も正本の版も上げない状態のエントリです。
  - スタンドアロン 0.4.x は、知らないエントリとして知らせ、保存し直してもバイト列のまま残します。
    モデルは開きませんが、セットは開けます。
  - Unity 版は、知らせて保存で落とします。失うのは相手の記録とポーズだけです。

### selection.bin

今の選択範囲です。本体のエントリで、little-endian です。選択範囲の版は 1 です。

| 欄 | 型 | 範囲 | 意味 |
|---|---|---|---|
| 印 | 4 byte | `YLSL` | |
| 選択範囲の版 | int | 1 | |
| 幅・高さ・タイルの大きさ | int 3 つ | セットの正本と同じでなければ断る | |
| タイルの数 | int | 0〜列 × 行 | |
| タイルごと | | | `x`・`y` の int と量（下） |

タイルごとの欄です。

| 欄 | 型 | 意味 |
|---|---|---|
| `x`・`y` | int 2 つ | タイルの位置。左下のタイルが (0, 0)。`y × 列 + x` の昇順 |
| 量 | タイルの大きさ² byte | 下の行から。0 でない量が 1 つ以上。文書の外の余白は 0 |

- 量のあるタイルだけを書くので、同じ選択範囲はいつも同じバイト列です。
- 長さが合わない・並びが違う・セットの正本と大きさが違うものは、開くのを断ります。
- Unity 版は、理由を知らせて選択範囲なしで開きます。

### selections.json と残した選択範囲

名前を付けて残した選択範囲です（中身の形式 8）。

```json
{ "format": 1, "selections": [ { "name": "前髪", "content": "<中身の印>" } ] }
```

索引は `sets/<ID>/selections.json` です。

| キー | 型 | 範囲 | 意味 |
|---|---|---|---|
| `format` | 整数 | 1 | ほかは読まない |
| `selections` | 配列 | 1 セットに 32 個まで | 残した選択範囲。並びの順 |
| `selections[].name` | 文字列 | 1〜256 文字。前後の空白なし。制御文字なし | 名前。並びの中で重ならない |
| `selections[].content` | 文字列 | 小文字の 16 進 32 桁 | 中身の印 |

中身は `sets/<ID>/selection-<印>.bin` です。

- 形は `selection.bin` と同じで、`YLSL` の選択範囲の版は 1 です。
- 印は、中身のバイト列の SHA-256 の先頭 128 bit です。小文字の 16 進 32 桁で、エントリの名前が 96 バイトまでのためです。
- 同じ中身は、1 つのエントリを共有します。

決まりは次のとおりです。

- 知らないキーは読み飛ばします。
- このアプリは、壊れた項目だけを理由つきで飛ばし、読める項目は読みます。
- 飛ばしたエントリは、バイト列のまま残ります。残した選択範囲を書き換えるまでです。
- 文書と大きさが違うものは飛ばします。
- このアプリは、書き直すときに、前の索引と `selection-*.bin` をセットごと全部置き換えます。使われなくなった中身を残しません。
- 1 つでもエントリがあれば、`ylp.json` の `format` を 8 にします。全部なくなれば 7 に戻します。
  外側の `YLP-3` は変えません。

## document.utpaint

`document.utpaint` は、セットの正本です。1 つのセットのレイヤー・画素・設定を全部持つバイナリです。
このアプリの読み手は `native.rs` の `NativeDocument::read` で、core の文書との変換は `core_bridge.rs` です。

以下の表の読み方です。

- 表の行は、ファイルに書かれる順に並べます。
- 「欄」は、このアプリの読み手が項目に付ける名前です。`NativeDocument::fields()` の道で、例は `layers[0].opacity` です。
- 「版」の列は、その欄がある正本の版です。空は、どの正本の版にもある欄です。

### 値の型

little-endian です。

| 型 | バイト |
|---|---|
| int | 4（符号付き） |
| byte | 1 |
| bool | 1。0 か 1。ほかは断る |
| double | 8（IEEE 754）。範囲の外・NaN・無限大は断る |
| GUID | 16。C# の `Guid.ToByteArray()` の順で、最初の 3 つの区切りは little-endian。空は全部 0 |
| 文字列 | int の長さ（0〜4096 バイト）と UTF-8 |
| バイト列 | 決まった長さ。色の RGBA8 は 4、RGB は 3、タイルは タイルの大きさ² × 4 |
| 塊 | 欄を続けて置いたもの。表の中で「塊」と書いたものは、その下の表が中身 |

- 座標は、左下が原点です。
- タイルの `x`・`y` は、左下のタイルが (0, 0) です。
- タイルの中の画素は、下の行から、行の中は左から並べます。
- 画素は straight RGBA8 で、透明画素の RGB も保ちます。

  個数の上限は「6 ＋ 一覧の数」です。
- 標準の 0〜5 だけの欄: 塗りつぶしの画像・グラデーション、フィルター、パスのマテリアル。
- 同じ並びの中で、同じチャンネルは 2 回置けません。

| `scope` | byte | 0〜2 | 表示の範囲。0 すべてのレイヤー・1 同じグループの中・2 選んでいるときだけ |

`flags` のビットです。

| ビット | 意味 |
|---|---|
| 0 | 表示 |
| 1 | スナップする特殊定規の印。直線定規では 0 |
| 2 | パースの 2 点。パースだけ |
| 3 | 線対称。対称だけで、`lines` が偶数のとき。0 は回転対称 |
| 4 | 見えない面にも写す。3D の対称だけ |
| 5〜7 | 0 |

点の意味は、種類ごとに次のとおりです。

| 種類 | a | b | up（3D） |
|---|---|---|---|
| 直線定規 | 端 | 端 | 作った面の法線 |
| 平行線 | 線の 1 点 | 向き（a から b） | 作った面の法線 |
| 同心円 | 中心 | 表示の半径（a から b の長さ） | 円の面の法線 |
| パース | 消失点 1 | 2 点のとき消失点 2 | 作った面の法線 |
| 対称 | 中心 | 最初の線の向き（a から b） | 回転の軸。最初の鏡の面は `up` と b − a を含む |

- 3D の点は、モデルの空間です。投影の箱・デカール・3D の対称と同じ空間で、モデルの三角形には結び付きません。
- 対称の写しは、線対称 N 本が二面体群の N 個、回転対称 N 本が回転の N 個です。
  - 2D は、線対称が `canvas_symmetry` の `mode` 5 と、回転対称が放射状（`mode` 4）と同じ写しです。
  - 3D は、鏡 1 枚（`a` を通り `up` と b − a を含む面）と `up` のまわりの回転です。
    線対称 N 本は鏡 1 枚と N/2 個の回転（N が 2 なら鏡だけ）、回転対称 N 本は N 個の回転です。
- 値の確かめは、次のとおりです。座標が有限、`a` と `b` が離れている（2D は 0.01 画素、3D は 1e-6）、
  3D の対称では b − a が `up` と平行でない。
- 種類に無い印は 0 です。`lines` は対称だけが持ち、`flags` のビット 2 はパース、ビット 3 は対称、ビット 4 は 3D の対称だけです。

アイランドごとのばらつき（67）の値は、次のように決まります。

- テクセルのモデルの UV アイランド（UV で辺を共有してつながる三角形）の番号 i と `seed` から、u を出します。
  - u = `cell_hash(seeds(seed)[0], i, 0, 0)` × 2^-32 で、[0, 1) です。
  - `cell_hash` は、ノイズと同じ整数の hash です。
- `min + (max − min) × u` を、`low`・`high`・`softness`・`invert` に通した値を、`blend` で合わせます。
- アイランドの番号は 1 から始め、アイランドのいちばん小さい三角形の番号の順です。モデルが同じなら解像度によらず同じです。
- アイランドの外のテクセルは、入力のままです。
- UV が重なったテクセルは、番号の小さい三角形のアイランドの値です。
- モデルが無い、またはアイランドの図が作業メモリの予算に収まらないときは、段は入力を通して理由を出します。
  予算は、文書のアイランドの図・帯の写しの予算です。
- アイランドの図は保存しません。モデルから作り直します。

画像（70）の段は、次のように値を決めます。

- 塗りつぶしレイヤーの画像と同じ投影・同じミップマップの読み方で、画像を読みます。
- 色のチャンネルでは、その画素の色にします。`invert` は RGB を反転し、アルファは見える度合いに掛けます。
- マスク・スカラーのチャンネルでは、選んだ成分を `low`・`high`・`softness`・`invert` に通した値を、`blend` で合わせます。
- 画像の値の無い画素は、入力のままです。外側が透明の画像の外と、位置のマップに面の無い画素です。
- 画像を選んでいない・アセットに無い・読めない・投影が読むマップが使えないときは、段は入力を通して理由を出します。

### パスの一覧

1 つのレイヤーの、下から順に描くパスの並びです（正本の版 27）。

- レイヤーの対象チャンネルの画素は、見せるパスを順に同じ作業面へ描いた結果です。
- 後のパスは前のパスの上に重なります。消しゴムのパスは、前のパスの画素を消します。

塗りつぶしレイヤーのパスは、次のとおりです。

- 画素（`channels`）は、パスを描いた結果だけです。
- 合成では、塗りつぶし → そのレイヤーの効果のスタック → パスの画素の順に重ねます。
- パスの画素は「通常」で重ねます。式は `src · a + dst · da · (1 − a)` です。
- 塗りつぶしレイヤーのパスは、1 本でも一覧の形で書きます。1 本の欄を使えるのは、ラスターレイヤーだけです。

| 欄 | 型 | 中身 |
|---|---|---|
| `count` | int | 1〜256 |
| `items[i].name` | 文字列 | 0〜128 文字（UTF-16）。制御文字なし。空なら、画面が並びの番号から名前を作る |
| `items[i].visible` | bool | 偽なら描かない。点と設定は残る |
| `items[i].surface` | bool | 真なら 3D のパス（`model_fingerprint` を持つ並び）、偽なら 2D のパス |
| `items[i].path` | 塊 | [パス](#パス)と同じ並び |
| `items[i].extra` | 塊 | 1 本のパスの並びに無い設定（[パスの拡張](#パスの拡張)） |

- 一覧のパスは、どれも同じ側（2D か 3D か）・同じ `channel`・同じ `model_fingerprint`（3D のとき）で、`id` が重なりません。
  このアプリは、合わないものを断ります。
- このアプリは、次のパスレイヤーだけを一覧の形で書きます。
  - 塗りつぶしレイヤーのパス
  - 2 本以上のパスレイヤー
  - 名前を付けたパスレイヤー
  - 隠したパスレイヤー
  - 拡張の設定を使うパスレイヤー。ストロークと消しゴム以外の種類・筆先・深さ・対称・滑らかでない点です。
- 名前の無い見せる 1 本のパスは、今までどおり `surface_path`・`canvas_path` に書きます。
  ストロークか消しゴムで、丸い筆先・角度 0・自動の深さ・対称なし・滑らかな点だけのものです。

描き方の詳しい決まりは `crates/yolu-core/src/paths/README.md` にあります。種類の意味は次のとおりです。

- ストローク: 丸いブラシのストロークです。今までのパスです。
- 消しゴム: ストロークと同じで、一覧の前のパスの画素を消します。
  1 本の欄で書くときは、消しゴムの種類をブラシの `erase` の印で表します。Unity 版と同じ並びです。
  どの読み手も、1 本の欄の `erase` の印を、消しゴムの種類として読みます。
- 指先: 一覧の前のパスの画素を、パスに沿って引きずります。
- 塗り: パスの曲線の内側を、ブラシの色・組の値と不透明度で塗ります。
  - 開いたパスは、終わりから始めへ閉じます。
  - 内側は、巻き数が 0 でない所です。
  - 3D は、点が全部 1 つの UV アイランドにあるときだけです。
    曲線を面へ投影した UV の多角形の内側のうち、そのアイランドの UV に入る所を塗ります。
- リボン: アセットの画像を、パスの向きに回した長方形のダブとして並べます。幅はブラシの直径です。
  - 色の種類のチャンネル（Color・Emission）は、画像の色にします。
  - ほかのチャンネルは、組の値（無ければブラシの色）にします。
  - どちらも、画像のアルファを覆いにして重ねます。
  - アセットに無い画像のリボンは、描き直せません。保存した画素は残ります。

対称は、次のように働きます。

- 映した側は持ちません。描くときに作って、元のパスのすぐ後に描きます。
- 2D は、キャンバスの対称の写しで、点と取っ手を写します。最初の恒等の写しは、元のパスです。
  - 線対称（`mode` 5）の写しは、`count` 個です。`count / 2` 枚の鏡（軸の角度が `angle` + 180 度 × k / (`count` / 2)）と `count / 2` 個の回転です。
  - `mode` 5 の `angle` が 90 度で `count` が 2 なら縦、0 度で 2 なら横、0 度で 4 なら両方と同じ写しです。
- 3D は、鏡の面で点の位置を映して、映した位置のいちばん近い面へ置きます。
  置ける面は、同じマテリアルで、向きが合い、許す距離の内側にある面です。
  許す距離は、ブラシの半径と、モデルの境界箱の対角線の 1% の大きい方です。
- 置けない点があれば、その写しは描きません。

筆先は、次のように置きます。

- 2D は、通常のブラシの筆先と同じです。角度はキャンバスの向きで、`follow` なら線の向きからです。
- 3D は、面のダブの中心の接平面に筆先を置きます。
  - 横の軸は、`follow` ならパスの進む向きです。
  - そうでなければ、モデルの +Y を接平面に落とした向きです。平行なら +X・+Z です。
  - そこから、角度だけ回します。
- 自動の深さは、ダブの間隔の 4 倍・区間の長さの 1/4・半径の 4 倍の大きい方です。今までの式です。

接線の意味は、次のとおりです。

- 区間（点 s → s + 1）の両端が滑らかなら、曲線は今までどおり、点を順に通る centripetal Catmull–Rom です。
- どちらかの端が角か取っ手なら、3 次のベジェです。
  - 滑らかな端の制御点は、Catmull–Rom のその端での微分 m から `点 ± m · (t2 − t1) / 3` です。t は centripetal の節です。
  - 角の端の制御点は、点そのものです。
  - 取っ手の端の制御点は、点 + 取っ手です。出る側は `outgoing`、入る側は `incoming` です。

### テキスト

テキストレイヤー（正本の版 30）は、ラスターのレイヤーがテキストの値を持ったものです。

- レイヤーの Color のチャンネルの画素は、この値とフォントから描いた結果です。ほかのレイヤーと同じタイルで保存します。
- このアプリは、画素をそのまま見せ、開くときに描き直しません。
- フォントのファイルは入れません。

| 欄 | 型 | 中身 |
|---|---|---|
| `algorithm` | int | 1。並べと塗りの版（下） |
| `content` | 文字列 | 文。UTF-8 で 4096 バイトまで。改行は LF、ほかの制御文字はタブだけ |
| `font_kind` | int | 0 アプリに同梱のフォント・1 フォントのファイル。OS に入っているフォントも、利用者が選んだファイルも 1 |
| `font_name` | 文字列 | `font_kind` が 0 のとき。同梱のフォントの名前。`a-z`・`0-9`・`-` の 1〜64 文字。今の名前は `biz-udpgothic`・`biz-udpgothic-bold` |
| `font_path` | 文字列 | `font_kind` が 1 のとき。フォントのファイルの道。1〜4096 バイト、制御文字なし。[配布用に保存](SAVE_FOR_DISTRIBUTION.md)の写しは、「素材の出どころのパス」を除く選びのとき（既定の全部選択では除く）だけ、ディレクトリを外したファイル名だけにする。除かない選びでは、絶対の道（ユーザー名を含みうる）がそのまま残る |
| `font_index` | int | `font_kind` が 1 のとき。束（.ttc）の中の番号。0 以上。束でなければ 0 |
| `font_sha256` | 文字列 | `font_kind` が 1 のとき。選んだときのファイルの中身の SHA-256。小文字の 64 桁 |
| `font_family` | 文字列 | `font_kind` が 1 のとき。フォントのファミリー名。name の 16 番、無ければ 1 番。英語の名前、無ければ最初の名前。0〜256 バイト、制御文字なし。読めなかった名前は空 |
| `font_postscript` | 文字列 | `font_kind` が 1 のとき。PostScript 名（name の 6 番）。0〜256 バイト、制御文字なし。読めなかった名前は空 |
| `font_weight` | int | `font_kind` が 1 のとき。太さ。OS/2 の usWeightClass、1〜1000 |
| `font_italic` | bool | `font_kind` が 1 のとき。斜体か。OS/2 の fsSelection の斜体・斜め |
| `size` | double | サイズ。1 em の画素、1〜4096 |
| `rgba` | RGBA8 | 文字の色。アルファは文字の不透明度で、レイヤーの不透明度とは別 |
| `line_height` | double | 行間（行の送り）。サイズに掛ける、0.1〜10 |
| `letter_spacing` | double | 字間（字ごとに足す送り）。サイズに掛ける、−1〜10 |
| `align` | int | 0 左・1 中央・2 右 |
| `x`・`y` | double | 基準の点。文書の画素、左下が原点、±1000000。1 行目の上端で、行は下へ進む |
| `rotation` | double | 基準の点のまわりの回転。度、反時計回りが正、−360〜360 |
| `wrap_width` | double | 折り返しの幅。画素、0〜1000000。0 は折り返さない |

`wrap_width` が 0 なら、揃えの基準は基準の点です。0 でなければ、基準の点から右へ、この幅の箱が基準です。

並べと塗り（`algorithm` 1）は、次のとおりです。

- 段落ごとに、左から右へ並べます。右から左の文字と縦書きは扱いません。
- 折り返しの幅があれば、空白の後と CJK の字の間で分けます。
- ヒンティングをかけずに、輪郭を塗ります。アンチエイリアスの覆う量をアルファにします。
  覆わない画素は、透明で RGB も 0 です。
- 同じ値・同じフォントなら、CPU・スレッドの数によらず、同じバイトです。
- 式を変えて同じ値の画素が変わるときは、`algorithm` を上げます。
  保存した画素は変わらず、文を直したときの描き直しだけが、新しい式になります。
- 可変フォントは、既定のインスタンスで描きます。

フォントを探す決まりは、このアプリの決まりです。どの読み手も守る検査ではありません。

- 同梱のフォントは、名前で探します。
- ファイルのフォントは、次の順に探します。
  1. `font_path` のファイルの中身が `font_sha256` と同じなら、それを使います。
  2. 違う・無いときは、OS に入っているフォントを `font_postscript` → `font_family` と `font_weight`（と `font_italic`）で探します。
  3. 最後に、`font_path` のファイルを使います。
     使うのは絶対の道のときだけです。ファイル名だけ・相対の道は、今の作業フォルダの別のファイルを拾わないよう、使いません。
- 見つけた中身の SHA-256 が違えば、「フォントが違います」と知らせます。
  保存した画素はそのままで、テキストを直したときに、見つけたフォントで描き直します。
  値の道・SHA-256・名前も、そのフォントのものになります。
- どこにも無ければ、開くのは断らず、保存した画素をそのまま見せます。
  テキストの値の編集だけを、理由を添えて断ります。別のフォントで黙って描き直しません。

### 文書をまたぐ決まり

- 効果（フィルター・Generator・Anchor・塗りつぶしの画像とグラデーション）とパスは、設定をセットの正本に持ち、評価した出力は書きません。
  - 評価は、読んだあとの合成のときに行います。
  - `composite/<チャンネル>.png` の合成にも、効果が入ります。
  - 入力がそろわない段は、入力のまま通ります。
- 親（`parent`）は、文書にあるグループで、子より上（大きい番号）にあります。グループの子は、親のすぐ下に続けて並びます。
- グループの入れ子は、このアプリでは 64 段までです（`yolu_core::MAX_GROUP_DEPTH`）。
  超えるファイルは、上限として断ります。Unity 版の読み手には上限がありません。
- Anchor の ID とフィルターの ID は、文書の中で重なりません。
- Anchor の段が自分のレイヤーの Anchor を指すものは、断ります。
- 消えた Anchor、または読むレイヤーより上にある Anchor を指す参照は、開くのを断らずにそのまま読みます。
  その段は入力を通して理由を出します。保存しても参照は残ります。
- アセットに無い `resource_id` は、開くのを断らずに ID を残します。
  塗りつぶしの値を見せて知らせます。画像の Generator の段は、入力を通して知らせます。
- 塗りつぶしのグラデーションは、アルゴリズムの版 2・合成 Replace であること。
- 点のグラデーション（アルゴリズムの版 1）の値は、次のとおりです。
  - 点 i の重みは `1 / (d² + s²)` です。d は点までの距離、s は広がり × 長さです。
  - 長さは、モデルの空間なら位置のマップの箱の対角線、UV の空間なら 1 です。
  - 色は、不透明度で重みを付けて混ぜます。不透明度は、重みで混ぜます。
  - s が 0 で点の真上なら、その点の色です。
  - モデルの空間は、次のとき、塗りつぶしの値を見せて理由を知らせます。
    位置のマップが覆わない画素と、位置のマップかモデルのルートが使えない文書です。

### 分けた正本

分ける前の正本（分ける前の正本の版 21〜25・27〜30・32〜35 の並び）が 512 MiB を超える文書だけを、分けて書きます。正本の版は 26 です。

| エントリ | 中身 |
|---|---|
| `document.utpaint`（ヘッダー） | `DOTPAINT`、int 26、int 分ける前の正本の版、int 部分の数（1 以上）。続けて、分ける前の並び（`id` から最後まで）から、バイト列の値（色・画素。`magic` のほか全部）を抜いたもの |
| `document.utpaint.1`・`.2`… | バイト列の値を、並びの順に。番号は 1 から続く。0 始まり・0 埋め・飛びは断る |

このアプリは、次のように区切って書きます。

- 2 番目からのレイヤーの始まりと、256 MiB を超える手前で区切ります。値 1 つは分けません。
- 今の部分も次のレイヤーの値も 16 MiB に満たなければ、レイヤーの始まりで区切りません。
- 変わらないレイヤーの部分は、前と同じ中身になり、復旧の世代で共有されます。
- レイヤーより後の値（手動の ID の色の `tag`）は、最後のレイヤーの値として数えます。
- 手動の ID の色の塊は、`tag`（`YLID`）が `Bytes` の値なので最後の部分に入ります。
  `count`・`binding`・色の並びは平の値なので、ヘッダーの末尾に入ります。

区切りの位置は決まっていません。どの読み手も、位置を決め打ちせずに、次を確かめます。

- 値が部分の境目をまたがない。
- 空の部分が無い。
- 部分の数（ヘッダーとエントリ）が合う。
- 全部の部分を余りなく使う。

読んだ項目は、分ける前の正本を読んだのと同じです。

部分の名前は、今の名前の決まりに収まります。そのため、`YLP-3` に収まる大きさのファイルにも、正本の版 26 の正本が入りえます。

## 派生のエントリ

### composite の合成 PNG

`composite/<チャンネル>.png` です。`<チャンネル>` は `Color`・`Roughness`・`Metallic`・`Height`・`Normal`・`Emission` です。

- どれかのレイヤーが有効にしている標準のチャンネルごとに、セットの正本の合成を書きます。
- 形式は straight RGBA8 の PNG です。色の型 6 で、補助のチャンクなし、画素は上の行からです。
- `Color` は、使うレイヤーが無くても書きます。
- Height から Normal を作る設定で Height を使っていれば、`Normal` も書きます。Normal は OpenGL の向きです。
- ユーザーチャンネルの合成は書きません。
- セットの正本を替えたときは、そのセットの `composite/` を消してから書き直します。
- Unity 版のインポーターは、この並びからセットのチャンネルを出します。

### meshmap のメッシュマップ

`meshmap-<種類>.bin` です。little-endian です。

`<種類>` は次のとおりです。

| 番号 | 種類 | 番号 | 種類 |
|---|---|---|---|
| 0 | `WorldNormal` | 5 | `TangentNormal` |
| 1 | `Position` | 6 | `Height` |
| 2 | `AmbientOcclusion` | 7 | `Id` |
| 3 | `Curvature` | 8 | `BentNormal` |
| 4 | `Thickness` | 9 | `Opacity` |

| 欄 | 型 | 中身 |
|---|---|---|
| 印 | 8 byte | `YLPMMAP\0` |
| メッシュマップの版 | int | 1〜3。書くのは 3 |
| 種類 | int | 0〜9 |
| エンジンの版 | int | 2 |
| メッシュのハッシュ | 文字列 | 文字列は int の長さ（0〜4096）と UTF-8 |
| トポロジーのハッシュ | 文字列 | 同じ |
| UV のチャンネル | int | |
| 幅 | int | |
| 高さ | int | |
| スロット | int | |
| パディング | int | |
| アンチエイリアスの段数 | int | メッシュマップの版 2 から。メッシュマップの版 1 は 1 |
| チャンネル数 | int | 種類で決まる。3 か 1 |
| スロットの数 | int | メッシュマップの版 3 から。0〜65536 個 |
| スロットの番号 | int × 数 | メッシュマップの版 3 から。昇順 |
| 設定の鍵 | 文字列 | 下 |
| 空間 | 文字列 | |
| ポーズ | 文字列 | |
| 元 | 文字列 | |
| 由来の境界箱の最小 x・y・z | double × 3 | |
| 由来の境界箱の最大 x・y・z | double × 3 | |
| 圧縮データの長さ | int | |
| 圧縮データ | Deflate | 展開した中身（下） |

- メッシュマップの版 1・2 には、スロットの数の欄がありません。スロットの欄の 1 つが、スロットです。負なら無しです。
- 展開した中身は、覆いの byte（テクセルの数）に続いて、チャンネルごとに 2 つの面です。
  - 16 bit の値の上位 byte の面
  - 16 bit の値の下位 byte の面
  - どちらも、行ごとに左の値との差です。

設定の鍵は、次のとおりです。

- ID マップの元は、`source=<元>;algorithm=2` です。必要なら、次の鍵が付きます。
  - マテリアル識別: `materials=<SHA-256>`
  - 手動の色: `manual=<SHA-256>`
- どの種類の鍵にも、重なった UV の優先が既定でないときだけ、末尾に次のうち変えたものが付きます。
  重なった UV の優先は、正本の版 33 の頭の欄 `bake_priority` です。既定は何も付きません。
  - `;owner=<決め方の名前>`: `LowestIndex` 以外のとき
  - `;outside=skip`: 0〜1 の外のアイランドを焼かないとき
  - `;islands=<SHA-256>`: 手で選んだアイランドがあるとき

決まりは次のとおりです。

- このアプリは、焼いて保存していないマップだけを書きます。開いたときのマップは、ファイルのバイト列のまま残します。
- どの条件で焼いたか（由来）が、今のモデル・設定と違えば、古いとして使いません。焼き直しを促します。
- Generator と投影はメッシュマップを読みます。無い・古いときは、値をそのまま出して理由を知らせます。

## 読み書きの決まり

このアプリの動きのうち、外のツールが守るべき事・知るべき事です。

### 開くとき

1. 外側を読み、manifest と全エントリの長さ・CRC・SHA-256 を確かめます。
   ファイルから開くときは、大きなエントリは位置だけを覚え、要るときに確かめ直しながら読みます。
2. `ylp.json` を読みます。無ければ中身の形式 1 です。
   今より新しい中身の形式なら、どのエントリにも触れずに、形式の番号と書いたアプリを添えて断ります。
3. 古い中身の形式なら、移行の段を順に通します。メモリの上だけで、ファイルは書き換えません（[中身の形式の版](#中身の形式の版)）。
4. `project.json` を読み、並びの全部のセットの正本と選択範囲、アセットの並びと中身を読みます。
   1 つでも読めなければ、開いているプロジェクトは何も変えません。
5. 知らないエントリを一覧にして知らせます。
   - core の文書にできないセットの正本は、セットと理由を知らせて、読むだけで開きます。元のバイト列のまま保存します。
     調整の種類が使わない値が既定でないもの、などです。
   - 手動の ID の色は、文書へ戻して開きます。
6. 入力がそろわない効果を含むセットも開きます。
   入力がそろわないのは、焼いたマップが無い・古い・モデルと照合できない、画像がアセットに無い、モデルが無い、のときです。
   - 開いたあとは読むだけにして、足りない入力を知らせます。
   - 保存済みの合成（`composite/Color.png`）を見せます。
   - 保存は、合成の画像に置き換えず、元の編集情報（セットの正本）をそのまま残します。
   - 入力がそろえば同じセットを編集できます。ベイクする・モデルを読む・画像がアセットに入る、のときです。
   - 保存済みの合成の画像は、最新の効果を再計算したものとは限りません。

### 読めないエントリ

読めないエントリの扱いは、種類で決まります。

| 種類 | 読めないとき |
|---|---|
| 本体 | 開くのを断る。Unity 版は `selection.bin` だけ、理由を知らせて選択範囲なしで開く |
| 記録（`ylp.json`） | 開くのを断る |
| 状態 | 既定に戻して知らせる。エントリはバイト列のまま残す。書き換えるまで |
| 派生 | 使わずに作り直す。本体の代わりにはしない |

### 知らないエントリ

知らないエントリは、今の中身の形式のどの読み手も知らない名前のエントリと、並びに無いセットの `sets/<ID>/` です。

- 開くときに、一覧で知らせます。
- このアプリは、バイト列のまま残します。
- Unity 版は、保存で落とします。

### 保存

1. 書いたものを読み直して確かめます。
2. 同じフォルダの一時ファイルに書いて、フラッシュします。
   - 名前は `.<名前>.<プロセス番号>-<通し番号>.pending~` です。
   - 名前が 200 バイトを超えるときは、先頭を切って指紋を付けた短い形にします。
3. 一時ファイルを読み直して確かめます。
4. 開いた・保存した時点のファイルの印（SHA-256・長さ・更新時刻）と、今のファイルが同じことを確かめます。
   違えば、外の書き換えとして上書きを断ります。
5. 最後の 1 回で置き換えます。途中で失敗しても、元のファイルはそのままです。

- 直前の版は、`<ファイル名>-backups~/` に退避します。
- 退避に残す数は設定で決めます（既定はすべて）。超えた古いものだけを消します。
- いつも今の形式で書き、`ylp.json` に保存したアプリと（分かれば）作ったアプリを記録します。
- Undo の履歴は保存しません。
- 古い読み手のために形式を下げて書く変換はありません。
  書く版は、使う機能で決まる最小の版です。機能を消して保存し直すと下がります（[正本の版の決まり](#正本の版の決まり)）。

### 復旧の世代

保存していない作業の書き置きです。`generation.rs` の `GenerationStore` が書きます。.ylp ではありません。

- 置き場の中に、`current`・`previous`（世代の名前）、`generations/<世代>/manifest.sha256`、`contents/<SHA-256>.bin` を置きます。
- 世代を確かめてから、`current` を最後に置き換えて確定します。
- manifest の 1 行目は、次のどちらかです。
  - `DOTPAINT-MANIFEST-1`: 中身を世代の中に持つ。
  - `DOTPAINT-MANIFEST-2`: 中身は `contents/` にあり、同じ中身は世代の間で 1 つを共有する。
- 続く行は `<SHA-256> <長さ> <名前>` です。
  名前は .ylp のエントリと同じ範囲です。`ylp.json`・`project.json`・`resources.json`・`resources/*`・`sets/<ID>/*` などです。
- 世代に添える一覧用の情報は `recovery.json` です。.ylp には入りません。
- Unity 版が書いた世代は、このアプリが読めます。
- 逆は読めません。`sets/<ID>/composite/Color.png` のような入れ子の名前を含む世代を、Unity 版は断ります。
- 量の数え方と置き場は [RECOVERY.md](RECOVERY.md) にあります。

- 分けた正本の、分ける前の正本の版も、同じ範囲で読みます。
  - スタンドアロン 0.5.x は、分ける前の正本の版 34 から上を断ります。
  - スタンドアロン 0.4.x は、分ける前の正本の版 27 から上を断ります。
- 1 つのセットでも正本の版が 22 以上なら、その .ylp は Unity 版では開けません。
  Unity 版で開くには、その機能を消して保存し直し、正本の版を 21 に戻します。
- Unity 版の読み手に実際に読ませた記録は、`crates/yolu-io/tests/fixtures/*.unity.txt` にあります。
  正本の版 22・23・24 は、`Runtime/Core` の読み手に読ませてあります。

手動の ID の色の塊（正本の版 19 から）の読み手は、次のとおりです。

- Unity 版（書き手でもあります）と、このアプリの 0.3.0 以降が読めます。
- 0.4.x までのアプリは、塊のあるセットを読むだけで開きます。理由を出し、元のバイト列のまま保存します。色は編集できません。
- 0.5.0 からは、色を文書へ戻して編集でき、保存でも残ります。

分けた正本（正本の版 26）と `YLP-4` の古い読み手は、次のとおりです。

- 正本の版 26 は、正本の版 25 までを読むスタンドアロンも、Unity 版も、範囲の外として断ります。
- Unity 版は、`YLP-4` のファイルをどれも断ります。断る理由は、ファイルによって次のように変わります。
  - 832 MiB を超える: 読みの予算を超えた。
  - それ以下で、1002 を超えるエントリがある: エントリが多すぎる。
  - 1 MiB を超える manifest がある: manifest が大きすぎる。
  - ほか: manifest の外側の版が新しいアプリのものである。

### 正本の版の決まり

正本の版について、次の決まりがあります。

- このアプリは、1〜25・27〜30・32〜35 と 26 を読みます。その版に無い欄・値を持つものは断ります。
- 新しい機能を使わない文書は、前の版と同じ並びで、版の数だけが違います。
- 分ける前の正本の版は、21〜25・27〜30・32〜35 だけです。ほかと、26 自身は断ります。
- 31 は欠番です。意味を決めておらず、このアプリは範囲に入れず、版の数で断ります。分ける前の正本の版でも同じです。
- 31 は、これからも割り振りません。新しい機能の版は、配った一番上の版より上の番号にします。

このアプリの書き手（`NativeDocument::from_core`）は、使う機能が要る一番小さな版で書きます。

| 使っている機能 | 書く正本の版 |
|---|---|
| 定規を持つレイヤー（グループ）、または線対称（`mode` 5）の 2D のパス | 35 |
| アンチエイリアスが なし でないパスのブラシ | 34 |
| ベイクの優先を既定から変えている | 33 |
| 継ぎ目の設定を切っている | 32 |
| テキストレイヤー | 30 |
| 点のグラデーション、または異方性を切った塗りつぶしの画像 | 29 |
| フィルターの段の種類 70〜79、または Generator の種類 66〜70 | 28 |
| パスの一覧 | 27 |
| グラデーションマップの混色 | 25 |
| 色調補正 | 24 |
| ノイズ・グランジ | 23 |
| ユーザーチャンネル | 22 |
| どれも無い | 21 |

- 表は、上から順に当てはめます。いちばん上に当てはまるものが、書く版です。
- 機能を消して保存し直すと、版も下がります。
- 開いたまま変えていないセットの正本は、元のバイト列のまま書きます。
- 512 MiB を超える正本だけ、分けた正本（正本の版 26）で書きます。分ける前の正本の版は、この表で決まります。

Unity 版に無い機能を使う文書だけを新しい版にするための決まりです。

- 正本の版 22〜25 と 27〜30・32〜35 は、Unity 版に無い機能を使う文書だけが、新しい版になります。
- Unity 版の読み手は、版の数だけで、ファイルに触れずに断ります。
- 中身の形式（7）は上げません。
- Unity ブリッジは 0.5.0 から .ylp を扱いませんが、版の数の意味は変えません。
- 種類の番号の 8〜63（Generator）・3〜63（調整）・7〜63（フィルター）は、Unity 版の並びのために空けたままにします。
- このアプリだけの種類は、64 から振ります。
- この決まりの理由は、[YLP_DECISIONS.md](YLP_DECISIONS.md) の [版の番号の付け方](YLP_DECISIONS.md#版の番号の付け方) にあります。

### .ylsmart

スマートマテリアル・スマートマスクの 1 つのファイルです。置き場に置き、.ylp のアセットにも同じバイト列で入ります。コードは `smart.rs` です。

- 外側は .ylp と同じ zip です。`mimetype` は `application/x-yolupainter-smart` です。
- manifest の 1 行目は `YOLUPAINTER-SMART-1` です。
- 名前は、根と `resources/` の下の 1 段です。

| エントリ | 種類 | 中身 |
|---|---|---|
| `smart.json` | 本体 | 下 |
| `layers.utpaint` | 本体 | 選んだレイヤーだけを持つ、`document.utpaint` と同じ形のバイナリ |
| `resources.json`・`resources/<content>.png` | 本体 | レイヤーが参照する画像があるとき。.ylp と同じ形（画像だけ） |
| `thumbnail.png` | 派生 | パネルの見本 |

`smart.json` の欄です。

| キー | 型 | 意味 |
|---|---|---|
| `format` | 整数 | 1 |
| `kind` | 文字列 | `smartMaterial`・`smartMask` |
| `name` | 文字列 | 名前 |
| `width`・`height`・`layers`・`channels` | 整数 | 読むときにレイヤーと比べ、違えば断る |
| `repin` | 配列 | ベイクへのピンがあった Generator の段の ID。置いた先で付け直す |
| `savedBy` | オブジェクト | 必須 |
| `thumbnailShape` | 文字列 | 任意。`"sphere"` なら見本が球 |

- 知らないキーは読み飛ばします。
- `layers.utpaint` は、正本の版 1〜21 で、保存したテクスチャセットの大きさです。
  - スマートマスクは、値の無い塗りつぶしレイヤー 1 つがマスクを持ちます。
  - モデルの上のパスは持ちません。
  - Generator は、ベイクへのピンを持ちません。
- ユーザーチャンネルと 64 からの種類は、入れません。このアプリは、理由を添えて断ります。
- `.ylmaterial`（置き場のマテリアル）は、塗りつぶしレイヤーを持つ `.ylsmart` と同じ形です。

### .ylbrush

.ylp のアセットに入る Unity 版のブラシの形です。このアプリは読んで、バイト列のまま残します。

- zip です。`mimetype` は `application/x-yolupainter-brush`、manifest の 1 行目は `YOLUPAINTER-BRUSH-1` です。
- `state.json` に、`schema` 1〜3 を書きます。外の筆先の ID `tipId`・`textureId`・`dualTipId` は空であること。
- `tip-0.png` から続く筆先は、256 枚までです。
- 任意で `texture.png`・`dual.png` を持ちます。
- PNG は、RGBA8 で 1〜2048 px です。

このアプリの利用者のブラシのファイル（設定のフォルダの `brushes/`）は、同じ拡張子のテキスト形式で、[BRUSH.md](BRUSH.md) にあります。

## 形式を変えるとき

### 手順

1. **本体・状態のエントリを追加する・名前や置き場を変える・意味を変える**ときは、中身の形式を上げ（`project::MAX_FORMAT`）、前の形式からの移行を追加します。
   - 上げないと、古い読み手が知らないエントリを落として保存し、作業を失います。
   - 使う文書だけを新しい形式にできるなら、そうします。中身の形式 8 がその例です。
2. 派生のエントリだけを追加するときは、中身の形式を上げなくてよいです。
   古い読み手は、知らないエントリとして知らせ、作り直します。
   - 名前の決まり（置けるフォルダ）を広げるなら、外側の版も上げます。
   - 状態のエントリは、古い読み手が落としても失うのがその状態だけなら、形式を上げずに追加できます。`look.json`・`pose.json` がその例です。
3. エントリの中身の版だけを変えるときは、そのエントリの版を上げ、古い版も読めるようにします。
   正本の版を上げるときは、新しい機能を使う文書だけを新しい版で書きます。正本の版 22〜25 がその例です。
4. **同じコミットで、この文書を直します。**
   - 直す所は、次のとおりです。
     - 概要の版の数の表（範囲と、このアプリが書く値を含む）
     - 読み手ごとの範囲
     - 正本の版ごとの追加と、正本の版の決まり
     - コードの定数
     - エントリの一覧と、その欄
   - 形を選んだ理由・採らなかった案・保証の射程は、[YLP_DECISIONS.md](YLP_DECISIONS.md) に節を足します。
5. 前の形式・版のファイルを試験のフィクスチャにして、開ける・中身が同じに読み書きできることを確かめます。
   例は `crates/yolu-io/tests/ylp/compatibility.rs` です。
