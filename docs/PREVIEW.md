# 3D ビューの質感

3D ビュー（スタンドアロンの Rust 版の自前の描画。wgpu）は、描いたチャンネルをそのままモデルに貼って見せます。
このページで「Unity 版」と書くのは、Unity のパッケージの 0.4.x までのプレビューです（0.5.0 以降の Unity ブリッジには、描く機能も 3D のプレビューも無い）。

見た目の式は Unity 版のプレビューのシェーダー
（`PreviewSurfaceLit`・`PreviewSurface`・`PreviewEnvironment`・`PreviewToneMap`）と、そのもとの Unity の Standard の BRDF（`UnityStandardBRDF.cginc` の
`BRDF1_Unity_PBS`、リニアのカラースペース）を WGSL（wgpu のシェーダー言語）に移したものです。同じ式を CPU でも書き（`crates/yolu-app/src/view3d/brdf.rs`）、試験が既知の値と
GPU の絵を照らします。見た目の種類を lilToon にしたテクスチャセットは、lilToon の式で描きます（[lilToon の見た目](#liltoon-の見た目)）。

## 表示の切り替え

3D ビューの右上の隅のアイコン「3D の表示」を押して出るメニューで選びます（並びは Unity 版と同じ）。

| 表示 | 見えるもの |
|---|---|
| マテリアル (PBR) | 金属の流儀の PBR。Color・Roughness・Metallic・Normal・Emission が効く。環境・光・トーンマッピングを使う。見た目が lilToon のセットは lilToon の式で描く |
| 中立 | Unity 版の簡単な明暗（`0.35 + 0.65 × saturate(n·L)`、ガンマの空間）。法線マップは効く。環境を使うときは環境の拡散と弱い映り込み |
| チャンネルだけ | Color・Roughness・Metallic・Normal・Emission・Height のどれか 1 つを、光・環境・トーンマッピングなしで値のまま |
| メッシュマップだけ | 今のテクスチャセットで焼いたメッシュマップ（AO・曲率・法線など）の 1 枚を、光・環境・トーンマッピングなしで値のまま。焼いていない種類は選べず、見ているマップが無くなるとマテリアルへ戻る |

右上の隅の「光・環境・トーンマッピング」のアイコンで小さなパネルが開きます。表示（光・環境・トーンマッピング。影の入り切りとやわらかさもここ）・画質（アンチエイリアスとブルーム）・視点の 3 つの面があります。
視点の面は、回転の中心（画面の中心・面の位置（自動深度）・モデルの中心・テクスチャセットの中心。既定は画面の中心）、ズームの中心（画面の中心へ・ポインタの所へ。既定は画面の中心）、
今のテクスチャセットの面を画面に収める「選んだ所に合わせる」です。右上の隅にはほかに、モデル全体が見える位置へ戻すアイコンと、3D の絵が元より縮んでいるときの警告の印が出ます。そのアイコンの下には軸の印（X・Y・Z の正と負の向きの丸）があり、丸を押すとその向きから見る視点になり、
真ん中の丸で透視と正投影が切り替わり、印のドラッグで視点が回ります。軸の向きの視点にしたときと、Alt を押しながらのドラッグで軸に吸い付いたときは正投影になり、回して軸から外れると透視に戻ります
（設定の「軸の向きで正投影」。既定は入。手で切り替えた投影は軸から外れても戻しません）。

- 環境: なし（一様な環境光）・空（Unity 版の既定の勾配）・スタジオ（暗い灰色の背景に面光源。金属の映り込みと回転が分かる）。明るさ・回転・背景に映すか（とそのぼかし）。
  空は上の軸のまわりに対称なので、回転は見た目を変えません。
- ライト: 強さ・方位・高さ（Unity 版の `PreviewSceneSettings` と同じ項目）。強さ 1（既定）は、Unity の場面の白・強さ 1 のディレクショナルライトと同じ明るさです。既定の来る向きは (−0.3, 0.65, +0.7)、つまりモデルの前（+Z）の斜め上です
  （Unity 版の既定 (−0.3, 0.65, −0.7) を Z で折り返した向きで、高さと横へのずれは同じ）。Unity は +Z を前にするので、前から見たときに逆光になりません（既定のカメラもモデルの前から見るので、開いた直後から明るい側が見えます）。
- 影: 主な光からモデル自身へ落ちる影（既定は切）と、そのやわらかさ（影の縁のぼかしの広さ。0% は影のマップの 1 画素ぶん、100% はモデルの大きさの約 2.5%）。
  マテリアルと中立の表示で効き、光なしの表示（チャンネルだけ・メッシュマップだけ）では使いません。
- トーンマッピング: なし・ニュートラル・ACES と露出（EV）。3D ビューの絵だけに当てます（テクスチャの値・書き出し・2D には当てません）。

### 画質（アンチエイリアスとブルーム）

どちらも 3D ビューの絵だけに当てます（テクスチャの値・書き出し・2D・塗るときの当たりには影響しません）。設定のファイル（`view3d_antialias`・`view3d_bloom`・
`view3d_bloom_strength`・`view3d_bloom_threshold`）に保存します。

- アンチエイリアス: 切・2×・4×・8×（既定 4×）。面を多サンプルで描いて縁をなめらかにします（MSAA）。使える数は GPU で決まり、対応しない数は押せません。
  描き先のメモリが上限を超える大きさ（大きなウィンドウの高い数・HDR・ブルームの組み合わせ）では、上限に収まる数へ自動で下げます（選んだ数は保ちます）。
  上限は、設定の「GPU のメモリ」が 3D の絵へ配る量と同じ大きさで、設定の合計（3D の絵・キャンバス・アセットのサムネイルへの配り）の中ではなく外に足します。描き先が
  上限まで載ると、合計に加えてその量まで使います（標準で 512 MiB。下の表の 4K の HDR＋ブルームの 4× が約 496 MiB）。3D の絵の取り分から引かないのは、
  ウィンドウの大きさやサンプル数を替えるたびに絵が縮み直すためです。ブルームとトーンマッピングは、多サンプルを 1 つに解決したあとの絵に当てます。
  確かめたのは、ソフトの描画（llvmpipe の Vulkan）で対応する 1× と 4× です。2×・8× と、Windows の D3D12・Vulkan の実機では確かめていません。
- ブルーム: 入・切（既定は切）、強さ、しきい値。露出を掛けたあとの明るさ（リニア。1 が白）がしきい値を超えた分を取り出し、縮めながらぼかして足し戻します
  （トーンマッピングの前）。発光（Emission）の強い所の周りが光って見えます。光なしの表示（チャンネルだけ・メッシュマップだけ）には足しません。切（入で強さ 0 も）のときは
  ブルームの処理を通らず、同じサンプル数でブルームを入れる前に描いた絵とバイトまで同じです（試験は入と切の往復で確かめています）。アンチエイリアスの既定が 4× になったので、
  多サンプルなしだった以前の版の絵とは縁が違います。

描き先のメモリの目安（解決後の絵・深度・多サンプルの色・HDR・ブルームの段）:

|---|---|---:|---:|---:|---:|
| 1920×1080 | 8 bit | 16 MiB | 40 MiB | 71 MiB | 134 MiB |
| 1920×1080 | HDR（トーンマッピング） | 32 MiB | 71 MiB | 119 MiB | 214 MiB |
| 1920×1080 | HDR＋ブルーム | 37 MiB | 76 MiB | 124 MiB | 219 MiB |
| 2560×1440 | 8 bit | 28 MiB | 70 MiB | 127 MiB | 239 MiB |
| 2560×1440 | HDR（トーンマッピング） | 56 MiB | 127 MiB | 211 MiB | 380 MiB |
| 2560×1440 | HDR＋ブルーム | 66 MiB | 136 MiB | 220 MiB | 389 MiB |
| 3840×2160 | 8 bit | 63 MiB | 158 MiB | 285 MiB | 538 MiB |

## チャンネルの意味

書き出し（`export::build`）と同じ値の意味で、見ているものと書き出したテクスチャの値は、次の違いを除いて同じです（不透明な画素のテクセルの一致は試験が照らします）。

- Color: 3D ビューは見せるために**乗算済み**にして上げます（透明の縁が黒くならない）。書き出しは straight RGBA（透明な画素の RGB を保つ）なので、半透明・透明の画素では値が違います。
  不透明な画素は同じです。Color の透明な所は市松の灰色の上に見えます。
- Color・Emission は sRGB のテクスチャとして持ち、GPU が読むときにテクセルをリニアへ直してから補間します（ミップもリニアで平均）。Unity がリニアの
  色空間で sRGB のテクスチャを読むのと同じで、色の境目の中間の色・遠くで縮んだ絵の明るさが Unity と揃います。Color の乗算済みもリニアで掛けます
  （sRGB(リニア(色) × α)）。市松の上に重ねる見え方（中立・チャンネルだけの表示と、マテリアル表示の透明な所）は、今までどおりガンマの値で重ねます。
- Emission: RGB は書き出しと同じ（値 × アルファ）。3D ビューはアルファも持ちますが読みません（書き出しはアルファを不透明にします）。
- Roughness・Metallic・Height: 値 × アルファ（塗っていない所は 0）で、書き出しと全テクセルが同じです。Roughness は滑らかさ = 1 − Roughness として読みます。
- Normal: Normal の出力（塗った法線を平らな法線に載せ、Height → Normal が有効なら Height から作った法線を土台に重ねたもの。OpenGL の Y+）で、書き出しと全テクセルが同じです。
- どのレイヤーも有効にしていないチャンネルは、書き出しの既定の値（Roughness 0.5・Metallic 0・Normal は平ら・Emission 黒・Color は透明）を見せます。

法線マップの接線は Unity の `Mesh.RecalculateTangents` と同じ MikkTSpace（`bevy_mikktspace`）で、三角形の角ごとに作ります（FBX も Live Link のモデルも）。
数万三角形のモデルでは数百ミリ秒かかるので別のスレッドで作り、出来るまでは前のモデルの接線で描きます（ポーズで毎回モデルが替わるときも描きを止めません）。

## 速さ

描くのは、カメラ・大きさ・モデル・塗った絵・表示の設定のどれかが変わったときだけです。塗った絵は、core が「変わった」と言うタイルだけを合成して上げます
（隣り合うタイルは 1 回の書き込みにまとめ、全面を作るときは 1024 行ずつの帯）。全面を作るときは、レイヤーが面を持つタイルだけを合成します。ただし塗りつぶし・調整レイヤーや、そのチャンネルに当たるフィルター・Generator（レイヤーのマスクのものを含む）があるときは、効果が面の無いタイルへも出るので全タイルを合成します。変わらなかったチャンネルは触らず、使っていないチャンネルはテクスチャを持ちません。
ミップマップは変わった範囲だけ作り直します（段ごとに、変わった範囲を 1 画素広げて描くので、奇数の大きさでも全面を作り直した結果と全部の段で一致します。試験が照らします）。
3D ビューへ上げる絵は、UV アイランドの外へ 16 テクセル塗り広げます（書き出しのパディングと同じ式。文書・書き出しは変えず、表示の写しだけ）。離れて見たときに
ミップの段がアイランドの外の透明・0（や、グラデーションデカールなど UV の外に値を作らない効果の下の塗りつぶしの色）を混ぜて、継ぎ目に線が出るのを防ぎます。
ミップマップ（段 1 以降）は、箱の平均でなく、UV の上の画素（アイランドと塗り広げの 16 テクセル）だけで作ります。UV の上かどうかを示す重みの絵（1 テクセル 1 バイト、ミップつき）を
セットごとに 1 つ持ち、チャンネルで共通に使います。重みの絵はメモリの予算に入ります（次の「メモリ」）。今のセットは、UV の覆いと塗り広げの段の地図をモデルの UV の形・文書の大きさごとに 1 度だけ作り、描いたタイルは、その周りの
塗り広げが届く所だけを塗り広げ直して上げます（全体を塗り広げたときと同じ値。試験が照らします）。ほかのセットは、文書の大きさのメモリをセットの数に比例して
残さないよう、文書が変わって同期するたびに覆いと段の地図を作り直します（4096² のセットで 0.1 秒ほど）。
Height → Normal の設定はレイヤーの合成を変えないので、設定が変わったら Normal を作り直します。
ギズモやスライダーをドラッグして文書が変更をまとめている間は、効果の出力がまだ評価されていないタイルを 1/4 の大きさで粗く合成して上げ、離したときに正確に上げ直します
（Height から作る Normal は隣の画素を読むので粗くしません）。粗く上げたタイルは塗り広げず、重みを使わない箱の平均でミップを作るので、その間だけアイランドの縁が少しにじみます。
離すと正確に上げ直して、にじみは消えます。

メモリ: 使っているチャンネルのテクスチャ全部（ミップ込み）の予算は 512 MiB です。重みの絵（塗り広げるとき。既定）は 1 テクセル 1 バイトとして、この予算に入ります。
4096² で 6 チャンネルすべて（約 341 MiB）は収まり、8192² の 6 チャンネル（約 1.33 GiB）は 1 段縮めて 4096² にします。予算を超える文書は、確保する前に 2 の累乗で縮めて持ち（箱で平均）、3D ビューの右上の隅に警告の印を出し、ツールチップに「縮小表示 1/2」のように言います（絵と書き出しは元の大きさのまま）。
新しいチャンネルを使い始めて予算を超えるときは、縮めを上げて全部を作り直します。縮めは上げるだけで、文書が替わると決め直します。GPU のテクスチャの辺の上限を超える文書も同じ道で縮めます。
メッシュマップの 1 枚も、辺の上限と予算（チャンネルの予算の半分）を超えるときは縮めます。

### 全部のテクスチャセットの絵

3D ビューは全部のテクスチャセットの絵を見せます（今のセットを替えても、前のセットの面から絵は消えません）。描く先は今のセットのままで、
ほかのセットの面には描けません。

- 今のセットは文書の大きさのまま（上の予算と縮め）。ほかのセットは、辺を 1024 までに縮めて（2 の累乗で、箱で平均）GPU に持ち、そのセットの文書が変わったとき
  （版・変化の記録）だけ、変わったタイルを同期します。使っているチャンネルは今のセットと同じで、Normal・Roughness なども効きます。
- メモリの予算（上の 512 MiB）には、今のセットの絵を先に入れ、残りにほかのセットを入れます。収まらないときは、今のセットから並びの上で遠いセットから持たず、
  そのセットの面は絵の無い描き方（市松）になります。テクスチャセットの一覧のそのセットの行に警告の印が付き、ツールチップが理由を言います。Unity の流し込み先が無い警告や
  「Unity に見せている」とも別の事実なので、印は 1 つのまま、ツールチップに並べて言います。3D が描かれていないあいだ（キャンバスのタブが前に出ている間）にモデルや今のセットが
  替わったときは、前の印を消します（3D が前に出たときに計算し直します）。
- 目を閉じたセット、モデルに面の無い（ポーズの「面を隠す」で全部の面を隠した）マテリアルのセットは持ちません（目を開く・面が戻るとき、文書から作ります）。
- 今のセットが替わると、前のセットの絵は、ミップの段をコピーして 1024 の大きさへ縮めて持ちます（GPU の中だけ。文書を合成し直しません）。辺が奇数などで、段の大きさが
  文書から縮めた大きさと合わないときだけ、その場で文書から作り直します（ほかのセットの作り直しと同じく、そのフレームの最初の 1 つなので 40 ms を超えても走ります）。
  替わった先のセットは文書の大きさで作り直します（これは従来から要る）。
- 替わるフレームの順番は、GPU のメモリが予算を超えて重ならないように決めてあります: 新しい今のセットの絵が取る分を予算から引いてほかのセットの持つ・持たないを決め、
  持たないものを捨て、前の絵を縮めてから、新しい今のセットの絵を作ります。前の絵（満量）と新しい絵（満量）が一度に載ることがありません。保証の射程は、直前のフレームの
  終わりに持っていた絵が予算に収まっているときです（予算を下げた直後のフレームは、下げる前に持っていた分が先に載ります）。測った最大は下の表。
- ほかのセットの合成の作業用のバッファ（CPU。帯 1024 行の分、Height から作る Wrap の Normal は文書全体。4096² で Wrap の Normal なら、1 セットで約 128 MiB の見積り）は、
  作り終えたら手放します。手放さないと、セットの数に比例して CPU のメモリが残ります（この分は GPU の予算に入りません）。今のセットのバッファは、描きの更新に使うので持ちます。
- ほかのセットの絵を新しく作る（文書を合成して縮める）のは、1 フレームの時間（40 ms）に収まるあいだと、そのフレームの最初の 1 つだけです。残りは次のフレームから
  （ウィンドウは次のフレームを求めます）。大きなセットが多いプロジェクトでも 1 フレームに重なって止まらず、絵が順に出てきます。小さな文書は 1 フレームで全部出ます。
- 描き方はマテリアルごとの描き呼び出しです。頂点をマテリアル順に並べ（モデルを替えたときだけ上げ直します。セットを替えても上げ直しません）、マテリアルごとに
  絵（6 チャンネル）の束ねを替えて描きます。絵を持たないマテリアルは隣り合うものを 1 回にまとめます。テクスチャの配列で 1 回に描く案は、文書の大きさがセットごとに違う
  （今のセットだけ別の解像度）ので大きさをそろえて作り直す手間と、レイヤーの数の上限が要り、得られるのは下の呼び出し数の分だけなので採りませんでした。
- メッシュマップだけの表示は、今のセットの面だけに貼ります（ほかのセットの面は絵の無い描き方）。

## Unity 版の見た目との比べ方

Unity ブリッジの 0.5.0 以降には 3D のプレビューが無いので、比べるには 0.4.x までの Unity 版のパッケージを使います。

1. Unity 版のプロジェクトのカラースペースを Linear にする。マテリアルは組み込みの Standard にする（Unity 版のプレビューは lilToon を描かない。lilToon の見た目の比べ方は下の
   [lilToon の見た目](#liltoon-の見た目)）。
2. 同じモデルを両方へ入れる（Live Link で同じモデルを送るか、同じ FBX を開く）。両方で「モデル全体が見える位置へ戻す」を押す。Unity 版は斜め後ろ（yaw 25°・pitch 10°）から、Rust 版は同じ斜めの角度でモデルの前（+Z 側。yaw 205°・pitch 10°）から始まる（モデルを開いた直後も同じ）ので、同じ向きから比べるには Unity 版のカメラを水平に 180° 回して、前から見る。
3. Unity 版の 3D ビューを「マテリアル」の見せ方にし、シーンの設定を既定（環境なし・影なし・トーンマッピングなし・露出 0・光は既定）に戻す。
   Rust 版は光のパネルの「既定に戻す」のあと、環境を「なし」にし、光の方位を −157°・高さを 40.5° にする（Unity 版の既定の来る向き (−0.3, 0.65, −0.7)。
   Rust 版の既定は前（+Z）の側から来る向きなので、そのままでは合わない）。光の強さを 0.769 にする（Unity 版の 3D ビューの光は、エディタのプレビューの
   ウィンドウのライトの色 0.769 × 強さ。Rust 版の強さは Unity の場面のディレクショナルライトの強さと同じ意味で、強さ 1 が白・強さ 1 のライト）。
   画質の面でアンチエイリアスを「切」にする（Unity 版は縁を滑らかにしない）。これで光（来る向き・明るさ）と環境光（灰色 0.5 の 0.4 倍）が同じになる。
4. 環境ありの比較は、Unity 版を「空」（既定の天頂・地平線・地面の色）、Rust 版も「空」にする。「スタジオ」は Rust 版だけ。
5. 数値で比べるなら、板（Unity の Quad と同じ向き）を真正面から見て、光を真正面（方位 180°・高さ 0°）に当て、Color (200, 120, 60) の塗りつぶしと
   Metallic・Roughness の塗りつぶしを入れる。中心の画素は、CPU の式（`brdf::standard_brdf`、光の強さ 0.769）で出す値と ±3 で一致する（Rust 版の試験
   `the_material_view_matches_the_cpu_brdf_head_on` は、同じ式を既定の強さ 1 で照らす）:

   | Metallic | Roughness | 中心の画素（sRGB） |
   |---:|---:|---|
   | 0 | 255 | 156, 94, 50 |
   | 0 | 128 | 172, 122, 95 |
   | 0 | 0 | 195, 155, 136 |
   | 255 | 128 | 255, 172, 89 |
   | 255 | 20 | 255, 255, 255 |
   | 128 | 200 | 145, 88, 48 |

   Unity 版で同じ板・同じ値（Standard の `_MainTex`・`_MetallicGlossMap`（R = Metallic、A = 1 − Roughness））を入れて、同じ点を見て比べる。

### Unity 版との違い（保証の射程）

- 3D ビューの初めのカメラ: Unity 版はモデルの斜め後ろ（−Z 側）から、Rust 版は同じ斜めの角度でモデルの前（+Z 側）から見る。「モデル全体が見える位置へ戻す」も同じ向き。
- 環境「なし」の映り込み: Rust 版は一様な環境光（灰色 0.5 の 0.4 倍）を映す。Unity 版はプレビューのシーンの既定のプローブで、同じとは確かめていない。
- 接線: Rust 版は MikkTSpace の角ごとの値、Unity の `RecalculateTangents` は頂点ごとに 1 つにまとめる。UV の継ぎ目・ミラーの境で法線マップの陰影が少し違いうる。
- テクスチャのミップマップ: Rust 版は UV の上の画素だけの押し引き（上の「速さ」）、Unity はエンジンのミップ。Rust 版は塗った絵を読むサンプラーに 16 倍の異方性フィルタリングを使い、斜めに見た面の絵がぼやけません
  （GPU が持たないときと、CPU で描くアダプター〔lavapipe など〕では 1 倍）。Unity 版の異方性の設定との一致は確かめていません。
- 影: Unity 版は Standard のシェーダーを書き換えられないので、最終の色の全体（映り込み・発光も）に「環境光 ÷（環境光 + 直接光 × n·L）」を掛けて暗くする
  重ね描きで近似する。Rust 版はシェーダーが自前なので、影のところの直接光（拡散と鏡面の両方）だけを消し、環境光・映り込み・発光は残す。ランバートの面なら
  拡散は Unity 版と同じ明るさになり、鏡面・映り込み・発光のある面では見た目が違う。偏りも違い、Unity 版はぼかしの半径に比例する定数、Rust 版は面の傾きから
  深さの勾配を出して読む点ごとに面の上の深さへ直す（ぼかしを広げても光に寝た面が自分に影を落とさない）。影は主な光 1 つからモデル自身の中へ落ちるものだけです。
- Unity のテクスチャの HDRI・視差（Height の視差マップ）は、Rust 版にはまだ無い。他のテクスチャセットの同時表示は、ほかのセットを辺 1024 までに縮めて見せる
  （今のセットは文書の大きさ）ので、ほかのセットの細かい絵は今のセットにするまで粗く見える。
- 色の空間: 質感の式はリニアで解いて、出力は「画面にそのまま出す値」（ガンマ）。Unity 版の Gamma のカラースペースの見た目とは合わない。
- Windows の D3D12・macOS の Metal での見た目と速さは、このコンテナでは確かめていない（スナップショットは llvmpipe で撮ったもので、実機では縁と補間が少し違う）。

## lilToon の見た目

テクスチャセットごとに、「マテリアル」のパネルの「見た目」で種類を「標準（PBR）」か「lilToon」にします。lilToon のセットは、3D ビューの
「マテリアル (PBR)」の表示で lilToon 2.3.4 の式で描きます（中立・チャンネルだけ・メッシュマップだけの表示は種類によらず同じ）。式は lilToon（MIT）の
シェーダーから WGSL（`crates/yolu-app/src/view3d/shaders/liltoon/` の部品）に移したもので、出どころと許諾は [第三者の許諾](../THIRD_PARTY.md#liltoon-の再現式の移植)。
見た目の設定はセットの .ylp の `look.json` に入ります（形式は [YLP_FORMAT.md](YLP_FORMAT.md) の「look.json」）。

### 既定の見た目

新しいプロジェクト・新しいテクスチャセット・モデル（FBX）や Live Link のマテリアルから作るセットは、lilToon で始まります（lilToon のシェーダーの
既定の値。影は切。メインカラー・ノーマルマップ・発光は同じ名前のチャンネルに割り当てる）。既定を入れることは Undo に入らず、「保存していない変更」にも
なりません。`look.json` の無い今までの `.ylp` は、開いても標準のまま（見た目を変えない）で、標準の設定は `look.json` を書きません。

- Live Link で Unity から受けたテクスチャがあるスロットは、割り当てが「どのレイヤーも使っていない標準のチャンネル」（新しいセットの既定の割り当て）なら、
  受けたテクスチャで描きます。書き出しも使っていないチャンネルの画像を書かないので、Unity の元のテクスチャで描くのが Unity の見え方と同じです。
  そのチャンネルを使い始める（レイヤーで有効にする）と、そのチャンネルで描きます。

マットキャップ設定・リムライト設定・ラメ設定 → ［拡張設定］輪郭線設定・距離フェード。機能の入切は、その機能の節の頭にあります（輪郭線も輪郭線設定の
頭。Unity ではシェーダーの名前が変わる）。値は lilToon のプロパティの名前と型のまま持ちます（知らないプロパティも消さずに残します）。

選んだ欄に「描かない」）、頂点カラー、ラメの形のテクスチャ、環境光の反射のキューブマップの差し替え、マットキャップの UV1 の合成、VR の値、
追加のライト（頂点ライト・ForwardAdd）、ライトマップ、霧。

- 値の約束: 色のプロパティは Unity と同じくガンマの値として持ち、リニアの色空間の Unity と同じ式でリニアに直して使います（Unity の
  `Mathf.GammaToLinearSpace`。1 未満は sRGB の式、1 以上は pow(値, 2.2)。lilToon の欄で 1 を超えて選べる色（`_BacklightColor`・`_MatCapColor`
  など。Unity の `[HDR]` ではない）は、16.948 → 505.9、2.119 → 5.218 になります）。`[HDR]` の色（`_EmissionColor`・`_Emission2ndColor`）は
  Unity がそのまま渡すので、リニアの値のまま使います。3D ビューの光の色（色 × 強さ。白・強さ 1 で 1）も Unity の `_LightColor0` と同じ式で、強さ 1 は Unity の場面の白・強さ 1 の
  ディレクショナルライトと同じ明るさです（Unity 2022.3 のリニアの色空間・lilToon 2.3.4 で、白いテクスチャの球の lilToon（既定の値・影あり）と
  Standard を同じ光と環境光で撮り、画素の差の平均 0.04 以下。試験 `light_of_strength_one_matches_a_unity_directional_light`）。
  どれも、Unity 2022.3 のリニアの色空間で、色のプロパティ・`[HDR]` の色・`[Gamma]` の数・光の色を浮動小数の描き先へ書いて測った値と同じです。
- テクスチャの読み方: 塗った絵（Color・Emission）とマットキャップの sRGB の画像は、Unity と同じくテクセルをリニアにしてから補間します。
  ユーザーチャンネルの sRGB のレイヤーと、Unity から受けた sRGB の絵は、ガンマの値のまま補間してからリニアにします（1 つの配列に sRGB とリニアのレイヤーが
  混ざるため。色の境目の中間の色が Unity より少し暗い）。
- テクスチャのスロット: スロットごとに、チャンネル（標準のチャンネルとユーザーチャンネル）、成分ごとの詰め合わせ（R・G・B・A をそれぞれ 0・1・チャンネルの成分から）、
  プロジェクトの画像（マットキャップの絵）のどれかを割り当てます。ユーザーチャンネルは、何も描いていない所をチャンネルの既定の値に重ねて読みます（書き出しの
  「lilToon の詰め方」と同じ値）。「lilToon のひな形」は、入にしている機能のマスクのユーザーチャンネルを 1 回の操作で作って割り当てます。
- スロットを描く: スロットの行の右の筆のボタンで、そのスロットのチャンネルを描くチャンネルにします。割り当てが無ければ、ひな形と同じ作りの
  ユーザーチャンネル（マスクはスカラーの白、色のレイヤーは透明の sRGB、法線は平ら）を作って割り当てます（1 回の Undo）。今描いているスロットはボタンが
  押し込まれた見た目になり、チャンネルの欄の行には、そのチャンネルを読む lilToon のスロットの印（ツールチップにスロットの名前）が出ます。
  マットキャップの絵のスロット（プロジェクトの画像）には筆のボタンがありません。
- 新しいチャンネル: スロットの選択肢（チャンネルの並びの最後）の「新しいチャンネル」は、割り当てがあっても、描く口と同じ作りの新しいユーザーチャンネルを
  作って割り当て、描くチャンネルにします（1 回の Undo。それまでのチャンネルは消さず、ほかのスロットが読んでいればそのまま）。成分ごとの詰め合わせの
  各成分の選択肢にもあり、その成分だけを新しいスカラーのチャンネル（名前は「スロットのチャンネル名 R/G/B/A」。何も描いていない所は、置き換える成分が
  0・1 ならその値、チャンネルならスロットの既定）にします。3D ビューが持つユーザーチャンネルの上限（16）を超えても作れ、超えた分は、スロットの行に
  「描かない」と出ます。マットキャップの絵のスロットには出ません。
- 値の約束（追加したもの）: `[Gamma]` の数（`_Metallic`・`_Reflectance`）は Unity と同じく sRGB → リニア（色と同じ式）にして使います。割り当てていないノーマルマップの
  スロットは Unity の既定のテクスチャ（`Texture2D.normalTexture` = (127, 127, 255, 255)）で読みます（ほぼ平らで、異方性反射の接線のマップを
  割り当てないときは lilToon と同じく接線が斜めになる）。
- 光: 3D ビューの主な光を Unity のディレクショナルライト（色は光の強さの灰色）、環境を Unity の環境光の SH（球面調和関数。環境「なし」は一様な灰色、空・スタジオは焼いた SH を回転に合わせて）として、
  lilToon がビルトインのレンダーパイプラインで使う OpenLit の式（`ComputeLights`）と lilToon の補正（明るさの下限・上限・モノクロ化）で光の色と向きを決めます。
- 半透明: Unity と同じく、リニアの空間で乗算済みの色を重ねます（描き先の sRGB の見え方へ 2 つ目のパスで描く）。トーンマッピングを使うときと、描き先の sRGB の見え方を
  作れない GPU（wgpu の GL。`DownlevelFlags::VIEW_FORMATS` が無い）では、ガンマの値のまま重ねるので、Unity より半透明の所が明るく見えます。面の並べ替えはしません（モデルの並びの順）。
- GPU のメモリ: lilToon のスロットが読むユーザーチャンネルは、セットごとに 2D テクスチャの配列（1 チャンネル 1 レイヤー、16 レイヤーまで、GL のために 2 レイヤー以上）に持ちます。
  配列も 3D ビューの全体の予算に入ります: 今のセットの配列は標準のチャンネルの絵の残りから（ほかのセットより先）、ほかのセットは標準のチャンネルの絵と配列を
  合わせて持つか持たないかを決めます。どちらもセットごとに 256 MiB（ミップ込み）までで、収まらなければ 2 の累乗で縮めます（マスクは標準のチャンネルより粗く
  見えることがあります）。17 個目からのユーザーチャンネルは持たず、そのスロットは割り当てのない既定で描きます（欄のスロットの行に「描かない」と出ます）。

### Live Link で Unity のマテリアルの値を使う

Live Link で開いた相手のマテリアルが lilToon なら、Unity が頼みに書いたそのマテリアルの値で、スタンドアロンは
そのマテリアルのテクスチャセットを lilToon の見た目で描きます（受け渡しの形は [LIVELINK.md](LIVELINK.md)）。Unity は読むだけで、マテリアル・テクスチャ・
インポート設定を変えません。lilToon かどうかは、シェーダーの名前だけでは決めません（似た名前のシェーダーを lilToon として描かない）: 値に lilToon の版の値
`_lilToonVersion` があるか、シェーダーが lilToon のパッケージ（`jp.lilxyzw.liltoon`）の物のときだけです。

- 受けるもの: シェーダーの名前・版・アセットの GUID・描画の順、プロパティの全部（色・数・ベクトル・整数。テクスチャのタイリングとオフセットは
  `<名前>_ST`）とキーワード、テクスチャのプロパティごとの絵のファイルの道。描いていないスロット（YoluPainter が描いた絵で見せるメインカラーでない、
  上の表のスロット）の絵は、スタンドアロンがファイルから読みます（辺 2048 まで縮める）。Unity の中にしかない絵（ファイルの無い生成物など）は
  読めないので、欄のスロットの行に理由が出ます。Unity で値を変えたら、Live Link のウィンドウのボタンで送り直します。
- どちらの値で描くか: Unity から来た値は「Unity の値」として、利用者の設定とは別に持ちます（Undo の段は増えません）。描くのは Unity の値の上に、
  欄で変えた項目を重ねたものです。欄で変えた項目は名前に「•」が付き、ツールチップに Unity の値が出ます（描画モード・輪郭線の入切も）。
  節の「既定に戻す」でその節は Unity の値に（基本設定の節は描画モードと輪郭線の入切も）、
  「Unity の値」の行の「Unity に合わせる」で、欄で変えた値・描画モード・輪郭線・種類の選びが外れます（スロットの割り当ては残ります）。
  種類は、受けたセットでは欄で選ばない限り lilToon です。Unity のマテリアルが lilToon でなくなると、Unity の値を外します。
- 描いた絵: メインカラー（`_MainTex`）は Color のチャンネルで描きます（書き出すと Unity のこのスロットへ返る絵）。描いていないスロットは、
  欄で割り当てていなければ Unity のテクスチャのファイルで描きます。新しいセットの既定の割り当て（ノーマルマップ → Normal・発光 → Emission）は、
  レイヤーがそのチャンネルを使うまでは割り当てていないのと同じで、Unity のテクスチャを受けていればそれで、Unity で空のスロット（絵が来ない・
  読めない）はそのスロットの既定のテクスチャ（白・黒・平ら）で描きます。使っていないチャンネルの値（発光なら黒）では読みません
  （Unity は空のテクスチャを既定で読むので、発光が白で光ります）。
  - セットごとにスロットの並び（上の表の順）で先の 16 枚まで。17 枚目からはそのスロットの既定のテクスチャで描き、欄のスロットの行に
    「描かない」と出ます（欄で前のスロットを割り当てると、その分だけ後ろのスロットが入ります）。
  - 2D テクスチャの配列で、辺 1024・1 つのセットで 96 MiB（ミップ込み）まで。3D ビューのメモリの予算の中で持ちます: 今のセットは標準の
    チャンネルの絵とユーザーチャンネルの配列の残りに収まるまで 2 の累乗で縮め、ほかのセットは標準のチャンネルの絵・ユーザーチャンネルの
    配列・受けたテクスチャを合わせて収まるときだけ持ちます。
  - 値は Unity が読んだまま（乗算済みにしない）で持ちます。A を不透明度でなく別の値に使うテクスチャ（X を A に持つノーマルマップの
    DXT5nm など）も、A が 0 の所の色も変わりません。ノーマルマップの X は lilToon と同じく A × R で読みます。
  - 全部のセットで受けたテクスチャ（画素）は 256 MiB まで持ちます（超えたテクスチャは持たずに知らせ、そのスロットは既定のテクスチャで描きます）。
- 保存: 設定の「Unity から受けたマテリアルの値を保存する」（既定は入）で、`.ylp` の `look.json` に Unity の値を入れます。テクスチャの画素は
  入れません。開き直すと Unity の値で描き、テクスチャは Live Link の相手の記録（`livelink.json`）の絵のファイルから読み直します。
  切ると次の保存で外します。受け取りは編集ではないので、受けただけでは「保存していない変更」になりません。

### Live Link で Unity の元のテクスチャを一番下のレイヤーに入れる

Unity のモデルを開くと、スタンドアロンはマテリアルごとにテクスチャセットを作ります。頼みに書かれた Color の流し込み先（スタンドアロンが描いた絵を見せるプロパティ。
メインカラーなど）の絵のファイルを読み、新しく作ったセットの一番下に「元の絵」のレイヤーとして入れるので、元のテクスチャの見た目のまま、その上に描けます。
書き出し（PNG・PSD）と `.ylp` には、普通のピクセルレイヤーとして入ります。頼みの形と上限は [LIVELINK.md](LIVELINK.md) にあります。

- 入れるセット: Live Link のモデルを受けたときに新しく作ったセットと、何も触っていない最初のセット（開いた・保存したファイルが無く、描いていない
  最初のプロジェクトの最初のセット）だけ。描いたセット・編集したセット・利用者が開いたプロジェクトのセットには入れません（描いたものを黙って変えない）。
- 最初のセットの大きさ: 何も触っていない最初のセットは、元の絵の大きさで作り直した文書へ入れます（既定の 2048 に 4096 の絵が縮みません）。大きさは新しく作る
  セットと同じ決め方で、絵の長い辺を 256〜4096 の 2 の冪に丸めます（600 の絵は 1024、8192 の絵は 4096）。同じセット（名前・マテリアルへの結び付け）のまま、文書だけを替えます。
  作り直した文書に元の絵が入らないとき（レイヤーの画素・1 回の操作の予算）は、今の文書へ縮めて入れ、レイヤーの欄に拡大縮小の印を付けます。
  新規プロジェクトのウィンドウで解像度を選んで作ったプロジェクトは、選んだ大きさのまま、元の絵を拡大縮小して入れます。
- 絵の無いマテリアル・読めない絵: 不透明な白（255, 255, 255, 255）の「元の絵」を入れます。Unity は絵の無いスロットを既定の白で描く（マテリアルの色 × 白）ので、
  つないだ瞬間に黒くなりません。Unity の中にしかない絵（ファイルの無い生成物）も白で、読めない絵は理由を知らせます。
- 絵の大きさがセットと違うとき: セットの大きさへ拡大縮小します（縮めは箱の平均、広げは双線形。アルファで重みを付けるので、透明な画素の RGB は混ざりません）。
  同じ大きさなら画素をそのまま入れます（透明な画素の RGB も）。リニアのテクスチャ（頼みの `srgb` が偽）は、Color のチャンネルが sRGB の画素を持つので、
  sRGB の画素へ直して入れます（見た目を変えません）。
- PSD の元の絵: Color の流し込み先の絵が PSD（sRGB）なら、平らな「元の絵」でなく PSD のレイヤーのままセットに入れます（[LIVELINK.md](LIVELINK.md)）。
- 送り直し: 元の絵のファイル（道・更新時刻・大きさ・`srgb`）が変わっていれば、元の絵を入れた直後のまま（描いていない・何も変えていない）のセットには新しい元の絵を入れ直し、
  触ったセットは変えずに知らせます。
- Undo: 作った直後の初期化として入れるので、Undo の履歴には入りません（履歴は空のまま。レイヤーを消すのは普通の操作で、Undo で戻せます）。変更の印も付かないので、
  受けただけでは「保存していない変更」になりません。
- レイヤーの欄の印: リニアから直した絵と拡大縮小した絵には、レイヤーの右に小さな印が付き、ツールチップに理由が出ます（原本のファイルのそのままの値には付きません）。
  印はそのセッションの間だけで、保存しません（開き直すと普通のレイヤーです）。
- 上限: 絵の辺 8192 まで・ファイル 512 MiB まで（超えれば縮めずに断り、理由を知らせます）。1 つの頼みで読む元の絵の画素は合計 512 MiB までです。
  文書のレイヤーの画素・1 回の操作の予算を超えるときは、入れずにその理由（予算）を知らせます。
- 保存と復元: 形式は変えません（元の絵も白も普通のピクセルレイヤーで、`.ylp` の版は上げません）。Unity 版（0.2.0）も普通のレイヤーとして開けます。

### Unity の lilToon との比べ

`crates/yolu-app/tests/gui_view3d/liltoon_reference.rs` の手で回す試験が、合成の素材（球・板・試しの人形）の場面ごとに 3D ビューの絵と、Unity で同じ場面を作る記述
（カメラ・光・環境光の SH・メッシュ・テクスチャ・プロパティ）を書き、`tools/liltoon-reference.cs` を Unity（2022.3.22f1・lilToon 2.3.4）で回して
同じ場面を lilToon で描き、両方の差を数えます。`tools/liltoon-reference.cs` は回すあいだだけプロジェクトのカラースペースを Linear にし（VRChat と同じリニアの色空間。Unity はその場で
リニアに替わり（`QualitySettings.activeColorSpace`）、2026-10-05 に撮り直した 34 場面の絵は前の絵と全画素が同じ。同じツールでガンマのまま撮ると、
全場面で 95 % 以上の画素が違う）、場面が使うテクスチャを読む

  影の受け方（`fd.attenuation`。影のマップで光が遮られた所は 0）を掛けて、影の中の逆光を消します（3D ビューも同じ式で、影を入れたときの影のマップを使う）。
- glitter・specular_toon の最大の差は、ラメの粒・トゥーンの光沢の縁の数画素です。ラメの乱数（lilToon の lilHashRGB4）と粒の並びは同じです。

  （実 GPU 28.16）・95 % 42 になります（llvmpipe の GL のほかの場面は、平均が上の表と 0.1 以内、95 % は uv が 3 で、ほかは同じ）。「片方だけ」も

  背景とみなす差（3 以内）に入ります。前は 6 列（5,135）でした: ガンマの値で乗算済みにした 8 bit のテクセルは、アルファの小さい所で色の丸めが大きく
  （アルファ 5/255 以下では、乗算を戻した B が 230 でなく 255）、薄い縁が 1 ほど明るく出ていました。
- 新しく描くようにした機能の場面（rim_shade 以降）は、利用者の設定（欄の値）で描いた比べです。Live Link で受けた値だけの比べは上の節です。

  比べたのは一様な環境での式（フレネル・滑らかさ・金属度・反射率・色）で、空・スタジオの環境の映り込み（反射プローブの絵とぼかし）は比べていません。

  逆光ライトの色のテクスチャ、影を落とす光での逆光ライトの影の受け方（`_BacklightReceiveShadow`）。

- ソフトの描画（アダプタが CPU のとき）は、使う機能とスロットの読み方（1 つの元から読む・ユーザーチャンネルの配列を回す・既定の値）をパイプラインの定数
  （WGSL の `override`）にして、そのセットで使う分だけのシェーダーを作ります。llvmpipe は分岐の先を全部実行するので、定数にしないと使っていない機能と元の読みの
  分まで毎回かかります（この変更の前は、同じ計測で lilToon（影）が標準の 4.6〜11 倍、全部が 5.4〜14 倍）。今は lilToon（影）が標準の 1.08〜1.24 倍、全部が 3.5〜9.1 倍
  （マスク 9 枚の配列の読み・マットキャップ・輪郭線のパスの分）です。
- その引き換えに、ソフトの描画では、機能の入切・距離フェードの強度や裏面の色のアルファの 0 との行き来・スロットの割り当ての変更の最初の 1 回に、パイプラインを作る手間がかかります
  （この計測で、4,800 三角形の lilToon の見た目へ初めて切り替えた 1 回が、2 回目からより約 0.1〜0.3 s 長い）。作ったパイプラインは持っておき（48 本を超えたらそのフレームで使わないものを捨てる）、
  同じ組み合わせへ戻るときは作り直しません。値のスライダーを動かしているあいだは作り直しません。
- 実 GPU（アダプタが CPU でないとき）は、全部の機能を入れた 1 本のパイプラインを使い、機能の入切は一様な値の分岐で選びます（入切のたびにシェーダーを作り直す引っかかりを
  避けるため）。実行ごとの平均の差で、lilToon（影）は標準と −0.3〜+0.5 ms、全部の機能と輪郭線で +1.4〜+3.7 ms です。
- 実 GPU の欄は WSL2 の `/dev/dxg` を Mesa の d3d12 ドライバで OpenGL へ通したもので、Windows の D3D12・Vulkan での値は未確認です。
