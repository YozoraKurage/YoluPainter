# 3D ビューの質感

3D ビュー（スタンドアロンの Rust 版の自前の描画。wgpu）は、描いたチャンネルをそのままモデルに貼って見せます。見た目の式は Unity 版のプレビューのシェーダー
（`PreviewSurfaceLit`・`PreviewSurface`・`PreviewEnvironment`・`PreviewToneMap`）と、そのもとの Unity の Standard の BRDF（`UnityStandardBRDF.cginc` の
`BRDF1_Unity_PBS`、リニアのカラースペース）を WGSL に移したものです。同じ式を CPU でも書き（`crates/yolu-app/src/view3d/brdf.rs`）、試験が既知の値と
GPU の絵を照らします。見た目の種類を lilToon にしたテクスチャセットは、lilToon の式で描きます（[lilToon の見た目](#liltoon-の見た目)）。

## 表示の切り替え

各ビューの見出しの右のドロップダウンで選びます（Unity 版と同じ並び）。

| 表示 | 見えるもの |
|---|---|
| マテリアル (PBR) | 金属の流儀の PBR。Color・Roughness・Metallic・Normal・Emission が効く。環境・光・トーンマッピングを使う。見た目が lilToon のセットは lilToon の式で描く |
| 中立 | Unity 版の簡単な明暗（`0.35 + 0.65 × saturate(n·L)`、ガンマの空間）。法線マップは効く。環境を使うときは環境の拡散と弱い映り込み |
| チャンネルだけ | Color・Roughness・Metallic・Normal・Emission・Height のどれか 1 つを、光・環境・トーンマッピングなしで値のまま |
| メッシュマップだけ | 今のテクスチャセットで焼いたメッシュマップ（AO・曲率・法線など）の 1 枚を、光・環境・トーンマッピングなしで値のまま。焼いていない種類は選べず、見ているマップが無くなるとマテリアルへ戻る |

見出しの光のボタンで「光・環境・トーンマッピング」の小さなパネルが開きます（影の入り切りと柔らかさもここ）。

- 環境: なし（一様な環境光）・空（Unity 版の既定の勾配）・スタジオ（暗い灰色の背景に面光源。金属の映り込みと回転が分かる）。明るさ・回転・背景に映すか（とそのぼかし）。
  空は上の軸のまわりに対称なので、回転は見た目を変えません。
- ライト: 強さ・方位・高さ（Unity 版の `PreviewSceneSettings` と同じ。既定の来る向きは (−0.3, 0.65, −0.7)）。
- 影: 主な光からモデル自身へ落ちる影（既定は切）と、その柔らかさ（影の縁のぼかしの広さ。0% は影のマップの 1 画素ぶん、100% はモデルの大きさの約 2.5%）。
  マテリアルと中立の表示で効き、光なしの表示（チャンネルだけ・メッシュマップだけ）では使いません。
- トーンマッピング: なし・ニュートラル・ACES と露出（EV）。3D ビューの絵だけに当てます（テクスチャの値・書き出し・2D には当てません）。

## チャンネルの意味

書き出し（`export::build`）と同じ値の意味で、見ているものと書き出したテクスチャの値は、次の違いを除いて同じです（不透明な画素のテクセルの一致は試験が照らします）。

- Color: 3D ビューは見せるために**乗算済み**にして上げます（透明の縁が黒くならない）。書き出しは straight RGBA（透明な画素の RGB を保つ）なので、半透明・透明の画素では値が違います。
  不透明な画素は同じです。Color の透明な所は市松の灰色の上に見えます。
- Emission: RGB は書き出しと同じ（値 × アルファ）。3D ビューはアルファも持ちますが読みません（書き出しはアルファを不透明にします）。
- Roughness・Metallic・Height: 値 × アルファ（塗っていない所は 0）で、書き出しと全テクセルが同じです。Roughness は滑らかさ = 1 − Roughness として読みます。
- Normal: Normal の出力（塗った法線を平らな法線に載せ、Height → Normal が有効なら Height から作った法線を土台に重ねたもの。OpenGL の Y+）で、書き出しと全テクセルが同じです。
- どの層も有効にしていないチャンネルは、書き出しの既定の値（Roughness 0.5・Metallic 0・Normal は平ら・Emission 黒・Color は透明）を見せます。

法線マップの接線は Unity の `Mesh.RecalculateTangents` と同じ MikkTSpace（`bevy_mikktspace`）で、三角形の角ごとに作ります（FBX も Live Link のモデルも）。
数万三角形のモデルでは数百ミリ秒かかるので別のスレッドで作り、出来るまでは前のモデルの接線で描きます（ポーズで毎回モデルが替わるときも描きを止めません）。

## 速さ

描くのは、カメラ・大きさ・モデル・塗った絵・表示の設定のどれかが変わったときだけです。塗った絵は、core が「変わった」と言うタイルだけを合成して上げます
（隣り合うタイルは 1 回の書き込みにまとめ、全面を作るときは 1024 行ずつの帯）。全面を作るときは、層が面を持つタイルだけを合成します。ただし塗りつぶし・調整の層や、そのチャンネルに当たるフィルター・Generator（層のマスクのものを含む）があるときは、効果が面の無いタイルへも出るので全タイルを合成します。変わらなかったチャンネルは触らず、使っていないチャンネルはテクスチャを持ちません。
ミップマップは変わった範囲だけ作り直します（段ごとに、変わった範囲を 1 画素広げて描くので、奇数の大きさでも全面を作り直した結果と全部の段で一致します。試験が照らします）。
Height → Normal の設定は層の合成を変えないので、設定が変わったら Normal を作り直します。

メモリ: 使っているチャンネルのテクスチャ全部（ミップ込み）の予算は 512 MiB です。4096² で 6 チャンネルすべて（約 320 MiB）は収まり、8192² の 6 チャンネル（約 1.28 GiB）は
1 段縮めて 4096² にします。予算を超える文書は、確保する前に 2 の累乗で縮めて持ち（箱で平均）、3D ビューの左下に「縮小表示 1/2」のように出します（絵と書き出しは元の大きさのまま）。
新しいチャンネルを使い始めて予算を超えるときは、縮めを上げて全部を作り直します。縮めは上げるだけで、文書が替わると決め直します。GPU のテクスチャの辺の上限を超える文書も同じ道で縮めます。
メッシュマップの 1 枚も、辺の上限と予算（チャンネルの予算の半分）を超えるときは縮めます。

### 全部のテクスチャセットの絵

3D ビューは全部のテクスチャセットの絵を見せます（Substance Painter と同じ。今のセットを替えても、前のセットの面から絵は消えません）。描く先は今のセットのままで、
ほかのセットの面には描けません。

- 今のセットは文書の大きさのまま（上の予算と縮め）。ほかのセットは、辺を 1024 までに縮めて（2 の累乗で、箱で平均）GPU に持ち、そのセットの文書が変わったとき
  （版・変化の記録）だけ、変わったタイルを同期します。使っているチャンネルは今のセットと同じで、Normal・Roughness なども効きます。
- メモリの予算（上の 512 MiB）には、今のセットの絵を先に入れ、残りにほかのセットを入れます。収まらないときは、今のセットから並びの上で遠いセットから持たず、
  そのセットの面は絵の無い描き方（市松）になります。テクスチャセットの一覧のそのセットの行に警告の印が付き、ツールチップが理由を言います。Unity の流し込み先が無い警告や
  「Unity に見せている」とも別の事実なので、印は 1 つのまま、ツールチップに並べて言います。3D が描かれていないあいだ（キャンバスのタブが前に出ている間）にモデルや今のセットが
  替わったときは、前の印を消します（3D が前に出たときに計算し直します）。
- 目を閉じたセット、モデルに面の無い（ポーズの「面を隠す」で全部の面を隠した）マテリアルのセットは持ちません（目を開く・面が戻るとき、文書から作ります）。
- 今のセットが替わると、前のセットの絵は、ミップの段をコピーして 1024 の大きさへ縮めて持ちます（GPU の中だけ。文書を合成し直しません）。辺が奇数などで、段の大きさが
  文書から縮めた大きさと合わないときだけ、その場で文書から作り直します（ほかのセットの作り直しと同じく、そのフレームの最初の 1 つなので 40 ms を超えても走ります）。
  替わった先のセットは文書の大きさで作り直します（これは従来から要る）。
- 替わるフレームの順番は、GPU のメモリが予算を超えて重ならないように決めてあります: 新しい今のセットの絵が取る分を予算から引いてほかのセットの持つ・持たないを決め、
  持たないものを捨て、前の絵を縮めてから、新しい今のセットの絵を作ります。前の絵（満量）と新しい絵（満量）が一度に載ることがありません。保証の射程は、直前のフレームの
  終わりに持っていた絵が予算に収まっているときです（予算を下げた直後のフレームは、下げる前に持っていた分が先に載ります）。測った最大は下の表。
- ほかのセットの合成の作業用のバッファ（CPU。帯 1024 行の分、Height から作る Wrap の Normal は文書全体。4096² で Wrap の Normal なら、1 セットで約 128 MiB の見積り）は、
  作り終えたら手放します。手放さないと、セットの数に比例して CPU のメモリが残ります（この分は GPU の予算に入りません）。今のセットのバッファは、描きの更新に使うので持ちます。
- ほかのセットの絵を新しく作る（文書を合成して縮める）のは、1 フレームの時間（40 ms）に収まるあいだと、そのフレームの最初の 1 つだけです。残りは次のフレームから
  （窓は次のフレームを求めます）。大きなセットが多いプロジェクトでも 1 フレームに重なって止まらず、絵が順に出てきます。小さな文書は 1 フレームで全部出ます。
- 描き方はマテリアルごとの描き呼び出しです。頂点をマテリアル順に並べ（モデルを替えたときだけ上げ直します。セットを替えても上げ直しません）、マテリアルごとに
  絵（6 チャンネル）の束ねを替えて描きます。絵を持たないマテリアルは隣り合うものを 1 回にまとめます。テクスチャの配列で 1 回に描く案は、文書の大きさがセットごとに違う
  （今のセットだけ別の解像度）ので大きさをそろえて作り直す手間と、層の数の上限が要り、得られるのは下の呼び出し数の分だけなので採りませんでした。
- メッシュマップだけの表示は、今のセットの面だけに貼ります（ほかのセットの面は絵の無い描き方）。

## Unity 版の見た目との比べ方

1. Unity 版のプロジェクトのカラースペースを Linear にする。マテリアルは組み込みの Standard にする（Unity 版のプレビューは lilToon を描かない。lilToon の見た目の比べ方は下の
   [lilToon の見た目](#liltoon-の見た目)）。
2. 同じモデルを両方へ入れる（Live Link で同じモデルを送るか、同じ FBX を開く）。両方で「モデル全体が見える位置へ戻す」を押して、同じカメラ（yaw 25°・pitch 10°）から始める。
3. Unity 版の 3D ビューを「マテリアル」の見せ方にし、シーンの設定を既定（環境なし・影なし・トーンマッピングなし・露出 0・光は既定）に戻す。
   Rust 版は光のパネルの「既定に戻す」のあと、環境を「なし」にする。これで光（来る向き・強さ 0.769）と環境光（灰色 0.5 の 0.4 倍）が同じになる。
4. 環境ありの比較は、Unity 版を「空」（既定の天頂・地平線・地面の色）、Rust 版も「空」にする。「スタジオ」は Rust 版だけ。
5. 数値で比べるなら、板（Unity の Quad と同じ向き）を真正面から見て、光を真正面（方位 180°・高さ 0°）に当て、Color (200, 120, 60) の塗りつぶしと
   Metallic・Roughness の塗りつぶしを入れる。中心の画素は、Rust 版の試験が CPU の式で出す値と ±3 で一致する（`the_material_view_matches_the_cpu_brdf_head_on`）:

   | Metallic | Roughness | 中心の画素（sRGB） |
   |---:|---:|---|
   | 0 | 255 | 156, 94, 50 |
   | 0 | 128 | 172, 122, 95 |
   | 0 | 0 | 195, 155, 136 |
   | 255 | 128 | 255, 172, 89 |
   | 255 | 20 | 255, 255, 255 |
   | 128 | 200 | 145, 88, 48 |

   Unity 版で同じ板・同じ値（Standard の `_MainTex`・`_MetallicGlossMap`（R = Metallic、A = 1 − Roughness））を入れて、同じ点を見て比べる。

### Unity 版との違い（保証の射程）

- 環境「なし」の映り込み: Rust 版は一様な環境光（灰色 0.5 の 0.4 倍）を映す。Unity 版はプレビューのシーンの既定のプローブで、同じとは確かめていない。
- 接線: Rust 版は MikkTSpace の角ごとの値、Unity の `RecalculateTangents` は頂点ごとに 1 つにまとめる。UV の継ぎ目・ミラーの境で法線マップの陰影が少し違いうる。
- テクスチャのミップマップ: Rust 版は箱の平均、Unity はエンジンのミップ。異方性フィルターは Rust 版には無い。
- 影: Unity 版は Standard のシェーダーを書き換えられないので、最終の色の全体（映り込み・発光も）に「環境光 ÷（環境光 + 直接光 × n·L）」を掛けて暗くする
  重ね描きで近似する。Rust 版はシェーダーが自前なので、影のところの直接光（拡散と鏡面の両方）だけを消し、環境光・映り込み・発光は残す。ランバートの面なら
  拡散は Unity 版と同じ明るさになり、鏡面・映り込み・発光のある面では見た目が違う。偏りも違い、Unity 版はぼかしの半径に比例する定数、Rust 版は面の傾きから
  深さの勾配を出して読む点ごとに面の上の深さへ直す（ぼかしを広げても光に寝た面が自分に影を落とさない）。影は主な光 1 つからモデル自身の中へ落ちるものだけです。
- Unity のテクスチャの HDRI・視差（Height の視差マップ）は、Rust 版にはまだ無い。他のテクスチャセットの同時表示は、ほかのセットを辺 1024 までに縮めて見せる
  （今のセットは文書の大きさ）ので、ほかのセットの細かい絵は今のセットにするまで粗く見える。
- 色の空間: 質感の式はリニアで解いて、出力は「画面にそのまま出す値」（ガンマ）。Unity 版の Gamma のカラースペースの見た目とは合わない。
- Windows の D3D12・macOS の Metal での見た目と速さは、このコンテナでは確かめていない（スナップショットは llvmpipe で撮ったもので、実機では縁と補間が少し違う）。

## lilToon の見た目

テクスチャセットごとに、プロパティの「マテリアル」のタブの「見た目」で種類を「標準（PBR）」か「lilToon」にします。lilToon のセットは、3D ビューの
「マテリアル (PBR)」の表示で lilToon 2.3.4 の式で描きます（中立・チャンネルだけ・メッシュマップだけの表示は種類によらず同じ）。式は lilToon（MIT）の
シェーダーから WGSL（`crates/yolu-app/src/view3d/shaders/liltoon.wgsl`）に移したもので、出どころと許諾は [第三者の許諾](../THIRD_PARTY.md#liltoon-の再現式の移植)。
見た目の設定はセットの .ylp の `look.json` に入ります（形式は `crates/yolu-io/README.md`）。

### 再現する範囲

欄の並びと名前は lilToon のインスペクターに合わせています。値は lilToon のプロパティの名前と型のまま持ちます（知らないプロパティも消さずに残します）。

| 節 | 描くもの |
|---|---|
| 基本設定 | 描画モード（不透明・カットアウト・半透明）、輪郭線の入切、Cull、裏面の色、裏面の法線の反転、裏面を影にする、非表示 |
| ライティング設定 | 明るさの下限・上限、ライトのモノクロ化、影色への環境光影響度、Unlit 化、アンチエイリアスシェーディング、光の向きの上書き |
| メインカラー / 透過設定 | 色・テクスチャ・色調補正（HSVG）とそのマスク、アルファマスク（置き換え・乗算・加算・減算）、カットアウトの閾値 |
| 影設定 | 1・2・3 影の色とテクスチャ、範囲・ぼかし、強度とそのマスク（顔の影の SDF を含む）、AO マスクとその範囲、ぼかしマスク、境界の色、ノーマルマップ強度、影を受け取る（3D ビューの影） |
| 発光設定 | 発光と発光 2nd の色・テクスチャ（UV はメインかリム。UV1〜UV3 はメインの UV で読む）・マスク・合成モード・メインカラーの強度・蛍光 |
| ノーマルマップ設定 | ノーマルマップと強度（接線は MikkTSpace） |
| マットキャップ設定 | マットキャップと 2nd の絵・マスク・合成モード・ライトの明るさ・影部分 / 裏面で無効化・ぼかし・ノーマルマップ強度・Z 軸回転キャンセル・パース補正・透明度を適用 |
| リムライト設定 | 色・テクスチャ・範囲・ぼかし・細さ・合成モード・ライト方向の影響度（直接光・間接光の幅と範囲）・影部分 / 裏面で無効化 |
| 輪郭線設定 | 裏返した殻（太さ・太さのマスク・距離補正・Z バイアス・太さ 0 の頂点を消す）、色・テクスチャ・色調補正・メインカラーから色を取得・ライトの明るさ・影を受け取る |

再現しないもの（値は持って保存しますが描きません）: メインカラー 2nd・3rd、デカール、グラデーションマップ、ディゾルブ、ディザー、ノーマルマップ 2nd、異方性、逆光、
リムシェード、光沢（反射）、ラメ、視差、距離フェード、AudioLink、ID マスク、ファー・宝石・屈折・テッセレーション・Lite の版（近い描き方で描く）、ステンシル、
時間で動く値（スクロール・点滅・グラデーション）、影色の LUT、追加のライト（頂点ライト・ForwardAdd）、ライトマップ、霧。

- 値の約束: 色のプロパティは Unity と同じくガンマの値として持ち、リニアに直して使います。`[HDR]` の色（`_EmissionColor`・`_Emission2ndColor`）は Unity がそのまま渡すので、リニアの値のまま使います。
- テクスチャのスロット: スロットごとに、チャンネル（標準のチャンネルとユーザーチャンネル）、成分ごとの詰め合わせ（R・G・B・A をそれぞれ 0・1・チャンネルの成分から）、
  プロジェクトの画像（マットキャップの絵）のどれかを割り当てます。ユーザーチャンネルは、何も描いていない所をチャンネルの既定の値に重ねて読みます（書き出しの
  「lilToon の詰め方」と同じ値）。「lilToon のひな形」は、入にしている機能のマスクのユーザーチャンネルを 1 回の操作で作って割り当てます。
- 光: 3D ビューの主な光を Unity のディレクショナルライト（色は光の強さの灰色）、環境を Unity の環境光の SH（環境「なし」は一様な灰色、空・スタジオは焼いた SH を回転に合わせて）として、
  lilToon がビルトインのレンダーパイプラインで使う OpenLit の式（`ComputeLights`）と lilToon の補正（明るさの下限・上限・モノクロ化）で光の色と向きを決めます。
- 半透明: Unity と同じく、リニアの空間で乗算済みの色を重ねます（描き先の sRGB の見え方へ 2 つ目のパスで描く）。トーンマッピングを使うときと、描き先の sRGB の見え方を
  作れない機材（wgpu の GL。`DownlevelFlags::VIEW_FORMATS` が無い）では、ガンマの値のまま重ねるので、Unity より半透明の所が明るく見えます。面の並べ替えはしません（モデルの並びの順）。
- GPU のメモリ: lilToon のスロットが読むユーザーチャンネルは、セットごとに 2D テクスチャの配列（1 チャンネル 1 層、16 層まで、GL のために 2 層以上）に持ちます。
  配列も 3D ビューの全体の予算に入ります: 今のセットの配列は標準のチャンネルの絵の残りから（ほかのセットより先）、ほかのセットは標準のチャンネルの絵と配列を
  合わせて持つか持たないかを決めます。どちらもセットごとに 256 MiB（ミップ込み）までで、収まらなければ 2 の累乗で縮めます（マスクは標準のチャンネルより粗く
  見えることがあります）。17 個目からのユーザーチャンネルは持たず、そのスロットは割り当てのない既定で描きます（欄のスロットの行に「描かない」と出ます）。

### Unity の lilToon との比べ

`crates/yolu-app/tests/liltoon_reference.rs` の手で回す試験が、合成の素材（球・板・試しの人形）の場面ごとに 3D ビューの絵と、Unity で同じ場面を組む記述
（カメラ・光・環境光の SH・メッシュ・テクスチャ・プロパティ）を書き、`tools/liltoon-reference.cs` を Unity（2022.3.22f1・lilToon 2.3.4）で回して
同じ場面を lilToon で描き、両方の差を数えます。`tools/liltoon-reference.cs` は回すあいだだけプロジェクトのカラースペースを Linear にし、テクスチャを読む lilToon の
機能を入れ、終わったら両方を元に戻します。lilToon の設定のファイル（`ProjectSettings/lilToonSetting.json`）が無いプロジェクトでは、元に戻せないので何も変えずに断ります。
撮った Unity の絵（合成の素材だけ）は `crates/yolu-app/tests/liltoon_unity/` に置き、普段の試験（`the_view_stays_within_the_measured_difference_from_unity_liltoon`）が
場面ごとの差を上限（下の表の値に余裕を足したもの。GL の半透明はガンマで重ねるので別の上限）と照らします。

```sh

# Unity で tools/liltoon-reference.cs を回す（`__DIR__` をそのフォルダにする）
LILTOON_REF_DIR=<フォルダ> cargo test -p yolu-app --test liltoon_reference compare -- --ignored --nocapture
```

  `prepare` の CPU の時間（2.8〜3.6 ms。この経路の書き込みの固定の手間）は見た目で変わりません。

- Windows の D3D12・Vulkan での値は未確認です。
