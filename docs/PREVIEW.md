# 3D ビューの質感

3D ビュー（スタンドアロンの Rust 版の自前の描画。wgpu）は、描いたチャンネルをそのままモデルに貼って見せます。見た目の式は Unity 版のプレビューのシェーダー
（`PreviewSurfaceLit`・`PreviewSurface`・`PreviewEnvironment`・`PreviewToneMap`）と、そのもとの Unity の Standard の BRDF（`UnityStandardBRDF.cginc` の
`BRDF1_Unity_PBS`、リニアのカラースペース）を WGSL に移したものです。同じ式を CPU でも書き（`crates/yolu-app/src/view3d/brdf.rs`）、試験が既知の値と
GPU の絵を照らします。lilToon など Unity のシェーダーそのものの再現ではありません（別の機能として後で扱います）。

## 表示の切り替え

各ビューの見出しの右のドロップダウンで選びます（Unity 版と同じ並び）。

| 表示 | 見えるもの |
|---|---|
| マテリアル (PBR) | 金属の流儀の PBR。Color・Roughness・Metallic・Normal・Emission が効く。環境・光・トーンマッピングを使う |
| 中立 | Unity 版の簡単な明暗（`0.35 + 0.65 × saturate(n·L)`、ガンマの空間）。法線マップは効く。環境を使うときは環境の拡散と弱い映り込み |
| チャンネルだけ | Color・Roughness・Metallic・Normal・Emission・Height のどれか 1 つを、光・環境・トーンマッピングなしで値のまま |
| メッシュマップだけ | 今のテクスチャセットで焼いたメッシュマップ（AO・曲率・法線など）の 1 枚を、光・環境・トーンマッピングなしで値のまま。焼いていない種類は選べず、見ているマップが無くなるとマテリアルへ戻る |

見出しの光のボタンで「光・環境・トーンマッピング」の小さなパネルが開きます（影の入り切りと柔らかさもここ）。

- 環境: なし（一様な環境光）・空（Unity 版の既定の勾配）・スタジオ（暗い灰色の背景に面光源。金属の映り込みと回転が分かる）。明るさ・回転・背景に映すか（とそのぼかし）。
  空は上の軸のまわりに対称なので、回転は見た目を変えません。
- ライト: 強さ・方位・高さ（Unity 版の `PreviewSceneSettings` と同じ。既定の来る向きは (−0.3, 0.65, −0.7)）。
- 影: 主な光からモデル自身へ落ちる影（既定は切）と、その柔らかさ（影の縁のぼかしの広さ。0% は影のマップの 1 画素ぶん、100% はモデルの大きさの約 2.5%）。
  マテリアルと中立の表示で効き、光なしの表示（チャンネルだけ・メッシュマップだけ）では使いません。
- トーンマッピング: なし・ニュートラル・ACES と露出（EV）。3D ビューの絵だけに当てます（テクスチャの値・書き出し・2D には当てません）。

## チャンネルの意味

書き出し（`export::build`）と同じ値の意味で、見ているものと書き出したテクスチャの値は、次の違いを除いて同じです（不透明な画素のテクセルの一致は試験が照らします）。

- Color: 3D ビューは見せるために**乗算済み**にして上げます（透明の縁が黒くならない）。書き出しは straight RGBA（透明な画素の RGB を保つ）なので、半透明・透明の画素では値が違います。
  不透明な画素は同じです。Color の透明な所は市松の灰色の上に見えます。
- Emission: RGB は書き出しと同じ（値 × アルファ）。3D ビューはアルファも持ちますが読みません（書き出しはアルファを不透明にします）。
- Roughness・Metallic・Height: 値 × アルファ（塗っていない所は 0）で、書き出しと全テクセルが同じです。Roughness は滑らかさ = 1 − Roughness として読みます。
- Normal: Normal の出力（塗った法線を平らな法線に載せ、Height → Normal が有効なら Height から作った法線を土台に重ねたもの。OpenGL の Y+）で、書き出しと全テクセルが同じです。
- どの層も有効にしていないチャンネルは、書き出しの既定の値（Roughness 0.5・Metallic 0・Normal は平ら・Emission 黒・Color は透明）を見せます。

法線マップの接線は Unity の `Mesh.RecalculateTangents` と同じ MikkTSpace（`bevy_mikktspace`）で、三角形の角ごとに作ります（FBX も Live Link のモデルも）。
数万三角形のモデルでは数百ミリ秒かかるので別のスレッドで作り、出来るまでは前のモデルの接線で描きます（ポーズで毎回モデルが替わるときも描きを止めません）。

## 速さ

描くのは、カメラ・大きさ・モデル・塗った絵・表示の設定のどれかが変わったときだけです。塗った絵は、core が「変わった」と言うタイルだけを合成して上げます
（隣り合うタイルは 1 回の書き込みにまとめ、全面を作るときは 1024 行ずつの帯）。変わらなかったチャンネルは触らず、使っていないチャンネルはテクスチャを持ちません。
ミップマップは変わった範囲だけ作り直します（段ごとに、変わった範囲を 1 画素広げて描くので、奇数の大きさでも全面を作り直した結果と全部の段で一致します。試験が照らします）。
Height → Normal の設定は層の合成を変えないので、設定が変わったら Normal を作り直します。

メモリ: 使っているチャンネルのテクスチャ全部（ミップ込み）の予算は 512 MiB です。4096² で 6 チャンネルすべて（約 320 MiB）は収まり、8192² の 6 チャンネル（約 1.28 GiB）は
1 段縮めて 4096² にします。予算を超える文書は、確保する前に 2 の累乗で縮めて持ち（箱で平均）、3D ビューの左下に「縮小表示 1/2」のように出します（絵と書き出しは元の大きさのまま）。
新しいチャンネルを使い始めて予算を超えるときは、縮めを上げて全部を作り直します。縮めは上げるだけで、文書が替わると決め直します。GPU のテクスチャの辺の上限を超える文書も同じ道で縮めます。
メッシュマップの 1 枚も、辺の上限と予算（チャンネルの予算の半分）を超えるときは縮めます。

影のマップ（光から見た深さ。2048²、16 MiB）は、影を初めて入れたときに作り、光の向きかモデルが変わったときだけ描き直します。カメラを回す・塗る・
柔らかさや光の強さを変えるときは、できている深さをそのまま読みます。一度作ったマップは、影を切っても持ち続けます（入れ直すたびに作り直さない）。影を一度も入れていないあいだは
1 × 1 の深さを束ねるだけで、16 MiB は要りません。

計測（2026-10-04、71148 三角形の球、4096² の文書、6 チャンネルすべてを使う。`cargo test -p yolu-app --test view3d_look -- --ignored --nocapture measure`）。
影なし・影ありは、同じ仕事・同じ量を、同じ実行の中で交互に 3 回ずつ測ります（1 回は 20 フレーム）。表は、実行 2 回（3 回ずつ）の平均と、その回ごとの平均の最小〜最大です。
「全体」は 1 フレームを回して GPU の完了まで待った時間、「CPU」はそのうち `prepare` の CPU の時間（GPU の実行は含まない）です。

| | llvmpipe（Vulkan・ソフト） | コンテナの実 GPU（OpenGL 経由・Mesa d3d12） |
|---|---|---|
| モデルを読んで接線まで（1 回目の実行） | 約 0.74 s | 約 0.56 s |
| 初めての構築（6 チャンネル 4096²、GPU のテクスチャ 320 MiB。1 回目の実行） | 約 0.93 s | 約 0.83 s |
| 影のマップの最初の 1 回（作る + 描く + そのフレーム。2 回の実行の範囲） | 41〜51 ms | 24〜32 ms |

| 1 フレーム（全体 / CPU、ms） | 影 | llvmpipe | コンテナの実 GPU |
|---|---|---|---|
| 描いている最中: 全チャンネルの 2 タイルずつが変わる | なし | 118（98〜158）/ 7.8（6.2〜11.7） | 28.9（24.4〜33.8）/ 20.6（17.1〜23.8） |
| | あり | 124（101〜153）/ 7.8（6.3〜9.6） | 30.1（25.2〜33.4）/ 21.4（17.6〜24.3） |
| 描いている最中: Color・Roughness の 1 タイルずつが変わる | なし | 53（45〜67）/ 0.7（0.6〜0.8） | 13.8（11.7〜15.0）/ 8.0（6.5〜9.6） |
| | あり | 60（48〜77）/ 0.8（0.6〜1.0） | 13.4（12.3〜15.7）/ 7.4（6.6〜8.3） |
| カメラを回す（絵は同じ） | なし | 27.8（20.3〜39.8）/ 0.2 | 5.2（4.2〜6.0）/ 3.6（2.5〜4.2） |
| | あり | 33.0（23.8〜46.8）/ 0.2 | 5.0（4.3〜6.2）/ 3.1（2.6〜3.7） |

- llvmpipe は他の作業と同じ CPU を使うので、実行ごとの値が大きく動きます（カメラを回す影なしは実行 1 回目が約 21 ms、2 回目が約 35 ms）。同じ実行の中の影あり / 影なしの比は
  カメラを回すとき 1.18・1.19、Color・Roughness を塗るとき 1.08・1.17、全チャンネルを塗るとき 1.04・1.07 で、ソフトの描画では影の読み（16 点の比較つきの標本）の費用が 1.04〜1.19 倍に出ます。
- 実 GPU では、影あり・影なしの差は回ごとのばらつきの中に入ります（全チャンネルで 1.12・0.98、Color・Roughness で 0.95・1.00、カメラを回すとき 0.90・0.98）。
- 実 GPU の欄は WSL2 の `/dev/dxg` を Mesa の d3d12 ドライバで OpenGL へ通したもので、Windows の D3D12 そのものではありません。この経路では
  `write_texture` 1 回に約 1.1 ms の固定の手間がかかり、描いている最中の CPU の大半はそれです。この経路では計測の終わりでプロセスが SIGSEGV で落ちます
  （数値は出たあとで、通常の試験でも同じです）。Windows の D3D12 での値は未確認です。

## Unity 版の見た目との比べ方

1. Unity 版のプロジェクトのカラースペースを Linear にする。マテリアルは組み込みの Standard にする（lilToon は式が違うので比べられない）。
2. 同じモデルを両方へ入れる（Live Link で同じモデルを送るか、同じ FBX を開く）。両方で「モデル全体が見える位置へ戻す」を押して、同じカメラ（yaw 25°・pitch 10°）から始める。
3. Unity 版の 3D ビューを「マテリアル」の見せ方にし、シーンの設定を既定（環境なし・影なし・トーンマッピングなし・露出 0・光は既定）に戻す。
   Rust 版は光のパネルの「既定に戻す」のあと、環境を「なし」にする。これで光（来る向き・強さ 0.769）と環境光（灰色 0.5 の 0.4 倍）が同じになる。
4. 環境ありの比較は、Unity 版を「空」（既定の天頂・地平線・地面の色）、Rust 版も「空」にする。「スタジオ」は Rust 版だけ。
5. 数値で比べるなら、板（Unity の Quad と同じ向き）を真正面から見て、光を真正面（方位 180°・高さ 0°）に当て、Color (200, 120, 60) の塗りつぶしと
   Metallic・Roughness の塗りつぶしを入れる。中心の画素は、Rust 版の試験が CPU の式で出す値と ±3 で一致する（`the_material_view_matches_the_cpu_brdf_head_on`）:

   | Metallic | Roughness | 中心の画素（sRGB） |
   |---:|---:|---|
   | 0 | 255 | 156, 94, 50 |
   | 0 | 128 | 172, 122, 95 |
   | 0 | 0 | 195, 155, 136 |
   | 255 | 128 | 255, 172, 89 |
   | 255 | 20 | 255, 255, 255 |
   | 128 | 200 | 145, 88, 48 |

   Unity 版で同じ板・同じ値（Standard の `_MainTex`・`_MetallicGlossMap`（R = Metallic、A = 1 − Roughness））を入れて、同じ点を見て比べる。

### Unity 版との違い（保証の射程）

- 環境「なし」の映り込み: Rust 版は一様な環境光（灰色 0.5 の 0.4 倍）を映す。Unity 版はプレビューのシーンの既定のプローブで、同じとは確かめていない。
- 接線: Rust 版は MikkTSpace の角ごとの値、Unity の `RecalculateTangents` は頂点ごとに 1 つにまとめる。UV の継ぎ目・ミラーの境で法線マップの陰影が少し違いうる。
- テクスチャのミップマップ: Rust 版は箱の平均、Unity はエンジンのミップ。異方性フィルターは Rust 版には無い。
- 影: Unity 版は Standard のシェーダーを書き換えられないので、最終の色の全体（映り込み・発光も）に「環境光 ÷（環境光 + 直接光 × n·L）」を掛けて暗くする
  重ね描きで近似する。Rust 版はシェーダーが自前なので、影のところの直接光（拡散と鏡面の両方）だけを消し、環境光・映り込み・発光は残す。ランバートの面なら
  拡散は Unity 版と同じ明るさになり、鏡面・映り込み・発光のある面では見た目が違う。偏りも違い、Unity 版はぼかしの半径に比例する定数、Rust 版は面の傾きから
  深さの勾配を出して読む点ごとに面の上の深さへ直す（ぼかしを広げても光に寝た面が自分に影を落とさない）。影は主な光 1 つからモデル自身の中へ落ちるものだけです。
- Unity のテクスチャの HDRI・視差（Height の視差マップ）・Unity 版の他のテクスチャセットの同時表示は、Rust 版にはまだ無い。
- 色の空間: 質感の式はリニアで解いて、出力は「画面にそのまま出す値」（ガンマ）。Unity 版の Gamma のカラースペースの見た目とは合わない。
- Windows の D3D12・macOS の Metal での見た目と速さは、このコンテナでは確かめていない（スナップショットは llvmpipe で撮ったもので、実機では縁と補間が少し違う）。

## 試験

```sh
cargo test -p yolu-app --lib view3d::                 # 式・環境・接線・矩形の決め方（GPU なし）
cargo test -p yolu-app --test view3d_look             # 見た目・上げ方・表示の切り替え（スナップショットは llvmpipe）
```
