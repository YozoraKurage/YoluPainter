# Unity との連携

[English](en/UNITY.md)

## Live Link

同じ PC で動く Unity エディターと接続します。Unity 2022.3 のプロジェクトに、**Live Link 対応の Unity 版 YoluPainter（VPM パッケージ `net.yozolab.yolupainter`）と OS に合うネイティブブリッジ**が必要です。`YozoLab → YoluPainter → Live Link` がない版では、この接続は利用できません。Windows 用は `yolu_bridge.dll`、Linux 用は `libyolu_bridge.so` です。

1. Unity のヒエラルキーでモデルのゲームオブジェクトを右クリックし、「Open in YoluPainter」を選びます（`YozoLab → YoluPainter → Live Link` の窓の大きなボタンでも同じです）。スタンドアロンが動いていなければ起動し、つないでモデルを送ります。スタンドアロンの場所は、インストーラーで入れたものを使います（別の場所なら初めに 1 回だけ選びます）。
2. スタンドアロンのテクスチャセット欄でマテリアルを選び、2D または 3D ビューで描きます。表示中で、Unity 側に Color の反映先があるセットの合成結果が Unity に送られます。
3. 作業を `.ylp` に保存します。スクリプトの再コンパイルや Play の出入りのあとは、Unity が自動でつなぎ直します。

スタンドアロンは起動すると Live Link を待ち受け、メニューバー右端の印に状態が出ます。「編集 → 設定…」（Ctrl+,）の「起動時に Live Link を待ち受ける」で切れます（`--livelink` を付けて起動すると、設定によらず待ち受けます。手動で始めるには「ファイル → Live Link」）。接続名・Connect・Send model などは Unity の窓の「詳しく」にあります。

Unity では lilToon・Standard などのマテリアルに描いた色を一時表示します。元のテクスチャやマテリアルのアセットへ書き込む操作ではありません。切断すると一時表示を外します。Live Link は作業ファイルの保存を代行しないため、スタンドアロン側で保存してください。

つなげるのは同じ PC の同じユーザーのプログラムだけです。スタンドアロンは待ち受けるたびに乱数の鍵を作り、自分だけが開けるフォルダ（Windows は `%LOCALAPPDATA%\YoluPainter\LiveLink`、Linux は `$XDG_RUNTIME_DIR/yolupainter` か `/run/user/<UID>/yolupainter`（無ければ `/tmp/yolupainter-<UID>`）、Mac は `/tmp/yolupainter-<UID>`）に置きます。Unity のブリッジは鍵を知っていることを挨拶で示し、スタンドアロンも鍵を知っていると確かめられてからモデルを送ります。つなぐ入り口（ソケット・名前付きパイプ）と、画素を渡す共有メモリのファイルも、そのユーザーだけが開けます。鍵に対応していない古い版とは、画面の下の知らせで理由を出してつなぎません（スタンドアロンと Unity のパッケージは同じ版にそろえてください）。待ち受けを始めるとき、落ちたスタンドアロンが残した共有メモリのファイルを片付けます。同じユーザーの別のプログラムは鍵のファイルを読めるので、つなげます。

接続できる Unity は一度に 1 つです。版の不一致や待ち受け失敗は画面の下の知らせに出ます。ブリッジを更新したときは Unity を再起動してください。接続名を変える場合は、スタンドアロン起動前に環境変数 `YOLUPAINTER_LINK_NAME` を設定し、Unity 側にも同じ名前を指定します（Unity の「Open in YoluPainter」から起動するときは、Unity の Link name がこの環境変数で渡されます）。

## Unity 版との .ylp の受け渡し

| 内容 | スタンドアロンでの扱い |
|---|---|
| `.ylp` 形式 1〜7、内部の文書形式 1〜24 | 読み込み。保存時は `.ylp` 形式 7 に更新（文書形式は使う機能で決まり、ユーザーチャンネル・ノイズ・グランジ・色調補正の行のとおり 21〜24） |
| ラスター層（6 つの標準チャンネル）、グループ（通過・分離）、マスク、塗りつぶし、調整（反転・レベル補正・色相/彩度/明度）、クリッピング、層のロック（透明部分・画素・位置・すべて）、チャンネルごとの有効と合成、Normal の設定 | 編集と保存。文書・レイヤーの ID、透明画素の RGB を保持。ロックは文書形式 12 の属性の並びで書き、ロックの無い文書は従来と同じバイト列 |
| ユーザーチャンネル | 編集と保存。ユーザーチャンネルのあるセットだけ文書形式 22 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません |
| ノイズ・グランジ（Rust 版だけの Generator の種類。無効な段も数える） | 編集と保存。この種類の段があるセットだけ文書形式 23 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません。段を消して保存し直すと 21（ユーザーチャンネルがあれば 22）に戻ります。`.ylsmart`（形式 1）には書けません |
| 色調補正 6 種（グラデーションマップ・トーンカーブ・カラーバランス・明るさ/コントラスト・2 値化・ポスタリゼーション。Rust 版だけの調整の層とフィルターの段の種類。無効な段も数える） | 編集と保存。この種類の層か段があるセットだけ文書形式 24 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません。層と段を消して保存し直すと 21（ユーザーチャンネルがあれば 22、ノイズ・グランジがあれば 23）に戻ります。`.ylsmart`（形式 1）には書けません |
| メッシュマップ（セットごとの `meshmap-<種類>.bin`） | 読み込み・保存。焼いて保存していないマップだけを書き、開いたときのものはそのまま残します。モデルや設定が今と違えば「古い」と表示し、使いません |
| フィルター（層・マスク）、Anchor、2D・3D のパス | 編集と保存。設定ごと保持し、評価は合成のときに行う（画面・書き出す合成の PNG に効果が入る） |
| メッシュマップ・画像を使う Generator、塗りつぶしの画像と投影・グラデーション、デカール | 編集と保存。メッシュマップ（今の条件で焼いたもの）・モデルのルート・棚の画像を評価に渡します。開いたとき、入力がそろわない効果（マップが無い・古い・照合できない、画像が棚に無い）を含むセットは読み取り専用（保存済みの合成を表示し、元の文書を保持し、足りない入力を表示）で、入力がそろえば（ベイクする・モデルを読む・画像が棚に入る）同じセットを編集できます。読むアンカーを選んでいない・ID の色が無いなど、文書の中で直せる設定の不備は読み取り専用の理由にしません |
| 手動の ID の色 | 含むセットを読み取り専用にし、理由を表示。元の文書を保持。手動の ID の色はスタンドアロンで付けられますが、付けた文書の保存は理由つきで断ります |
| 読み取り専用セットの見た目 | 保存済みの Color 合成画像を表示。画像がない・読めない場合は空の表示と理由を提示 |
| アセットの棚（`resources.json` と `resources/`: 画像・ブラシ・マテリアル・スマートマテリアル・スマートマスク） | 読み込み・保存。棚を変えたときだけ書き直し（書き手の名前は YoluPainter、Unity の版の欄は standalone）、変えていなければ開いたときのバイト列のまま残します。このアプリで入れたスマートマテリアル・スマートマスクは Unity 版が読める `.ylsmart`（形式 1）です |
| 編集していないセット、埋め込みリソース、未知の追加エントリ | 元のデータを保持して保存 |
| グループの入れ子が 64 段（1 本の鎖に重なるグループの数）を超えるセット | 読み込みを拒否して理由を表示（ファイルには触れません）。Unity 版には入れ子の上限が無いので、Unity 版で 64 段を超えて重ねた `.ylp` は、このアプリでは開けません。編集・PSD の取り込みも 64 段までです |
| より新しい形式や未知の値、壊れたファイル | 読み込みを拒否して理由を表示 |

Unity へ戻すときは、形式 7 と文書形式 21 を読める Unity 版で開いてください（ユーザーチャンネル・ノイズ・グランジ・色調補正があるセットを含む `.ylp` は、それらを消してから保存し直してください）。古い Unity 版へ戻すための形式への変換はありません。読み取り専用セットは合成画像に置き換えて保存するのではなく、元の編集情報を残します。ただし、保存済み画像は最新の効果を再計算したものとは限りません。

編集したセットは文書形式 21（ユーザーチャンネルがあれば 22、ノイズ・グランジがあれば 23、色調補正があれば 24）と、使っている標準チャンネルの合成画像で保存します。Undo の履歴は保存しません。`.ylp` 全体の ZIP バイト列や、ウィンドウ配置・モデルの接続状態まで両アプリで同じになることは保証しません。

上書き時の直前の版は、同じフォルダの `<ファイル名>-backups~/` に残ります。既定ではすべて残して自動削除せず、メニューの「表示」の「設定…」にある「退避を残す数」で、新しい順に残す数（0〜1000。0 は残しません）を選べます（その数を超えた古い退避だけを消します）。保存先の名前は `.ylp` で終わる必要があり、保存先のフォルダーがなければ作ります。読み込み後に別のアプリがファイルを書き換えた場合は、上書きを断ります。同じファイルを両アプリで同時編集せず、保存してからもう一方で開き直してください。
