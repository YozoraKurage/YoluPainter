# Unity との連携

[English](en/UNITY.md)

## Live Link

同じ PC の Unity エディターから、シーンのモデル（アバターなど）をスタンドアロンで開きます。Unity 2022.3 以降のプロジェクトに、**Unity ブリッジ（VPM パッケージ
`net.yozolab.yolupainter`）**が要ります。ブリッジはスタンドアロンと同じ番号の版で出すので、更新するときは両方を同じ版にそろえてください。
受け渡しは同じ PC のフォルダに置く JSON のファイルで行い、ネイティブのライブラリは使いません（仕様は [LIVELINK.md](LIVELINK.md)）。

1. Unity で Hierarchy のオブジェクトを右クリックして「Open in YoluPainter」（GameObject メニューにもあります）を選ぶか、`YozoLab → YoluPainter → Live Link` のウィンドウでオブジェクトを選んで
   「YoluPainter で開く」（英語の表示では Open in YoluPainter）を押します。スタンドアロンが起きていなければ起動します。
   スタンドアロンはそのオブジェクトの FBX と絵のファイルを自分で読み、マテリアルごとにテクスチャセットを作ります（元の絵は一番下のレイヤー「元の絵」。PSD はレイヤーのまま）。lilToon のマテリアルは、
   Unity の値で 3D ビューに描きます（lilToon の版の値を持つマテリアル・lilToon のパッケージのシェーダーだけ。名前が似ているだけのシェーダーは lilToon として描きません）。
2. Unity でポーズや BlendShape・マテリアルの値を変えたら、同じボタンで送り直します（FBX は読み直さず、ポーズと値だけを当てます。ポーズのパネルやポーズのモードで動かしたボーンも上書きします。元の絵のファイルが変わっていれば、
   何も触っていないセットには入れ直し、触ったセットは変えずに知らせます）。
3. 「ファイル → テクスチャを書き出す…」のウィンドウで出力テンプレートを「lilToon」にして書き出すと、出力先の既定は Unity が知らせたフォルダです。書いた PNG のうち、lilToon のマテリアルのプロパティ（`_MainTex`・`_BumpMap` など）に
   当たる物を Unity が取り込み、マテリアルに当てるかを Unity のウィンドウで確かめます。ほかのテンプレートとチャンネルごとの PNG は Unity へ返しません。
4. 作業は `.ylp` に保存します。Live Link で開いたモデル（FBX の並び・レンダラーとマテリアルの結び・ポーズ）も `.ylp` に残り、Unity なしで開き直せます。
   Unity から受けたマテリアルの値を `.ylp` に残すかは、設定の同じ区分の「Unity から受けたマテリアルの値を保存する」（既定は入）で選べます。
   「配布用に保存」で「モデルの参照」を除くと、写しからこの記録も除かれます（[SAVE_FOR_DISTRIBUTION.md](SAVE_FOR_DISTRIBUTION.md)）。

スタンドアロンは「編集 → 設定…」（Ctrl+,）の「Live Link と外からの操作」の「Unity の Live Link を受け付ける」（既定は入）の間、Unity から開きます（`--livelink` を付けて起動すると、設定によらず受け付けます）。
メニューバー右端の印に状態が出ます（受け付けていない・受付中・Unity から開いた文書・合わない物がある・フォルダを使えない）。印を押すと小さなウィンドウに「Live Link: 受付中」の形の状態と
開いているオブジェクト（「Unity: 名前」）が出て、受け付ける／受け付けないを切り替えられます。「ファイル」メニューの「Live Link」でも切り替えられます。

- 開けるのは、FBX から取り込んだメッシュのレンダラーだけです（.asset のメッシュなどは、Unity のウィンドウに理由を出して送りません）。取り込みの設定の「軸の変換を焼く」
  （Bake Axis Conversion）を入れた FBX は開けません。
- 違うオブジェクトを開くとき、保存していない変更があれば「開く」と同じく確かめます（開くのをやめると、Unity に理由を返します）。描いている最中・保存の途中に Unity から
  開いたときは、終わってから当てます。
- 受け渡しのフォルダ（Windows は `%LOCALAPPDATA%\YoluPainter\LiveLink`、Mac は `~/Library/Application Support/YoluPainter/LiveLink`、Linux は
  `~/.local/share/YoluPainter/LiveLink`）は、そのユーザーだけが入れるフォルダにします。ほかの人も入れるフォルダは使いません。同じユーザーの別のプログラムは、
  そのフォルダにファイルを置けます。
- Unity のプロジェクトの元のテクスチャ・マテリアルのアセットには、利用者がマテリアルに当てると決めたときだけ書き込みます。

## Unity 版との .ylp の受け渡し

Unity ブリッジは 0.5.0 から `.ylp` を開きません。Unity の中で描く機能・`.ylp` と `.ylsmart` の取り込み・PSD の読み書き・メッシュマップのベイクを外し、Live Link と
マテリアルへの適用だけのパッケージになりました。描く・`.ylp` を開く・保存するのはスタンドアロンです。Assets に置いた `.ylp` は、Unity では普通のファイルです。

0.4.x までの Unity 版で `.ylp` を開くときに読める範囲（外側・中身の形式・正本の版・知らないエントリの扱い）は、[YLP_FORMAT.md](YLP_FORMAT.md) の「読み手ごとの範囲」にあります。
Unity 版が読めるのは正本の版 21 までなので、ユーザーチャンネル・ノイズ・グランジ・色調補正・0.5.0 の効果などを使ったセットを含む `.ylp` は、ファイルに触れずに断られます。
そこへ戻すには、スタンドアロンでその機能を消して保存し直します（版が 21 に戻ります）。名前を付けて残した選択範囲（「覚えた選択範囲」）を使った `.ylp`（形式 8）も断られるので、
全部消して保存し直すか、「配布用に保存」で「覚えた選択範囲」を除いた写しにします（[SAVE_FOR_DISTRIBUTION.md](SAVE_FOR_DISTRIBUTION.md)）。古い Unity 版のための形式への変換はありません。
