# Unity との連携

[English](en/UNITY.md)

## Live Link

同じ PC の Unity エディターから、シーンのモデル（アバターなど）をスタンドアロンで開きます。Unity 2022.3 のプロジェクトに、**Live Link 対応の Unity 版 YoluPainter（VPM パッケージ
`net.yozolab.yolupainter`）**が要ります。受け渡しは同じ PC のフォルダに置く JSON のファイルで行い、ネイティブのライブラリは使いません（仕様は [LIVELINK.md](LIVELINK.md)）。

1. Unity の `YozoLab → YoluPainter → Live Link` の窓でシーンのオブジェクトを選び、「YoluPainter で開く」を押します。スタンドアロンが起きていなければ起動します。
   スタンドアロンはそのオブジェクトの FBX と絵のファイルを自分で読み、マテリアルごとにテクスチャセットを作ります（元の絵は一番下のレイヤー「元の絵」。PSD はレイヤーのまま）。lilToon のマテリアルは、
   Unity の値で 3D ビューに描きます（lilToon の版の値を持つマテリアル・lilToon のパッケージのシェーダーだけ。名前が似ているだけのシェーダーは lilToon として描きません）。
2. Unity でポーズや BlendShape・マテリアルの値を変えたら、同じボタンで送り直します（FBX は読み直さず、ポーズと値だけを当てます。ポーズの欄で手で動かした分も上書きします。元の絵のファイルが変わっていれば、
   何も触っていないセットには入れ直し、触ったセットは変えずに知らせます）。
3. 「ファイル → 書き出し」で書き出すと、置き場の既定は Unity が知らせたフォルダです。書いた PNG は Unity が取り込み、マテリアルに当てるかを Unity の窓で確かめます。
4. 作業は `.ylp` に保存します。Live Link で開いたモデル（FBX の並び・レンダラーとマテリアルの結び・ポーズ）も `.ylp` に残り、Unity なしで開き直せます。

スタンドアロンは「編集 → 設定…」（Ctrl+,）の「Unity の Live Link を受け付ける」（既定は入）の間、Unity から開きます（`--livelink` を付けて起動すると、設定によらず受け付けます）。
メニューバー右端の印に状態が出ます（受け付けていない・受付中・Unity から開いた文書・合わない物がある・フォルダを使えない）。印を押すと小さな窓に「Live Link: 受付中」の形の状態と
開いているオブジェクト（「Unity: 名前」）が出て、受け付ける／受け付けないを切り替えられます。

- 開けるのは、FBX から取り込んだメッシュのレンダラーだけです（.asset のメッシュなどは、Unity の窓に理由を出して送りません）。取り込みの設定の「軸の変換を焼く」
  （Bake Axis Conversion）を入れた FBX は開けません。
- 違うオブジェクトを開くとき、保存していない変更があれば「開く」と同じく確かめます（開くのをやめると、Unity に理由を返します）。描いている最中・保存の途中に Unity から
  開いたときは、終わってから当てます。
- 受け渡しのフォルダ（Windows は `%LOCALAPPDATA%\YoluPainter\LiveLink`、Mac は `~/Library/Application Support/YoluPainter/LiveLink`、Linux は
  `~/.local/share/YoluPainter/LiveLink`）は、そのユーザーだけが入れるフォルダにします。ほかの人も入れるフォルダは使いません。同じユーザーの別のプログラムは、
  そのフォルダにファイルを置けます。
- Unity のプロジェクトの元のテクスチャ・マテリアルのアセットには、利用者がマテリアルに当てると決めたときだけ書き込みます。

## Unity 版との .ylp の受け渡し

`.ylp` の形式の仕様（エントリ・版・どの読み手がどこまで読めるか）は [YLP_FORMAT.md](YLP_FORMAT.md) にあります。

| 内容 | スタンドアロンでの扱い |
|---|---|
| `.ylp` 形式 1〜8、内部の文書形式 1〜26・28 | 読み込み。保存時は `.ylp` 形式 7 に更新（名前を付けて残した選択範囲を使う文書だけ形式 8。文書形式は使う機能で決まり、ユーザーチャンネル・ノイズ・グランジ・色調補正の行のとおり 21〜24、グラデーションマップの混色を使えば 25、0.5.0 の効果の行のとおり 28。512 MiB を超える文書は 26） |
| 名前を付けて残した選択範囲（セットごとの `selections.json` と `selection-<中身の印>.bin`。1 セットに 32 個まで。今の選択範囲 `selection.bin` とは別） | 編集と保存。使う文書だけ `.ylp` 形式 8 で保存し（外側の `YOLUPAINTER-YLP-3` と文書形式は変えません）、全部消して保存し直すと形式 7 に戻ります。形式 7 までしか読めない読み手（0.3.x のスタンドアロン・Unity 版 0.2.0 以降のパッケージのウィンドウとインポーター）は、書いたアプリを添えて「新しい形式」と断り、開いても保存し直しても何も失いません。配布用に保存では既定で除き、Unity 版でも開ける形式 7 の写しにできます |
| モデルのポーズ（根の `pose.json`。休みの形からの差を、骨の名前の道と BlendShape の名前で持つ） | 編集と保存（状態のエントリで、形式は上げません）。同じモデルを開くと戻し、合わない項目は理由つきで飛ばします。0.3.x のスタンドアロンは知らないエントリとしてバイト列のまま残し、Unity 版は知らないエントリとして知らせて保存で落とします（失うのはポーズだけ）。Live Link の相手のポーズは `livelink.json` に残します |
| Live Link の相手（根の `livelink.json`。FBX の並び・レンダラーとマテリアルの結び・ポーズ・相手） | 保存（状態のエントリで、形式は上げません）。開くと Unity なしで同じモデルとポーズに開き直します。0.4.x のスタンドアロンは知らないエントリとして知らせ、バイト列のまま残します（モデルは開きませんが、テクスチャセットは開けます）。Unity 版は知らせて保存で落とします（失うのは相手の記録とポーズだけ） |
| ラスター層（6 つの標準チャンネル）、グループ（通過・分離）、マスク、塗りつぶし、調整（反転・レベル補正・色相/彩度/明度）、クリッピング、層のロック（透明部分・画素・位置・すべて）、チャンネルごとの有効と合成、Normal の設定 | 編集と保存。文書・レイヤーの ID、透明画素の RGB を保持。ロックは文書形式 12 の属性の並びで書き、ロックの無い文書は従来と同じバイト列 |
| ユーザーチャンネル | 編集と保存。ユーザーチャンネルのあるセットだけ文書形式 22 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません |
| ノイズ・グランジ（Rust 版だけの Generator の種類。無効な段も数える） | 編集と保存。この種類の段があるセットだけ文書形式 23 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません。段を消して保存し直すと 21（ユーザーチャンネルがあれば 22）に戻ります。`.ylsmart`（形式 1）には書けません |
| 色調補正 6 種（グラデーションマップ・トーンカーブ・カラーバランス・明るさ/コントラスト・2 値化・ポスタリゼーション。Rust 版だけの調整の層とフィルターの段の種類。無効な段も数える） | 編集と保存。この種類の層か段があるセットだけ文書形式 24 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）ではその `.ylp` を開けません。層と段を消して保存し直すと 21（ユーザーチャンネルがあれば 22、ノイズ・グランジがあれば 23）に戻ります。`.ylsmart`（形式 1）には書けません |
| 0.5.0 の効果（フィルターの段: 値の切り出し・値の幅・ノイズに沿ったぼかし・方向ぼかし・ゆがみ・太らせる・細らせる・輪郭の検出・ハイパス・メディアン・グロー。Generator: 模様・光・マスクの組み立て。無効な段も数える） | 編集と保存。この種類の段があるセットだけ文書形式 28 で保存し、文書形式 21 までしか読めない Unity 版（0.2.0 など）と、文書形式 26 までしか読めない 0.4.x のスタンドアロンではその `.ylp` を開けません。段を消して保存し直すと、使う機能に応じて 21〜25 に戻ります。`.ylsmart`（形式 1）には書けません |
| メッシュマップ（セットごとの `meshmap-<種類>.bin`） | 読み込み・保存。焼いて保存していないマップだけを書き、開いたときのものはそのまま残します。モデルや設定が今と違えば「古い」と表示し、使いません |
| フィルター（層・マスク）、Anchor、2D・3D のパス | 編集と保存。設定ごと保持し、評価は合成のときに行う（画面・書き出す合成の PNG に効果が入る） |
| メッシュマップ・画像を使う Generator、塗りつぶしの画像と投影・グラデーション、デカール | 編集と保存。メッシュマップ（今の条件で焼いたもの）・モデルのルート・アセットの画像を評価に渡します。開いたとき、入力がそろわない効果（マップが無い・古い・照合できない、画像がアセットに無い）を含むセットは読み取り専用（保存済みの合成を表示し、元の文書を保持し、足りない入力を表示）で、入力がそろえば（ベイクする・モデルを読む・画像がアセットに入る）同じセットを編集できます。読むアンカーを選んでいない・ID の色が無いなど、文書の中で直せる設定の不備は読み取り専用の理由にしません |
| 手動の ID の色 | 編集でき、保存で残ります。Unity 版が読める版（21）のまま書くので、色を付けただけの文書は Unity 版でも開けます |
| 読み取り専用セットの見た目 | 保存済みの Color 合成画像を表示。画像がない・読めない場合は空の表示と理由を提示 |
| アセット（`resources.json` と `resources/`: 画像・ブラシ・マテリアル・スマートマテリアル・スマートマスク） | 読み込み・保存。アセットを変えたときだけ書き直し（書き手の名前は YoluPainter、Unity の版の欄は standalone）、変えていなければ開いたときのバイト列のまま残します。このアプリで入れたスマートマテリアル・スマートマスクは Unity 版が読める `.ylsmart`（形式 1）です |
| 編集していないセット、埋め込みリソース、未知の追加エントリ | 元のデータを保持して保存 |
| グループの入れ子が 64 段（1 本の鎖に重なるグループの数）を超えるセット | 読み込みを拒否して理由を表示（ファイルには触れません）。Unity 版には入れ子の上限が無いので、Unity 版で 64 段を超えて重ねた `.ylp` は、このアプリでは開けません。編集・PSD の取り込みも 64 段までです |
| より新しい形式や未知の値、壊れたファイル | 読み込みを拒否して理由を表示 |

Unity へ戻すときは、形式 7 と文書形式 21 を読める Unity 版で開いてください（ユーザーチャンネル・ノイズ・グランジ・色調補正・0.5.0 の効果があるセットを含む `.ylp` は、それらを消してから保存し直してください。覚えた選択範囲を使う `.ylp` は、覚えた選択範囲を全部消して保存し直すか、配布用に保存で「覚えた選択範囲」を除いた写しにしてください）。古い Unity 版へ戻すための形式への変換はありません。読み取り専用セットは合成画像に置き換えて保存するのではなく、元の編集情報を残します。ただし、保存済み画像は最新の効果を再計算したものとは限りません。

編集したセットは文書形式 21（ユーザーチャンネルがあれば 22、ノイズ・グランジがあれば 23、色調補正があれば 24、グラデーションマップの混色があれば 25、0.5.0 の効果があれば 28）と、使っている標準チャンネルの合成画像で保存します。Undo の履歴は保存しません。`.ylp` 全体の ZIP バイト列や、ウィンドウ配置・モデルの接続状態まで両アプリで同じになることは保証しません。

上書き時の直前の版は、同じフォルダの `<ファイル名>-backups~/` に残ります。既定ではすべて残して自動削除せず、メニューの「表示」の「設定…」にある「退避を残す数」で、新しい順に残す数（0〜1000。0 は残しません）を選べます（その数を超えた古い退避だけを消します）。保存先の名前は `.ylp` で終わる必要があり、保存先のフォルダーがなければ作ります。読み込み後に別のアプリがファイルを書き換えた場合は、上書きを断ります。同じファイルを両アプリで同時編集せず、保存してからもう一方で開き直してください。
