# yolu-io

Unity 版 `.ylp` の形式1〜7と `document.utpaint` の版1〜21、Rust 版が足した版22（ユーザーチャンネル）・版23（手続き型の Generator）・版24（色調補正。下）を読み書きする。層（ラスター・塗りつぶし・調整・グループ、マスク、クリッピング、チャンネルごとの合成）の文書は `yolu-core::Document` と相互変換できる。

```rust,no_run
use yolu_io::{NativeValue, SaveTarget};

let (project, mut target) = SaveTarget::open("sample.ylp")?;
let set = &project.sets()[0];
let document = set.document.with_value(
    "layers[0].name",
    NativeValue::Text("背景".into()),
)?;
let changed = project.with_document(&set.id, &document)?;
target.save(&changed)?;
# Ok::<(), yolu_io::Error>(())
```

## 読み書き

- `Project::read` はZIPのCRC・manifestのSHA-256・長さ・名前・展開予算を検証し、テクスチャセット、正本、選択範囲、リソースを読む。
- `NativeDocument::fields()` はディスク順の型付き項目を返す。例: `layers[0].opacity`、`layers[0].channels[0].tiles[0].rgba`。整数、真偽値、倍精度数、GUID、UTF-8文字列、画素のバイト列を区別する。GUIDのバイト列はC#の `Guid.ToByteArray()` 順。
- 正本にはチャンネルとタイル、マスク、調整、フィルター、Generator、塗りつぶし画像・投影・デカール・グラデーション、2D/3Dパス、Anchor、手動ID色を保持する。`to_bytes` は各値を元の順で再符号化し、浮動小数点演算や画素変換をしない。
- `with_value` は既存項目の差し替え後に正本全体を再検証する。版や個数だけを変更して不整合になった場合は断る。層・タイルの編集は対応範囲を検査したうえでcoreのAPIを使える。
- `Project::to_bytes` は元の形式を保ち、エントリ内容とmanifestをバイト一致で再保存する。ZIPの時刻・圧縮結果・追加フィールドは一致の対象外。
- `migrated_entries` は形式7の並びへメモリ上で移行したエントリ。`ylp.json` は除き、元の形式と書いたアプリは `info()` で取得する。
- `upgraded(writer)` は明示的に形式7へ更新する。正本の版は変えない。未知のエントリ・JSONキーも保持する。知らないエントリは `unknown_entries()` と `notes()` で知らせる。
- 形式7の `TextureSet::material` は `MaterialRef`（名前と任意のアセットGUID/符号付き64 bitの`fileId`、未割当、旧スロット参照）。名前だけなら重複可、アセット・未割当・スロットは排他的。旧 `materialSlot` はメモリ上で `material: {"slot": …}` へ移行する。`with_material` は形式7の参照を検証して変更する。
- `Project::create(writer, sets, current)` は形式7の新しいプロジェクトを作る（各セットは `SetSpec` で、ID・名前・`MaterialRef`・正本・使っているチャンネルごとの合成PNG）。`with_sets(writer, sets, current)` は形式7のセットの並び・名前・マテリアル参照・現在のセットを置き換え、正本と合成を差し替える。元のセットは全部が並びに要る（セットを消すのは `with_sets_dropping(writer, sets, current, dropped)`。呼び手が確かめた消すセットのIDを渡すと、並びから外し、`sets/<ID>/` の下の正本・選択範囲・合成・メッシュマップ・PSD原本を全部消す。どちらにも無いセット・両方にあるセット・ファイルに無いIDは断る）。正本が `None` のセットはエントリをバイト列のまま残し、正本を替えたセットの `composite/` は消してから渡されたPNG（`composite_pngs` の出力。標準のチャンネルだけ、同じチャンネルは1回）を書く。各セットと根の知らないJSONキー、選択範囲・メッシュマップ・PSD原本・根のほかのエントリは残し、`savedBy` を書き手にする。どちらも書いたものを読み直して検証する。サムネイル（`thumbnail.png`）は作り直さない。
- `Project::view_model()` / `with_view_model(path)` はスタンドアロン版が view.json（状態のエントリ）に残すモデルのファイル（FBX）の参照 `standaloneModel.path`（.ylp からの相対か絶対の文字列。1〜1024 文字、制御文字なし）を読み書きする。view.json の任意の項目を足すだけなので形式も正本の版も変えない。view.json が無ければ Unity 版の読み手が受け入れる最小の形（`modelAssetGuid` は空、`selectedChannel` は 0）で作り、あれば Unity 版が書いたモデルのGUID・表示の状態を含む知らないキーを残す。読めない view.json は参照を書くときだけ最小の形に作り直し、参照を外すだけなら触らない。
- 選択範囲（`selection.bin`）は `Selection` で読み書きし、`Selection::from_core` / `to_core` でcoreの `SelectionMask` と行き来する。書くバイト列はC#の `SelectionBinary.Write` と同じ（量のあるタイルだけを (y, x) の順に並べる）。`Project::with_selection(set_id, Some(&selection))` はセットの選択範囲だけを差し替え、`None` は選択なし（エントリを消す）。正本と大きさが違う選択範囲は再検証で断り、ほかのエントリには触らない。読み込み直後の文書へは `Document::restore_selection` で戻す（Undoの段は増えない）。
- `Project::mesh_map(set_id, kind, max_bytes)` はセットのメッシュマップ（`meshmap-<種類>.bin`、版1〜3）を予算付きで読む。形式1・2は根のエントリ、形式3以降はセットの下。`with_mesh_map(set_id, map)` は派生物だけを置き換えて版3で書き、文書と未知のエントリを保つ。書けるのは形式7だけで、旧形式は先に `upgraded` で移行する（形式5・6のメッシュマップは版2・スロット1つのまま移行で変わらず、置き換えたものから版3になる）。
- `GenerationStore` は復旧用の世代の置き場（Unity 版の `GenerationStore` と同じディスクの形: `current`・`previous`・`generations/<世代>/manifest.sha256`・`contents/<SHA-256>.bin`、見出し `DOTPAINT-MANIFEST-1|2`。Unity 版が書いた世代はこの置き場が読める。逆は、`sets/<ID>/` の下の入れ子の名前（開いた `.ylp` の合成の PNG など）を含む世代を Unity 版は読めない）。`commit` は世代を作り、書いたものを読み直して確かめ、世代の名前へ改名し、`previous`、最後に `current` を置き換える（途中で落ちても `current` は前の世代のまま読める。確定していない作りかけは失敗したときに片付ける）。変わらないエントリは内容の札で世代の間で共有し、`keep` を渡すと確定の後に `current`・`previous` を守って超えた分の古い世代だけを消す（整理の失敗は確定した保存を取り消さない）。`expected` に札を渡すと、外の書き手が `current` を変えていれば断る（`Changed`）。排他は OS のロック（別の書き手が持っていれば待たずに `Busy`）。`list` は世代の一覧（新しい順。manifest と各エントリの存在・長さだけ見て、壊れた世代には理由を付ける）、`load_generation` は名前で選んだ世代を全エントリのハッシュまで確かめて読み、`remove_generation` は世代を 1 つ捨てる（`current`・`previous` を残りで一番新しい世代へ付け替えてから消し、使われなくなった共有の中身も消す）。`Project::from_entries` は世代から読んだエントリをそのまま `Project` にする。`RecoveryInfo` は世代に添える一覧用の `recovery.json`。
- `Archive` は外側だけを検証する低水準API。各正本やリソースの検証まで必要な場合は `Project` を使う。

## coreとの変換・合成PNG

`NativeDocument::to_core()` は C# の `DocumentBinary.Read` と同じ意味で、正本をcoreの文書にする。

| 正本 | core |
|---|---|
| 層の種類（ラスター・塗りつぶし・調整・グループ）、入れ子、通過・分離（合成モード） | 層の並びと親。ID・名前・表示・不透明度・26合成モード・クリッピング |
| ラスターマスク（有効・反転・濃度・画素） | マスク |
| 層のロック（版12。属性の印のビット1と、直後の int。透明部分1・画素2・位置4・すべて8） | `LayerLocks`。読み込みの最後に `set_locks_for_load` で付ける。ロックの無い層は書かず、ロックの無い文書は版11までと同じ並び |
| チャンネルごとの面（Color〜Emission とユーザーチャンネル）と有効の印、無効にしたチャンネルの画素 | 層のチャンネルの面と有効 |
| チャンネルごとの合成モード・不透明度（版14） | `ChannelBlend` |
| 塗りつぶしのチャンネルごとの値と有効 | 塗りつぶしの値と有効 |
| 調整（反転・レベル補正・色相/彩度/明度。版24 からグラデーションマップ・トーンカーブ・カラーバランス・明るさ/コントラスト・2 値化・ポスタリゼーションも）と対象のチャンネル | 調整の設定と対象 |
| Normal の出力の設定（版7） | `NormalSettings` |
| ユーザーチャンネルの一覧（版22） | 文書のチャンネルの一覧（番号・名前・種類・色空間・既定値） |

文書・層のIDと透明画素のRGBを保ち、読み込み操作をUndo履歴に残さない。読み込みの予算はcoreの画素の予算（256 MiB）で、超えたら層・タイルを添えて断る。

`core_issues()` は変換を断る項目を、層の機能ごとに1つ（`manual_id_colors（手動の ID 色）` の形）返す。coreに無い機能 — 手動ID色 — と、タイル外周の非ゼロ余白、coreの予算超過、**調整の種類が使わない値が既定ではない正本**が対象。最後のものは、C#の読み手が種類ごとの作り方で黙って既定に戻すので、coreへ渡すと保存で値が変わるために断る。非表示の層・無効にしたマスクの中身でも断り、黙って捨てない。正本の読み書きは引き続き可能で、断った文書は元のバイト列のまま保存される。

`NativeDocument::from_core(&document)` は C# の `DocumentBinary.Write` と同じ並びで正本を作る。Rust 版だけの色調補正 6 種の調整の層かフィルターの段があれば**版24**、Rust 版だけの Generator の種類（ノイズ・グランジ）の段があれば**版23**、どちらも無くてユーザーチャンネルが無ければ**版21**（Unity 0.2.0 が読める）、あれば**版22**。寸法は8192以下、タイル寸法は8〜512の2の累乗、層は2048まで、文字列はUTF-8で4096バイトまで。描画中のストロークは保存を拒否する。値の無い塗りつぶしのチャンネルと、グループの有効の印は、合成に効かず C# の書き手も書かないので書かない（C#が書いた正本を読んで書き戻すとバイト一致する）。旧版や空タイルのディスク配置まで再現するAPIではない。原本の版・項目・並びをバイト一致で戻すときは、元の `NativeDocument::to_bytes()` を使う。

```rust,no_run
use yolu_io::{NativeDocument, Project};
let project = Project::read(&std::fs::read("sample.ylp")?)?;
let set = project.sets().iter().find(|s| s.id == project.current_set()).unwrap();
let mut core = set.document.to_core()?; // 対応外の項目があれば、編集を始める前に断る。
core.add_group("グループ", None)?;
let native = NativeDocument::from_core(&core)?;
let changed = project.with_document(&set.id, &native)?; // 他セット・リソース・未知エントリを保持。
# Ok::<(), yolu_io::Error>(())
```

### ユーザーチャンネル（正本の版 22）

Unity 版の形式にはユーザーチャンネル（coreの番号6〜63）が無い。Rust 版が、ユーザーチャンネルのある文書だけを**正本の版22**で書く。ユーザーチャンネルが無い文書は今までどおり版21で、.ylp の形式は**7のまま**（YLP_FORMAT の「エントリの中身の版だけを変えるときは、そのエントリの版を上げる」）。

位置は、版7以降のNormalの設定（algorithm・derive・strength・edges・direction）の直後、層の数の直前:

| 欄 | 中身 |
|---|---|
| int 数 | 1〜58。0個の一覧は書かない（ユーザーチャンネルが無ければ版21で書く） |
| 数回、番号の昇順 | int 番号（6〜63。標準の0〜5は一覧に置かない。歯抜けでよい。重複・降順は断る）、string 名前（1〜128文字、制御文字なし、標準の6つ・ほかのユーザーチャンネルと重ならない）、int 種類（0 色・1 スカラー・2 法線）、int 色空間（0 sRGB・1 線形）、4 byte 既定のRGBA |

層の中でチャンネルの番号を持つ欄 — チャンネルごとの合成、塗りつぶしの値、調整の対象、ラスターのチャンネル — は、標準の0〜5に加えて一覧にある番号を置ける（個数の上限は 6 が 6＋一覧の数になる）。一覧に無い番号は断る。色相/彩度の対象は色（種類 0）のチャンネルだけ（標準ではColorとEmission）。標準のチャンネルだけの欄（塗りつぶしの画像・グラデーション、フィルター、パスのマテリアル）は0〜5のまま。版21以前に一覧は無く、標準以外の番号は断る。版22では一覧は1個以上（版23は0個でもよい）。版21以前に一覧を差した正本、版を22以上にしないで一覧を差した正本、一覧の破損はどれも理由を添えて断る。

Unity 0.2.0 は版22を「Unsupported archive version; source retained unchanged.」で断る。C#の `DocumentBinary.Read` / `ReadId` / `YlpFormat.Open`（`Runtime/Core` をそのままコンパイル）にRustが書いた版22を読ませた記録が [`user-channels-v22.unity.txt`](tests/fixtures/user-channels-v22.unity.txt) で、外側の .ylp と `project.json` は読め、開く手順のセットの正本の読みで断る（全部のセットを読めてから入れ替えるので、Unityの状態は変わらず、ファイルも書き換えない）。記録の最後の行は、ウィンドウ（`TexturePaintWindow`）が正本の読みの失敗に付ける文を、読み手の例外から同じ形に組み立てたもの。

選んだ理由と、採らなかった案:

- **版を上げる（採用）。** Unity版が新しい機能を足すたびに使ってきた決まりで、古い読み手は版の数だけで、ファイルに触れずに断る。ユーザーチャンネルが無い文書は版21のままなので、既存の文書、Rust版で保存した大多数の文書をUnity 0.2.0が開ける。
- **全部の文書を版22（0個の一覧）で書く。** Unity 0.2.0がRust版で保存した文書を1つも開けなくなる。ユーザーチャンネルを使わない人まで巻き込むので採らない。失うもの: チャンネルを足すと版が22に、全部消すと21に変わる（保存のたびに今の中身で決まる）。
- **.ylp の形式を8にする。** Unity 0.2.0は `ylp.json` の時点でファイル全体を断る。ユーザーチャンネルを持たないセットも巻き添えになる。形式を上げる決まり（エントリの追加・意味の変更）に当たらない。
- **ユーザーチャンネルの画素を別のエントリに置き、`document.utpaint` は版21のままにする。** Unity 0.2.0は知らないエントリとして一覧に出すだけで、そのまま開き、保存するとそのエントリを落とす。ユーザーチャンネルを黙って失う保存ができてしまうので、「未対応の情報を黙って捨てない」に反する。
- **版21のまま番号6〜63を許す。** Unity 0.2.0は `Invalid or duplicate channel` の汎用の文で断り、新しい版が要るとは言えず、破損と区別できない。名前・種類・色空間・既定値の置き場も無い。
- **`ylp.json` に機能の旗を足す。** Unity 0.2.0は知らないキーを読み飛ばすので、効かない。

移行: 版1〜21はそのまま読め（ユーザーチャンネルの一覧は空）、coreを通して保存すると版21（ユーザーチャンネルがあれば版22）になる。版22を読むRust版は、版21までを読む規則を変えない。版22から21へ戻すには、ユーザーチャンネルを消して保存し直す。

保証の射程と失うもの:

- 1つのセットでも版22なら、その .ylp 全体をUnity 0.2.0は開けない（セットごとには開けない）。Unityで開く必要があるときは、ユーザーチャンネルを消したファイルを保存する。版22から21へ直す移行はUnity側には無い。
- 版22の意味はこの節の表に固定する。Unity版が版22以降を別の意味で使うなら、同じ形式を仕様にして揃える（版の数が食い違うと、どちらの書き手も相手の文書を読み違える）。
- ユーザーチャンネルはC#に書き手が無いので、その合成はC#の合成との一致を保証しない（coreの合成の式と、往復のバイト一致の範囲）。合成のPNG（`composite/<チャンネル>.png`）は標準のチャンネルだけで、ユーザーチャンネルの分は書かない。
- 保証の範囲は `Runtime/Core` の読み手（`DocumentBinary`・`YlpFormat`）の結果まで。Unityのウィンドウ（EditorWindow）の操作の結果は範囲に含めない。

### 手続き型の Generator（正本の版 23）

Generator の種類に、Rust 版だけの**ノイズ（64）**と**グランジ（65）**を足す。Unity 版の種類は 0〜7 で、8〜63 は Unity 版が将来足す余地として空け（Rust 版は使わず、読み手は断る）、Rust 版は 64 から振る。マップを読まず、位置（メッシュマップの Position）・向き（WorldNormal）・UV から値を作る。この種類の段がある文書だけを**正本の版23**で書く。ほかの文書の版は今までどおり（21、ユーザーチャンネルがあれば22）で、.ylp の形式は**7のまま**。

版23 は、版22 の中身に次を足したもの:

- ユーザーチャンネルの一覧の数は 0〜58（版22 は 1〜58。0個でも一覧の数を書く。ユーザーチャンネルが無い文書でも版23 になるため）。
- Generator の種類は 0〜7 に加えて 64・65。8〜63 は断る。
- 種類 64・65 の Generator の欄（共通の欄・ピンの後）は、手続き型の欄で終わる。共通の欄のうち、重ねるノイズ（noise_amount・noise_scale・noise_seed・noise_space）、balance・axis・direction・bent_normal は既定のままにする（検査で断る）。low・high・softness・invert（しきい値・コントラスト）・blend・ピンは使う。ピンの候補は WorldNormal（0）と Position（1）。アルゴリズムの版は 1（式を変えるときに上げる）。

| 欄 | 中身 |
|---|---|
| int 空間 | 0 位置（3D）・1 トライプラナー・2 UV（周期を巻く） |
| float 大きさ | 0.001〜1（モデルの境界箱の対角線・UV の長い辺に対する 1 セルの割合） |
| int シード | 全範囲 |
| float 回転 x・y・z | 度、−360〜360（UV では効かない） |
| float にじみ・float 境目の幅 | 0〜1 |
| 種類 64（ノイズ）だけ | int 基底（0 値・1 Perlin・2 Worley）、int セルの出力（0 F1・1 F2・2 F2−F1。Worley 以外は 0）、int 重ね方（0 fBm・1 ridged・2 turbulence）、int オクターブ（1〜8）、float ラクナリティ（1〜4）、float ゲイン（0〜1） |
| 種類 65（グランジ）だけ | int プリセット（0 汚れの斑・1 錆の斑・2 傷の筋・3 ほこり・4 指紋・5 布目・6 ひび・7 飛沫・8 塗装の剥げ・9 木目・10 革のしぼ） |

評価の約束: 位置（Position）のマップが使える間は、位置から 3D で評価する（UV の島の継ぎ目で模様がずれない）。2D の模様のプリセット（傷の筋・指紋・布目）は、位置の空間では自動でトライプラナー（向きのマップが要る。塗りつぶしの投影と同じ重み）。位置のマップが使えない（無い・古い・大きさが違う・ピンと違う・境界箱が 0）ときは、入力のまま通さず UV の空間に落とし、理由を `BoundGenerator::fallback` と `Document::fallback_effect_list` で返す（値は出ている。UV では x・y の格子を周期で巻くので端で継ぎ目が出ず、回転は効かない）。式は + − × ÷ sqrt floor と整数だけで書き（sin・cos・pow・exp を使わない）、同じ設定・シード・マップなら、スレッド数・領域・ブロックの大きさに依らず同じバイトになる。

Unity 0.2.0 は版23 を、版22 と同じく「Unsupported archive version; source retained unchanged.」で断る。C#の `DocumentBinary.Read` / `ReadId` / `YlpFormat.Open`（`Runtime/Core` をそのままコンパイル）にRustが書いた版23を読ませた記録が [`procedural-v23.unity.txt`](tests/fixtures/procedural-v23.unity.txt)（正本は [`procedural-v23.utpaint`](tests/fixtures/procedural-v23.utpaint)）。

選んだ理由と、採らなかった案:

- **版を上げる（採用）。** ユーザーチャンネルと同じ流儀で、古い読み手は版の数だけで、ファイルに触れずに断る。この種類を使わない文書は版21（ユーザーチャンネルがあれば22）のままなので、Unity 0.2.0が開ける範囲は変わらない。
- **版21のまま種類 64・65 を許す。** 版の数が食い違うと、どちらの書き手も相手の文書を読み違える（版22 の節と同じ理由）。Unity 版が将来 64 以降を別の意味で使うと、同じ版21 のファイルの意味が割れる。
- **既存の種類（EdgeWear・Dirt）の「重ねるノイズ」を拡張する。** 同じ種類の画素が Unity 版と変わり、C# の正解との全バイト一致（338事例）を壊す。
- **.ylsmart（形式1）に入れる。** 形式1 は Unity 版と共有で、版23 の断片を入れた .ylp を Unity 版が棚ごと開けなくなる。ユーザーチャンネルと同じく、この種類を含む素材は `SmartFile::from_core` が理由を添えて断る（`REFUSAL_RUST_GENERATORS`）。失うもの: ノイズ・グランジを使った層を「層から保存」で棚へ入れられない（同梱の素材はコードで作った core の素材を棚の「組み込み」に並べるので影響しない）。形式2 を決めれば入れられる。

移行: 版1〜22はそのまま読める。この種類の段を消して保存し直すと、版21（ユーザーチャンネルがあれば22）に戻る。

保証の射程と失うもの:

- 1つのセットでも版23 なら、その .ylp 全体をUnity 0.2.0は開けない。Unityで開く必要があるときは、ノイズ・グランジの段を消した（または焼き込んだ）ファイルを保存する。
- 画素は Rust の式で、C#に対応する実装が無い。外部の正解は無く、`tests/procedural-index.txt`（実装を固定するハッシュ。回帰の固定）と性質の試験（決定性・継ぎ目・取消・予算・検査）で守る。式を変えると既存の文書の見た目が変わるので、変えるときはアルゴリズムの版を上げて古い式を残す。
- 数値の一致は Linux x86_64 で確かめた範囲。Windows での確認は未測定。
- 保証の範囲は `Runtime/Core` の読み手（`DocumentBinary`・`YlpFormat`）の結果まで。Unityのウィンドウ（EditorWindow）の操作の結果は範囲に含めない。

### 色調補正（正本の版 24）

調整の層とフィルターの段の種類に、Rust 版だけの色調補正 6 種を足す: **64 グラデーションマップ・65 トーンカーブ・66 カラーバランス・67 明るさ/コントラスト・68 2 値化・69 ポスタリゼーション**。Unity 版の種類（調整は 0〜2、フィルターは 0〜6）の後ろの 7〜63 は Unity 版が将来足す余地として空け（Rust 版は使わず、読み手は断る）、Rust 版は 64 から振る（手続き型の Generator と同じ）。この種類の調整の層かフィルターの段（無効な段も数える）がある文書だけを**正本の版24**で書く。ほかの文書の版は今までどおり（21・22・23）で、.ylp の形式は**7のまま**。

版24 は、版23 の中身に次を足したもの:

- 調整の種類とフィルターの種類は、64〜69 も取る（7〜63 は断る）。版23 までの正本に 64 以上の種類があれば、読み手は断る。
- 調整の層は 8 つの値（既定のまま書く）のあとに `detail`、フィルターの段は Generator の欄のあとに `adjust` のブロックを持つ。中身は種類ごとに次のとおり。

| 64 グラデーションマップ | bool 逆向き、ランプ（色の分岐点 2〜32・不透明度の分岐点 2〜32・値のカーブ。塗りつぶしのグラデーションと同じ並び） |

| 66 カラーバランス | シャドウ・中間・ハイライトの各 3 本（シアン/レッド・マゼンタ/グリーン・イエロー/ブルー。float −100〜100）、bool 輝度を保つ |

選んだ理由と、採らなかった案:

- **使う文書だけ版を上げる（採用）。** ユーザーチャンネル・手続き型と同じ流儀で、古い読み手は版の数だけで、ファイルに触れずに断る。色調補正を使わない文書は版21・22・23 のままなので、Unity 0.2.0が開ける範囲は変わらない。

- 1つのセットでも版24 なら、その .ylp 全体をUnity 0.2.0は開けない。Unityで開く必要があるときは、色調補正の層と段を消した（または焼き込んだ）ファイルを保存する。

- PSDの調整レイヤーとしての読み書きは、下の「PSD・PSB」の表のとおり。

## PSD・PSB

`psd` はUnity版と同じRGB8 PSDコーデック。`psd::Document`・`Layer`・`Mask`・`Adjustment` はcoreの文書に依存しないデータ型で、レイヤーとRGBAの行は上から下。名前、正の一意なPSDレイヤーID、キャンバス外の画素、透明画素のRGBを保持する。

```rust,no_run
use yolu_io::psd::{self, CompatibilityMode, Limits};
let limits = Limits::default();
let origin = psd::read(&std::fs::read("sample.psd")?, &limits)?;
for note in origin.diagnostics() {
    eprintln!("{}: {}", note.code, note.message);
}
if origin.mode() == CompatibilityMode::EditableRaster {
    let mut document = origin.to_core()?; // 変換対象外の情報があれば理由を添えて拒否。
    document.add_layer("新しい層")?;
    let edited = psd::Document::from_core(&document)?;
    let bytes = psd::write_edited(&origin, &edited, &limits)?;
    // bytesを新規出力または外部改変検知・一時ファイル置換を備えた保存処理へ渡す。
}
# Ok::<(), yolu_io::Error>(())
```

| 要素 | 読み取り・書き出し |
|---|---|
| PSD v1 RGB8、raw / PackBits RLE | 読める。書き出しはraw。統合画像は白背景のRGB＋元の透明度を格納 |
| ラスター、26合成モード、クリッピング、表示・不透明度、Unicode名・ID | 読み書き。ID欠落・不正・重複を名前で補修しない |
| ラスターマスク | 矩形・既定値0/255・有効/無効・濃度・画素を保持 |
| グループ | 入れ子、通過・分離、マスク、グループと区切りのIDを保持。coreのグループへ（入れ子はPSDの予算の32段まで） |
| 調整 | 反転、RGB一括のレベル補正、マスターの色相/彩度。PSDの整数刻みで保持。チャンネル別補正・Colorize等は保護。色調補正6種は `grdm`（グラデーションマップ）・`curv`（トーンカーブ）・`blnc`（カラーバランス）・`brit`＋`CgEd`（明るさ/コントラスト）・`thrs`（2値化）・`post`（ポスタリゼーション）。刻みの間は丸めず断り、表せない中身（ノイズ型のグラデーション・点が16を超えるか両端が0と255でないか隣が6刻み未満のカーブ・旧式の明るさ/コントラストなど）は `PreserveOnly` で原本を保持 |
| 単色塗りつぶし `SoCo` | RGBの色を保持。8bit未満の端数は丸めて通知。画素キャッシュを使わないことも通知 |
| レイヤーロック `lspf` | 透明・画素・位置・全体を保持。対応のないビットは通知 |
| 描画に関係しない既知メタデータ、sRGB IEC61966-2.1、1:1ピクセル比 | 編集可能として受理し、書き出しに含まれない情報を `NotCarriedIntoExport` で通知 |
| PSB、RGB8以外、ZIP圧縮、未知タグ・調整、効果、テキスト、スマートオブジェクト、ベクターマスク | `PreserveOnly` と理由を返し、原本全体だけを保持。PSBの復号・新規生成はしない |
| 構造破損・予算超過 | `Rejected`。原本保持上限内なら原本バイトは残る |

`psd::read` / `read_stream` は `ReadResult` を返す。編集可能な場合にだけ `document()` が値を持つ。`original_bytes()` / `copy_original_bytes()` は元のファイル全体で、原本保持予算を超えたときだけ保持しない。未知情報を編集後のファイルへ部分的に継ぎ足す方式ではない。**取り込んだ原本の編集保存には `write_edited` を使う**。`PreserveOnly`・`Rejected` はそこで拒否する。`write` は新しく作ったPSDスナップショット用。

原本コピーはバックアップ・保全のためで、外部で変更されたファイルを上書きする許可にはならない。PSD APIはファイルシステムを操作しない。保存先の外部改変検出・バックアップ・最後の一度の置換は呼び出し側の責務で、.ylp用の `SaveTarget` をPSDには使えない。

`ReadResult::to_core` と `psd::Document::to_core/from_core` はColorの写しを変換する。ラスター・グループ（入れ子、通過・分離）・単色の塗りつぶし・調整（反転・レベル補正・色相/彩度・色調補正6種）・クリッピング・ラスターマスク（有効/無効・濃度）・層のロック・26合成モード・表示・不透明度が対象。読み込み時にUndo履歴を残さず、PSDの層IDとグループの区切りのIDはcoreの永続IDに埋め込んで再出力する。同名レイヤーもIDで区別する。並びはUnity版の取り込みと同じ（下から上、グループの中身はグループのすぐ下）。

- `from_core`（coreからPSDへ）: 上の中身をPSDの形で書く。ロックは `lspf` に、透明部分・画素・位置・すべて（`0x80000000` だけで書く）のまま書き、透明部分のロックは層の記録の印のビット0にも書く。マスクは画布との差の外接矩形と、矩形が小さくなるほうの既定値（255か0）で書く。層の合成モードと不透明度はColorでの実効の値（チャンネルごとの設定があればそれ）で書く。PSDが持てない中身は、平らにも黙って落とすこともせず、層の名前と機能ごとの理由で拒否する: 反転したマスク（PSDに非破壊の反転が無い）、クリッピングされたグループ、半透明の塗りつぶし、PSDの刻み（0〜255の整数・ガンマは1/100・1度・1%。色調補正は位置1/4096・中点1%・不透明度とカーブの点1/255・整数のスライダー）の間にある調整とPSDの範囲外のレベル補正、層が効くほかのチャンネルの実効の合成がColorと違うもの（PSDの層は1組しか持てない。効くチャンネルは、明示の設定があるチャンネルと、調整なら有効なチャンネル、グループなら標準のチャンネル。Colorだけが層の値と違う調整・グループも断る）、Color以外のチャンネルの画素・有効の印・塗りつぶしの値、無効にしたColor（調整はColorで無効なもの）、フィルター・Generatorの段（無効・効いていない段も。効果入りの合成は統合画像だけに入り、層の画素と食い違うため）、Anchor、パス。調整の効くチャンネルはPSDに持てないので書かず、読み込み直すと効く標準のチャンネル全部に効く調整になる（Unity版の取り込みと同じ）。`psd::export_blockers(&document)` は断る層と理由（`Refusal`）を全部返し、画面が画面の言語で言い分けるために使う（`from_core` は日本語の診断で初めの1つを返す）。
- `to_core`（PSDからcoreへ）: 上の中身をcoreの層にする。キャンバス外の画素・キャンバス外にある既定値と違うマスクの値は、切り捨てずに拒否する（`core_issues()`）。層のロック（lspfのビット0・1・2・31）はcoreの層のロックへ入れる（`set_locks_for_load`。読み込みの最後に付け、履歴を残さない。`from_core` の逆で、すべては個別のビットを足さない）。`.ylp` にも書ける（版12の並び）ので、取り込みは外さず断らない。

coreからの出力矩形はタイルの範囲になり、不透明度は最も近い1/255へ丸める。原本の圧縮や矩形までバイト一致で戻すAPIではない。

既定の `Limits` は原本・出力各128 MiB、寸法8192、キャンバス16,777,216画素、256レイヤー記録（区切りを含む）、復号256 MiB、メタデータ4 MiB、名前4096 UTF-16単位、診断128件、グループ32段。書き出しは確保前に構造・画素・出力長を検証する。`read` は全体をメモリで扱うため、ストリーミング型の大規模文書向けではなく、これらはプロセス全体の使用メモリの保証ではない。

`read` は統合画像を参照合成と比較する。通常合成だけで大きく違えば編集を止め、合成モード・マスク・グループ・調整等があれば `CompositeDiffers` で見え方の差を知らせる。参照合成はYoluPainterの式であり、Photoshop/CSPの見え方の再現を保証しない。色調補正6種の参照合成もcoreの式をそのまま使うので、この比較はPSDへの書き込みと読み込みの食い違いを見るもので、PhotoshopやCLIP STUDIOの式との独立した照合ではない（書き出した統合画像はこの道具の式の結果で、Photoshopが調整レイヤーを再評価すると見た目が変わりうる）。再生成・検証の条件は [PSDフィクスチャ](tests/fixtures/psd/README.md) を参照。

### 写しとしての取り込み（`psd::import_copy`）

原本を保つ読み（`read`）は、PSDの情報を黙って捨てないために、編集できない中身が1つでもあれば原本の保持だけにする。元のPSDへ書き戻さない使い方（アプリの読み込み）には、別の入口 `import_copy(&mut reader, &CopyOptions { source_budget, cancel })` がある。`Read + Seek` から流して読み、原本のバイト列は持たない（付加情報は層ごと・タグごとに読んで捨て、層の画素は1枚ずつ復号してcoreへ入れてすぐ捨てる）。原本の保持の上限（128 MiB）は掛からず、層の数・画布・層の画素・層1枚の付加情報の上限は呼び手が渡す `source_budget`（アプリでは設定の「レイヤーの画素」）から決まる（層の数は予算1 MiBにつき1枚で256〜32767枚）。結果は `CopyOutcome` で、取り込めない理由（`CopyRefusal`: PSB・RGB8以外・予算を超える・壊れている・レイヤーなし）か、coreの文書と知らせ（`ImportNote`）。

知らせは、機能（`ImportFeature`）と扱い（`ImportAction`）ごとに1件で、当たった層の名前（初めの8枚）と数が付く。**無視**（見え方にも内容にも効かない情報）・**落とす**（層の画素は残すが、その機能の設定・元のデータは持たない。画素を持たない未対応の調整は層ごと）・**変わる**（評価できない効果など、合成がPSDの統合画像と変わり得るもの。層の画素のまま取り込む）に仕分け、表は [docs/PSD.md](../../docs/PSD.md)。層IDは、欠落・重複・不正の層だけに、名前では補修せず新しいIDを振る（有効で一意なIDは並びによらず変えない）。取り込んだ文書の合成は、行の帯ごとにPSDの統合画像と照らして、最大の差と差のある画素の数を知らせる。`read` のように通常合成の大きな差で取り込みを止めることはせず、差は知らせるだけにする（画布が予算に比べて大きいとき、統合画像が無い・読めないときは照らさず、その旨を知らせる）。読む圧縮は raw・PackBits RLE・ZIP・予測つきZIP。

## ブラシ形式の取り込み

`brushes` は他のアプリのブラシのファイルを core のブラシ（`yolu_core::Brush`）にする。アプリへの口は 1 本で、メモリ上のバイト列からは `import_bytes`。

```rust,no_run
use yolu_io::brushes::{import, Unrepresented};

let set = import(std::path::Path::new("chalk.abr"))?;
for brush in &set.brushes {
    // brush.brush は core のブラシ。筆先・質感の画像は Arc で共有する（同じ筆先を使うプリセットは同じ画像を指す）。
    for note in &brush.unrepresented {
        println!("{}", note); // 表せなかった設定（note.english() は英語）
    }
}
# Ok::<(), yolu_io::brushes::BrushImportError>(())
```

| 形式 | 読めるもの | 断るもの |
|---|---|---|
| GIMP `.gbr` | 版 1・2・3。グレーと RGBA（アルファだけを筆先にして注記）。間隔は直径（長い辺）に対する割合に直す | 16 bit 浮動小数点（CinePaint）、署名・ヘッダーの食い違い、名前が 256 バイトを超えるもの |
| GIMP `.gih` | 画像ホース（1〜256 セル。セルごとに大きさが違ってよい）。`sel0` が `incremental` なら順番、`random` ならランダム（`sel0` が無いときは、`dim` があればランダム、無ければ順番）。筆圧・角度・速さ・傾きの選び方と多次元の並びは近似して注記。ファイルのセルが宣言より少なければ、あるだけで使って注記 | セルの途中で切れているもの |
| GIMP `.vbr` | 版 1.0・1.5。円は丸い筆先、正方形・ひし形・スパイクは筆先の画像に描く（縁は GIMP と少し違うことがあるので注記） | 64 KiB を超えるファイル（読み込む前に断る）、スパイク 21 以上、範囲外の数、知らない形・版 |
| Photoshop `.abr` | 版 1・2（計算で描くブラシ、画像の筆先、PackBits）、版 6〜10 の筆先（`samp`）とプリセット（`desc`）。ゆらぎ・散布・筆圧・フェード・ペンの傾き・回転・方向・色の変化・デュアルブラシ・質感（模様は ID だけで対応づけ、名前では対応づけない。合わせ方 8 種・拡大・反転）・筆先の反転 | 版 3〜5 と 11 以降、知らない記録、16 bit の圧縮された筆先、プリセットのない空のファイル |
| Photoshop `.pat` | グレー・インデックス・RGB・16 bit の模様を、深さ 1 の質感を持つ丸いブラシにする | CMYK・Lab・ビットマップ・ZIP 圧縮・1 辺が 2048 を超える模様（理由つき。使える模様が 1 つも無ければ全体を断る） |
| PNG | 暗いほど塗り、白と透明は塗らない（被覆率 = (1 − 輝度) × アルファ）。グレー・グレー+アルファ・RGB・RGBA・パレット・tRNS・1〜16 bit | 1 辺が 2048 を超える画像（画素を読む前に断る） |
| CLIP STUDIO `.sut` | SQLite のサブツール。ブラシの名前、筆先と質感の画像（素材のプレビューの PNG）、大きさ・不透明度・流量・硬さ・間隔・真円率、筆圧の影響（最小値と曲線）。色の混ぜ・吹き付け・デュアルブラシ・入り抜き・手ぶれ補正・色の変化・合成モード・筆先の向き・傾きと速さとランダムの影響は注記。形と確かめた範囲は [docs/BRUSH_IMPORT.md](../../docs/BRUSH_IMPORT.md) | SQLite でないもの、ブラシの表（`Node`）が無いもの、読めるブラシが無いもの、128 MiB を超えるファイル、読み取りの上限（命令の数・経過時間・展開する画素）を超えるもの |
| `.kpp`（Krita のプリセット）・その他 | — | 理由つきで断る |

**表せない設定は捨てない。** 元のアプリにあって core のブラシで表せないもの（最小の直径、ノイズ、ウェットエッジ、描点ごとのテクスチャ、数のゆらぎ、1 軸だけの散布、筆圧以外のコントロールの一部、デュアルブラシの反転、色つきの筆の色など）、近似したもの（ホースのセルの選び方、スパイクの形、グレーへの変換）、読めなかったものは、`Unrepresented` に型で載る。そのブラシの設定のものは `ImportedBrush::unrepresented`、ファイル全体のもの（読めなかった設定の節・模様の節、読み飛ばした節、`.pat` の使えなかった模様）は `ImportedSet::notes` に 1 回だけで、ブラシごとには複製しない（ブラシの数との積で増えるため。画面でも無関係なブラシに他の模様の失敗が並ばない）。文は種類と値から画面が言語ごとに作る（`Display` は日本語、`english()` は英語）。プリセットの形が壊れて取り込めなかったものは `ImportedSet::skipped` に理由つきで載る（ABR の C# 版は黙って読み飛ばしていた）。core の拡張（筆先の反転・ペンの軸の回転・質感の合わせ方 8 種）は、C# 版が「未対応」にしていたものも写す。背景色はブラシに入っていないので、色の変化の `secondary` は取り込みでは触らない。

**信頼できないファイル。** ダウンロードしたブラシを読む前提で、パニックせず、数や長さの宣言で先に確保しない。ファイルは 256 MiB まで（`.sut` は 128 MiB、VBR は 64 KiB まで。読む前に断る）、展開する筆先・模様の画素の合計は 256 MiB まで（PackBits は 2 バイトで 128 画素へ展開できるので、小さなファイルが巨大な画像になる形を予算で断る。質感の「反転」で新しく作る画像も、模様ごとに 1 つを共有して予算から引く）、筆先・模様の個数は 1 万まで（ABR の版 6 以降の筆先と模様の節も。画素 1 つの筆先は画素の予算では止まらない）、記述子は深さ 32・値の数 100 万まで。ファイル全体の注記に並べる知らない節の種類は 64 まで（残りは節の数を 1 つの注記で知らせる）。有限でない数（NaN・無限大）のある設定の節は読めないものとして、筆先だけを注記つきで取り込む。名前は制御文字を除いて 128 文字までにし、節のキー・型名など形式の印は制御文字を `?` にして、画面の文に制御文字が入らない。画面の文にはオフセットなどの内部の数を出さない（`Fault` の値には残る）。壊れ方は全バイトの書き換え・全長での切り詰め・極端な値・挿入と削除・ゴミ入力で試す（`tests/brush_import_hostile.rs`、約 25 万通りに `.sut` の約 32 万通りが加わる）。`.sut` は SQLite をメモリの上の読み取り専用で、防御モード・長さと命令数と時間の上限つきで開き（拡張を読み込む関数は有効化せず、SQL の `load_extension()` は断られる）、決まった表と読む列だけを問い合わせる（`src/brushes/sut/db.rs`）。

**Unity 版（C#）との照合。** `tests/brush_golden.rs` は、手で組んだ 88 事例、同梱の Krita の GIMP 形式の実ファイル 37 個、手で組んだ事例を壊した約 1.1 万の入力を C# の読み手（`Runtime/Core/Brushes`）に通した結果（`tests/fixtures/brushes/`、`tools/csharp-golden/brushes.sh` で作る）と比べる: 取り込めたか・断ったかと、取り込んだ設定（数値は全ビット、筆先・質感・デュアルの画素は指紋）が同じ。C# が検証の例外で落ちる入力（NaN の筆の大きさなど）と、有限でない数のある設定の節は比べない。PNG の筆先は Unity のエンジン（`Texture2D.LoadImage`）を通り Core の外なので、同梱の PNG 39 個の被覆率を別の復号器（Pillow、`tools/brush-fixtures/png_tips.py`）で同じ式に通した指紋と比べる（`tests/brush_bundled.rs`）。Unity のエンジンそのものとの照合はしていない。

**同梱の筆先。** `brushes::bundled::krita4()` は Krita 4 の既定の筆先 76 個（CC0 1.0。原本のバイト列と出どころ・SHA-256 は葉のクレート `yolu-brush-sets`）を、取り込みと同じ読み手でブラシにする（半径を 4〜40 に収め、筆圧で不透明度は変えない）。原本のまま `include_bytes!` で持つ: 11.5 MB で、実行ファイルでは使わなければ読まれず、インストーラーの圧縮で配布の増分は 4 MB ほど。別のクレートにしたのは、`yolu-io` を再ビルドするたびにデータを読み直さず、`yolu-io` の rlib に混ぜないため。

## リソースと未対応の中身

画像はRGBA8のPNGを復号し、寸法と下の行からの画素ハッシュを検証する。スマートマテリアル・スマートマスク・マテリアル・ブラシは埋め込まれたファイル全体を保持する。内側のmanifest、正本、種別、チャンネル、画像、ブラシのschema・画像参照も検証する。

ブラシ設定の描画上の意味、.ylp内のPSD原本・合成PNG・メッシュマップ・画面設定の自動復号は未実装（効果の実行は core の `Document` が行い、メッシュマップと画像は `Document::set_effect_inputs` で渡す。画像リソースからの入力は `Project::image_inputs`）。PSD単体は上記のAPIで読み書きできる。これらは読み飛ばして破棄せず、原本のエントリとして残す。`notes()` を呼び出し側の画面に提示できる。画像リソース以外のPNGをすべて復号するAPIではない。

形式8以降、正本23以降、未知の列挙値・アルゴリズム版は理由を添えて断る。ZIP64・暗号化・分割ZIP、RGBA8以外のリソースPNGは扱わない。正本とZIPの1エントリは512 MiB、ZIPの展開総量は768 MiB・1000エントリ、復号リソースも768 MiBまで。これらはデータ量の上限であり、プロセスの最大メモリ使用量の保証ではない。

## 保存

`SaveTarget::open` はSHA-256・長さ・更新時刻を記録する。外部の書き換えは内容（SHA-256と長さ）で見分け、更新時刻だけが変わった（同期ツールなど）ものは書き換えとして扱わない。`create` は新規保存専用。保存ではメモリで検証し、保存先と同じフォルダの一時ファイルに書いて `sync_all`、読み直して検証、外部改変を再確認してから `rename` で一度だけ確定する。置換に失敗しても削除してから移動する手順には切り替えない。

直前の版は `<ファイル名>-backups~/` に `<名前>-<UTC の時刻（ミリ秒）>.ylp` の名前（Unity版と同じ）で退避する。同じ時刻の退避があるときと時計が戻っているときは下線を足し、名前の順がいつも新しい順になる。保持数は呼び出し側が `BackupKeep`（すべて・N・0）で決め、既定はすべて残す（`save`）。`save_with` は整理の結果を `SaveReport` で返す。0 は退避しない（すでにある退避は消さない）。整理は置換で確定した後だけで、この文書の退避を新しい順に、今回の退避を含めて N 件になるよう古い方を消す。利用者が名前を変えて残したファイル・別の文書の退避・フォルダーやリンクは数えず、消さない。消せなくても保存は成功のままで、消せなかったものと理由が `prune_failures` に載る。以前の版がSHA-256名で退避したものは、最も古い退避として数える（互いは更新時刻の順。名前に順が無いので、同期やコピーで更新時刻が変わると古い順は保証しない）。退避は最後の確かめの後・置換の直前に作り、置換まで届かなかった保存は、作った退避（と作ったフォルダー）を消す。前の版の置き場が普通のファイルやシンボリックリンクで塞がれていれば、保存先に触らず `SaveConflict` で断る（プロジェクトのデータの不正とは言い分ける。退避しない設定では置き場に触らない）。保存先が開いたあとに消されていれば、外部の変更として断り、無いファイルの代わりに書き始めない。

新規の保存先（`create`）は、名前が `.ylp`（大文字小文字は問わない）で終わっていなければ、ディスクに触る前に断る（`SaveConflict`。開いたファイルの名前が違っても `open` は読めるが、保存は断る）。保存先のフォルダーはなければ保存のときに作り、保存が確定しなかったときは、作った空のフォルダーだけを消す（もとからあるフォルダーと、他のものが入ったフォルダーは消さない）。最後は置き換えない移動で確定する: 確かめてから移すのではなく、移す操作そのものが、先にあれば断る。Linux（glibc）は `renameat2` の `RENAME_NOREPLACE`、それが使えない場所とほかのUnixは `hard_link` してから元の名前を消す（消せなくても保存は確定済みで成功とし、残った一時ファイルは保存の後始末が消し直す）、Windowsは `MoveFileExW` を置き換えのフラグなしで呼ぶ。どれも使えないファイルシステム（FAT系・一部のネットワーク共有など）では、ロックの使えない場所と同じく断らずに、もう一度確かめてから置き換える移動で確定する（その間に外から作られる競合は防げない）。外から先に作られていたものは上書きせず、そのまま残す。上書き保存は置き換える移動のままで、直前までの印の確かめが守る。

保存は保存先ごとに1つずつで、`.<ファイル名>.save.lock~` を開いてOSの排他ロックを持つ。別の保存が持っていれば `SaveConflict`（進行中）で断り、そのファイルは消さない。ロックはファイルがあるかではなくロックを持っているかで決めるので、クラッシュで残ったファイルは次の保存を止めず、終わると消える。ロックが使えないファイルシステム（ロックを取る操作そのものが失敗する所）では、C#（.NET の FileShare.None）と同じく排他なしで続ける（断るとその場所へ保存できなくなる）。そこでも置換の前の印の確かめは働き、ロックのファイルは終わると消える。置換の後の失敗は失敗として返すが、新しい版は確定していて（`stamp()` も新しい版）、次の保存はそのまま通る。非協調プロセスが最後の検査と置換の間に書く競合と、電源断時のディレクトリ永続性は保証の対象外。

## 書き出し（テンプレートとパディング）

`export` は書き出しのテンプレート（`yolu_core::export`。Unity Standard / URP Lit・HDRP Lit・lilToon）の画像をフォルダへPNGで書く。ファイル名はUnity版と同じ `<名前>[_<セット名>]_<接尾辞>.png`（セットが複数のときだけ `_<セット名>`。使えない文字は `_`）。

```rust,no_run
use yolu_core::export::ExportTemplate;
use yolu_core::padding::Reach;
use yolu_io::export::{write_template, PaddingSpec, SetExport, WriteOptions};

# let (document, coverage): (yolu_core::Document, Vec<bool>) = unimplemented!();
let report = write_template(
    std::path::Path::new("out"),
    &ExportTemplate::unity_standard(),
    &SetExport {
        stem: "Texture",
        set_name: None,
        document: &document,
        occlusion: None,
        padding: Some(PaddingSpec { coverage: &coverage, reach: Reach::Fill }),
        max_working_bytes: 1 << 30,
    },
    &WriteOptions::default(),
)?;
for image in &report.written {
    // Unityの取り込み設定は書かない。ここで渡す。
    println!("{} srgb={} normal_map={}", image.file_name, image.srgb, image.normal_map);
}
# Ok::<(), yolu_io::export::ExportError>(())
```

- 書く画像は、読むものがある画像だけ（`should_write`）。使っていないチャンネルしか読まない画像は書かず、`skipped` に接尾辞を返す。
- 手順は、(1) 名前・大きさ・上書きを確かめる、(2) 画像を1枚ずつ作って隠しの一時ファイルへ書き、`sync_all` して読み戻し、RGBAが一致することを確かめる、(3) 全部が済んでから1枚ずつ `rename` で置き換える。(2) までに失敗・取消すれば元のファイルは1つも変わらず、一時ファイルも残らない。(3) の途中の失敗だけ `ExportError::Partial` で済んだ分を知らせる（新しく作った分は消す）。
- 既にあるファイルは、既定では置き換えず `WouldReplace`（何も書かない）。`existing_files` で見せて確かめてから `Overwrite::Replace`。置き換えない設定では `hard_link` で置くので、調べた後に他のプロセスが作ったファイルも上書きしない。フォルダ・リンクは置き換えない。
- 複数のテクスチャセットは `plan_template` で書く画像とファイル名を出し、`clashes` で名前の重なりを確かめ、`write_images`（中身は呼び手の関数から1枚ずつ）で全部を1回の手順にする。
- 画像の中身は1枚ずつしか持たない。上限は1辺8192（Unity版の `RgbaPng` と同じ）。PNGは `composite_png` と同じエンコーダ（行ごとの適応フィルター、圧縮バイトはdeflate実装の版に依存）。
- Unityのインポートの設定（sRGB・ノーマルマップ・アルファを透明度に）はファイルに書かない。`WrittenImage` の `srgb`・`normal_map`・`alpha_is_transparency` を後で使う。
- 取消は `WriteOptions::cancel` の旗（置き換えを始める前まで）。塗り広げの途中でも旗を見て、どこで止まっても `ExportError::Cancelled` で返る。
