# yolu-io

`.ylp` の形式1〜8（1〜7 は Unity 版が書いた形式。8 は名前を付けて残した選択範囲を使うファイルだけ。下）と、`document.utpaint` の版1〜30・32〜35（31 は欠番）と、外側の `YLP-1`〜`4`（`YLP-4` は今の上限に収まらない大きな .ylp。下）を読み書きする。版1〜21 は Unity 版が書いた版で、22 以降は Rust 版が追加した版: 22 ユーザーチャンネル・23 手続き型の Generator・24 色調補正・25 グラデーションマップの混色・26 分けた正本・27 パスの一覧・28 0.5.0 の効果・29 点のグラデーション・30 テキストレイヤー・32 継ぎ目の設定・33 ベイクの優先・34 パスのブラシのアンチエイリアス・35 定規とパスの線対称（下）。形式の仕様（エントリ・JSON の形・正本の欄・版）は [docs/YLP_FORMAT.md](../../docs/YLP_FORMAT.md)。ファイル全体・正本全体をメモリに作らず、流して読み書きする。レイヤー（ラスター・塗りつぶし・調整・グループ、マスク、クリッピング、チャンネルごとの合成）の文書は `yolu-core::Document` と相互変換できる。

```rust,no_run
use yolu_io::{NativeValue, SaveTarget};

let (project, mut target) = SaveTarget::open("sample.ylp")?;
// 正本は骨組みだけを持ち、画素は要るときに流して読む。小さな文書は `with_value` などでメモリの正本にして書き換えられる
let set = &project.sets()[0];
let document = set.document.with_value(
    "layers[0].name",
    NativeValue::Text("背景".into()),
)?;
let changed = project.with_document(&set.id, &document)?;
target.save(&changed)?;
# Ok::<(), yolu_io::Error>(())
```

## 読み書き

- `Project::read`（メモリのバイト列）・`Project::open(path, limits)`（ファイルを流して）は、ZIPのCRC・manifestのSHA-256・長さ・名前・上限（`Limits`。設定の予算から。下の「大きな文書」）を検証し、テクスチャセット、正本、選択範囲、リソースを読む。ファイルから開いたエントリは小さなもの（1 MiB まで）だけをメモリに置き、ほかはファイルの中の位置（`Blob`）で持って、要るときに位置から流して読む（読むたびに長さ・SHA-256・CRC を確かめ直す。読むのは開いたファイルのハンドルから。外で改名・移動・削除・別のファイルへの置き換えをされても、開いたときの中身を読む。下の「保存」）。`Blob::hold_in(dir, keep)` は中身を別のフォルダへ置き直す（中身のファイルはハードリンク、できなければ確かめながら流して写す。`keep` が手放されるとフォルダごと片付ける。アプリは復旧の世代から開いたプロジェクトに使い、その世代が後で整理・破棄されても保存できるようにする）。
- `TextureSet::document` は `SetDocument`（正本の骨組み（`Bytes` の値（色・画素）を持たない項目）と、元: 置いてある正本・メモリの正本・core の文書）。`to_core_within(budget)` はレイヤーごとに流して core の文書にし（持つのはレイヤー 1 枚ぶん。予算を超えたら途中で止める）、`to_native` / `to_bytes` は小さな文書のためにメモリの正本にする（512 MiB まで。超える正本は中身を読まずに `Error::Budget` で断る）。
- `NativeDocument::fields()` はディスク順の型付き項目を返す。例: `layers[0].opacity`、`layers[0].channels[0].tiles[0].rgba`。整数、真偽値、倍精度数、GUID、UTF-8文字列、画素のバイト列を区別する。GUIDのバイト列はC#の `Guid.ToByteArray()` 順。
- 正本にはチャンネルとタイル、マスク、調整、フィルター、Generator、塗りつぶし画像・投影・デカール・グラデーション、2D/3Dパス、Anchor、手動ID色を保持する。`to_bytes` は各値を元の順で再符号化し、浮動小数点演算や画素変換をしない。
- `with_value` は既存項目の差し替え後に正本全体を再検証する。`with_values` は複数の項目をまとめて差し替え、再検証は 1 回だけ（同じ項目を 2 回は差し替えない）。版や個数だけを変更して不整合になった場合は断る。レイヤー・タイルの編集は対応範囲を検査したうえでcoreのAPIを使える。
- `Project::to_bytes` は元の形式を保ち、エントリ内容とmanifestをバイト一致で再保存する。ZIPの時刻・圧縮結果・追加フィールドは一致の対象外。
- `migrated_entries` は形式7の並びへメモリ上で移行したエントリ。`ylp.json` は除き、元の形式と書いたアプリは `info()` で取得する。
- `upgraded(writer)` は明示的に形式7へ更新する。正本の版は変えない。未知のエントリ・JSONキーも保持する。知らないエントリは `unknown_entries()` と `notes()` で知らせる。
- 形式7の `TextureSet::material` は `MaterialRef`（名前と任意のアセットGUID/符号付き64 bitの`fileId`、未割当、旧スロット参照）。名前だけなら重複可、アセット・未割当・スロットは排他的。旧 `materialSlot` はメモリ上で `material: {"slot": …}` へ移行する。`with_material` は形式7の参照を検証して変更する。
- `Project::create(writer, sets, current)` は形式7の新しいプロジェクトを作る（各セットは `SetSpec` で、ID・名前・`MaterialRef`・正本（`DocumentSource`: メモリの正本か core の文書の写し。core の文書は全体の正本をメモリに作らず、書くときにレイヤーごとに流して作る）・使っているチャンネルごとの合成PNG）。`with_sets(writer, sets, current)` は形式7のセットの並び・名前・マテリアル参照・現在のセットを置き換え、正本と合成を差し替える。元のセットは全部が並びに要る（セットを消すのは `with_sets_dropping(writer, sets, current, dropped)`。呼び手が確かめた消すセットのIDを渡すと、並びから外し、`sets/<ID>/` の下の正本・選択範囲・合成・メッシュマップ・PSD原本を全部消す。どちらにも無いセット・両方にあるセット・ファイルに無いIDは断る）。正本が `None` のセットはエントリをバイト列のまま残し、正本を替えたセットの `composite/` は消してから渡されたPNG（`composite_pngs` の出力。標準のチャンネルだけ、同じチャンネルは1回）を書く。各セットと根の知らないJSONキー、選択範囲・メッシュマップ・PSD原本・根のほかのエントリは残し、`savedBy` を書き手にする。どちらも書いたものを読み直して検証する。サムネイル（`thumbnail.png`）は作り直さない。
- `Project::view_model()` / `with_view_model(path)` はスタンドアロン版が view.json（状態のエントリ）に残すモデルのファイル（FBX）の参照 `standaloneModel.path`（.ylp からの相対か絶対の文字列。1〜1024 文字、制御文字なし）を読み書きする。view.json の任意の項目を追加するだけなので形式も正本の版も変えない。view.json が無ければ Unity 版の読み手が受け入れる最小の形（`modelAssetGuid` は空、`selectedChannel` は 0）で作り、あれば Unity 版が書いたモデルのGUID・表示の状態を含む知らないキーを残す。読めない view.json は参照を書くときだけ最小の形に作り直し、参照を外すだけなら触らない。
- `Project::look(set_id)` / `with_look(set_id, look)` はスタンドアロン版のセットの見た目の設定（`sets/<ID>/look.json`。下の「見た目の設定」）を読み書きする。`None` はエントリを消す（標準の見た目。Unity から受けた値があればエントリを残して本体だけを既定にする）。書けるのは形式7だけ。読めない（壊れた・新しい形式の）ものはエラーを返し、エントリはバイト列のまま残る。`received_look(set_id)` / `with_received_look(set_id, received)` は同じエントリの、Live Link で Unity から受けた値（`received`）だけを読み書きする（本体と知らないキーはそのまま。読めないエントリには書かずに断る）。
- 選択範囲（`selection.bin`）は `Selection` で読み書きし、`Selection::from_core` / `to_core` でcoreの `SelectionMask` と行き来する。書くバイト列はC#の `SelectionBinary.Write` と同じ（量のあるタイルだけを (y, x) の順に並べる）。`Project::with_selection(set_id, Some(&selection))` はセットの選択範囲だけを差し替え、`None` は選択なし（エントリを消す）。正本と大きさが違う選択範囲は再検証で断り、ほかのエントリには触らない。読み込み直後の文書へは `Document::restore_selection` で戻す（Undoの段は増えない）。
- 名前を付けて残した選択範囲（`sets/<ID>/selections.json` と `selection-<中身の印>.bin`。形式8）は `Project::saved_selections(set_id)`（読めた項目 `items` と、飛ばした項目と理由 `skipped`。壊れた項目だけを飛ばし、飛ばしたエントリはバイト列のまま残る）と `with_saved_selections(set_id, &items)`（セットの索引と中身を全部置き換える。決まりに合わない並びは断る）で読み書きする。選択範囲は今の選択範囲（`selection.bin`）と同じ `YLSL` の版1で、中身の印は SHA-256 の先頭 128 bit（エントリ名が `sets/<ID>/` を含めて 96 文字までのため）。1 セットに 32 個まで、名前は前後の空白がなく 1〜256 文字・制御文字なし・重ならない。使う文書だけ `ylp.json` の形式を 8 にし（外側の `YOLUPAINTER-YLP-3` は変えない）、全部なくなれば 7 に戻す（書き換えのたびに整える）。形式7までの読み手は形式8を書いたアプリを添えて断る（`Error::UnsupportedFormat`。対応上限は `MAX_FORMAT`）。配布用の写しは `Removal::SavedSelections` で除ける。
- モデルの今のポーズ（根の `pose.json`。状態のエントリで形式は上げない）は `Project::pose()`（読めなければエラー。エントリはバイト列のまま残る）と `with_pose(Some(&pose))`（`None` はエントリを消す）で読み書きする。`yolu_io::pose::StoredPose` は休みの形からの差（ボーンは名前の道、BlendShape はメッシュ名と名前の組）で、範囲外・数でない値・単位でない回転・重なり・上限（ボーン 4096・BlendShape 4096）のあるものはエントリごと断る。0.3.x のスタンドアロンは知らないエントリとしてバイト列のまま残し、Unity 版は知らせて保存で落とす（失うのはポーズだけ）。配布用の写しは `Removal::ModelReference` と一緒に除く。
- `Project::mesh_map(set_id, kind, max_bytes)` はセットのメッシュマップ（`meshmap-<種類>.bin`、版1〜3）を予算付きで読む。形式1・2は根のエントリ、形式3以降はセットの下。`with_mesh_map(set_id, map)` は派生物だけを置き換えて版3で書き、文書と未知のエントリを保つ。書けるのは形式7だけで、旧形式は先に `upgraded` で移行する（形式5・6のメッシュマップは版2・スロット1つのまま移行で変わらず、置き換えたものから版3になる）。
- `GenerationStore` は復旧用の世代の置き場（Unity 版の `GenerationStore` と同じディスクの形: `current`・`previous`・`generations/<世代>/manifest.sha256`・`contents/<SHA-256>.bin`、見出し `DOTPAINT-MANIFEST-1|2`。Unity 版が書いた世代はこの置き場が読める。逆は、`sets/<ID>/` の下の入れ子の名前（開いた `.ylp` の合成の PNG など）を含む世代を Unity 版は読めない）。`commit` は世代を作り、書いたものを読み直して確かめ、世代の名前へ改名し、`previous`、最後に `current` を置き換える（途中で落ちても `current` は前の世代のまま読める。確定していない作りかけは失敗したときに片付ける）。変わらないエントリは内容の札で世代の間で共有し、`keep` を渡すと確定の後に `current`・`previous` を守って超えた分の古い世代だけを消す（整理の失敗は確定した保存を取り消さない）。`expected` に札を渡すと、外の書き手が `current` を変えていれば断る（`Changed`）。排他は OS のロック（別の書き手が持っていれば待たずに `Busy`）。`list` は世代の一覧（新しい順。manifest と各エントリの存在・長さだけ見て、壊れた世代には理由を付ける）、`load_generation` は名前で選んだ世代を全エントリのハッシュまで確かめて読み、`remove_generation` は世代を 1 つ捨てる（`current`・`previous` を残りで一番新しい世代へ付け替えてから消し、使われなくなった共有の中身も消す）。`Project::from_entries` は世代から読んだエントリをそのまま `Project` にする（エントリは小さなものだけメモリに置き、ほかは置き場の中身のファイルを指す）。書くのも確かめるのも流して（エントリ全体をメモリに読まない）、量の上限は `with_limits`（下の「大きな文書」）。`RecoveryInfo` は世代に添える一覧用の `recovery.json`。
- `Archive` はメモリの中の zip の外側だけを検証する低水準API（`.ylsmart`・`.ylbrush`・アセットと、今の形（`YLP-1`〜`3`）の .ylp。`YLP-4` は読まない）。`Package` は .ylp の外側を流して読み書きする（`YLP-1`〜`4`）。各正本やリソースの検証まで必要な場合は `Project` を使う。

### 見た目の設定（`look.json`）

`Project::look` / `with_look` / `received_look` / `with_received_look`（上）が読み書きする。形と決まりは [docs/YLP_FORMAT.md](../../docs/YLP_FORMAT.md) の「look.json」、別のエントリにした理由は [docs/YLP_DECISIONS.md](../../docs/YLP_DECISIONS.md) の「見た目の設定を別のエントリにした」。

## coreとの変換・合成PNG

`NativeDocument::to_core()` は C# の `DocumentBinary.Read` と同じ意味で、正本をcoreの文書にする。

| 正本 | core |
|---|---|
| レイヤーの種類（ラスター・塗りつぶし・調整・グループ）、入れ子、通過・分離（合成モード） | レイヤーの並びと親。ID・名前・表示・不透明度・26合成モード・クリッピング |
| ラスターマスク（有効・反転・濃度・画素） | マスク |
| レイヤーのロック（版12。属性の印のビット1と、直後の int。透明部分1・画素2・位置4・すべて8） | `LayerLocks`。読み込みの最後に `set_locks_for_load` で付ける。ロックの無いレイヤーは書かず、ロックの無い文書は版11までと同じ並び |
| チャンネルごとの面（Color〜Emission とユーザーチャンネル）と有効の印、無効にしたチャンネルの画素 | レイヤーのチャンネルの面と有効 |
| チャンネルごとの合成モード・不透明度（版14） | `ChannelBlend` |
| 塗りつぶしのチャンネルごとの値と有効 | 塗りつぶしの値と有効 |
| 調整（反転・レベル補正・色相/彩度/明度。版24 からグラデーションマップ・トーンカーブ・カラーバランス・明るさ/コントラスト・2 値化・ポスタリゼーションも）と対象のチャンネル | 調整の設定と対象 |
| Normal の出力の設定（版7） | `NormalSettings` |
| ユーザーチャンネルの一覧（版22） | 文書のチャンネルの一覧（番号・名前・種類・色空間・既定値） |
| レイヤー・グループの定規（版35。1 レイヤーに 64 本まで） | レイヤーの定規（`Ruler`） |

文書・レイヤーのIDと透明画素のRGBを保ち、読み込み操作をUndo履歴に残さない。読み込みの予算はcoreの画素の予算（256 MiB）で、超えたらレイヤー・タイルを添えて断る。

`core_issues()` は変換を断る項目を、レイヤーの機能ごとに1つ（`layers[2].adjustment.gamma（調整の種類が使わない値が既定ではない）` の形）返す。対象は、coreに無い項目、タイル外周の非ゼロ余白、coreの予算超過、**調整の種類が使わない値が既定ではない正本**。最後のものは、C#の読み手が種類ごとの作り方で黙って既定に戻すので、coreへ渡すと保存で値が変わるために断る。非表示のレイヤー・無効にしたマスクの中身でも断り、黙って捨てない。正本の読み書きは引き続き可能で、断った文書は元のバイト列のまま保存される。

`NativeDocument::from_core(&document)` は C# の `DocumentBinary.Write` と同じ並びで正本を作る。使う機能が要る一番小さな版で書く: 定規を持つレイヤー（グループ）か線対称の 2D のパスがあれば**版35**、パスのブラシのアンチエイリアスが「なし」でないパスがあれば**版34**、ベイクの優先を既定から変えていれば**版33**、継ぎ目の設定を切っていれば**版32**、テキストレイヤーがあれば**版30**、点のグラデーションか異方性を切った塗りつぶしの画像があれば**版29**、0.5.0 のフィルター（種類 70〜79）かジェネレーター（種類 66〜70）があれば**版28**、パスの一覧の形で書くパスがあれば**版27**、混色（通常でない混色モードか区間の混合率曲線）を使うグラデーションマップがあれば**版25**、Rust 版だけの色調補正 6 種の調整レイヤーかフィルターの段があれば**版24**、Rust 版だけの Generator の種類（ノイズ・グランジ）の段があれば**版23**、どちらも無くてユーザーチャンネルが無ければ**版21**（Unity 0.2.0 が読める）、あれば**版22**。手動の ID の色（`Document::id_colors`）は、空でなければレイヤーの後の塊（版19。`tag` `YLID`・数・指紋・番号の昇順の色）に書き、版は変えない（空なら塊を書かない）。読むときは指紋が今のモデルと合うかを見ずに、書いてあったとおり `Document::restore_id_colors` で戻す（照合は使う側）。寸法は8192以下、タイル寸法は8〜512の2の累乗、レイヤーは2048まで、グループの入れ子は64段まで（`yolu_core::MAX_GROUP_DEPTH`。読み手も同じ上限で、超えるファイルは壊れたファイルでなく上限として断る）、文字列はUTF-8で4096バイトまで。描画中のストロークは保存を拒否する。値の無い塗りつぶしのチャンネルと、グループの有効の印は、合成に効かず C# の書き手も書かないので書かない（C#が書いた正本を読んで書き戻すとバイト一致する）。旧版や空タイルのディスク配置まで再現するAPIではない。原本の版・項目・並びをバイト一致で戻すときは、元の `NativeDocument::to_bytes()` を使う。

```rust,no_run
use yolu_io::{NativeDocument, Project};
let project = Project::read(&std::fs::read("sample.ylp")?)?;
let set = project.sets().iter().find(|s| s.id == project.current_set()).unwrap();
let mut core = set.document.to_core()?; // 対応外の項目があれば、編集を始める前に断る。
core.add_group("グループ", None)?;
let native = NativeDocument::from_core(&core)?;
let changed = project.with_document(&set.id, &native)?; // 他セット・リソース・未知エントリを保持。
# Ok::<(), yolu_io::Error>(())
```

### Rust 版だけの正本の版（22 以降）

`NativeDocument::from_core` は、Unity 版に無い機能（ユーザーチャンネル・ノイズとグランジ・色調補正・グラデーションマップの混色・パスの一覧・0.5.0 の効果・点のグラデーション・テキストレイヤー・継ぎ目の設定・ベイクの優先・パスのブラシのアンチエイリアス・定規とパスの線対称）を使う文書だけを新しい版で書く（上）。欄の並び・範囲・古い読み手の扱いは [docs/YLP_FORMAT.md](../../docs/YLP_FORMAT.md) の「document.utpaint」と「版と互換」、選んだ理由は [docs/YLP_DECISIONS.md](../../docs/YLP_DECISIONS.md)。

### 大きな文書（正本の版 26）と大きな .ylp（`YLP-4`）の読み書き

形（分けた正本・`YLP-4` の上限と zip64・古い読み手の断り）は [docs/YLP_FORMAT.md](../../docs/YLP_FORMAT.md)。今の上限に収まるプロジェクトは 1 バイトも変えない（試験は形式 1〜6 の実物のフィクスチャを読んで書き戻し、今の書き手（`Archive::to_bytes`）とバイトまで同じ）。
量の上限は `Limits`（設定の「レイヤーのメモリ」の予算 `load_source_bytes` から）。超えたら、どの予算かを言って（`Error::Budget`。文は `OVER_LAYER_PIXELS_DOCUMENT`・`OVER_LAYER_PIXELS_TOTAL` で、数・セットの ID・上限の導き方は入れない。画面の英語はこの文で見分けて訳す）展開の前に断る。書いたものを読み直して確かめるときは予算で断らない（`Limits::unbounded`）。`Limits::check` は、保存した文書を今の予算で開き直せるかを読み手と同じ数え方で見積もる（アプリは保存の知らせで言う）。開くときの画素の上限は、core に入れる途中で同じ予算が見る（`to_core_within`）。

**書き手の近道**（`YLP-4` だけ。今の形は今の書き手とバイトまで同じにするため、いつも 1 本のスレッドで圧縮し直す）: 同じ中身（長さと SHA-256）の圧縮した
バイト列がファイルにあれば（変わらないエントリ・前の保存の同じ中身の部分）、そのまま写す。4 MiB 以上のエントリは、はじめの 1 MiB を試しに圧縮して 97% 未満に
縮まなければ圧縮しない。縮むものは 1 MiB ずつのかたまりを別々のスレッド（8 本まで）で圧縮して 1 つの Deflate の流れに並べる（pigz と同じ形: 前のかたまりの
終わりの 32 KiB を辞書にし、終わりでないかたまりは Sync の flush でバイトの境目に揃える。出力はスレッドの数に依らない）。写したものも書いた後の読み直しで
長さ・CRC・SHA-256 を確かめる。

**メモリと流れ**: 保存・開く・復旧の書き置きで、core の文書（とその写し）のほかに持つのはレイヤー 1 枚ぶんの並びと小さな作業域だけ（ファイル全体・zip 全体・正本
全体をメモリに作らない）。

- 保存（`SaveTarget::save_with`）は 2 回に分ける: 1 回目に全エントリの長さと SHA-256 を数えて manifest を作る（core の文書から作る正本は、レイヤーごとに作りながら
  数え、読み手でも読み直す）。2 回目に一時ファイルへ流して書く。書いた一時ファイルを流して読み直して確かめ（manifest が書こうとしたものと同じ）、置き換えた後の
  ファイルを指すプロジェクトを `SaveReport::project` で返す（次の保存・書き置きは、変わらないエントリをそのファイルから写す。保存に使った core の文書の写しは
  手放す。外側・移行後のエントリ・セットの正本は向け直した後も同じエントリを持つので、次の作り直しで変わっていない正本の骨組みを読み直さない）。ファイルの印
  （SHA-256）と退避の写しも流して数える。
- 開く: 全エントリを 1 回流して長さ・CRC・SHA-256 を確かめ（分けない正本は、このとき骨組みも読む。版 26 はヘッダーと部分の長さだけ）、`to_core_within` で
  もう 1 回流してレイヤーごとに core の文書へ入れる。
- 復旧の世代（`GenerationStore`）も流して書き・確かめる。中身の SHA-256 が同じエントリ（変わらないセット・変わらないレイヤーの部分）は前の世代と共有して書かない。
  共有の中身は、このツールが流して確かめたあと長さと更新時刻が変わっていなければ、次の確定でハッシュを数え直さない（保証の射程: 更新時刻を変えずに同じ長さで
  書き換える外の書き手は、確定のときには見つけない。開く（`load`）ときはいつも全部を数える）。量の上限は `with_limits(Limits)`（上と同じ数え方）。

**試験の口**: `Thresholds::scoped`（このスレッドの間だけ、今の形の上限・zip64 の閾値・正本を分ける閾値・部分の大きさ・小さなレイヤーをまとめる大きさ・メモリに残す
大きさを小さくする）で、小さな文書のまま大きな形の道を全部通す。読み手の上限（`Limits`）は変えない。

**測定**（`cargo test -p yolu-io --test projects bigdoc::measure -- --ignored --nocapture`、4096²・60 レイヤー（塗り 40・線画 15・雑音 5）・レイヤーの画素 2110 MiB、開発のビルド（このクレートは
opt-level 1）、Linux のコンテナ・32 コア）: 新規の保存 13 s（ファイル 460 MiB。並べて圧縮する前は 53 s）、1 レイヤーを変えた上書き保存 6.8 s、開く 3.4 s ＋ core へ
6.5 s、書き置き 1 回目 5〜11 s（2110 MiB を書く）・2 回目 2.2 s（書いたのは 44 MiB）。保存・書き置きの最大 RSS の増えは 60 MiB 以下（開くは core の文書の分
だけ増える）。

現在のセットのColor合成をPNGにする例（出力先は新規ファイル）:

```sh
cargo run -p yolu-io --example composite_png -- sample.ylp output.png
```

`composite_png(&core)` は下原点のRGBAをPNGの上からの行へ並べ、Unity版 `RgbaPng` と同じ適応フィルター・チャンク配置で出力する。`composite_pngs(&core)` は、どれかのレイヤーが有効にしている標準チャンネル（Height → Normal を作る設定で Height を使っていれば Normal も。Normal は Unity 向けの OpenGL の出力）ごとに同じ形式のPNGを返す。Color は使うレイヤーが無くても含める。Unity版のインポーターは `composite/<チャンネル>.png` の並びからセットのチャンネルを出すので、`SetSpec` にはこれを渡す。flate2のzlibバックエンド（libz-sys）を使う。圧縮結果はdeflate実装の版にも依存し、すべてのランタイム・画像での一致を保証するものではない。
圧縮の流れは 2 通り。`composite_pngs` とアセットの画像（.ylp の中に入る PNG）は 1 本の流れで、バイトは前の版と同じ。`composite_png` とテクスチャの書き出し（`export`）は、フィルターした行の流れが 1 MiB を超えると 1 MiB ずつのかたまりに分けて並べて圧縮し、1 本の zlib の流れにつなぐ（かたまりは前の 32 KiB を辞書に、最後でなければ Sync の flush で終える。Adler-32 はかたまりごとに数えて合わせる）。画素は同じで普通の PNG として読め、バイトはスレッドの数に依らないが、1 本の流れより少し大きい。1 MiB 以下の絵は 2 つの形でバイトまで同じ。

## PSD・PSB

`psd` はUnity版と同じRGB8 PSDコーデック。`psd::Document`・`Layer`・`Mask`・`Adjustment` はcoreの文書に依存しないデータ型で、レイヤーとRGBAの行は上から下。名前、正の一意なPSDレイヤーID、キャンバス外の画素、透明画素のRGBを保持する。

```rust,no_run
use yolu_io::psd::{self, CompatibilityMode, Limits};
let limits = Limits::default();
let origin = psd::read(&std::fs::read("sample.psd")?, &limits)?;
for note in origin.diagnostics() {
    eprintln!("{}: {}", note.code, note.message);
}
if origin.mode() == CompatibilityMode::EditableRaster {
    let mut document = origin.to_core()?; // 変換対象外の情報があれば理由を添えて拒否。
    document.add_layer("新しいレイヤー")?;
    let edited = psd::Document::from_core(&document)?;
    let bytes = psd::write_edited(&origin, &edited, &limits)?;
    // bytesを新規出力または外部改変検知・一時ファイル置換を備えた保存処理へ渡す。
}
# Ok::<(), yolu_io::Error>(())
```

| 要素 | 読み取り・書き出し |
|---|---|
| PSD v1 RGB8、raw / PackBits RLE | 読める。書き出しはraw。統合画像は白背景のRGB＋元の透明度を格納 |
| ラスター、26合成モード、クリッピング、表示・不透明度、Unicode名・ID | 読み書き。ID欠落・不正・重複を名前で補修しない |
| ラスターマスク | 矩形・既定値0/255・有効/無効・濃度・画素を保持 |
| グループ | 入れ子、通過・分離、マスク、グループと区切りのIDを保持。coreのグループへ（入れ子はPSDの予算の32段まで） |
| 調整 | 反転、RGB一括のレベル補正、マスターの色相/彩度。PSDの整数刻みで保持。チャンネル別補正・Colorize等は保護。色調補正6種は `grdm`（グラデーションマップ）・`curv`（トーンカーブ）・`blnc`（カラーバランス）・`brit`＋`CgEd`（明るさ/コントラスト）・`thrs`（2値化）・`post`（ポスタリゼーション）。刻みの間は丸めず断り、グラデーションマップの混色（混色モード・混合率曲線）と値のカーブは、厳密な書き出しでは断り、焼き込みの書き出しでは停止点の列へ展開する（近似。差は書く前の確認のウィンドウに出す）。表せない中身（ノイズ型のグラデーション・点が16を超えるか両端が0と255でないか隣が6刻み未満のカーブ・旧式の明るさ/コントラストなど）は `PreserveOnly` で原本を保持 |
| 単色塗りつぶし `SoCo` | RGBの色を保持。8bit未満の端数は丸めて通知。画素キャッシュを使わないことも通知 |
| レイヤーロック `lspf` | 透明・画素・位置・全体を保持。対応のないビットは通知 |
| 描画に関係しない既知メタデータ、sRGB IEC61966-2.1、1:1ピクセル比 | 編集可能として受理し、書き出しに含まれない情報を `NotCarriedIntoExport` で通知 |
| PSB、RGB8以外、ZIP圧縮、未知タグ・調整、効果、テキスト、スマートオブジェクト、ベクターマスク | `PreserveOnly` と理由を返し、原本全体だけを保持。PSBの復号・新規生成はしない |
| 構造破損・予算超過 | `Rejected`。原本保持上限内なら原本バイトは残る |

`psd::read` / `read_stream` は `ReadResult` を返す。編集可能な場合にだけ `document()` が値を持つ。`original_bytes()` / `copy_original_bytes()` は元のファイル全体で、原本保持予算を超えたときだけ保持しない。未知情報を編集後のファイルへ部分的に継ぎ足す方式ではない。**取り込んだ原本の編集保存には `write_edited` を使う**。`PreserveOnly`・`Rejected` はそこで拒否する。`write` は新しく作ったPSDスナップショット用。

原本コピーはバックアップ・保全のためで、外部で変更されたファイルを上書きする許可にはならない。PSD APIはファイルシステムを操作しない。保存先の外部改変検出・バックアップ・最後の一度の置換は呼び出し側の責務で、.ylp用の `SaveTarget` をPSDには使えない。

`ReadResult::to_core` と `psd::Document::to_core/from_core` はColorの写しを変換する。ラスター・グループ（入れ子、通過・分離）・単色の塗りつぶし・調整（反転・レベル補正・色相/彩度・色調補正6種）・クリッピング・ラスターマスク（有効/無効・濃度）・レイヤーのロック・26合成モード・表示・不透明度が対象。読み込み時にUndo履歴を残さず、PSDのレイヤーIDとグループの区切りのIDはcoreの永続IDに埋め込んで再出力する。同名レイヤーもIDで区別する。並びはUnity版の取り込みと同じ（下から上、グループの中身はグループのすぐ下）。

- `from_core`（coreからPSDへ）: 上の中身をPSDの形で書く。ロックは `lspf` に、透明部分・画素・位置・すべて（`0x80000000` だけで書く）のまま書き、透明部分のロックはレイヤーの記録の印のビット0にも書く。マスクはキャンバスとの差の外接矩形と、矩形が小さくなるほうの既定値（255か0）で書く。レイヤーの合成モードと不透明度はColorでの実効の値（チャンネルごとの設定があればそれ）で書く。PSDが持てない中身は、平らにも黙って落とすこともせず、レイヤーの名前と機能ごとの理由で拒否する: 反転したマスク（PSDに非破壊の反転が無い）、クリッピングされたグループ、半透明の塗りつぶし、PSDの刻み（0〜255の整数・ガンマは1/100・1度・1%。色調補正は位置1/4096・中点1%・不透明度とカーブの点1/255・整数のスライダー）の間にある調整とPSDの範囲外のレベル補正、レイヤーが効くほかのチャンネルの実効の合成がColorと違うもの（PSDのレイヤーは1組しか持てない。効くチャンネルは、明示の設定があるチャンネルと、調整なら有効なチャンネル、グループなら標準のチャンネル。Colorだけがレイヤーの値と違う調整・グループも断る）、Color以外のチャンネルの画素・有効の印・塗りつぶしの値、無効にしたColor（調整はColorで無効なもの）、フィルター・Generatorの段（無効・効いていない段も。効果入りの合成は統合画像だけに入り、レイヤーの画素と食い違うため）、Anchor、パス。調整の効くチャンネルはPSDに持てないので書かず、読み込み直すと効く標準のチャンネル全部に効く調整になる（Unity版の取り込みと同じ）。`psd::export_blockers(&document)` は断るレイヤーと理由（`Refusal`）を全部返し、画面が画面の言語で言い分けるために使う（`from_core` は日本語の診断で初めの1つを返す）。
- `to_core`（PSDからcoreへ）: 上の中身をcoreのレイヤーにする。キャンバス外の画素・キャンバス外にある既定値と違うマスクの値は、切り捨てずに拒否する（`core_issues()`）。レイヤーのロック（lspfのビット0・1・2・31）はcoreのレイヤーのロックへ入れる（`set_locks_for_load`。読み込みの最後に付け、履歴を残さない。`from_core` の逆で、すべては個別のビットを足さない）。`.ylp` にも書ける（版12の並び）ので、取り込みは外さず断らない。

coreからの出力矩形はタイルの範囲になり、不透明度は最も近い1/255へ丸める。原本の圧縮や矩形までバイト一致で戻すAPIではない。

既定の `Limits` は原本・出力各128 MiB、寸法8192、キャンバス16,777,216画素、256レイヤー記録（区切りを含む）、復号256 MiB、メタデータ4 MiB、名前4096 UTF-16単位、診断128件、グループ32段。`write`（厳密な書き出しの無圧縮の書き手）は確保前に構造・画素・出力長を検証する。`read` は全体をメモリで扱うため、ストリーミング型の大規模文書向けではなく、これらはプロセス全体の使用メモリの保証ではない。実物の大きさの書き出し（下）の上限は、`Limits::for_export(budget)` が呼び手の予算（アプリでは設定の「レイヤーのメモリ」）から決める。

`read` は統合画像を参照合成と比較する。通常合成だけで大きく違えば編集を止め、合成モード・マスク・グループ・調整等があれば `CompositeDiffers` で見え方の差を知らせる。参照合成はYoluPainterの式であり、Photoshop/CSPの見え方の再現を保証しない。色調補正6種の参照合成もcoreの式をそのまま使うので、この比較はPSDへの書き込みと読み込みの食い違いを見るもので、PhotoshopやCLIP STUDIOの式との独立した照合ではない（書き出した統合画像はこのツールの式の結果で、Photoshopが調整レイヤーを再評価すると見た目が変わりうる）。再生成・検証の条件は [PSDフィクスチャ](tests/fixtures/psd/README.md) を参照。

### 実物の大きさの書き出し（`ExportPlan::write_psd`・`psd::verify_stream`）

焼き込みの書き出し（`plan_export` → `ExportPlan`）には、メモリに全レイヤーを作る `build` のほかに、レイヤーを 1 枚ずつ流して書く `write_psd(&document, &ctl, &mut out, compression)` がある。`out` は `Write + Seek`（書き始めが先頭）。先にヘッダーと全レイヤーの記録（矩形・チャンネルの長さは仮の値）を書き、レイヤーの画素を PSD の記録の順に 1 枚ずつ評価して圧縮して書き（書いたらすぐ捨てる）、レイヤーを書き終えてから統合画像を作って書き、最後に先頭へ戻って確定した記録を書き直す。メモリにはレイヤー 1 枚ぶんと記録の表しか持たず、全レイヤーの画素の合計に上限が無い（Normal の焼き込みと平らの 1 枚は、統合画像を書いたレイヤーから作る・1 枚のレイヤーそのものなので、全レイヤーをメモリに組み、合計を予算で止める）。`ExportControl` は取消の旗と `source_budget`（設定の「レイヤーのメモリ」。レイヤーの記録は予算 1 MiB につき 1 件で 256〜32767 件、キャンバスは予算に入る範囲、辺は 30000、`None` は C# と対の固定の上限）と `max_file_bytes`（既定と上限は PSD の 2 GiB。圧縮したあとの大きさを書きながら見る。全レイヤーをメモリに作る道も同じ）を持つ。予算・形式の上限で書けないときは `ExportError::Overrun(Overrun)`（キャンバスの画素の数・辺の上限・レイヤーの記録の件数と上限・レイヤーの名前つきの予算超過・2 GiB）で、画面が種類から言語ごとの文を作る。`Written` は書いたバイト数・レイヤーの数と、書いたバイト列の照合用の `Checksum`（先頭の書き直しの前後を考えて、先頭と後ろを別々に数えた CRC-32 と長さ。`Checksum::matches(&mut reader, cancel)` で、読み戻したファイルが書いたとおりかを確かめる）を持つ。書きかけを消すのは呼び手の仕事。

圧縮は `Compression::Raw`（Unity 版とバイト一致。`write`・厳密な書き出しはこれ）か `Compression::Rle`（PackBits。レイヤーとマスクは 1 チャンネルずつ、圧縮して小さくならなければ無圧縮。統合画像は全体で 1 つ）。メモリ上の文書は `write_with(&document, &limits, compression)` で書ける。

`psd::verify_stream(&mut reader, cancel)` は、書いた PSD を最後まで流して読み戻して確かめる。`import_copy` と同じ読み手（レイヤーの記録・チャンネルの復号・統合画像の読み）を通すが、core の文書は作らないので、焼いた画素が文書の予算を超えても確かめは止まらず、メモリは圧縮したチャンネル 1 本ぶんと統合画像 1 枚（レイヤー・マスクのチャンネルは画素を持たずに行を展開して確かめる。ZIP のチャンネルだけ面 1 枚）。ヘッダーの寸法は PSD の上限 30000 まで、統合画像の場所はファイルの残りがその圧縮の最小の長さを満たすときだけ取る（化けた寸法の大きさを先に確保しない）。全レイヤー・マスク・統合画像のすべての行の復号（行は並べて展開する。統合画像は面 1 枚ぶんの圧縮したデータをまとめて読む）、記録の長さとデータの長さの一致、ファイルの終わりが統合画像の終わりであること、取り込みで落とす・変わるものが無いことを確かめる（書いた画素が文書の画素と同じかは見ない。書いたバイト列との一致は `Checksum::matches`）。読み戻しと照合を 1 度の読みで行うときは、読み手を `Checksum::recount(reader)`（`Recount`）で包んで `verify_stream` に渡し、そのあと `Recount::finish(cancel)` で照らす（読み戻しが読んだバイトをその場で数え、飛ばした区間と残りだけを読み足す。`psd::check_written` はこの形）。

### 写しとしての取り込み（`psd::import_copy`）

原本を保つ読み（`read`）は、PSDの情報を黙って捨てないために、編集できない中身が1つでもあれば原本の保持だけにする。元のPSDへ書き戻さない使い方（アプリの読み込み）には、別の入口 `import_copy(&mut reader, &CopyOptions { source_budget, cancel })` がある。`Read + Seek` から流して読み、原本のバイト列は持たない（付加情報はレイヤーごと・タグごとに読んで捨て、レイヤーの画素は1枚ずつ復号してcoreへ入れてすぐ捨てる）。原本の保持の上限（128 MiB）は掛からず、レイヤーの数・キャンバス・レイヤーの画素・レイヤー1枚の付加情報の上限は呼び手が渡す `source_budget`（アプリでは設定の「レイヤーのメモリ」）から決まる（レイヤーの数は予算1 MiBにつき1枚で256〜32767枚）。結果は `CopyOutcome` で、取り込めない理由（`CopyRefusal`: PSB・RGB8以外・予算を超える・壊れている・レイヤーなし）か、coreの文書と知らせ（`ImportNote`）。

知らせは、機能（`ImportFeature`）と扱い（`ImportAction`）ごとに1件で、当たったレイヤーの名前（初めの8枚）と数が付く。**無視**（見え方にも内容にも効かない情報）・**落とす**（レイヤーの画素は残すが、その機能の設定・元のデータは持たない。画素を持たない未対応の調整はレイヤーごと）・**変わる**（評価できない効果など、合成がPSDの統合画像と変わり得るもの。レイヤーの画素のまま取り込む）に仕分け、表は [docs/PSD.md](../../docs/PSD.md)。レイヤーIDは、欠落・重複・不正のレイヤーだけに、名前では補修せず新しいIDを振る（有効で一意なIDは並びによらず変えない）。取り込んだ文書の合成は、行の帯ごとにPSDの統合画像と照らして、最大の差と差のある画素の数を知らせる。`read` のように通常合成の大きな差で取り込みを止めることはせず、差は知らせるだけにする（キャンバスが予算に比べて大きいとき、統合画像が無い・読めないときは照らさず、その旨を知らせる）。読む圧縮は raw・PackBits RLE・ZIP・予測つきZIP。

## ブラシ形式の取り込み

`brushes` は他のアプリのブラシのファイルを core のブラシ（`yolu_core::Brush`）にする。アプリへの口は 1 本で、メモリ上のバイト列からは `import_bytes`。

```rust,no_run
use yolu_io::brushes::{import, Unrepresented};

let set = import(std::path::Path::new("chalk.abr"))?;
for brush in &set.brushes {
    // brush.brush は core のブラシ。筆先・質感の画像は Arc で共有する（同じ筆先を使うプリセットは同じ画像を指す）。
    for note in &brush.unrepresented {
        println!("{}", note); // 表せなかった設定（note.english() は英語）
    }
}
# Ok::<(), yolu_io::brushes::BrushImportError>(())
```

| 形式 | 読めるもの | 断るもの |
|---|---|---|
| GIMP `.gbr` | 版 1・2・3。グレーと RGBA（アルファだけを筆先にして注記）。間隔は直径（長い辺）に対する割合に直す | 16 bit 浮動小数点（CinePaint）、署名・ヘッダーの食い違い、名前が 256 バイトを超えるもの |
| GIMP `.gih` | 画像ホース（1〜256 セル。セルごとに大きさが違ってよい）。`sel0` が `incremental` なら順番、`random` ならランダム（`sel0` が無いときは、`dim` があればランダム、無ければ順番）。筆圧・角度・速さ・傾きの選び方と多次元の並びは近似して注記。ファイルのセルが宣言より少なければ、あるだけで使って注記 | セルの途中で切れているもの |
| GIMP `.vbr` | 版 1.0・1.5。円は丸い筆先、正方形・ひし形・スパイクは筆先の画像に描く（縁は GIMP と少し違うことがあるので注記） | 64 KiB を超えるファイル（読み込む前に断る）、スパイク 21 以上、範囲外の数、知らない形・版 |
| Photoshop `.abr` | 版 1・2（計算で描くブラシ、画像の筆先、PackBits）、版 6〜10 の筆先（`samp`）とプリセット（`desc`）。ゆらぎ・散布・筆圧・フェード・ペンの傾き・回転・方向・色の変化・デュアルブラシ・質感（模様は ID だけで対応づけ、名前では対応づけない。合わせ方 8 種・拡大・反転）・筆先の反転 | 版 3〜5 と 11 以降、知らない記録、16 bit の圧縮された筆先、プリセットのない空のファイル |
| Photoshop `.pat` | グレー・インデックス・RGB・16 bit の模様を、深さ 1 の質感を持つ丸いブラシにする | CMYK・Lab・ビットマップ・ZIP 圧縮・1 辺が 2048 を超える模様（理由つき。使える模様が 1 つも無ければ全体を断る） |
| PNG | 暗いほど塗り、白と透明は塗らない（被覆率 = (1 − 輝度) × アルファ）。グレー・グレー+アルファ・RGB・RGBA・パレット・tRNS・1〜16 bit | 1 辺が 2048 を超える画像（画素を読む前に断る） |
| CLIP STUDIO `.sut` | SQLite のサブツール。ブラシの名前、筆先と質感の画像（素材の独自の入れ物 C2F の原寸の画像。読めなければ素材のプレビューの PNG）、大きさ・不透明度・流量・硬さ・間隔・真円率、筆圧の影響（最小値と曲線）、傾きの影響（大きさ・不透明度・流量へ。曲線は直線に近似）、入り抜き（大きさへ。画素）、手ぶれ補正、筆先の角度と角度のランダム（写せた設定は `ImportedBrush::mapped`）。色の混ぜの旗だけのもの・吹き付け・デュアルブラシ・色の変化・合成モード・速さとランダムの影響・向きの筆圧/傾き/速さの影響は注記。サブツールのフォルダを探して一覧にする部分は `brushes::clipstudio`（読むだけ）。形と確かめた範囲は [docs/BRUSH_IMPORT.md](../../docs/BRUSH_IMPORT.md) | SQLite でないもの、ブラシの表（`Node`）が無いもの、読めるブラシが無いもの、128 MiB を超えるファイル、読み取りの上限（命令の数・経過時間・展開する画素）を超えるもの |
| `.kpp`（Krita のプリセット）・その他 | — | 理由つきで断る |

**表せない設定は捨てない。** 元のアプリにあって core のブラシで表せないもの（最小の直径、ノイズ、ウェットエッジ、描点ごとのテクスチャ、数のゆらぎ、1 軸だけの散布、筆圧以外のコントロールの一部、デュアルブラシの反転、色つきの筆の色など）、近似したもの（ホースのセルの選び方、スパイクの形、グレーへの変換）、読めなかったものは、`Unrepresented` に型で載る。そのブラシの設定のものは `ImportedBrush::unrepresented`、ファイル全体のもの（読めなかった設定の節・模様の節、読み飛ばした節、`.pat` の使えなかった模様）は `ImportedSet::notes` に 1 回だけで、ブラシごとには複製しない（ブラシの数との積で増えるため。画面でも無関係なブラシに他の模様の失敗が並ばない）。文は種類と値から画面が言語ごとに作る（`Display` は日本語、`english()` は英語）。プリセットの形が壊れて取り込めなかったものは `ImportedSet::skipped` に理由つきで載る（ABR の C# 版は黙って読み飛ばしていた）。core の拡張（筆先の反転・ペンの軸の回転・質感の合わせ方 8 種）は、C# 版が「未対応」にしていたものも写す。背景色はブラシに入っていないので、色の変化の `secondary` は取り込みでは触らない。

**信頼できないファイル。** ダウンロードしたブラシを読む前提で、パニックせず、数や長さの宣言で先に確保しない。ファイルは 256 MiB まで（`.sut` は 128 MiB、VBR は 64 KiB まで。読む前に断る）、展開する筆先・模様の画素の合計は 256 MiB まで（PackBits は 2 バイトで 128 画素へ展開できるので、小さなファイルが巨大な画像になる形を予算で断る。質感の「反転」で新しく作る画像も、模様ごとに 1 つを共有して予算から引く）、筆先・模様の個数は 1 万まで（ABR の版 6 以降の筆先と模様の節も。画素 1 つの筆先は画素の予算では止まらない）、記述子は深さ 32・値の数 100 万まで。ファイル全体の注記に並べる知らない節の種類は 64 まで（残りは節の数を 1 つの注記で知らせる）。有限でない数（NaN・無限大）のある設定の節は読めないものとして、筆先だけを注記つきで取り込む。名前は制御文字を除いて 128 文字までにし、節のキー・型名など形式の印は制御文字を `?` にして、画面の文に制御文字が入らない。画面の文にはオフセットなどの内部の数を出さない（`Fault` の値には残る）。壊れ方は全バイトの書き換え・全長での切り詰め・極端な値・挿入と削除・ゴミ入力で試す（`tests/brushes/brush_import_hostile.rs`、約 25 万通りに `.sut` の約 32 万通りが加わる）。`.sut` は SQLite をメモリの上の読み取り専用で、防御モード・長さと命令数と時間の上限つきで開き（拡張を読み込む関数は有効化せず、SQL の `load_extension()` は断られる）、決まった表と読む列だけを問い合わせる（`src/brushes/sut/db.rs`）。素材の C2F は SQLite 本体を通さず自前で読み（`src/brushes/sut/c2f.rs`。塊の数・行の大きさ・木の深さ・画像の大きさに上限を置き、作る行の大きさ（256 MiB）と展開する画素（256 Mi 画素）は 1 つの `.sut` の取り込み全体の合計で縛り、標準の展開器で開けなかった先頭の塊は読まない）、壊れていれば・合計を使い切ったあとなら素材の画像は無いものとして扱う（壊し方は `tests/brushes/brush_import_sut_layer.rs` の約 3400 通りと、上限・断りの理由ごとの試験）。

**Unity 版（C#）との照合。** `tests/brushes/brush_golden.rs` は、手で作った 88 事例、同梱の Krita の GIMP 形式の実ファイル 37 個、手で作った事例を壊した約 1.1 万の入力を C# の読み手（`Runtime/Core/Brushes`（Unity ブリッジのタグ 0.4.0。0.5.0 で外れた））に通した結果（`tests/fixtures/brushes/`、`tools/csharp-golden/brushes.sh` で作る）と比べる: 取り込めたか・断ったかと、取り込んだ設定（数値は全ビット、筆先・質感・デュアルの画素は指紋）が同じ。C# が検証の例外で落ちる入力（NaN の筆の大きさなど）と、有限でない数のある設定の節は比べない。PNG の筆先は Unity のエンジン（`Texture2D.LoadImage`）を通り Core の外なので、同梱の PNG 39 個の被覆率を別の復号器（Pillow、`tools/brush-fixtures/png_tips.py`）で同じ式に通した指紋と比べる（`tests/brushes/brush_bundled.rs`）。Unity のエンジンそのものとの照合はしていない。

**同梱の筆先。** `brushes::bundled::krita4()` は Krita 4 の既定の筆先 76 個（CC0 1.0。原本のバイト列と出どころ・SHA-256 は葉のクレート `yolu-brush-sets`）を、取り込みと同じ読み手でブラシにする（半径を 4〜40 に収め、筆圧で不透明度は変えない）。原本のまま `include_bytes!` で持つ: 11.5 MB で、実行ファイルでは使わなければ読まれず、インストーラーの圧縮で配布の増分は 4 MB ほど。別のクレートにしたのは、`yolu-io` を再ビルドするたびにデータを読み直さず、`yolu-io` の rlib に混ぜないため。

## リソースと未対応の中身

画像はRGBA8のPNGを復号し、寸法と下の行からの画素ハッシュを検証する。スマートマテリアル・スマートマスク・マテリアル・ブラシは埋め込まれたファイル全体を保持する。内側のmanifest、正本、種別、チャンネル、画像、ブラシのschema・画像参照も検証する。

ブラシ設定の描画上の意味、.ylp内のPSD原本・合成PNG・メッシュマップ・画面設定の自動復号は未実装（効果の実行は core の `Document` が行い、メッシュマップと画像は `Document::set_effect_inputs` で渡す。画像リソースからの入力は `Project::image_inputs`）。PSD単体は上記のAPIで読み書きできる。これらは読み飛ばして破棄せず、原本のエントリとして残す。`notes()` を呼び出し側の画面に提示できる。画像リソース以外のPNGをすべて復号するAPIではない。

形式9以降、正本の版34以降と欠番の31、未知の列挙値・アルゴリズム版は理由を添えて断る。暗号化・分割ZIP、RGBA8以外のリソースPNGは扱わない。ZIP64 は `YLP-4` だけ。今の形（`YLP-3` まで）は1エントリ512 MiB・展開総量768 MiB・1000エントリ、`YLP-4` の上限は下の「大きな文書」。復号リソースは768 MiBまで。メモリに全部載せて読む正本（`NativeDocument::read`・`from_core`）は512 MiBまで。これらはデータ量の上限であり、プロセスの最大メモリ使用量の保証ではない。

## 保存

`SaveTarget::open`（既定の予算）・`open_within(path, limits)` はファイルを流して開き、SHA-256・長さ・更新時刻を記録する（読む間に長さか更新時刻が変われば断る）。外部の書き換えは内容（SHA-256と長さ）で見分け、更新時刻だけが変わった（同期ツールなど）ものは書き換えとして扱わない。`create` は新規保存専用。保存では、ディスクに触る前に全エントリを数えて確かめ（1 回目）、保存先と同じフォルダの一時ファイルに流して書いて `sync_all`、読み直して検証、外部改変を再確認してから `rename` で一度だけ確定する。置換に失敗しても削除してから移動する手順には切り替えない。変わらないエントリは開いたファイルから流して写す。そのために、開いた .ylp のハンドルを持ち続け（大きなエントリだけ。全部が小さければ開いた後は閉じる）、パスでは開き直さずに、ハンドルから位置を指定して読む（Unix は `read_at`、Windows は `seek_read`。ファイルのカーソルを使わないので、何本読んでも互いの位置を動かさない）。標準の開き方で持つ（Windows でも、Rust の標準ライブラリの既定は読み・書き・削除を共有する）ので、開いている .ylp を外で改名・移動・削除しても、POSIX の置換（別のファイルを同じ名前へ `rename`）や OneDrive などの置き換えをされても、ハンドルは開いたときの中身を読み続ける: 別名の保存は、外で何をされても開いたときの中身から書ける（外のファイルには触らない）。これは Linux で試験により確かめている。Windows（NTFS）でも、標準ライブラリの共有の既定と `fs::rename` の動きからそうなる想定で作ってあるが、実機の Windows では確かめていない。同じ名前への上書きは、保存先が消された・中身が変わったと断る（外の変更を黙って潰さない）。同じファイルを外で同じ場所のまま書き換えられた（上書きコピーなど）ときは、読むたびの長さ・SHA-256・CRC の確かめで、壊れたエントリとして断る。保存の確かめで開いた一時ファイルのハンドルは、置換のあと、そのまま保存後の置き場になる（置換のあとにパスで開き直さないので、確かめたファイルそのものを読み続け、置換から開き直しまでの間に差し替えられる競合も無い。`SaveReport::project`）。

置換が、このプロセス自身の開いたハンドルのせいで通らないことがある: 置換の規則が POSIX でないファイルシステム（FAT・exFAT・一部のネットワーク共有）。NTFS では外のツール（ウイルス対策・同期）が掴んでいるのが普通の原因で、自分のハンドルは置換を妨げない想定（実機の Windows では確かめていない）。置換が共有違反・アクセス拒否になったときは、まず自分のハンドルを手放さずに 0.3 秒待ってやり直す。その間に通れば、保存前のプロジェクトの写しは読めたまま。通らないときだけ、このプロセスが開いている保存先のハンドルを手放して残りの待ちでやり直し、置き換えられなければ掴み直す（開いたときと長さが同じファイルだけ。中身は読むたびの確かめが見る）。置き換えられたなら手放したまま: 保存前のプロジェクトの写しは、読もうとすると `SOURCE_RELEASED` で断る（保存した後のプロジェクトは新しいファイルから読める）。原因が外のツールでも、0.3 秒を超えて掴まれていれば同じく手放す（原因は見分けられない）。アプリは、開いたファイルを置き換える保存の前に復旧の書き置きの終わりを待ち、配布用に保存の写しがある間は保存しない（その読みは保存前のプロジェクトのハンドルを使うため）。

Windows の置換（上書き・新規・退避の移動）は、共有違反・ロック違反・アクセス拒否のときだけ短くやり直す。同期のツール・ウイルス対策が一時的に保存先や一時ファイルを掴んでいるときの失敗で、たいてい 1 秒以内に手放される。待ちは 10・20・40…ms と倍にして 300 ms で頭打ち、合計 1.5 秒で諦めて本当の失敗として返す（上書きは、最初の 0.3 秒は上の自分のハンドルを手放さずに待つ。保存は呼び手のスレッドで回る）。アクセス拒否は本当の権限の不足でも出るが、そのときは待っても通らず同じ失敗を返す。Unix は開いているファイルに妨げられないので、やり直さない。

直前の版は `<ファイル名>-backups~/` に `<名前>-<UTC の時刻（ミリ秒）>.ylp` の名前（Unity版と同じ）で退避する。同じ時刻の退避があるときと時計が戻っているときは下線を足し、名前の順がいつも新しい順になる。`backup_origin(path)` は、退避のフォルダーの中の退避ならそれを作った元のファイルの場所を返す（利用者が名前を変えて置いたファイルや別のファイルの退避は `None`）。保持数は呼び出し側が `BackupKeep`（すべて・N・0）で決め、既定はすべて残す（`save`）。`save_with` は整理の結果を `SaveReport` で返す。0 は退避しない（すでにある退避は消さない）。整理は置換で確定した後だけで、この文書の退避を新しい順に、今回の退避を含めて N 件になるよう古い方を消す。利用者が名前を変えて残したファイル・別の文書の退避・フォルダーやリンクは数えず、消さない。消せなくても保存は成功のままで、消せなかったものと理由が `prune_failures` に載る。以前の版がSHA-256名で退避したものは、最も古い退避として数える（互いは更新時刻の順。名前に順が無いので、同期やコピーで更新時刻が変わると古い順は保証しない）。退避は最後の確かめの後・置換の直前に作り、置換まで届かなかった保存は、作った退避（と作ったフォルダー）を消す。写しは一時の名前 `.<ファイル名>.<pid>-<番号>.pending~`（退避のフォルダーの中）へ書いて同期し、中身を確かめてから最終の名前へ置き換えない移動で移す（強制終了された保存が一時の名前の写しを残しても、退避として数えず、保持数の枠を取らない）。退避は保存先とは独立したバイト列の写しで、ハードリンクにはしない。前の版の置き場が普通のファイルやシンボリックリンクで塞がれていれば、保存先に触らず `SaveConflict` で断る（プロジェクトのデータの不正とは言い分ける。退避しない設定では置き場に触らない）。保存先が開いたあとに消されていれば、外部の変更として断り、無いファイルの代わりに書き始めない。

新規の保存先（`create`）は、名前が `.ylp`（大文字小文字は問わない）で終わっていなければ、ディスクに触る前に断る（`SaveConflict`。開いたファイルの名前が違っても `open` は読めるが、保存は断る）。保存先のフォルダーはなければ保存のときに作り、保存が確定しなかったときは、作った空のフォルダーだけを消す（もとからあるフォルダーと、他のものが入ったフォルダーは消さない）。最後は置き換えない移動で確定する: 確かめてから移すのではなく、移す操作そのものが、先にあれば断る。Linux（glibc）は `renameat2` の `RENAME_NOREPLACE`、それが使えない場所とほかのUnixは `hard_link` してから元の名前を消す（消せなくても保存は確定済みで成功とし、残った一時ファイルは保存の後始末が消し直す）、Windowsは `MoveFileExW` を置き換えのフラグなしで呼ぶ。どれも使えないファイルシステム（FAT系・一部のネットワーク共有など）では、ロックの使えない場所と同じく断らずに、もう一度確かめてから置き換える移動で確定する（その間に外から作られる競合は防げない）。外から先に作られていたものは上書きせず、そのまま残す。上書き保存は置き換える移動のままで、直前までの印の確かめが守る。

保存は保存先ごとに1つずつで、`.<ファイル名>.save.lock~` を開いてOSの排他ロックを持つ。別の保存が持っていれば `SaveConflict`（進行中）で断り、そのファイルは消さない。ロックはファイルがあるかではなくロックを持っているかで決めるので、クラッシュで残ったファイルは次の保存を止めず、終わると消える。ロックが使えないファイルシステム（ロックを取る操作そのものが失敗する所）では、C#（.NET の FileShare.None）と同じく排他なしで続ける（断るとその場所へ保存できなくなる）。そこでも置換の前の印の確かめは働き、ロックのファイルは終わると消える。置換の後の失敗は失敗として返すが、新しい版は確定していて（`stamp()` も新しい版）、次の保存はそのまま通る。非協調プロセスが最後の検査と置換の間に書く競合と、電源断時のディレクトリ永続性は保証の対象外。

保存の一時ファイル `.<ファイル名>.<pid>-<番号>.pending~` と退避の一時ファイルは、保存が強制終了されると（`Drop` が走らない）残る。排他ロックが取れた（この保存先へ保存している者は他にいない）保存だけが、同じフォルダにある、この保存先の形（`.<ファイル名>.<数字>-<数字>.pending~`）のものを、自分の一時ファイルを作る前に消す。退避のフォルダーの分は、退避を作る保存（保存先に前の版があり、退避しない設定でない）だけが、置き場が本物のフォルダーのときに、退避を作る前に消す。別の保存が進行中のとき・ロックの使えないファイルシステム（誰も保存していないと確かめられない）・別の保存先の一時ファイル・利用者のファイル・退避しない設定の置き場・シンボリックリンクや普通のファイルで塞がれた置き場には触らない。消せなくても保存は続ける（次の保存でやり直す）。ファイル名が 200 バイトより長いときは、一時ファイルの名前（OS の上限 255 バイトを超えないように）と、この見分けの `<ファイル名>` を、先頭を切って全体の FNV-1a（16 桁）を付けた名前にする（先頭が同じ別の長い名前の一時ファイルと取り違えない）。一時ファイルとロックのファイルは、Windows では隠し属性つきで作る（先頭の `.` では隠れないため）。隠し属性は置換の直前に外す（付けたまま移すと、保存した .ylp が隠しファイルになる）。

## 書き出し（テンプレートとパディング）

`export` は書き出しのテンプレート（`yolu_core::export`。Unity Standard / URP Lit・HDRP Lit・lilToon）の画像をフォルダへPNGで書く。ファイル名はUnity版と同じ `<名前>[_<セット名>]_<接尾辞>.png`（セットが複数のときだけ `_<セット名>`。使えない文字は `_`）。

```rust,no_run
use yolu_core::export::ExportTemplate;
use yolu_core::padding::Reach;
use yolu_io::export::{write_template, PaddingSpec, SetExport, WriteOptions};

# let (document, coverage): (yolu_core::Document, Vec<bool>) = unimplemented!();
let report = write_template(
    std::path::Path::new("out"),
    &ExportTemplate::unity_standard(),
    &SetExport {
        stem: "Texture",
        set_name: None,
        document: &document,
        occlusion: None,
        padding: Some(PaddingSpec { coverage: &coverage, reach: Reach::Fill }),
        max_working_bytes: 1 << 30,
    },
    &WriteOptions::default(),
)?;
for image in &report.written {
    // Unityの取り込み設定は書かない。ここで渡す。
    println!("{} srgb={} normal_map={}", image.file_name, image.srgb, image.normal_map);
}
# Ok::<(), yolu_io::export::ExportError>(())
```

- 書く画像は、読むものがある画像だけ（`should_write`）。使っていないチャンネルしか読まない画像は書かず、`skipped` に接尾辞を返す。
- 手順は、(1) 名前・大きさ・上書きを確かめる、(2) 画像を1枚ずつ作って隠しの一時ファイルへ書き、`sync_all` して読み戻し、RGBAが一致することを確かめる、(3) 全部が済んでから1枚ずつ `rename` で置き換える。(2) までに失敗・取消すれば元のファイルは1つも変わらず、一時ファイルも残らない。(3) の途中の失敗だけ `ExportError::Partial` で済んだ分を知らせる（新しく作った分は消す）。
- 既にあるファイルは、既定では置き換えず `WouldReplace`（何も書かない）。`existing_files` で見せて確かめてから `Overwrite::Replace`。置き換えない設定では `hard_link` で置くので、調べた後に他のプロセスが作ったファイルも上書きしない。フォルダ・リンクは置き換えない。
- 複数のテクスチャセットは `plan_template` で書く画像とファイル名を出し、`clashes` で名前の重なりを確かめ、`write_images`（中身は呼び手の関数から1枚ずつ）で全部を1回の手順にする。
- 画像の中身は1枚ずつしか持たない。上限は1辺8192（Unity版の `RgbaPng` と同じ）。PNGは `composite_png` と同じエンコーダ（行ごとの適応フィルター、1 MiB を超える行の流れはかたまりに分けて並べて圧縮。圧縮バイトはdeflate実装の版に依存）。
- Unityのインポートの設定（sRGB・ノーマルマップ・アルファを透明度に）はファイルに書かない。`WrittenImage` の `srgb`・`normal_map`・`alpha_is_transparency` を後で使う。
- 取消は `WriteOptions::cancel` の旗（置き換えを始める前まで）。塗り広げの途中でも旗を見て、どこで止まっても `ExportError::Cancelled` で返る。

## そのほかの口

- `atomic`: 一時ファイルへ書いて最後の 1 回の置換で確定する書き込み（設定・ブラシ・プリセット・素材・キャッシュ・ダウンロード）。一時ファイルは置き先と同じフォルダの `.{ファイル名}.{pid}-{通し番号}.pending~`（ファイル名が 200 バイトを超えるときは、先頭を切って指紋を付ける）、書いたら `sync_all`、置換は `rename` で、Windows の共有違反・ロック違反・アクセス拒否のあいだは合計 1.5 秒までやり直す。失敗したら一時ファイルを消し、置き先は前のまま。
- `psd::write_verified`: 検証つきの PSD の書き出し。同じフォルダの一時ファイルへ流して書き、同期し、最後まで流して読み戻して確かめ（`verify_stream`）、書いたバイト列と CRC-32・長さで照らしてから確定する（置き換える `rename`、または「あれば失敗」の `hard_link`）。読めない・書いたものと違う PSD は確定しない。
- `library`: 個人のライブラリ（プロジェクトをまたいで使う素材のフォルダ）の読み書き。PNG・`.ylsmart`・`.ylbrush`・`.ylmaterial` を拡張子で見分け、フォルダの外のファイルは一覧・読み・書き・消しの対象にしない。
- `distribution`: 配布用の写し。開いている .ylp から、取り込んだ PSD の原本・どのレイヤーにも使われていないアセット・モデルの場所（`pose.json`・Live Link で開いたモデルの記録 `livelink.json` を含む）・焼いたメッシュマップ・Unity のマテリアルの値・知らないエントリ・アセットの出どころの道（テキストレイヤーのフォントのファイルの場所はファイル名だけ）などを種類ごとに除いた写し（`Project::distribution_inventory`・`Project::for_distribution`・`Removal`）を作る。作業用のファイルは変えない。
- `fonts`: OS に入っているフォントの一覧（`fontdb`）と、テキストレイヤーのフォントを探す決まり（覚えた場所は絶対の道のときだけ使い、ファイル名だけ・相対の道は名前で探す。形は [docs/YLP_FORMAT.md](../../docs/YLP_FORMAT.md) の「テキスト」）。
- `livelink`: Live Link の相手の文書（根の `livelink.json`）の検査（大きさ・JSON のオブジェクト・`format`）。中身はアプリが読む。

cargo test --workspace

レイヤーの種類・チャンネルの正本は、C#の実際の書き手が作った文書と、coreにして書き戻した正本の全バイト一致、全チャンネルの合成とNormalのファイル出力の全バイト一致で照合する。Rustが書いた正本は、C#の読み手に読ませた結果を記録して固定する（版21は読めて、書き直すと同じバイト列になり、全チャンネルの合成が一致する。版22は断られる）。フィクスチャの対応範囲と再生成方法は [fixtures/README.md](tests/fixtures/README.md) を参照。
