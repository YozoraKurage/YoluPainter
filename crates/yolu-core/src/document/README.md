# 文書のレイヤーの操作

`Document` の編集は単独の書き手から行います。ストローク中は構造の編集・変形・サイズ変更・Undo/Redo を断ります。

- `set_layer_locks` / `change_layer_locks`: 透明部分・画像・位置・すべてのロック。親グループのロックも効きます。拒否は `CoreError::LayerLocked` に対象とロックの持ち主を返します。
- `topmost_of`: 複数選択の重複と、選んだグループに含まれる子を除きます。削除・複製・表示・移動・一段移動は複数でも一回の Undo です。
- `transform_layer` / `transform_layers`: 全チャンネルとマスクを移動・回転・拡大縮小します。選択範囲があると、その部分だけを持ち上げ、選択範囲も同じ段で移動します。`transform_layer_region` は明示範囲との交差を移し、選択範囲自体は動かしません。
- `resize_image`: 最近傍・双線形・面積平均で画像と選択範囲を変更します。透明画素の RGB と法線の正規化を保ち、Height → Normal の強さを縮尺に合わせます。`resize_canvas` は画素を補間せず、指定位置へ置いてキャンバスの外を切り落とします。どちらも `ResizeReport` を返し（縮小で外れた覚えた選択範囲の数は `dropped_saved_selections` に、履歴を消す呼び手が知らせられるよう文でなく数で挙げます）、レイヤー・マスク・選択範囲を同じ道（タイルごとに、読む元が無ければ飛ばし、全部が同じ一様な色なら計算せず埋める。まとまりごとに取消を確認）で作ります。効果とパスは次のとおりに動かします: `resize_image` はぼかし・シャープの半径を縦横の倍率の幾何平均に合わせ（上限へ収めた分は報告に書く）、2D のパスは点とブラシの半径を合わせて描き直します（C# の `Resampled` と同じ）。モデルの上のパスは残り、`ResizeReport::surface_path_layers` にレイヤーを挙げます。`resize_canvas` は 2D のパスの点を画素と同じだけずらして描き直し（C# に対応する操作は無く、Rust 独自の決めです）、半径は変えません。どちらも、新しい大きさで段の到達半径・作業メモリが上限を超えるなら何も変えずに断り、評価のキャッシュは全部捨てます。`resize_image` の失敗しうる前半（結果の写しを作る）は `prepare_resize_image`、後半（1 回の Undo の段として入れる）は `commit_prepared_resize` に分けて使えます。複数の文書を「全部変えるか 1 つも変えないか」で変えるとき、先に全部を準備すれば、途中の文書が予算で断られても、先の文書の履歴（Undo・Redo）を積んだり落としたりしません。準備のあとに文書が変わった・別の文書のものを入れるのは、何も変えずに断ります。
- `merge_down` / `merge_visible` / `merge_group` / `merge_layers`: 結合した結果と元の合成を比較し、許容差を超える場合は拒否します。`LayerMergeReport` は比較・変化した画素数と最大の保存値の差・見える差を返します。許容差の既定相当は `Document::MERGE_ROUNDING_TOLERANCE`（2）、255 はすべての差を許します。結合は効果とパスを画素へ焼き込み（結果は効果を持たず、`LayerMergeReport::notes` に印が付きます）、効いていない効果（使えるマップや Anchor が無い Generator・置けないデカール）があれば、落とさずに `CoreError::InactiveEffect` で断ります。下のレイヤーのマスクは、残すとき（分離の結合でないとき）は効果ごと結果へ移るので見ませんが、分離の結合は画素へ焼くので、そのマスクの効いていない Generator も断ります（C# はここを見ずに黙って落とします。Rust は意図して断り、`seam_ops` の試験が確かめます）。上のレイヤーの Anchor は結果へ移り、下のレイヤーの Anchor は無くなります（読む段は理由を出して入力のまま通します）。
- `set_rulers` / `move_rulers` / `set_snap_ruler`: レイヤー（グループも）に付く定規（直線定規・平行線・同心円・パース・対称。1 つのレイヤーに 64 個まで）を替えます。作る・動かす・消す・別のレイヤーへ移す・設定を変える・スナップする特殊定規の印を付けるが、それぞれ 1 回の Undo で、画素も合成も変えません。`coalesce` を付けると、ドラッグやスライダーを 1 回にまとめます。`rulers_seen_from` は描くレイヤーから見える定規（表示の範囲・定規の表示・持ち主とその親の目）、`snapping_special_rulers` は効く特殊定規（2D と 3D で別に、印のある 1 つ）を返します。複製した定規は新しい ID で写り、結合は外すレイヤーの定規を結果のレイヤーへ全部移し（64 個を超えるときだけ断ります）、`resize_image`・`resize_canvas` は 2D の定規の点だけを画素と同じに動かします。スマートマテリアルには定規が入らず、写すと外れて知らせます。

レイヤーの画素のコピー・カット・ペーストと置き換え（`clipboard.rs`）と、複数の編集を 1 回の Undo にまとめる `batch`（`batch.rs`）。

- `save_selection` / `rename_saved_selection` / `delete_saved_selection` / `recall_saved_selection` / `restore_saved_selections`: 名前を付けて文書に残した選択範囲（`saved_selections`。最大 32 個、名前は前後の空白がなく 1〜256 文字・制御文字なし・重ならない）。残す・名前を変える・消す・今の選択範囲との組み合わせ（`SelectionCombine`）での呼び戻しは、どれも 1 回の Undo で、画素は変えません。同じ名前で残し直すとその場所を入れ替え、同じ中身・同じ名前なら段を積みません。履歴の重さは、入れ替わった側で共有していない選択範囲の大きさです。キャンバスの大きさを変える操作（`resize_image` / `resize_canvas`）は、残した選択範囲も今の選択範囲と同じ道で新しい大きさへ作り直し（縮小で何も選ばなくなるものは外して報告に書く）、取り消せば元の大きさのものへ戻ります。レイヤーの変形は動かしません。`capture_snapshot` の写しは同じ並びを持ち、元の編集に追従しません。`restore_saved_selections` は読み込み直後の復元（段も版も増えず、履歴ができた後・決まりに合わない並びは断る）。
- `copy_pixels` / `copy_merged`: 選択範囲（無ければ全体）のレイヤー自身の画素（マスクなら灰色の不透明）か見えている合成を、値のある画素の外接矩形の `PixelClipboard` へ写す。文書は変えない。全部選ばれた画素は透明画素の RGB ごと、部分的な画素は透明へ向かってプリマルチプライドで混ぜる。矩形が `max_bytes` を超えた時点で断る（タイルは Y、次に X の順に、一操作の予算の 1/4（最大 16 MiB）ずつ読む）。
- `cut_pixels`: 写してから `fill`（消す）・`fill_mask`（見せる）で消す 1 回の Undo。塗りつぶし・調整・グループは写す前に断り、画像・透明部分のロックで断る（マスクはすべてのロックだけ）。ロックの検査は写す前なので、断ったときは何も写さない。
- `paste_as_layer`: 新しいラスターレイヤー（指定チャンネルだけ）を追加し、選択を外す 1 回の Undo。写したときと同じ大きさの文書へは元の位置、違えば中央（整数の割り算は 0 へ丸める）で、はみ出す分は切って数を返す。外の画像は `PixelClipboard::from_image`（その画像の大きさの文書から写したものとして扱う）。履歴の段は `Compound`（費用は段の合計 + 32。C# の `CompositeCommand`）。
- `replace_pixels`: 文書と同じ大きさの画像で置き換える。透明部分のロックでは色だけを置き換える。
- `batch`: 中の編集を本物の文書へ当てて、積まれた段を 1 つの `Compound`（費用は合計のまま。C# の `CompoundCommand`）にまとめる。失敗（`Err`・panic）では積まれた段を新しい方から戻し、Redo と履歴のバイト数も始める前へ戻す。履歴の整理は終わってから 1 回だけ。中ではストローク・Undo・Redo・履歴を消す書き込み（読み込み用の直接の書き込み）を `CoreError::BatchActive` で断り、入れ子にもできない（`ensure_loadable` がその入口で、レイヤー・チャンネルの確かめより先。C# の `RefuseInBatch` の位置と同じで、まとめの中で無効なチャンネルや無いレイヤーを渡しても、断る理由は `BatchActive`）。
- 断りは `CoreError::Clipboard(ClipboardRefusal)`。パスレイヤーの `cut_pixels` は、画素の書き込みと同じパスレイヤーの断り（ロックのあと）がそのまま返り、`ClipboardRefusal` には入りません（C# の `CutPixels` も断ります）。

`tests/reference/clipboard_golden.rs` が、実 C# Core の出力と全バイトで照らす（`tools/csharp-golden/run.sh clipboard`。1019 事例を並列度 1 と 4 で）。事例はレイヤー・マスク・チャンネル 6 つ・選択範囲 4 通り・上限 4 通りのコピー、レイヤーの属性を変えた文書の結合してコピー、ロック 5 通りと型の拒否のカット、貼り先の大きさ 3 通り・選択範囲・グループの中・一操作と画素の予算の拒否のペースト、ロックと選択範囲と `within_selection` の置き換え、`batch` の成功・失敗・禁止。出力は結果の型（ロックは断ったレイヤーと持ち主）・写し・履歴のバイト数・文書の全状態と、Undo・Redo の後の状態で、C# は事例ごとの SHA-256 を `golden/clipboard/index.txt` に書く（食い違ったときは `GOLDEN_FULL` と `CLIPBOARD_GOLDEN_DUMP` で出力そのものを比べる）。この照合の射程の外: 断った理由の文（型だけ）、`SourceBudget` が尽きる境目の細かい数（貼り先の予算を「今の画素 + 8」にした 1 通りだけ）、並列に動かす画素の計算が同じ結果になること以外の速さ。

画素を書く入口は、書く前に `Document::pixel_write_guard`（ロックで断り、透明部分のロックでアルファを守るかを返す）を通し、返した値を `StrokeState::new` の `keep_alpha` か塗りつぶしの式（`fill_pixel`）へ渡します。どちらも `keep_alpha` は必須の引数なので、新しい入口が渡し忘れるとコンパイルが落ちますが、守れるのはそこまでです（`false` を書く入口や、`edit_material_region` のクロージャで引数を無視する入口は通り、`edit_region`・`edit_region_tiles` は関門を通さずに呼べます）。入口を追加し忘れても見つける仕組みは無く、後述の `write_entries` の表に追加することだけが防波堤です。断るのは、無効のチャンネルを有効にしたり面を作ったりする前です（断ったあとに何も残りません）。マスクへ書く入口はすべてのロックだけで断ります（`refuse_lock`）。

検査の順は C# と同じです。画素の入口は、ラスターレイヤーかどうかの型の検査がロックより先で、断ったときにロックの名指しは出ません（`begin_stroke` の 4 入口だけは、調整・グループのレイヤーではロックが先です。C# の `BeginStroke` が面を取る `GetChannel` の型の拒否をロックの検査のあとに置くためで、塗りつぶしレイヤーだけ型が先です）。無効のチャンネルの拒否は、単チャンネルの範囲の塗り（`fill`・`gradient`・`begin_triangle_fill`）ではロックより先、単チャンネルのストロークではロックのあとです。マスクへ書く入口とマスクを変える入口（`set_layer_mask_*`・`remove_layer_mask`）は、マスクの有無の確認がロックより先で、マスクの無いレイヤーはどのロックでも「マスクが無い」で断ります。`add_layer_mask` は逆に、もうマスクがあるかの確認が先です。パス（`LayerPath`）で描かれたレイヤーへの手の書き込み（ストローク・塗りつぶし・グラデーション・マテリアル）は、次の描き直しで消えるので断ります。この断りはロックのあとです（C# は `RefuseLockedPixels` → `RefusePathLayer` の順）。動かす操作（`transform_layer(s)`）だけは、パスレイヤーの断りがロックより先です（C# の `RequireTransformable`）。パスレイヤーはマスクには描けます。効果の設定を変える入口（段・Anchor・読む先・塗りつぶしの画像と投影とグラデーション・値・パスの付け替え）もロックを確かめます: 画素を変えない設定はすべてのロックだけで、画素を決め直す設定は画像・透明部分のロックでも断ります。変わらない設定（`set_fill_value` の同じ値・`set_channel_enabled` の同じ状態）は、ロックより先に何もせず戻ります（C# と同じ）。`set_fill_value` は塗りつぶしレイヤーかどうかの型の検査も、ロックより先です。組（material）を持たないパスレイヤーは、パスが描くチャンネルを無効にできません（組を持つパスはどのチャンネルも無効にできます）。

| 入口 | 検査 |
| --- | --- |
| `begin_stroke` / `begin_stroke_in` / `begin_brush_stroke` | `pixel_write_guard` |
| `begin_material_stroke` / `begin_material_brush_stroke` | `pixel_write_guard`（全チャンネルが `keep_alpha`） |
| `begin_triangle_fill` / `begin_material_triangle_fill` | 上の入口を通り、返った `keep_alpha` を三角形の式へ |
| `fill` / `fill_material` / `gradient` / `gradient_material` | `pixel_write_guard`（範囲の式は `fill_pixel`） |
| `begin_mask_stroke` / `begin_brush_mask_stroke` / `begin_mask_triangle_fill` / `fill_mask` / `gradient_mask` / `apply_smart_mask` | `refuse_lock(ALL)` |

`tests/edit/docops.rs` の `every_pixel_write_entry_goes_through_the_layer_locks` が、入口ごとに（レイヤー自身のロックと親グループのロックで）断ること・断ったあとに何も変わらないこと（履歴・変更番号・全チャンネルの有効と画素・マスク）・ロックを外せば同じ入口が通ることを確かめます。入口を追加したら `write_entries` へ追加します。

透明部分のロックは描画・塗りつぶしのアルファを固定し、アルファ 0 の RGB もそのまま残します。消去と選択部分の変形は拒否します。画像ロックでもレイヤー全体の整数画素の移動とマスクへの描画は可能です。位置ロックは変形を拒否します。全ロックでも名前・表示・レイヤー順・複製・削除は可能です。読み込み用の `import_tile` / `set_channel_pixel` はロック検査を迂回するため、読み込みの最後に `set_locks_for_load` を使います。多くのタイルを読み込むときの `import_tiles_with` は、`import_tile` を順に呼ぶのと同じ結果・同じ誤りで、タイルの中身を書くことと詰めをワーカーへ分けます。

原子的な複数操作は、タイルを共有する準備用の状態（`Document::edit_copy`）で計算し、成功した状態だけを交換します（`State`）。Undo は再計算せず元の状態へ戻します。`edit_copy` と `State::take` は `Document` の項目を `..` なしで全部挙げ、準備用へ写さない・交換しない項目には理由を書いてあります。`Document` に項目を追加するとここでコンパイルが落ちるので、準備用の文書だけが変わって本物に反映されない、ということが黙って起きません。交換するのはレイヤー・寸法・Normal の設定・選択範囲・名前を付けて残した選択範囲だけで、チャンネルの表・履歴・進行中のストローク（マテリアルのストロークと三角形の塗りを含む）・変化の記録・予算・手動の ID 色は本物の文書のものです（ID 色はレイヤーの操作・変形・サイズ変更で変わりません）。効果の状態（`effects`）は、入力（メッシュマップ・画像・モデルのルート）と予算・ブロックの大きさだけ準備用へ写します（結合・変形・サイズ変更は準備の中で段を追加し、合成して前後を比べるので、入力が無いと本物と違う見た目で比べてしまいます）。評価のキャッシュ・元画素の時計・Anchor の解決の署名は写さず、交換もしません（準備用の文書の時計は 0 から数え直すので、持ち込むと別の内容に同じ鍵が付き得ます）。交換で画素が変わったレイヤーは、`swap_state` が前後で同じ ID のレイヤーのタイルを比べて、中身が違うタイルだけ元画素の時計を進めるので、評価の出力は新しい画素から作り直され、画素を変えない交換（複数のレイヤーの表示の切り替え・並べ替え・複製・削除）はキャッシュを捨てません。キャンバスの大きさが変わる交換は、キャッシュを全部捨てます。複製は効果と Anchor に新しい ID を付け（写しの中の Anchor を読む段は写しを読みます）、結合は残すマスクの段にも新しい ID を付けます（`renew_effect_ids`）。

変化の記録（`changed_tiles`）の印は、交換が変え得るレイヤーだけに前後の両方で付けます（`Dirty`）。ロックだけの変更は何も付けず（単独の `set_layer_locks` と同じ）、削除・複製・表示・一段移動・結合・変形は動いたレイヤー（グループは中身ごと）、サイズ変更は全レイヤーです。クリッピングの組は、レイヤーが 1 つでも動けば付けます。画素予算と一操作の予算は別です。変形は対象タイルの元の格納量 + タイルごと 64 バイト、結合は結果の格納量 + タイルごと 64 バイトを一操作の予算に数えます。レイヤーの複製は共有した画素も画素予算に数えます。取消可能な変形・画像サイズ変更はタイルのまとまりごとに取消を確認します。

C# の `Resampled` は履歴なしの別文書を返しますが、Rust のサイズ変更は寸法・画素・選択範囲・設定を一回の Undo で戻すため、前後の格納量（+128）を履歴の費用に数えます。この費用は文書の 2 倍以上になるので、履歴の予算（既定 64 MiB）に入らないことがあります（4096² の 1 レイヤーを 2048² へ縮めると前後で約 80 MiB）。そのときも断らず、そのサイズ変更の 1 段だけは予算を超えて残し（古い段を落とす）、`ResizeReport::history_over_budget` で知らせます。残るのはその段が最新の間だけで、次の編集の整理では普通の段として落とし得ます。断る案（4096² 級の文書が既定の予算で大きさを変えられなくなる）と、黙って Undo を落とす案（サイズ変更の取り返しが付かなくなる）は採りませんでした。画素の予算を超える・取り消すときは、履歴を落とさずに断ります。解像度変更自体は C# と同様にレイヤーのロックを無視します。幅・高さは 1〜8192 です。

レイヤーのロックの保存は I/O 側（yolu-io の `core_bridge`）が `locks()`（書く）と `set_locks_for_load`（読み終えてから付ける）でつなぎ、正本の版 12 の並びで読み書きします。文書は効果（フィルター・Generator・Anchor・塗りつぶしの画像と投影とグラデーション）とパスを持ち、レイヤーの操作はそれらも扱います（上の各項目と `effects/README.md` の「レイヤーの操作」）。C# の `BakeFilters`（1 枚のレイヤーの効果を画素へ焼く）に当たる操作は、まだ core にありません。

C# の正解を作るツール（`tools/csharp-golden/`）の C# の元は Unity ブリッジのタグ `0.4.0` の `Runtime/Core` で、場所は環境変数 `YOLUPAINTER_UNITY_SOURCE` で渡します（0.5.0 の Unity ブリッジには無い）。

照合は `tools/csharp-golden/run.sh docops` で実 C# Core の人工データを生成し、`cargo test -p yolu-core --test reference docops_golden::` で実行します。582 事例を、並列度 1 と 4 で全バイト比較します。生画素・レイヤーの属性・親子・マスク・選択範囲・合成・結合報告・履歴バイト数・Undo/Redo を比べますが、画像サイズ変更（`resize`・`selected_resize` の 108 事例）は C# の `Resampled` が履歴なしの別文書を返すため、変更直後の画素・属性だけです（サイズ変更の Undo・履歴・予算は `tests/edit/docops.rs` と `resize.rs` の試験が見ます）。結合がロックで断られる・断られない 34 通り（`mergelock`。断ったレイヤー・ロックの持ち主・ロックと、断ったあとの文書が変わらないこと、親グループの継承を含む）と、動く画素の外接矩形 `transform_bounds`（`bounds`・`selected_bounds`）も C# と比べます。

効果・パスとロックとレイヤーの操作のつなぎ目は、`tools/csharp-golden/run-seam.sh` が実 C# の `PaintDocument` に同じ台本を通して書く `tests/golden/seam.txt`（511 事例）を、`cargo test -p yolu-core --test reference seam_golden::` が並列度 1 と 4 で全バイト比較します。効果の設定の入口 × ロック × レイヤー／親グループ、手の書き込み × ロック × パスレイヤー／ラスターレイヤー、変形、パスレイヤーの追加、複製・削除・並べ替え・結合・画像の大きさを、結果の型（断ったレイヤー・持ち主・ロック）・履歴の費用・前後と Undo/Redo の文書（全チャンネルの合成）まで含めて比べます。照合は人工データ・メッシュマップ無しの範囲で、マップを要る段（形のグラデーションなど）は「効かない効果」としての扱いだけを照らし、3D のパスの描き直しとキャンバスだけを動かす `resize_canvas` は C# に無いので照らしません。意図して C# と変えた所は 3 つです: 読まれている Anchor が結合で無くなったときの変化を結合の報告が数える（C# は数えそこなう）、分離の結合で下のマスクの効いていない Generator を断る（golden の事例は分離にならない形）、名前を省いたときの既定の Anchor 名（golden は名前を渡す）。

ロックを立てたレイヤーへの塗り（マテリアルのストローク・範囲の塗り・グラデーション 2 種・三角形の塗り・単チャンネルのグラデーション・三角形の塗り・ストローク、マスクへの 4 種）は `tools/csharp-golden/run-material.sh` が書く `tests/golden/material.txt` の `lock`（1024 事例）・`lockmask`（512 事例）を `cargo test -p yolu-core --test reference material_golden::` が並列度 1 と 4 で全バイト比較します。断ったレイヤー・ロックの持ち主・ロック、断ったあとの Undo/Redo の可否と全チャンネルの有効・画素、通ったときの Undo/Redo の後の画素まで見ます。レイヤーの画素は、透明な画素がチャンネルごとに違い（アルファの式にチャンネル番号が入る）、文書の選択範囲を立てた事例、無効にしたチャンネルへ書く単チャンネルの事例、マスクの無いレイヤーの事例を含みます。塗りつぶし・調整・グループのレイヤーへの書き込みで、型の拒否とロックの拒否のどちらが先かは `locknr`（576 事例。並列度 1 だけ）が照らします。

この照合の射程の外: 予算の拒否（ストローク・画素・履歴）は C# と照らしません。巻き戻しの数え方が C# と違う（Rust はチャンネルごとに覆いを持つ。`rollback` の行が C# の値と倍率を固定する）ため、ロックの下で予算が尽きる境目は C# と一致せず、Rust の試験（`locked_writes_refused_by_the_stroke_budget_leave_everything_as_it_was` ほか）が、断ったあとに元へ戻ることだけを見ます。マスクを持つレイヤーへの `apply_smart_mask`・手動の ID 色（レイヤーの操作で変わらないことは `manual_id_colours_survive_layer_operations_transforms_and_resizes`。C# の `Resampled` は持ち越さない）も、C# との全バイトの照合には入っていません。

計測は `cargo run -p yolu-core --release --example docops_bench` と `tools/csharp-golden/run.sh docops-bench` で、人工 2 レイヤーの 512² / 1024²、各三回の中央値を出します。疎なレイヤー（8192²・描いたタイルが 1 枚、残りは無いか一様）のサイズ変更は `-- --sparse` です（計測の値は STATUS に書きます）。

合成の入口は用途ごとに 4 つあります。どれも画素の値は `composite_into` と同じバイトです（粗い合成を除く）。
- `composite_into`: 矩形を呼び手の領域へ。描いている間は、描くレイヤーより下の覚え（下の項）を使います。
- `composite_tiles`: 散らばったタイル（表示のように、変わった所を何枚も作り直すとき）の束。計画を 1 回作ってタイルをワーカーへ分けるので、1 枚ずつ呼ぶより 1 枚あたりの時間が短い（比は文書と負荷による。計測の台の `--only call` が「1 枚ずつ ÷ 束」を出す）。端のタイルはキャンバスの内側だけ。
- `composite_coarse_tiles`: 歩幅（タイルの一辺の約数）ごとに 1 画素を拾った粗い合成。正確な絵ができるまでの仮の絵と、スライダーのドラッグ中の表示のため。画素 (i, j) はタイルの左下から (i·歩幅, j·歩幅) の画素の合成と同じバイトで、効果の出力は、評価していないブロックがあれば粗く評価した近似（縮めた読み元で、ぼかし・シャープの半径を歩幅で割る。キャッシュには入れない）、全部が評価済みなら正確な出力を拾います。行の核（SIMD の道）へは読み元を 64 画素ずつ詰めた刻み 4 で渡すので、粗い合成も道の違いが効きます（`cargo run -p yolu-core --release --example coarse_bench` が、辺・レイヤー数・歩幅・スレッド数ごとの 1 回の時間を出します）。`effects_pending` が、そのタイルの正確な合成に評価が要るかを返し、`is_coalescing` がスライダーのドラッグ中かを返します。
- `composite_below`・`composite_pixel`・グループの出力は、覚えを使わない参照の道です。

小さな合成を呼んだスレッドだけで行うか、行の帯に割ってワーカーへ分けるかは、そのタイルで画素のあるレイヤーの数と重ね方の重さから見積もった仕事の量で決めます（1 枚のタイルの計算が 0.1 ms 前後のとき、分ける費用が 0.4 ms 前後かかるため）。結果は分け方によりません。

描いている間の下の覚え（`composite/memo.rs`）: ストロークが手を付けたタイルについて、描くレイヤーを含む段の手前までの重ねた結果（段ごとに RGBA8 へ丸めた途中の値）を、グループの入れ子の段ごとに覚え、描くレイヤーの段とその上の段だけを重ねます。手前までの結果から続けるので、全レイヤーを下から重ねた結果とバイトで同じです。上のレイヤーの重なりは、合成モード・調整・クリッピング・通過のグループが下の結果に依るので覚えず、そのタイルで画素のある上のレイヤーだけを毎回重ねます。覚えの大きさは、ストロークの予算から巻き戻し用の写しを引いた残りの中（超えるタイルは覚えず今の道。ストロークが進んで巻き戻しが育ち、残りに収まらなくなったら覚えを手放すので、点を追加し終えた時点と合成のあとは、覚え + 巻き戻しが予算に収まる。1 点を追加している最中の瞬間は、巻き戻しが先に育つので覚えの分だけ越え得る）。描くレイヤーの画素以外の変化（変化の記録の `mark` を通るもの）・ストロークの終わり・取り消し・Anchor を読む効果があるときは捨てて使いません。`set_composite_memo(false)` で切れ、`composite_memo_stats` で使った・作った・予算で飛ばした・手放したタイルの数が分かります。

計測の台は `cargo run -p yolu-app --release --example comp2d_bench -- --synthetic 2048`（`--psd <ファイル> --label A`、`--dense 1024 24`、`--only stroke|visible|opacity|effect|zoom|open|hash|merge|call`）で、見える範囲ごと（枠なし・全体を表示・等倍）の同期の時間を TSV で出します。`--only call` は、合成の呼び出し 1 回あたりの時間と、1 枚ずつ呼ぶ場合と束の比（「1 枚ずつ ÷ 束」。繰り返しごとに続けて測った比の最小・中央値・最大）を出します。全タイルの歩幅つきの粗い合成（歩幅 2・4・8）と、キャンバス全体を 1 回の矩形で合成する時間（スレッド 1・既定）も出します。`--only merge` は、表示に寄与するレイヤーの結合と、上から最初に結合できるレイヤーを下へ結合する時間を、結合後の合成の指紋つきで出します（結合は Undo で戻す）。
