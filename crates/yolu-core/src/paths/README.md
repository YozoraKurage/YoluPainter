# 編集できるパス

`CanvasPath` はキャンバスの点、`SurfacePath` は三角形番号と重心座標の点を持ちます。`PathBrush` の半径は前者では画素、後者ではモデルの空間です。`material: None` は基準チャンネルとブラシ色、`Some` は重複のない標準6チャンネルの組です。構造体を直接編集でき、評価の入口で必ず検証します。微小な負の重心座標は `PathPoint::new` で正規化します。

`render_canvas` と `render_surface` は `Options` の大きさ・予算で、チャンネルごとの新しい `Surface` を返します。文書・選択・Undoには触れません。失敗・取消では結果全体を返しません。呼び元は成功した結果とパスをまとめて確定してください。評価した画素を既存レイヤーに入れる操作、保存、UndoはこのAPIに含まれません。

レイヤーは何本ものパスの一覧（`LayerPathEntry`。名前・表示・パス）を持ち、`render_list` が見せるパスを下から順に同じ作業面へ描きます（後のパスが上。消しゴム・指先のパスは前のパスの画素に効く）。一覧のパスは同じ側（2D か 3D）・同じ基準チャンネル・（3D は）同じ指紋に限ります。

点ごとの接線（`Tangent`）: 区間の両端が滑らかなら下の Catmull–Rom、どちらかが角か取っ手なら 3 次のベジェ（`bezier.rs`。滑らかな端の制御点は Catmull–Rom のその端の微分から）。角・取っ手の無いパスは前と同じバイトで描きます。取っ手は点からの向きで、3D は休みの形のモデルの空間です。

種類（`PathStyle.kind`）: ストローク（下の丸いブラシ）・消しゴム（同じストロークで消す）・指先（同じ曲線で前の画素を引きずる。3D は面のダブを丸ごと塗り、UV の継ぎ目で前の位置を忘れる）・塗り（`fill.rs`。曲線の内側を 4 × 4 の副標本で。3D は 1 つの UV アイランドの中だけ）・リボン（`ribbon.rs`。アセットの画像を向きに回した長方形のダブで並べる・伸ばす。画像は `Options::images` から）。

対称（`PathStyle.symmetry`）: 2D はキャンバスの対称（縦・横・両方・放射状・線対称。線対称は Rust 版だけ）、3D は休みの形のモデルの空間の鏡の面。映した側は持たず、描くときに作って元のパスのすぐ後に同じ作業面へ描きます。3D の丸い筆先は縁のアンチエイリアス（`PathBrush::anti_alias`）が効き、筆先の画像を持つパスには効きません。

2D は centripetal Catmull–Rom の折れ線を既存の丸いブラシへ渡します。3D は今の三角形から位置を復元し、曲線を法線方向へ投影して、既存の面のダブを描きます。投影できないサンプルは描かず `gaps` に数えます。ダブの拒否や0..1外の覆いはエラーです。指紋は三角形数・並び・レンダラー・スロット・UVから作り、位置とポーズを含めません。不一致なら理由付きで拒否します。

## 互換性と予算

`tools/csharp-golden/run-paths.sh <出力先>` は Unity 版（ブリッジのタグ `0.4.0`。場所は環境変数 `YOLUPAINTER_UNITY_SOURCE`）の原文から人工データの正解を作ります。試験が読む `tests/golden/paths` を作り直すときは、そこを出力先に渡します（省くと `target/csharp-paths/golden`）。収録した25入力・27面の全バイト、3Dのダブ数・欠落数、指紋4形状、拒否理由19件を `cargo test -p yolu-core --test paths` で照合します。

- 2D の入力は空・1点・2点・曲線・重複・キャンバス外・筆圧0・チャンネルの組です。消しゴムの入力は、空の作業面に消すので全画素が0のままになることだけを照らします（消しゴムの意味の照合ではありません）。
- 3D の入力は、平面上の空・1点・2点・曲線・重複・チャンネルの組に加えて、離れた平面の間（欠落が出る）、高さの違う平面、法線が合わない急な面（法線の判定と下からのレイ）、筆圧0の点（ダブの省略。ブラシの筆圧の割り当て2通り）です。急な面と指紋の形は別レンダラー・別スロットを含みます。
- 指紋は、平面・離れた平面・急な面（レンダラー1・スロット2）・レンダラーとスロットが非零や負で UV が小数・負・-0.0 の形の4つで C# と一致させています。位置とポーズが指紋に入らないことは、位置だけ動かした面で別に確かめています。
- 拒否理由は、予算・サンプル数・指紋の不一致・2D の点・ブラシ・組に加え、3D の指紋の長さ（空・128・129文字と、UTF-16 で 128・130 単位になる絵文字の列）・点の数（4096・4097）・半径の上限・標準外のチャンネル・重複する組です。

ワーカー数は、C# との照合の27面を1・2・4で全バイト一致させています。ただし照合のキャンバスは64²で、3D は1ダブの遮蔽のレイが1024本に届かず、どのワーカー数でも逐次の経路を通ります。そこで3D は別の試験で、256²のキャンバス・半径0.2のダブ（1ダブ8000本余のレイ）が複数のワーカーに分かれる大きさでも、覆いの板を挟んだ面で1・2・4の結果が一致することを確かめています（C# との照合ではなく自己一致）。2D は並列のタイルの閾値を0にして通常は並列にならない小さなキャンバスも並列経路に通します。

Unity の `Bounds.SqrDistance` は既存の正解生成器の代替式を使います。ネイティブの `Vector3.Slerp` は Mono 単体で実行できないため、生成器では同一法線の場合だけ恒等写像に置き換え、それ以外を拒否します。**異なる法線を結ぶ3Dパスは実装されていますが、Unity実行環境との全バイト一致は未検証です。** Rustの角をまたぐ試験は決定性の確認であり、C#照合ではありません。

ソースとストロークの予算は全チャンネルの合計です。現行の単チャンネル用ブラシをチャンネルごとに保持するため、組のストローク予算には覆いもチャンネル数分含みます。C# は覆いを共有するため、この場合はRustの方が保守的に拒否します。組の合計検査は各入力点・画素の処理後に行い、途中の確保を含めた厳密なプロセスメモリ上限ではありません。各ブラシ内部は個別の上限を先に検査します。単チャンネルのソース・巻き戻し予算の拒否理由はC#と照合しています。塗り（種類 `Fill`）は、多角形の点・副標本の行ごとの交わり・3D の曲線とアイランドの升の覚えを、リボンの集めた画素と同じくストロークの予算に（1つあたりの大きさの見積もりで）数え、超えるなら `StrokeBudgetExceeded` で断ります。

2D は合計400万サンプル、3D は各区間100万分割を上限にします。C# の整数変換で範囲を超える極端な入力もRustでは明示的に拒否します。取消はRustで追加した機能で、各サンプル・ダブ・画素・結果返却前に確認します。既存ブラシや面のダブを一度呼んだ内部では中断しません。確認の場所ごとの回数を台帳に取り、各場所の初め・2回目・真ん中・最後の確認で旗を立てる単一ワーカーの試験（時間に頼りません）で、その確認でCanceledが返り、後の確認へ進まず、結果を返さないことを確かめています。並列実行では画素の演算順を変えず、チャンネルは入力順に評価します。
