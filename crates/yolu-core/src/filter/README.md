# 非破壊フィルター

`filter::evaluate` は読み取り専用の `Source` と順序付きの `Stage` を受け、指定領域の RGBA8 を返す。画像全体がメモリにある場合は
`Image::new` を使える。タイルの場合は `Source::pixel` でキャンバス座標をタイル内の座標へ変換する。評価中の入力と Generator の値は固定する。
入力の更新・履歴・保存はこのAPIでは行わない。成功時だけ返された画像を採用する。

対応する通常フィルターはぼかし・シャープ・ノイズ・レベル・反転・正規化。各段は有効状態と強さを持つ。
色とスカラーは同じ画素式を使い、スカラーの色ノイズを拒否する。接空間法線はベクトルを再正規化するぼかしだけを受け付ける。
マスクは入力の A を隠す量として不透明グレーに展開し、出力を RGB=0・A=隠す量に戻す。

Rust 版だけの色調補正の段（グラデーションマップ・トーンカーブ・カラーバランス・明るさ/コントラスト・2 値化・ポスタリゼーション。段の種類の番号は
64〜69）は、調整の層（`adjust`）と同じ値の型と式を使い、強さは元の色との混ぜ。画素ごとの点の処理で半径は 0。グラデーションマップとカラーバランスは
色だけ（スカラー・マスクは拒否）、トーンカーブはスカラーとマスクでは RGB 全体の曲線だけが効き、どれも接空間法線には置けない。

ぼかしは前乗算した16ビット値を横・縦の順で整数の箱ぼかしに通す。3回の箱の半径の合計が指定半径になる。
キャンバス外では端の画素を反復し、タイル境界では隣のタイルを読む。点演算も透明画素のRGBを処理するが、シャープは透明画素を保つ。
ぼかしで出力アルファが0になる画素は元のRGBを保つ。部分的な強さはアルファが変わる場合に前乗算で混ぜる。
正規化の統計は指定領域だけでなく、その段への入力全体のアルファが正の画素から求める。
`statistics` は統計だけを求める（返す並びは段と同じで、有効な Normalize の段だけが `Some`）。走査はブロック並列で、結果は並列度・ブロックの
大きさによらない。`Options::statistics` に渡した段は走査せずその値を使うので、文書側が（入力・スタック・Generator の値の）世代ごとに
統計を持てば、領域ごとの `evaluate` が全画像を読み直さない。渡す値の由来の照合は呼び出し側で、このモジュールは段の種類と数だけを検証する。

Generator 段には `GeneratorInput` が返す解決済みスカラー、またはランプ適用後のRGBAを渡す。7種類の合成は C# の
`BoundGenerator.Combine` と同じ。照合は 2 通り: `Combine` 単体の密な照合（透明画素の扱いとマスクの変換は照合ツール側の写し）と、
C# の実 `FilterEngine` が解決した値（`BoundGenerator.TryValue` とランプの評価）をそのまま入力にした通しの照合（スカラー・ランプ付き・
マスク・値なしの画素・前後の段との組み合わせ）。照合の外はマップからの値の計算で、Rust には無い。
スカラー入力は有限の0..1に限る。スカラーのチャンネル・マスク用のランプは呼び出し側でグレーに評価する。マスクでは可視度に変換して合成し、隠す量へ戻す。欠損座標を `None` で返すと入力を保つ。
マップ自体の生成、由来の照合、Anchor の依存解決、ランプの評価、無効なマップの理由表示はこのモジュールの外で扱う。

予算は返却画像と同時に生きている作業バッファの合計。入力、サンプラーが所有するメモリ、メタデータ、スレッドスタックは含めない。
C# のブロック画素の見積りに縦パスの行累積と返却画像を加えるため、C# の作業予算と同じ数値でも拒否境界は一致しない。
最大32段・有効段の半径合計512画素は C# と同じ。予算で同時実行数を制限する（主処理は返却画像を引いた残り、統計の走査は返却画像を
確保する前なので予算いっぱいまで）。rayon の呼び出し元プールを使うので、`ThreadPool::install` で並列度を指定できる。各画素の演算順序は
並列度によらない。

取消フラグはブロック・行・段の境界で確認する（ぼかしとシャープは箱ぼかしの横・縦の各パスと出力も行ごと、点の段・Generator の
サンプリング・統計の走査もブロックと行ごと）。最後の確認を通ってから完成画像を返すので、計算が済んだ後に立てても取消になる。
設定不正、予算不足、取消では完成画像を返さず、入力を変えない。
C# の FilterEngine 自体には取消トークンの引数がないため、取消フラグはこのAPIで追加した契約である。

画素の計算（強さでの混ぜ・表の段・ノイズ・箱ぼかし・ぼかしとシャープの最後の行）は、x86_64 では AVX2・SSE4.1 を実行時に見分けて使う（`filter/rows.rs`）。
結果のバイトは画素ごとの式と同じで、他の CPU では画素ごとの式のまま。割り算の丸め（箱ぼかしの平均と乗算済みから戻す除算）は、f64 の演算が整数の商の
切り捨てと一致する範囲（分子が 2²⁶ 程度まで・商の端からの距離が丸めの誤差より十分大きい: 箱ぼかしは 0.5/(2r+1) 以上、乗算済みから戻す除算は 1/(2·qa) 以上）だけで行う。環境変数 `YOLU_SIMD` で道を下げられる。
