# 非破壊フィルター

`filter::evaluate` は読み取り専用の `Source` と順序付きの `Stage` を受け、指定領域の RGBA8 を返す。画像全体がメモリにある場合は
`Image::new` を使える。タイルの場合は `Source::pixel` でキャンバス座標をタイル内の座標へ変換する。評価中の入力と Generator の値は固定する。
入力の更新・履歴・保存はこのAPIでは行わない。成功時だけ返された画像を採用する。

対応する通常フィルターはぼかし・シャープ・ノイズ・レベル・反転・正規化。各段は有効状態と強さを持つ。
色とスカラーは同じ画素式を使い、スカラーの色ノイズを拒否する。接空間法線はベクトルを再正規化するぼかしだけを受け付ける。
マスクは入力の A を隠す量として不透明グレーに展開し、出力を RGB=0・A=隠す量に戻す。

Rust 版だけの色調補正の段（グラデーションマップ・トーンカーブ・カラーバランス・明るさ/コントラスト・2 値化・ポスタリゼーション。段の種類の番号は
64〜69）は、調整レイヤー（`adjust`）と同じ値の型と式を使い、強さは元の色との混ぜ。画素ごとの点の処理で半径は 0。グラデーションマップとカラーバランスは
色だけ（スカラー・マスクは拒否）、トーンカーブはスカラーとマスクでは RGB 全体の曲線だけが効き、どれも接空間法線には置けない。

ぼかしは前乗算した16ビット値を横・縦の順で整数の箱ぼかしに通す。3回の箱の半径の合計が指定半径になる。
キャンバス外では端の画素を反復し、タイル境界では隣のタイルを読む。点演算も透明画素のRGBを処理するが、シャープは透明画素を保つ。
ぼかしで出力アルファが0になる画素は元のRGBを保つ。部分的な強さはアルファが変わる場合に前乗算で混ぜる。
正規化の統計は指定領域だけでなく、その段への入力全体のアルファが正の画素から求める。
`statistics` は統計だけを求める（返す並びは段と同じで、有効な Normalize の段だけが `Some`）。走査はブロック並列で、結果は並列度・ブロックの
大きさによらない。`Options::statistics` に渡した段は走査せずその値を使うので、文書側が（入力・スタック・Generator の値の）世代ごとに
統計を持てば、領域ごとの `evaluate` が全画像を読み直さない。渡す値の由来の照合は呼び出し側で、このモジュールは段の種類と数だけを検証する。

Generator 段には `GeneratorInput` が返す解決済みスカラー、またはランプ適用後のRGBAを渡す。7種類の合成は C# の
`BoundGenerator.Combine` と同じ。照合は 2 通り: `Combine` 単体の密な照合（透明画素の扱いとマスクの変換は照合ツール側の写し）と、
C# の実 `FilterEngine` が解決した値（`BoundGenerator.TryValue` とランプの評価）をそのまま入力にした通しの照合（スカラー・ランプ付き・
マスク・値なしの画素・前後の段との組み合わせ）。照合の外はマップからの値の計算で、Rust には無い。
スカラー入力は有限の0..1に限る。スカラーのチャンネル・マスク用のランプは呼び出し側でグレーに評価する。マスクでは可視度に変換して合成し、隠す量へ戻す。欠損座標を `None` で返すと入力を保つ。
マップ自体の生成、由来の照合、Anchor の依存解決、ランプの評価、無効なマップの理由表示はこのモジュールの外で扱う。
Generator の段は行ごとに `GeneratorInput::sample_row` を 1 回（透明な画素が 16 画素以上続く所は分けて）呼び、値を作ってから画素ごとに合成する。
既定の `sample_row` は `sample` を 1 画素ずつ呼ぶので、`sample` だけの入力もそのまま使える。透明な画素（マスク以外）の値は前と同じく使わない
（短い隙間の画素は値を作って捨てる）。行の値の作業領域（ブロックの幅 × 16 バイト）は画素のバッファではないので予算に含めない。
文書の評価は束縛済みの Generator の行の評価（SIMD の道）へ渡し、結果のバイトは画素ごとに `sample` を呼んだときと同じ（`filter/generated.rs` の試験が、
全部の種類・ランプの混色・色・スカラー・マスクを、この CPU が持つ全部の道で、前の画素ごとの評価をそのまま書いた参照と比べる）。粗い評価（歩幅で拾う）は画素が
離れているので 1 画素ずつのまま。

予算は返却画像と同時に生きている作業バッファの合計。入力、サンプラーが所有するメモリ、メタデータ、スレッドスタックは含めない。
C# のブロック画素の見積りに縦パスの行累積と返却画像を加えるため、C# の作業予算と同じ数値でも拒否境界は一致しない。
最大32段・有効段の半径合計512画素は C# と同じ。予算で同時実行数を制限する（主処理は返却画像を引いた残り、統計の走査は返却画像を
確保する前なので予算いっぱいまで）。rayon の呼び出し元プールを使うので、`ThreadPool::install` で並列度を指定できる。各画素の演算順序は
並列度によらない。

取消フラグはブロック・行・段の境界で確認する（ぼかしとシャープは箱ぼかしの横・縦の各パスと出力も行ごと、点の段・Generator の
サンプリング・統計の走査もブロックと行ごと）。最後の確認を通ってから完成画像を返すので、計算が済んだ後に立てても取消になる。
設定不正、予算不足、取消では完成画像を返さず、入力を変えない。
C# の FilterEngine 自体には取消トークンの引数がないため、取消フラグはこのAPIで追加した契約である。

画素の計算（強さでの混ぜ・表の段・ノイズ・箱ぼかし・ぼかしとシャープの最後の行）は、x86_64 では AVX2・SSE4.1 を実行時に見分けて使い、aarch64 では NEON を使う（`filter/rows.rs`）。
結果のバイトは画素ごとの式と同じで、他の CPU では画素ごとの式のまま。割り算の丸め（箱ぼかしの平均と乗算済みから戻す除算）は、f64 の演算が整数の商の
切り捨てと一致する範囲（分子が 2²⁶ 程度まで・商の端からの距離が丸めの誤差より十分大きい: 箱ぼかしは 0.5/(2r+1) 以上、乗算済みから戻す除算は 1/(2·qa) 以上）だけで行う。環境変数 `YOLU_SIMD` で道を下げられる。

## UV の継ぎ目をまたぐ近傍の段（`seams.rs`）

`Options::seams` を渡すと、近傍の段（到達半径 1 以上）は UV の継ぎ目をまたいで読みます。段の前に、入力の写しのアイランドの外の帯のテクセルを、帯の写し（`geometry::SeamBand`）が指す相手のアイランドの画素で埋め（双線形。前乗算して混ぜ、接空間の法線は継ぎ目の向きで XY を回す）、段の後はアイランドの外を入力のまま戻します（書き出しのパディングとは別）。点の段はそのままです。相手の画素がブロックの入力の外にあるときは、その点を含む小さな矩形を前の段までで評価して読むので、ブロックの分け方で同じ画素の値は変わりません。帯の写し・アイランドの図・位相の対応は、初めて要るときに作ります（粗い評価もブロックを並べる前に 1 回作って各ブロックへ渡します。rayon のスレッドの中から作るときは並列にせず、同じ順・同じ値で順に作るので、作る間に別のブロックが同じ物を待って止まることがありません）。文書の設定 `filter_seams`（既定は入。切ると正本の版 32）が、モデルの UV の位相がある文書でこれを使います。

## 0.5.0 の段（種類 70〜79）

値の表の 2 種（ヒストグラムスキャン・ヒストグラムレンジ）は点の処理（`point` の 256 の表）、近傍の 8 種は `spatial.rs`。どれもスカラーの 1 本の道
（SIMD にしない）なので、`YOLU_SIMD` の道によらず同じバイト。近傍の足し込みは f64（双線形・平均）か整数（箱ぼかし・度数）。

| 種類 | 式 | 到達半径 | 値の種類 |
|---|---|---|---|
| ヒストグラムスキャン | 幅 w = max(1 − contrast, 1/255)、out = clamp((in − (position − w/2)) / w) | 0 | スカラー・マスク |
| ヒストグラムレンジ | out = clamp(position + (in − 0.5) × range) | 0 | スカラー・マスク |
| スロープぼかし | 内蔵の値ノイズ（Generator の値ノイズと同じ hash、格子の辺 scale 画素）の勾配の向きへ、自分と intensity × k / samples（k = 1〜samples）の位置を双線形（乗算済み）で読み、平均・最小・最大 | ceil(intensity) | 色・スカラー・マスク |
| 方向のぼかし | 角度の向き（多項式の sin・cos）の両側 ±distance を 2·ceil(distance)+1 点（512 まで）で読み、乗算済みで平均 | ceil(distance) | 色・スカラー・マスク |
| ゆがみ | 値ノイズの勾配 ÷ 1.875 × intensity（長さは intensity まで）ずらした位置を双線形で読む | ceil(intensity) | 色・スカラー・マスク |
| モルフォロジー | 丸い範囲（dx² + dy² ≤ r²）の最大・最小（行ごとの最大・最小の表で引く。透明な画素は数えない） | radius | スカラー・マスク |
| エッジ検出 | width でぼかし（ぼかしと同じ 3 回の箱）、Sobel の強さ / (4 × 255) を 0〜1 に、threshold 以下は 0 | width + 1 | スカラー・マスク |
| ハイパス | out = 0.5 + in − ぼかし(in, radius)（ぼかしの段と同じ値）。A は元のまま | radius | 色・スカラー・マスク |
| メディアン | 正方形の範囲の下の中央値（RGB は A が正の画素だけ、A は全部。端は端の画素を繰り返す） | radius | 色・スカラー・マスク |
| グロー | out = in + ぼかし(max(in − threshold, 0))（乗算済みの値）× intensity。A は元のまま | radius | 色 |

画像の外は端の画素を繰り返し、読む位置は到達半径の中へ寄せるので、ブロックの分け方・領域・並列度で同じ画素は同じ値になる。A を変えない段の透明な画素と、
結果の A が 0 になる画素は入力の RGB のまま。作業メモリの見積りは種類ごと（`spatial::working_bytes`）で、ぼかしと同じく予算と到達半径の合計 512 の検査に入る。
粗い評価（`coarse`）では画素で数える長さ・半径・ノイズの大きさを歩幅で割る。
