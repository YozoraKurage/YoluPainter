# 塗りつぶし画像の評価

`fill_image` は文書を持たず、入力から straight RGBA8 の画像や領域を返します。左下原点、行優先です。UV・平面・トライプラナー・球面・円柱・デカールに対応します。レイヤーへの設定、リソースの検索、Undo と保存は呼び手の仕事です。

1. `ImageMipChain::build` に画像、色変換、輝度変換、追加段の予算、取消フラグを渡します。元画像は借用します。Color/Emission で線形画像を読む場合は `Conversion::LinearToSrgb`、ほかは `None`。Roughness/Metallic/Height では `luminance = true` にします。法線は色変換しません。
2. `FillInput` に `Projection`、解像度、画像と代替値を入れ、`FillSampler::bind` で入力を検証します。モデル投影には位置マップ、元の境界箱、モデルのフレームを渡します。トライプラナーとデカールは法線も必要です。
3. `render(x, y, width, height, budget, cancel)` で領域を評価します。`pixel` は1画素、`decal_coverage` は形画像を掛ける前の箱・奥行き・面の向きによる被覆率を返します。

ミップは奇数辺の最後の3テクセルも含めて平均し、プリマルチプライドの重みで双線形・三線形補間します。`FillInput::anisotropic`（デカールの別チャンネルの形は `shape_anisotropic`）を立てると、画素の足跡（隣の画素との位置の差から求めたテクセルの差）が細長いとき、長い向きに沿って細長さの数（切り上げ。1% までの端数は切り捨て、上限 `MAX_ANISOTROPY` = 16）の点を等しい間で取り、各点を短い向きの長さ（上限で足りなければ長さ ÷ 数）の段で読んで平均します。足跡が丸い・拡大・片方の差が分からない画素は、立てても C# と同じ 1 回の三線形です。既定は立てない（C# と全バイト一致）で、文書はレイヤーのチャンネルごとの設定（既定は立てる）を渡します。立てた道は、Rust で撮った正解（`tests/golden/fill-image-anisotropic`）と全バイトで比べます。結果のアルファが0に丸まった画素のRGBも C# の規則で残します。投影の回転順、近い隣を選ぶ足跡、経度の継ぎ目、トライプラナーの混ぜ幅は C# `FillImageSampler` と同じです。Rayon の呼び出し元のプールで並列度を設定できます。

デカールのチャンネルが画素ごとに変わる値（グラデーションのランプの結果など）を持つときは、`apply_decal_to_value`（1 画素）か `render_decal_values`（領域。値は領域と同じ並びの RGBA8）に値を渡します。C# の `ApplyDecalToValue` と同じく、箱・奥行き・面の向き・別チャンネルの形の被覆だけを値のアルファにかけ、自身の画像は使いません（`FillInput::image` の有無に依らない）。置けないデカールは透明で、デカール以外の投影は拒否します。`FillInput::fallback` の1色で代用すると、値が画素ごとに変わるチャンネルが黙って単色になります。

デカールは位置・法線がない画素と箱の外で透明になります。形の画像はチャンネル順の最初の画像を呼び手が選びます。そのチャンネル自身は `image` だけ、別のチャンネルは `shape` にも渡してください。自身の画像を重ねて `shape` に渡すとアルファを二重に掛けます。値だけのチャンネルは `image = None` です。画像を指定したのに読み込めなかった場合は `missing_image = true` にして理由を残します。

## geometry との接続

`ModelMaps::from_geometry` は `SurfaceGeometry` の三角形・UV 重心座標・面法線から16 bitの位置と法線を作ります。マテリアルを指定し、重複UVは入力順の最初の面を採ります。メモリ予算は13バイト/画素、作業予算は三角形とUVの照合回数です。bounds と revision を保持します。

この経路は面法線・画素中心1点・余白なしです。C# の完全なメッシュベイカー（スムーズ法線、高ポリ参照、アンチエイリアス、余白埋め）の代替ではありません。その結果を使う場合は `Map` へ16 bit RGBと被覆を渡します。古いマップは呼び手が `stale_position` / `stale_normal` で明示します。

## 予算と拒否

- ミップ予算は C# と同じく段0を除く RGBA8 の総量です。管理配列や借用元の画像は含みません。新しいミップを作る前に旧ミップと合わせた常駐量も制限する場合は、呼び手が残予算を渡します。
- 領域出力の予算は返すバイト数です。取消はミップの段と行、出力の行と256画素ごと、geometry の三角形と行で確認し、途中の出力を返しません。配列確保そのものを途中停止する契約ではありません。
- C# の独立した `ImageMipChain` / `FillImageSampler` には取消と出力予算の引数がありません。Rust の追加保証です。文書・キャッシュ全体の予算を再現するものではありません。
- 未解決画像・不足/旧世代/別解像度のマップ・不明なモデルフレームは `reason()` で区別します。通常投影は代替値、置けないデカールは透明です。不正設定は `FillError` で拒否します。
- C# の `MayCover` / `MayCoverTiles` / `AddDecalTiles`（位置タイルの境界でデカールが覆えないタイルを先に外す最適化）は移していません。評価する領域は呼び手が決めて `render` に渡します。
- 極端なモデル座標で中間計算があふれる場合や、保守的に見積もった画像テクセル座標が32 bit整数を超える場合は、評価前に拒否します。範囲外の `double → int` が実行環境依存になる C# との差です。幅・高さは1〜8192です。

## 照合と計測

`cargo test -p yolu-core --test reference fill_image::` で既知解・拒否・予算・取消・C# 正解との全バイト照合を実行します。デカールの画素ごとの値（`ApplyDecalToValue`）は、同じ8設定のデカールに座標だけで決まる値を渡した8事例を同じ並列度・タイル分割・1画素の経路で照合します。geometry から焼いたマップは、平面・トライプラナー・デカールへそのまま渡して既知の画素を確かめます（z の幅が0の板と斜めの板。位置の符号化と bounds の受け渡しが1つずれると落ちます）。取消は `cargo test -p yolu-core --lib cancellation_tests` で、ミップ構築・geometry・通常出力・デカールの値出力を確かめます。試験専用の単一ワーカーで、行・段・256画素ごとの取消確認を数えて途中で旗を立て、後続の確認へ進まず取消を返すことを検証します。経過時間や実機での応答時間は合否に使いません。48事例（6投影×8設定）は37×29画素、奇数辺/1画素辺、透明RGB、色/輝度変換、3種類の外側、縮小/拡大、回転するモデルと配置、デカールの別画像/値を含みます。Rust並列度1/2/4とタイル分割、C#並列度1/4も照合します。

正解は `tools/csharp-golden/fill.sh golden` で Unity に依存しない C# Core の原文（Unity ブリッジのタグ `0.4.0` の `Runtime/Core`）をビルドして再生成します。`YOLUPAINTER_UNITY_SOURCE` と `YOLUPAINTER_CORE_UNITY_DATA` で原本とUnity同梱ツールの場所を指定できます。`source.txt` に版と評価式の指紋を残します。`contracts.txt` は不正設定12件と5×3画像のミップ予算11/12バイト境界です。

4096²の比較は次のコマンドで実行します（Linux、CPU 0〜3を使用）。

```sh
cargo build --release -p yolu-core --example bench_fill_image
taskset -c 0-3 target/release/examples/bench_fill_image 3 4
taskset -c 0-3 tools/csharp-golden/fill.sh bench 3 4
```

人工画像31×23、各投影の同じ設定、予熱1回と実測3回です。出力の確保を含み、マップとミップの準備は除外します。デカールは箱外を含むので全画素を画像で覆う場合の速度ではありません。Rust は release、C# は最適化有効・Monoです。実データやWindowsの性能を保証しません。
