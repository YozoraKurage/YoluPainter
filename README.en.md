# YoluPainter-rs

A standalone version of YoluPainter. Paint textures on a 2D canvas and 3D models, and save your layers (including groups, masks, fills, and adjustments) and channels in `.ylp` files. Connect to the Unity version of YoluPainter through Live Link to preview your painted colors on the actual materials in a Unity scene.

Windows is the primary platform. Mac and Linux support is experimental.

## Features

- Paint with brushes and an eraser. Includes 13 built-in brushes, Size, Hardness, Spacing, Opacity, Flow, image tips, Jitter, paper texture, Dual Brush, Color Dynamics, Fade, pen tilt and rotation, Speed, Stabilizer and Taper, and effect brushes (Blur, Smudge, Clone). Windows Ink pressure can control Size, Opacity, Flow, and Hardness, and each one has a minimum (the value at zero pressure) and a curve. How pressure comes out differs from pen to pen: View → Pen Pressure… sets a low and high limit and a curve (it can also work them out from strokes you draw in its frame at your usual strength, and you can add, move, and remove curve points in the frame). It is a per-device setting and is not stored in documents or brushes.
- Brush interface: the Brushes panel on the left lists brushes by group (Pen, Brush, Airbrush, Eraser, Effects, Special), with each brush's name and a sample stroke drawn using its settings. Click a row to switch brushes, or use the “+” at the bottom right to save the current settings as your own brush. You can duplicate, rename (double-click), delete, drag to reorder, and reset brushes. Built-in brushes cannot be deleted; changing their settings marks them as “modified.” Below the list, Tool Properties (Size, Opacity, Hardness, Flow, Spacing, pressure toggles, Stabilizer) and the preset diameter circles in Brush Size provide quick adjustments. The adjustment button opens Brush Details (Shape, Stroke, Pressure, Taper & Pen, Jitter, Texture, Dual Brush, Color Dynamics, Effect, Symmetry). Pressure sets, for each of Size, Opacity, Flow, and Hardness, whether pressure is used, its minimum, and its curve (add, move, and remove points). This window can be moved and kept open while painting. The eraser (`E`) uses the last brush used in the Eraser group. Custom brushes are saved as individual files in `brushes/` in the settings folder; damaged files are skipped and reported at startup. A brush that uses a pressure minimum or curve is written in a newer format (version 2); an older app that reads only version 1 skips it and reports why (brushes that do not use them keep the same version and contents as before).
- Add, delete, duplicate, rename, and drag to reorder layers; nested, collapsible groups; layer masks (enable, invert, density, painting on masks); fills; adjustments (Invert, Levels, Hue/Saturation/Lightness); clipping; visibility; opacity; 26 blend modes; undo and redo.
- Select multiple layers (`Ctrl`/`Shift`-click) to delete, duplicate, group, merge, toggle visibility, move up or down one position, drag, or lock them together. Painting still targets a single layer.
- Merge layers: Merge Down (`Ctrl+E`), groups, selected layers, or Merge Visible (`Ctrl+Shift+E`). A single undo restores the original layers. If merging would change the appearance by more than one rounding step, the number of affected pixels is shown for confirmation. When merging is unavailable (no layer below, hidden layers, locks, etc.), a short reason is shown and nothing changes.
- Layer locks (alpha, pixels, position, all). Toggle them through the lock icon in a layer row (click to remove the layer's own lock), the context menu, or Lock in Properties. A group's locks apply to its contents. Locks are saved and restored in `.ylp`, PSD (`lspf`), and `.ylsmart`.
- Move / Transform (`V`). Use the bounding-box handles to move, scale (`Shift` preserves the aspect ratio), or rotate (`Shift` snaps to 15°) the selected layer, including its contents if it is a group, all selected layers if several are selected, or the selected pixels and selection itself if a selection exists. While dragging, only the transformed outline is shown. Release the pointer or press `Enter` to apply; `Esc`, loss of window focus, or switching tools cancels without changes. Arrow keys move by 1 pixel (`Shift`: 10). Rotate 90°, Flip Horizontal, Flip Vertical, numeric transforms, and interpolation (Bilinear, Nearest) are available through the Layer and Edit menus, the options bar, and Properties. Each operation can be undone in one step.
- Material painting: in the Material tab, choose channels from Color, Roughness, Metallic, Height, Normal, and Emission, and paint them in one stroke using their respective values (the drawing color for Color, a color for Emission, 0–1 for data channels, and tilt for Normal). Works in 2D, 3D, Fill, and Polygon Fill. A single undo restores all channels.
- Fill (`G`) and Polygon Fill (`4`): target triangles, mesh parts, UV islands, or materials (Fill also supports similar colors in 2D). The region under the pointer is highlighted as faces in 3D and UV outlines in 2D. Fill paints only inside the current selection. Polygon Fill adds regions as you drag and creates one undo step when released.
- Path (`P`): draw editable curves through successive points on the 2D canvas or a 3D model's surface. Click to add points, click a curve to insert a point into that segment, drag points to move them, and press `Delete` to remove them. Paths can be open or closed, with per-point width (a substitute for pressure, smoothly interpolated along the curve), a path brush (Size, Hardness, Spacing, Opacity, Flow, and toggles for width to affect Size, Opacity, and Flow), and the set of channels selected in Brush Material (painted together in one operation). Each point operation is one undo step; dragging a point redraws the path on release (`Esc` cancels, while loss of window focus commits the movement so far). Path layers cannot be painted on by hand, and locked layers refuse edits. Rasterize (also available in the layer context menu) removes the path while keeping its current pixels. 3D paths are bound to model triangles and barycentric coordinates and saved in `.ylp`. Paths drawn on a different model cannot be edited. Replacing the model rebinds paths to nearby faces of the same material and redraws them. Paths that cannot be rebound, including those that cannot be redrawn because of pixel or alpha locks, are removed while retaining the current pixels; layers with an all lock retain their binding to the previous model. The result reports counts and the first reason. Curves are Catmull–Rom curves passing through the points; there are no Bézier handles. A closed path has its first and last points at the same location, forming a corner there.
- ID Color Select (`Shift+W`): create a selection from colors in a baked ID map (`Shift` to add, `Ctrl` to subtract). You can also assign manual ID colors to individual mesh parts. Manual ID colors cannot yet be written to `.ylp`, so saving a document containing them is refused with a reason.
- Selections: combine Rectangle Select, Ellipse Select, Lasso, Polygon Select, and Magic Wand (tolerance, contiguous, all layers) using replace, add, subtract, or intersect. Modify them with Invert, Expand, Contract, Border, Feather, and Sharpen Edge. Brushes and the eraser affect only the selection. Selections are created on the 2D canvas and saved per texture set in `.ylp`.
- Symmetry: 2D offers vertical, horizontal, both, and radial (2–16), with a movable center and axes shown on the canvas. 3D offers mirroring across planes perpendicular to the model's X, Y, or Z axis and radial symmetry (2–16) around an axis. Planes can be placed at the model origin or the center of its bounds, with an option to paint copies onto hidden faces; planes and axes appear in the 3D view. A copy that misses the surface or lands on a different texture set is skipped. Symmetry cannot be combined with Smudge or Clone.
- Channels: six standard channels plus user channels (add, name, type). Choose the painting channel and the channel displayed in 2D. Each layer can have its own enable state, blend mode, and opacity per channel.
- Japanese and English interface (switch through the View menu).
- Zoom, pan, rotate, and flip the 2D view horizontally. These change only the view; saved images are not rotated or flipped.
- 2D canvas compositing: when a usable GPU is available, changed tiles are composited on the same GPU that renders the application. Compositing falls back to the CPU for software GPUs, documents whose painted tiles exceed the GPU memory budget (512 MiB; tiles have both GPU and CPU copies), sizes beyond the device's texture limit (8192 by default), or documents using features unsupported by GPU compositing (adjustment layers, isolated groups, Normal channels). This applies only to the displayed composite; saving, export, and the 3D view always use CPU results. Override the choice with the `YOLUPAINTER_CANVAS` environment variable (`auto`, `gpu`, `cpu`).
- Paint on the demo cube in the 3D view or on a model received through Live Link. Switch texture sets by material. In 3D, Size, Hardness, Flow, Opacity, pressure, color, Color Dynamics, erasing, stencils, and effect brushes (Blur, Smudge, Clone) work; image tips, Jitter, Texture, Dual Brush, Fade, pen tilt and rotation, Speed, and Stabilizer are limited to the 2D canvas. 3D Smudge and Clone sample across UV island seams. Set the clone source with an `Alt`-click released without moving. Aligned preserves the offset from the previous stroke, and All layers samples the visible layer composite.
- 3D appearance: switch between Material (PBR with the same BRDF as Unity Standard, showing Roughness, Metallic, Normal, and Emission), Neutral, and Channel in the header. A small panel provides environment (Sky, Studio), lighting, and tone-mapping settings. See [docs/PREVIEW.md](docs/PREVIEW.md).
- Open FBX models, pose them with bone rotations and BlendShapes, and paint on the posed surface (poses are not saved). Each material has a texture set; you can paint on the faces assigned to the current set's material.
- Create, open, and save `.ylp` files. See the [table below](#exchanging-ylp-files-with-the-unity-version) for compatibility with the Unity version.
- Recovery after a crash. When there are unsaved changes, a background thread writes a recovery generation 15 seconds after detecting a change (or 15 seconds after the previous checkpoint while continuously painting), after 10 completed strokes, on loss of focus, or on exit. Checkpoints are not taken during a stroke or PSD import; they wait until painting finishes. Generations use the same structure as `.ylp`, sharing unchanged sets with the previous generation. The on-disk storage layout matches the Unity version, and generations written by Unity can be read. Generations containing composite PNGs from an opened `.ylp` cannot be read by the Unity version. Checkpoint failures show a reason in the status bar without interrupting painting. On the next launch after a crash, the Recovery window lists generations (original name, number of sets, elapsed time) to open or discard. It is also available at any time through File → Recovery…. Recovered documents are named “Untitled (Recovered)” and do not overwrite the original `.ylp`; choose a destination when saving. The interval (10 seconds to 5 minutes) and retained generations (2–20) can be selected in the window and are written to `recovery.conf` (`interval`, `strokes`, `generations`, `directory`) in the settings folder. Generations from cleanly closed sessions are retained up to the configured total, while those from crashed sessions remain until discarded. If `recovery.conf` cannot be read, recovery uses the default interval and reports the reason in the status bar; because the retention setting is unknown, generations are not pruned and the configuration file is not overwritten. Composite PNGs and mesh maps are omitted from generations as derived data, although those already present in an opened `.ylp` are preserved. Layer locks and manual ID colors cannot yet be written to `.ylp`, so checkpoints for documents containing them are also refused with a reason. This has not yet been verified on physical Windows hardware.
- Mesh map baking (View → Bake Mesh Maps…). Bake world normals, position, AO, curvature, thickness, ID, and other maps from the 3D view's model for each checked texture set in a background thread, with progress and cancellation. Choose Auto, GPU, or CPU. Auto uses a usable hardware GPU if available, otherwise the CPU. If the GPU is unavailable, exceeds its budget, or fails during baking, a reason is shown and baking restarts on the CPU. GPU results are not byte-identical to CPU results: f32/f64 rounding and ray hit differences produce deviations up to roughly 3% for AO, thickness, and bent normals; measurements are in [`crates/yolu-gpu/README.md`](crates/yolu-gpu/README.md). The baking device is not saved, so rebaking with the same settings on a GPU-equipped machine can change values within those differences, including exported AO PNGs. Baked maps are saved per set in `.ylp` and can be overlaid on the 2D canvas. Maps whose model or settings have changed are marked stale and are not used for exported AO. High-poly projection cannot be selected.
- Effects (the Filter menu, Add Filter in Properties, and the layer list): indented rows below each layer show its anchors, pixel effects, mask anchors, and mask effects (higher rows are applied later). Add Gaussian Blur, Sharpen, Noise, Levels, Invert, Normalize (Layer), or generators that derive values from baked mesh maps (Edge Wear, Dirt, Position Gradient, Shape Gradient, Thickness, Direction, ID Color, Anchor) to the painting channel's pixels or a mask. Toggle effects using the eye icon, move them up or down, delete them, or click a row to show its settings in Properties (values, strength, input maps and their status, range, breakup, blending). Each operation is one undo step, and slider drags are grouped into one step. Effects cannot be added to layers locked with All, including inherited group locks; pixel, alpha, or position locks alone allow them. If a generator's input map is missing, stale, or cannot be matched to the model, its row is marked with a reason and it passes the input through unchanged; baking makes it take effect. Named anchors can be placed on layers or masks and read by an Anchor generator on a layer above. References invalidated by reordering or deletion are reported in the status area. For an ID Color generator, use Pick from ID Map in Properties, then click the 2D canvas or 3D view to add that color (`Ctrl` removes it, up to 32 colors). Shape Gradient ramps and handles in the 3D view, and baking filters into pixels, are not yet available.
- Template export (File → Export → Template). Write packed PNGs for Unity Standard / URP Lit, HDRP Lit, and lilToon into a folder for all texture sets, named `<name>[_<set-name>]_<image>.png`. Colors are extended beyond UV boundaries (padding, omitted when there is no model), and baked AO is used when available. Existing files are replaced only after confirmation. Cancellation or failure before the final replacement begins leaves the original files unchanged. Export includes the same effects as the display (filters, generators reading mesh maps, and shelf images). If effects remain inactive, for example because an input map is missing, the application reports that they are absent from the exported images.
- Import PSD (RGB8) through File → Import, either adding a new texture set or replacing the current set's document, and export through File → Export → PSD. Editable PSDs can be imported, with raster layers, groups, solid-color fills, adjustments (Invert, Levels, Hue/Saturation), masks, and clipping becoming layers. Preserve-only files, rejected files, and content the application cannot handle (such as pixels outside the canvas) show a reason and leave everything unchanged. Layer locks (alpha, pixels, position, all) are written to `lspf` on export and restored on import; bits not represented by PSD are reported in the import result. Export writes a Color copy. Inverted masks, clipped groups, translucent fills, adjustments between PSD's representable increments, content in channels other than Color, per-channel blending different from Color, filters, generators, anchors, or paths cause export to be refused with a reason. Imported PSD files are not overwritten.
- Asset shelf (Assets on the left). Use Save Layer or Save Mask to store the selected layer (including a group's contents) or its mask as a Smart Material or Smart Mask. Place shelf assets into the current texture set by double-clicking, using the context menu or Place, or dragging into the layer list. Smart Materials go between rows or inside groups; Smart Masks go onto the target row's mask. Placement is one undo step. Assets are stretched to fit texture sets of a different size. The shelf is saved in `.ylp` resources and restored on opening. Import and export external `.ylsmart` files, including by dropping them onto the window. Shelf images can be placed as individual layers. Assets containing embedded images, generator rebinding, or content the core cannot represent, such as certain filters, are listed but cannot be placed; a reason is shown. Exporting them preserves the original for use in Unity. Brushes and materials are also listed only. Layers using user channels or Noise/Grunge (generator types exclusive to the Rust version) cannot be written to `.ylsmart` and are refused with a reason; layer locks are retained in assets. After the shelf entries come 14 built-in Smart Materials (rusted iron, chipped painted metal, wood, etc.), constructed procedurally without images and all using Noise/Grunge. They can only be placed: they cannot be deleted, exported, or captured with Save Layer, and are not stored in the `.ylp` shelf. Placed groups are ordinary layers, and their `.ylp` uses document format 23 as described in the table below. The shelf holds up to 256 items; additions beyond that are refused with a reason. Save Layer for large assets or a nearly full shelf runs in a background thread, during which deletion and import are refused. Deletion and import can pause the application for several seconds on shelves of several hundred MiB, depending on shelf size.
- Stencil (the Stencil tab in Properties). Load a PNG and paint through the translucent image overlaid on either the 2D canvas or the 3D view. Grayscale images supply an amount (luminance × alpha), and color images supply color; choose Auto, Amount, or Color. Adjust repeating (horizontal, vertical, both), inversion, overlay opacity, size, and angle. The stencil stays fixed to the screen; hold `T` and drag to move it (see the [controls table](#basic-controls)). It also works with effect brushes (Blur, Smudge, Clone) in both 2D and 3D. Stencils are application state, saved neither in `.ylp` nor in brush presets, and remain when creating or opening a document. This feature has been verified in Linux tests; physical Windows Direct3D 12/Vulkan hardware, pens, and high-DPI displays have not yet been verified.
- Eyedropper (`I`): pick the value at a point in the 2D canvas or 3D view as the drawing color for the painting channel. By default it reads only the selected layer; the options bar can switch to the composite of all layers. With material painting enabled, it samples all six channels into the material values without changing the set of channels being painted. In 2D, `Alt`-click temporarily picks a value while using Brush, Eraser, Fill, or Polygon Fill (`Alt` orbits in 3D).
- Channel export (File → Export → Channel as PNG… / All Channels as Images…): export the painting channel to a single PNG, or all used channels from all texture sets into a folder. Values are the channel composites as-is, without packing or tinting; only Normal follows the file Y direction in the Normal settings. Names are `<name>[_<set-name>]_<channel>.png`. Padding beyond UV boundaries, overwrite confirmation, and cancellation work as in template export.
- Normal settings (Normal in the Channels panel): Height → Normal (strength, clamp/wrap edges) and file Y direction (OpenGL/DirectX). These document settings are saved in `.ylp` and changes can be undone. The same values apply to the 3D preview and exported Normal.
- Settings (View → Settings…): language, export padding, memory budgets (undo history and layer pixels are project-wide totals; the current texture set receives the configured budget minus the other sets' usage; the per-operation budget is also used by export, while the minimum undo count is per set; Auto derives budgets from physical memory; opening `.ylp` reads pixels up to the configured budget, with a 256 MiB minimum), CPU threads (from the next launch), display compositing (2D canvas only; save, export, and the 3D view always use CPU results), shelf location, and Backups to Keep. Only non-default values are written to `YoluPainter/settings.conf` in the settings folder. Invalid values reset only the affected setting to its default, with the reason shown in the status area.
- Fill images and projection: in a fill layer's Image field, choose the image for the painting channel by dragging from the asset shelf or clicking the field to open a list, which also allows importing a PNG file. Projection offers UV, Tri-planar, Planar, Spherical, Cylindrical, and Decal, with tiling, offset, rotation, triplanar blending, decal depth, and backface edge settings. Non-UV projections show a box and handles in the 3D view (movement arrows, rotation rings, and face-size handles; `Shift` for both sides, `Ctrl` for snapping). Use them to move the projection, and `Q` to hide or show them. Center, rotation, and size can also be entered numerically. Data channels read image values directly; color channels convert linear images to sRGB. Projection positions and normals come from baked mesh maps. While maps are missing or stale, the field shows a reason and the constant value is displayed instead of the image. Images from the shelf and positions/normals from baked maps are passed to evaluation. Sets in an opened `.ylp` remain read-only while maps or images are missing, showing the missing inputs; baking or adding images to the shelf makes them editable.
- Decals: drag a shelf image onto a model in the 3D view to add a fill layer in one undo step, oriented toward the face at the drop point and sized to the image's aspect ratio (view up becomes image up). Move it with the handles and adjust culling in Projection. Until position and normal maps are supplied for evaluation, the field shows a reason and the image is not displayed.
- World-space gradients: in a fill layer's World Space Gradient, set a Box, Sphere, or Plane volume using 3D view handles to vary values in the painting channel (except Normal). Values depend on model position, avoiding UV seams. Color stops (value stops for data channels) and opacity stops are separate, with midpoints between stops, five ramp presets, and a value curve (four presets, adding and moving points). A Position mesh map is required. Until it is supplied for evaluation, the field shows a reason and the constant value is used.
- Gradient (`Shift+G`): drag on the 2D canvas to paint a linear or radial gradient from the starting point (drawing color) to the endpoint (transparent or the secondary color), using premultiplied-alpha interpolation. It affects the painting channel of the selected layer, all selected material channels when material painting is enabled (including between two materials by setting the current material as the endpoint), or the mask when painting a mask (white/black). One undo restores it. Unavailable in the 3D view.

PNG import is limited to stencils and fill images (added as shelf images). `.ylsmart` files can be imported into the shelf.

## Download and installation

Download from [Releases](https://github.com/YozoraKurage/YoluPainter-rs/releases). Windows (64-bit) has two distribution formats.

- `yolupainter-<version>-x86_64-pc-windows-msvc-setup.exe` (installer): installs per user without administrator privileges. The default destination is `%LOCALAPPDATA%\Programs\YoluPainter` (changeable), with a Start menu entry and optional `.ylp` file association. Uninstall through Settings → Apps; you will be asked whether to remove settings, brushes, and recovery data as well (they remain if no prompt is shown). Use `/S` for silent installation, `/ASSOC=1` to enable file association (`/ASSOC=0` to disable it), and `/RUN` to launch the application after installation.
- `yolupainter-<version>-x86_64-pc-windows-msvc.zip`: extract and run `yolupainter.exe`; no installation is needed.

### Updates

On first launch, the application asks whether to check for updates at startup. Only choosing Yes enables a request to GitHub for the latest version on each launch. Change this at any time through Help → Check for Updates at Startup, or check manually through Help → Check for Updates….

When a new version is available, the Help heading shows an indicator. On Windows installed through the installer, “Update to YoluPainter x.y.z” downloads, verifies, and installs the update, asking you to save first if there are unsaved changes. Downloads are used only after verifying the signed update metadata's signature, size, and SHA-256. Portable Windows ZIP distributions and Linux open the release page instead. Applications built from source do not have update menu items; only distribution builds embed the update public key.

### Startup warning (SmartScreen)

Current distributions are not code-signed. If Windows SmartScreen displays “Windows protected your PC,” choose “More info” → “Run anyway” to launch.

## Requirements and running from source

You need the stable Rust toolchain and a C/C++ build environment. See the [Rust installation instructions](https://doc.rust-lang.org/book/ch01-01-installation.html). Obtain and extract the source, then run the following commands in the folder containing `Cargo.toml`. The first build needs an internet connection to download dependencies.

The display requires a GPU and compatible driver. Rendering uses [wgpu](https://docs.rs/wgpu/30.0.1/wgpu/struct.Backends.html): Direct3D 12 or Vulkan on Windows, Metal on Mac, and Vulkan or other backends on Linux. Unity is not required to run the application on its own.

### Windows

Prepare 64-bit Windows, Visual Studio Build Tools with “Desktop development with C++” (including the Windows SDK), and Rust's MSVC toolchain. Run in PowerShell:

```powershell
cargo build --release -p yolu-app --locked --target x86_64-pc-windows-msvc
.\target\x86_64-pc-windows-msvc\release\yolupainter.exe
```

For pen tablets, enable Windows Ink in the tablet driver too. The pen buttons in the brush's Tool Properties select which settings respond to pressure. If the pen's pressure is too strong or too weak, adjust it in View → Pen Pressure….

### Mac (experimental)

Install Xcode Command Line Tools and Rust, and run on a system with Metal support.

```sh
cargo build --release -p yolu-app --locked
./target/release/yolupainter
```

There is no dedicated pen input handling equivalent to Windows Ink. Mouse operation is the baseline; pressure input depends on the OS and input device. The current Unity bridge build tool does not generate a Mac library.

### Linux (experimental)

Prepare a C/C++ compiler, `pkg-config`, an X11 or Wayland desktop, and a GPU driver. File dialogs require a D-Bus session, `xdg-desktop-portal`, and a portal backend for your desktop. The interface font (BIZ UDPGothic) is embedded in the executable, so a system Japanese font is not required.

Example package names on Debian/Ubuntu are `build-essential`, `pkg-config`, `libxkbcommon-dev`, `libwayland-dev`, `libvulkan1`, `xdg-desktop-portal`, and `xdg-desktop-portal-gtk`. Use the appropriate GPU driver for your hardware.

```sh
cargo build --release -p yolu-app --locked
./target/release/yolupainter
```

You can paint with a mouse. Pressure input depends on the desktop environment and input device.

## Basic controls

At startup, a 2048 × 2048 canvas and a demo cube appear. Choose a color in the Color panel and left-drag in the 2D or 3D view to paint. Select the painting layer in the Layers panel and add layers from the Layer menu as needed.

| Action | Input |
|---|---|
| Brush / Eraser | `B` / `E` |
| Fill / Gradient / Polygon Fill / ID Color Select | `G` / `Shift+G` / `4` / `Shift+W` |
| Path (click to add points, insert on a curve, or drag points) | `P` |
| Delete the selected path point (or the last point if none is selected) | `Delete` / `Backspace` |
| Smaller / larger brush | `[` / `]` |
| Selection tools (Rectangle Select / Ellipse Select / Lasso / Polygon Select / Magic Wand) | `M` / `Shift+M` / `L` / `Shift+L` / `W` |
| Select All / Deselect / Invert Selection | `Ctrl+A` / `Ctrl+D` / `Ctrl+Shift+I` |
| Add / subtract / intersect selection | `Shift` / `Ctrl` / `Shift+Ctrl` + drag with a selection tool (also available in the options bar) |
| Button bar below the selection (deselect, invert, expand, contract, fill, clear, copy to a new layer, make a mask) | Appears below a selection (move it using the handle at the left; hide it through the Select menu). Clear: `Delete`; copy to a new layer: `Ctrl+J` (`Ctrl+J` duplicates the layer when there is no selection) |
| Close a polygon / remove its last point | `Enter` (or click the first point or double-click) / `Backspace` |
| Move / Transform tool | `V` (drag to move, scale, or rotate; arrow keys move 1 pixel, or 10 with `Shift`; `Enter` commits during a drag, `Esc` cancels) |
| Select layers (toggle / range / add range) | `Ctrl`-click / `Shift`-click / `Ctrl+Shift`-click in the Layers panel |
| Merge Down / Merge Visible / Duplicate / Group | `Ctrl+E` / `Ctrl+Shift+E` / `Ctrl+J` (copies the selection to a new layer if a selection exists) / `Ctrl+G` |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z` or `Ctrl+Y` |
| Copy / Cut / Copy Merged / Paste | `Ctrl+C` / `Ctrl+X` / `Ctrl+Shift+C` / `Ctrl+V` (also in the Edit menu) |
| Cancel the current stroke, selection operation, or path point drag (otherwise deselect the point) | `Esc` |
| Zoom in 2D | Wheel, or `Ctrl+Space` + left-drag horizontally around the pressed point; releasing without moving zooms in, or out with `Alt` |
| Pan in 2D | Middle-drag, or `Space` + left-drag |
| Rotate in 2D | `R` + left-drag, or `Shift` + middle-drag |
| Reset 2D rotation / flip horizontally | `Shift+R` / `H` |
| Fit 2D to the view | `Ctrl+0` |
| Rotate / move / resize the stencil | Hold `T` and left-drag (`Shift` snaps to 15°) / middle-drag or `Ctrl` + left-drag / right-drag or `Alt` + left-drag (both 2D and 3D) |
| Bypass the stencil | Hold `N` |
| Orbit in 3D | Right-drag, or `Alt` + left-drag |
| Hide / show fill projection and gradient box handles | `Q` |
| Pan in 3D | Middle-drag, `Space` + left-drag, or add `Shift` to an orbit gesture |
| Zoom in 3D | Wheel, or `Ctrl+Space` + left-drag (as in 2D) |
| Pen | Side buttons act as the right button; `Alt`, `Space`, `Ctrl+Space`, and `R` work as with the left mouse button. Only an unmodified pen tip (or eraser end) with no side buttons pressed paints |
| New / Open / Save / Save As | `Ctrl+N` / `Ctrl+O` / `Ctrl+S` / `Ctrl+Shift+S` |

Copy and Cut take pixels from the selection (or the entire layer if there is no selection) in the painting channel, or the mask if painting a mask, and also put the same pixels on the OS clipboard as an image. Paste creates a new layer and accepts images copied from other applications; images larger than the texture set cannot be pasted. On Linux, the OS clipboard uses Wayland when data-control is supported, otherwise X11.

On Mac, read `Ctrl` in this table as `Command`; menus still display `Ctrl`. You can also open `.ylp` files by dragging them onto the window. If you lose sight of the model, use View → Frame the Model in the 3D View. To restore panels, use View → Reset Panel Layout.

## Live Link with Unity

Connect to the Unity Editor running on the same PC. A Unity 2022.3 project needs **a Live Link-enabled version of YoluPainter for Unity (VPM package `net.yozolab.yolupainter`) and the native bridge for your OS**. Versions without `YozoLab → YoluPainter → Live Link` cannot use this connection. The bridge is `yolu_bridge.dll` on Windows and `libyolu_bridge.so` on Linux.

1. Start the standalone application and enable File → Live Link. The status area at the bottom shows that it is waiting for Unity.
2. In Unity, open `YozoLab → YoluPainter → Live Link`, set `Link name` to `yolupainter-livelink`, and press `Connect`.
3. Specify the model's GameObject in the scene. Press `Use selection` to use the current selection, then `Send model`.
4. Select a material in the standalone application's Texture Sets panel and paint in the 2D or 3D view. The composite of the displayed set is sent to Unity when that set has a Color destination in Unity.
5. Save your work as `.ylp`. End the connection with `Disconnect` in Unity or File → Live Link in the standalone application.

Unity temporarily displays painted colors on materials such as lilToon and Standard. This does not write to the original texture or material assets, and disconnecting removes the temporary display. Live Link does not save your working file; save it in the standalone application.

Only programs running as the same user on the same PC can connect. Every time the standalone application starts listening, it creates a random key in a folder accessible only to that user: `%LOCALAPPDATA%\YoluPainter\LiveLink` on Windows; `$XDG_RUNTIME_DIR/yolupainter` or `/run/user/<UID>/yolupainter` on Linux, falling back to `/tmp/yolupainter-<UID>`; and `/tmp/yolupainter-<UID>` on Mac. The Unity bridge proves knowledge of the key during the handshake and sends the model only after verifying that the standalone application also knows it. The connection endpoint (socket or named pipe) and shared-memory files carrying pixels are also accessible only to that user. Older versions without key support are refused with a reason in the status area; use matching versions of the standalone application and Unity package. When listening starts, shared-memory files left by a crashed standalone application are cleaned up. Other programs running as the same user can read the key file and connect.

Only one Unity instance can connect at a time. Version mismatches and listening failures appear in the status area. Restart Unity after updating the bridge. To change the connection name, set the `YOLUPAINTER_LINK_NAME` environment variable before launching the standalone application and use the same name in Unity.

## Exchanging .ylp files with the Unity version

| Content | Handling in the standalone application |
|---|---|
| `.ylp` formats 1–7, internal document formats 1–23 | Readable. Saving updates the file to `.ylp` format 7; document format depends on the features used (21, 22, or 23, as described in the user channel and Noise/Grunge rows) |
| Raster layers (six standard channels), groups (pass-through/isolated), masks, fills, adjustments (Invert, Levels, Hue/Saturation/Lightness), clipping, layer locks (alpha, pixels, position, all), per-channel enable and blending, Normal settings | Editable and saveable. Document/layer IDs and RGB values of transparent pixels are preserved. Locks use the document format 12 attribute layout; documents without locks retain the same bytes as before |
| User channels | Editable and saveable. Only sets with user channels are saved in document format 22. Unity versions supporting only document formats up to 21 (such as 0.2.0) cannot open that `.ylp` |
| Noise/Grunge (generator types exclusive to the Rust version, including disabled stages) | Editable and saveable. Only sets containing these stages use document format 23. Unity versions supporting only document formats up to 21 (such as 0.2.0) cannot open that `.ylp`. Removing the stages and saving returns the set to format 21 (22 with user channels). They cannot be written to `.ylsmart` (format 1) |
| Mesh maps (per-set `meshmap-<kind>.bin`) | Loaded and saved. Only newly baked, unsaved maps are written; maps present when opening are preserved as-is. Maps whose model or settings differ from the current ones are marked stale and not used |
| Filters (layers/masks), Anchor, 2D/3D paths | Editable and saveable. Settings are preserved and evaluated during compositing, so effects appear on screen and in exported composite PNGs |
| Generators using mesh maps or images; fill images, projections, gradients; decals | Editable and saveable. Evaluation receives mesh maps baked for the current conditions, the model root, and shelf images. On opening, sets with effects lacking inputs (missing, stale, or unverifiable maps, or images absent from the shelf) are read-only: the saved composite is displayed, the original document is preserved, and missing inputs are listed. Once inputs are available (by baking, loading a model, or adding shelf images), the same set becomes editable. Settings that can be fixed within the document, such as no selected anchor or no ID colors, do not make a set read-only |
| Manual ID colors | Sets containing them are read-only, with a reason shown, and the original document is preserved. Manual ID colors can be assigned in the standalone application, but saving a document containing them is refused with a reason |
| Appearance of read-only sets | Displays the saved Color composite. If it is missing or unreadable, an empty view and a reason are shown |
| Asset shelf (`resources.json` and `resources/`: images, brushes, materials, Smart Materials, Smart Masks) | Loaded and saved. Rewritten only when the shelf changes, with YoluPainter-rs as the writer; otherwise the original bytes are preserved. Smart Materials and Smart Masks added by this application use `.ylsmart` (format 1), readable by Unity |
| Unedited sets, embedded resources, unknown additional entries | Original data is preserved when saving |
| Newer formats, unknown values, damaged files | Opening is refused with a reason |

To return a file to Unity, use a version that reads `.ylp` format 7 and document format 21. If a `.ylp` contains sets with user channels or Noise/Grunge, remove those features and save again first. There is no conversion to formats for older Unity versions. Read-only sets retain their original editing data when saved instead of being replaced by flattened composites. However, saved images may not reflect a fresh evaluation of the latest effects.

Edited sets are saved in document format 21 (22 with user channels, 23 with Noise/Grunge), along with composites of the standard channels in use. Undo history is not saved. Identical ZIP bytes for the entire `.ylp`, window layouts, and model connection state across the two applications are not guaranteed.

The version immediately before an overwrite is kept in `<filename>-backups~/` beside the file. By default all backups are retained without automatic deletion. Backups to Keep in View → Settings… lets you retain the newest 0–1000 backups (0 keeps none); only older backups beyond that count are removed. The destination filename must end in `.ylp`; missing destination folders are created. If another application has changed the file since it was opened, overwriting is refused. Do not edit the same file simultaneously in both applications: save, then reopen it in the other application.

## Code signing policy

Current distributions (installers and executables) are not code-signed. As usage grows, we plan to apply for free code signing from the [SignPath Foundation](https://signpath.org/).

- Author (source changes), reviewer, and signing approver: all roles are held by [YozoraKurage](https://github.com/YozoraKurage) (one person).
- Privacy: the application does not send information over the network except to query GitHub for the latest version when you choose to check for updates (by enabling Check for Updates at Startup or selecting Check for Updates…). The query is an ordinary HTTPS request to fetch an update metadata file. Apart from the application name and version in the User-Agent, no information identifying the user is included. Live Link communicates only within the same machine.
  This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

## Measuring CPU performance together

On Linux, run `tools/bench-all.sh --runs 5 --threads 4` to run the existing Rust and C# compositing, brush, and surface benchmarks in sequence with the same repeat count, thread limit, and CPU allocation.
A comparison table is written to `target/bench-all/summary.md`, with logs and run conditions in the same location. Requires Python 3.10 or later, taskset, and the Unity-bundled C# tools mentioned above.
Use `--source DIR` to specify the Unity version's location, or options such as `--only blur` to limit M2 brush types (compositing, the regular brush, and surface benchmarks always run).
Compositing and brush results use medians excluding two warm-up runs; surface results use medians without warm-up. Filters include Levels and the Blur/Smudge brushes. GPU and comprehensive coverage of standalone filters are outside the scope.
